    Фиксы по диалогу — что поправить (чтобы не потерять)¶

    Вопрос 1: Откуда intent → whitelist, что если LLM вернула не из whitelist¶

    • Источник: хард-оверрайд (5) → LLM 25 шаблонов → regex-fallback
    • Whitelist проверяет любой intent после трёх источников
    • Если LLM вернула id не из 5 YAML → не падать, canExecute=false → NO_ROLL + лог whitelist blocked {dslId} для дообучения
    • Не переклассифицировать вторым вызовом LLM (дорого), NO_ROLL + лог

    Вопрос 2: 25 шаблонов vs 150 команд¶

    • 25 — шаблоны с параметром, 150 — их конкретики
    • Пример: CHECK{skill} покрывает 16 CHECK_*, ATTACK{type} — 7 ATTACK_*
    • LLM видит 25, whitelist хранит 150 для точных условий CHECK_PERCEPTION false / INVESTIGATION true — мапим CHECK{investigation} → CHECK_INVESTIGATION при проверке
    • 150 не выкинуты, 25 — интерфейс

    Вопрос 3: Хард-оверрайд vs LLM — конфликт¶

    • Примеры: надеваю на него наручники → EQUIP (должен GRAPPLE), разведи огонь в его глазах → CAMP (должен SOCIAL), прячусь за спину союзника → HIDE (должен DEFEND)
    • Фикс: оверрайд только слово + цель/контекст: надеваю + SELF + предмет в инвентаре → EQUIP, иначе → LLM; разведи огонь без в глазах → CAMP, иначе LLM
    • Если оверрайд сработал но whitelist режет → откат в LLM

    Вердикт: хард-оверрайд vs whitelist — дублирование, вариант C¶

    • A убрать полностью → NO_ROLL вместо действия — не ok
    • B контекстный оверрайд → возвращает regex-хрупкость
    • C минимальный оверрайд (2-3 очевидных) + LLM + whitelist — выбран 
      hard_override:
  - "надеваю\\s+(молот|меч|шлем|броню...)" + SELF → EQUIP
  - "снимаю\\s+(молот|меч|шлем...)" + SELF → UNEQUIP
  - "прячусь$|прячусь\\s+в\\s+(тени|укрытии)" + SELF → HIDE
      Остальное — LLM + whitelist

    Вопрос 4: Валидатор vs Whitelist — дублирование (ATTACK без врага)¶

    • Сейчас оба режут ATTACK без врага
    • Решение: Whitelist первичен (YAML — дизайн, аудит), Validator — тонкая обёртка targetType + вызов whitelist.canExecute
    • Из Validator убрать дубли hasEnemy/hasSpellSlots, оставить только targetType и ALLOW для NO_ROLL

    Вопрос 5: NO_ROLL — что дальше (социал→каст→NO_ROLL)¶

    • NO_ROLL — финал для движка (нет HP/XP), но не для игрока: narrator.narrate всё равно идёт → игрок получает ответ без кубика
    • Проблема: социал→CAST→NO_ROLL = фрустрация Ничего не произошло вместо социал-проверки
    • Риски: второй LLM вызов дорого, fallback по "кастую" — эвристика, переклассификация может ошибиться (CAST со слотами vs без)
    • Вердикт C гибрид — выбран:
    • CAST без слотов + без "кастую" → SOCIAL без LLM (контекст)
    • CAST со слотами → NO_ROLL + лог (LLM ошиблась)
    • Логировать все whitelist blocked для промпта
    • A убрать оверрайд → NO_ROLL — не ok, B контекстный оверрайд → хрупкость, C гибрид — баланс

    Вопрос 6: XP — кто начисляет (уточнения)¶

    • Слой XP — только движок (TurnResolver → GainXp), LLM описывает
    • Сейчас: hide 15, check 25-75, социал 25, открыл/взломал 25, убил 50-300, задание 100-300, NO_ROLL 0 + xpTriggers разово
    • Уточнения — per-location/per-object/per-NPC, не per-rest (иначе фарм отдыхом):
    • hide_success → !scene.hasHidden, check_success → !scene.hasSearched, search_room_01 + location:room_01
    • Убил → !enemy.defeated, задание → !quest.completed, сундук → !object.isOpened, социал → !npc.isPersuaded
    • Баланс: исследование 15 → 50 если первое, + milestone 50 за сцену, иначе бой выгоднее
    • Фикс: xpTriggers: Set<location/object/npc/enemy> сбрасывать не на rest, а по флагу объекта

    Вопрос 7: Состояния — кто накладывает¶

    • Слой состояний — только движок (ApplyStatus + statusDurations + tickDurations), LLM описывает, XP не даётся
    • Сейчас: isIncapacitated блокирует ход, Скрыт→advantage, Уклонение→disadvantage, tick в конце хода
    • Дыры: 7.1 только isIncapacitated — нет Restrained/Grappled/Prone → нет движения, Blinded/Deafened → нет восприятия; 7.2 whitelist/validator не проверяют statuses и не сообщают причину Парализован; 7.3 duration=1 без saveEnds CON DC12 — не канон (спасбросок каждый ход)
    • Фикс: canMove/canAttack/canSpeak по statuses, связь statuses→whitelist + сообщение причины, tick в конце + saveEnds
    • [x] 7.1 canAct/canMove/canSpeak/canAttack/canPerceive по statuses (GameState) + blockedCapabilityReason
    • [x] 7.2 TurnResolver блокировка хода с причиной вы Парализован
    • [x] 7.3 saveEnds CON DC12 в конце хода: успех снимает статус (натуральные 20/1 — крит/фейл) + tick в конце

    Вопрос 8: Реакции — не обрабатываются¶

    • Реакция — триггер движка, не intent игрока; сейчас только OPPORTUNITY_ATTACK, нет Shield/Counterspell/Hellish Rebuke + 12 feat-реакций
    • Дыры: 8.1 выбор игрока (модалка использовать реакцию?, не автоматика); 8.2 16+ реакций в whitelist; 8.3 разные триггеры ENEMY_LEAVES/PLAYER_TAKES_DAMAGE/ENEMY_CASTS/PLAYER_FALLS → реакции; 8.4 экономия 1/раунд reactionUsedThisRound
    • Фикс: reaction_triggers.yml + whitelist REACTION: hasReaction && !reactionUsedThisRound + предложение реакции игроку
    • [x] 8.4 экономия: hasReaction в whitelist (ActionParser/SessionService ctx) + OPPORTUNITY_ATTACK/SHIELD/COUNTERSPELL/HELLISH_REBUKE gated + тесты
    • [x] 8.2 каталог: 16 реакций в reaction_triggers.yml (3 триггера), ReactionTriggerRegistryTest
    • [x] 8.3 триггеры (базовые): reaction_triggers.yml + ReactionTriggerRegistry + availableReactions в TurnResponse; триггеры PLAYER_TAKES_DAMAGE/PLAYER_FALLS → SHIELD/HELLISH_REBUKE/UNCANNILY_DODGE/DEFLECT_MISSILES/FEATHER_FALL/SLOW_FALL; ENEMY_LEAVES/ENEMY_CASTS отложены (нет модели действий врага)
    • [x] 8.1 выбор игрока: ReactionResolver (16 кодов) + SessionService.processReactionTurn (ретроактивный follow-up ход) + TurnRequest.reaction в OpenAPI + ReactionModal на фронте; ReactionResolverTest

    Вопрос 9: Множественные действия¶

    • Составные Атакую и отступаю → сейчас 1 intent, отступаю теряется
    • Фикс: LLM сплитит ["Атакую","отступаю"] → whitelist + actionEconomy 1 Action+1 Bonus+Move
    • Дыры: 9.1 порядок важен MOVE→ATTACK ok, ATTACK→DISENGAGE нет — обрабатывать последовательно, блокировать второе; 9.2 тип в whitelist (HIDE у плута Bonus); 9.3 остаток движения movementUsed+planned>total; 9.4 реакции вне хода; 9.5 Action Surge исключение extraAction
    • ATTACK+DISENGAGE 2 Action → NO_ROLL выбери одно, ATTACK+HIDE(Bonus) у плута → OK

    Вопрос 10: Концентрация — кто следит¶

    • Слой концентрации — только движок (concentrationSpell + activeModifiers + tickDurations), LLM описывает
    • Сейчас: новый конц. каст сносит старый, NO_ROLL/HIDE не трогают
    • Дыры: 10.1 DC = max(10, dmg/2) не 10; 10.2 auto-drop при Incapacitated/Unconscious/Paralyzed/Stunned/Petrified без спасброска; 10.3 DISMISS_SPELL добровольно; 10.4 урон от окружения тоже триггерит; 10.5 множественные спасброски по источникам
    • Фикс: DC = max(10, dmg/2), if Incapacitated → drop, DISMISS_SPELL, onDamage(any) → save, per source save

    Вопрос 11: LLM-нарратив vs результат — валидация¶

    • Результат известен движку, LLM должна писать промах→промахнулся, но может попал
    • Дыры: 11.1 поиск слов хрупок не попал ловит попал; 11.2 patch ломает смысл; 11.3 retry 1 + fallback шаблон MISS→промахнулся; 11.4 флейвор промах но отступил не ошибка; 11.5 Structured Output {"narrative":..., "hits":false} надёжней regex
    • Фикс: retry 1 + fallback шаблон, Structured Output если GigaChat умеет JSON, гибкая проверка только явных убил/попал vs промах

    Вопрос 12: Смерть и спасброски¶

    • Слой смерти — только движок (HP 0 → Без сознания, deathSave 0/0, 3 успеха→Стабилен, 3 провала→CharacterDied/RestoreCheckpoint 50%), LLM описывает
    • Дыры: 12.1 авто-спасбросок каждый ход без текста игрока; 12.2 20→1 HP / 1→2 провала; 12.3 урон по бессознательному автокрит +2 провала, dmg>maxHp → мгновенно; 12.4 лечение→1 HP, стабилизация→без сознания; 12.5 RestoreCheckpoint permadeath/keep_xp; 12.6 массивный урон
    • Фикс: auto DEATH_SAVE в начале хода, 20/1 криты, damage>maxHp → isDead, heal→1 HP, massive damage

    Вопрос 13: Инициатива — кто определяет¶

    • Слой инициативы — только движок (d20+Лов игрок, d20+Dex враг, сортировка), LLM описывает ты быстрее
    • Сейчас: игрок → applyEnemyTurn без очереди, Dex не кидается
    • Дыры: 13.1 один раз за бой, новый враг вставляется; 13.2 сюрприз пропуск хода; 13.3 0 HP вне очереди; 13.4 групповая один/индивидуально; 13.5 легендарные вне хода; 13.6 сброс при выходе из боя → новая инициатива
    • Фикс: rollInitiative() при enemyAppeared + combatStarted флаг, surprise failedPerception, legendaries after_player_turn

    Вопрос 14: Отдых и восстановление¶

    • Слой отдыха — только движок (RestService 1ч 1 Hit Dice d6-d12 по классу краткосрочный, 8ч HP 100% ½ Hit Dice spellSlots длительный), LLM описывает костёр
    • Сейчас: Hit Dice всегда d8, игрок не выбирает 1..N, длинный снимает Poisoned (не канон), short<2 хаус-рул, нет прерывания ≥1ч и 24ч окна
    • Дыры: 14.1 d8 не универсален d6-d12; 14.2 игрок выбирает 1..N HD (heal = roll(NdX)+CON*N); 14.3 длинный не снимает Poisoned а -1 Exhaustion; 14.4 лимит 2/день не канон; 14.5 прерывание ≥1ч сброс; 14.6 24ч окно longRest
    • Фикс: hitDie по классу, shortRest(toSpend), longRest → Exhaustion-1, onInterrupt(60), 24h флаг

    Итог — архитектура intent как контракт (14 слоёв)¶

    Движок детерминированно считает HP/урон/XP/лут/состояния/концентрацию/смерть/инициативу/отдых, LLM — только enum 25 шаблонов + нарратив. Защита 3 уровня LLM → Валидатор(target) → Whitelist(YAML) + NO_ROLL с нарративом. Все 14 слоёв отделены, фарм закрыт per-location, HIDE не дропает, социал≠каст.

    Тест-план e2e: дроп и лут предметов¶

    Автоигрок tools/e2e-player/. Прогон: каждый кейс ×3 итерации с ротацией стилей игрока (осторожный тактик / импульсивный авантюрист / внимательный исследователь) и разными классами персонажей. Дата: 2026-10-27.

    1. Область покрытия (карта механики по коду)¶

    Механика Код Как тестируем
    Подбор с земли (LOOT-интент) TurnResolver.resolveLoot (kt:3644) — матч по имени/itemNameMentioned, первый подошедший debug-хук drop_item + say/agent_goal
    Матчер коротких имён ItemSearch.itemNameMentioned (kt:38): слово >3 символов — contains; 2-3 — граница слова слева падежи, частичные имена, «меч»
    Килл-лут LootTable.rollForEnemy (kt:24): шанс по maxHp (25/50/70/90%), elite (archetype elite_*/hp≥50) — ×2 шанс и +1 предмет; pity: hp<50% → шанс ≥90% + potion-bias spawn_enemy + бой; elite_1 (hp 30) → дроп 100% ×2 (детерминированный)
    Дедуп на земле SessionService ItemDropped (kt:3244): одноимённый предмет на земле не дублируется два одинаковых drop-хука
    Стек при подборе PickUpItem (kt:3255): одноимённый в инвентаре → quantity += подбор двух одинаковых зелий по очереди
    XP за подбор resolveLoot: GainXp(nonCombatXp(10)) xp increased_from_setup
    Использование (USE_ITEM) resolveUseItem (kt:3208): зелье → Heal (hpBonus каталога, иначе 2d4); свиток с damageBonus → урон врагу; стоп-слова «яд»; fuzzy-склонения drop+pickup+use цепочки
    Экипировка resolveEquip (kt:3298): equip/unequip, идемпотентность, swap в слоте drop+pickup+equip цепочки
    Нарративная выдача GRANT_ITEM/GRANT_UNIQUE + gift-fallback (SessionService kt:1506-1711), гейт lootGrantJustified наблюдательные кейсы (LLM-зависимые)
    Лут в бою LOOT ∈ provokingIntents (kt:3725) — подбор в бою провоцирует контратаку предмет на земле + активный враг
    Контейнеры LootTable.rollForContainer (kt:97): «обыск сундука» → 60% дроп наблюдательный (сцена от LLM)

    Группа A. Подбор с земли (детерминированные, хук drop_item)¶

    # id Сетап Шаги DoD
    L-01 loot_pickup_single drop «Клинок», rogue agent_goal «подбери оружие» «Клинок» в инвентаре; нет на земле
    L-02 loot_pickup_declension drop «Клинок», fighter say «подбираю клинок» (вин. падеж) в инвентаре; нет на земле
    L-03 loot_pickup_partial_name drop «Рунический Меч», ranger say «поднимаю меч» (часть имени) «Рунический Меч» в инвентаре
    L-04 loot_short_name (сущ.) drop «Меч», rogue say «подбираю меч» в инвентаре
    L-05 loot_dropped_item (сущ.) drop «Клинок», rogue agent_goal в инвентаре; нет маркера item_already_owned
    L-06 loot_pickup_multiple drop «Клинок» + «Кинжал», monk agent_goal «подбери оба предмета», ≤4 ходов оба в инвентаре; земля пуста
    L-07 loot_pickup_specific_of_many drop «Клинок», «Сапоги», «Амулет»; paladin say «подбираю сапоги» «Сапоги» в инвентаре; «Клинок» и «Амулет» остались на земле
    L-08 loot_pickup_all_wording drop «Клинок» + «Кинжал»; barbarian say «подбираю всё, что лежит» ожидание: хотя бы один предмет подобран. Дефект-кандидат: resolveLoot без имени → «Рядом нет предметов»
    L-09 loot_pickup_nonexistent земля пуста; wizard say «подбираю драконий ятаган» description «Рядом нет предметов»; инвентарь и XP неизменны
    L-10 loot_pickup_twice drop «Клинок»; fighter подобрать, затем повторный say второй ход — «нет предметов»; в инвентаре ровно 1 «Клинок» (quantity=1)
    L-11 loot_pickup_stacking drop «Зелье лечения» (POTION); cleric подобрать → повторный drop хук → подобрать предмет в инвентаре с quantity=2
    L-12 loot_ground_dedup два drop-хука «Клинок» подряд; bard без ходов, check на земле ровно 1 «Клинок» (droppedItems[1] absent)
    L-13 loot_pickup_xp_reward drop «Клинок»; sorcerer подобрать xp increased_from_setup (+10)

    3. Изменения в инструменте¶

    • predicates.py: новый оператор present (путь существует и не пуст — отрицание absent) для DoD «дроп выпал» (L-14).
    • Остальное — существующие средства: drop_item/set_state/spawn_enemy хуки, loot_if_dropped, turn-DoD, forbidden_markers.

    4. Процедура¶

    1. Написание сценариев (субагент, паттерны из README и существующих сценариев).
    2. Smoke: 3 репрезентативных кейса ×1 (A, C, D группы).
    3. Полный прогон: 35 кейсов ×3 = 105 ранов, батчами (отчёт пишется в конце процесса).
    4. Анализ report.md + jsonl: FAIL — дефекты движка; FLAKY — расследование до первопричины.
    5. Фикс дефектов движка (только основной агент), юнит-тесты cd backend && ./gradlew :app:test -q.
    6. Перепрогон исправленного + полный регресс лута ×3.
    7. Devlog 176, коммиты fix(rules)/test(tools), пуш.

    5. Известные ограничения (не дефекты)¶

    • Дроп с обычных врагов вероятностный — условный подбор loot_if_dropped (skip при невыпадении ≠ FAIL).
    • «Подбираю всё» без имени предмета — ожидаемый дефект-кандидат L-08 (resolveLoot матчит только по имени).
    • GRANT_ITEM из нарратива — LLM-зависим, кейсы группы F наблюдательные.
    • Один предмет за ход подбора (firstOrNull в resolveLoot).

    Движок правил¶

    B-01 — Классификация действий¶

    Severity: high
    Источник: GP-1, GP-2, GM2 (эпизоды «шарики → Сила», «невидимость → атака»)

    Проблема: TurnResolver определяет тип действия по наивным regex-подстрокам. Примеры из сессии: - «создать заклинание невидимости» → матч заклин в ATTACK_PATTERN → атака по AC, «Промах». - «призрачные шарики, которые сильно…» → матч сил в STRENGTH_PATTERN → «Проверка: Сила 10» с модификатором −1.

    Корень: TurnResolver.kt:171 (заклин в атаке), :174–175 (сил без границы слова).

    Критерий: - Заклинания не попадают в resolveAttack; появляется отдельный resolveSpell с характеристикой заклинателя (Интеллект/Мудрость/Харизма) и своим DC. - Регулярки учитывают границы слов; физические характеристики не применяются к магии. - Суммон разрешается отдельно от атаки и от generic-броска.

    B-02 — No-roll для не-действий¶

    Severity: medium
    Источник: GP-3

    Проблема: Описание сцены, бег без опасности и суммон кидают бессмысленный d20 через resolveGeneric (в сессии: 15, 18, 10), который не влияет на нарратив и создаёт шум.

    Критерий: - Категория no-roll для чистого описания/безопасного перемещения. - Суммон (голем/оружие) разрешается по своей механике с учётом стоимости (см. B-07).

    B-03 — Полная формула броска и объявление DC/AC до броска¶

    Severity: high
    Источник: GP-5, GM2#3, GM2#4

    Проблема: - В карточке атаки не показан бонус игрока: «Атака: AC 10, d20 = 12, итого 12». - DC/AC цели не объявляется до броска. - AC захардкожен как 10 для всех целей (TurnResolver.kt:42).

    Критерий: - Всегда выводить полную формулу: d20 + модификатор = итог. - Объявлять Сложность N (проверка) или AC N (атака) до броска. - AC берётся из профиля противника, а не из константы.

    B-04 — Модель противника: HP/AC, ход NPC, контратаки¶

    Severity: high
    Источник: GP-4, GP-5, GM2#5

    Проблема: Враги существуют только в нарративе LLM. Волк и нага ни разу не бросили собственную атаку, не нанесли урон, не имеют HP/AC. Игрок не рискует.

    Критерий: - Сущность Combatant (hp, maxHp, ac, attackBonus, damageDie). - После хода игрока, если противник жив и в бою, детерминированный ход NPC: бросок атаки, урон/эффекты по персонажу. - В UI отображается состояние врага (HP, AC).

    B-05 — Один ход = одно действие; последствия провала¶

    Severity: high
    Источник: GM2#5, GP-4

    Проблема: Провал невидимости не дал последствий — игрок в том же ходу переключился на атаку шариками. Одно действие «добивается» за счёт другого броска.

    Критерий: - Один ход игрока = одно действие. - При провале ГМ описывает последствия (например, нага атакует с преимуществом) и спрашивает, как игрок реагирует, а не даёт бесплатное повторное действие.

    B-06 — Прогресс цели и условия победы¶

    Severity: medium
    Источник: GP-8

    Проблема: Игрок не видит, сколько урона нанесено врагу и сколько осталось. Нет чёткого итога боя (смерть врага / победа).

    Критерий: - После урона показывать оставшееся HP цели (Кровавый волк 4/15 HP). - При смерти врага движок фиксирует enemyDefeated и передаёт в нарратив.

    B-07 — Стоимость магии и «цена успеха»¶

    Severity: medium
    Источник: GP-7, GM2#7

    Проблема: Призыватель бесплатно призывает голема, секиру, орбы, невидимость. Успехи почти не имеют осложнений — игра превращается в «walkthrough».

    Критерий: - Ресурс магии (мана/слоты/перезарядка); resolveSpell/resolveSummon списывает стоимость. - Нехватка ресурса отклоняет действие до броска. - Возможна «цена успеха» (голем истощён, вспышка привлекает врагов) — через движок или правила нарратива (см. B-08).

    Нарратив ГМа (промпт / LLM)¶

    B-08 — Убрать варианты-подсказки ГМа¶

    Severity: high
    Источник: GM2#1 (главная проблема)

    Проблема: Каждый раунд ГМ перечисляет 3 варианта: «можете приказать голему… Также можете отступить… Или же можете осмотреться…». Игрок превращается в выбиральщика меню.

    Критерий: - Запрет на перечисление вариантов в системном промпте. - Вместо вариантов — чистое описание ситуации + вопрос «Что делаешь?». - Косвенная помощь — через детали окружения (треснувший свод, тенистый проход), без явного списка действий.

    B-09 — Порядок «бросок → результат → нарратив»¶

    Severity: high
    Источник: GM2#2, GP-6

    Проблема: Описание успеха/провала идёт до броска: в эпизоде с невидимостью ГМ пишет «заклинание распадается» до показа «Промах». Если бы бросок был успешным, нарратив стал бы ложным.

    Критерий (жёсткая последовательность): 1. Игрок озвучивает действие. 2. ГМ объявляет проверку (кость, характеристика, DC). 3. ГМ генерирует/показывает бросок. 4. Вердикт «Успех»/«Провал» отдельной строкой. 5. Только после этого — нарратив, соответствующий результату.

    B-10 — Качество вывода: дубли, связность¶

    Severity: medium
    Источник: GM2#6

    Проблема: В вводной сцене дважды написано «Стив только попал… оглянувшись…» — артефакт генерации.

    Критерий: - Правила в промпте против повторов/самокопирования. - Пост-обработка/проверка связности первого нарратива (проверка повторов фраз).

    Сессия 30.08.2026 — «след кабана» (новые наблюдения, живой LLM)¶

    Диалог (сокращённо, механика перед нарративом):

    1. Иду по следу кабана. → Без проверки → generic «шаг вперёд / вход в пещеру»
    2. Новострить слух — нет ли звуков из пещеры → Без проверки → generic «ветер доносит шёпот»
    3. войти в пещеру. Очень тихо → Без проверки → generic «земля дрожит»
    4. Быстро кинуть ловушку. Если кабан — приручу, если враг — атакую из лука → d20 19+0=19 Попадание урон 3 / враг 6+2=8 Промах → нарратив-поляна/алтарь (несвязан с ловушкой)
    5. повтор той же ловушки → 15+0=15 Попадание урон 2 / враг 18+2=20 Успех урон 6 → нарратив уже корректный: «иглобрюх, капкан, алтарь пульсирует, сталактит, расщелина»
    6. Положить на тетиву три стрелы… → 10+0=10 Промах / враг 17+2=19 Успех урон 2 → нарратив-stub «шаг вперёд» (десинхрон)
    7. повтор трёх стрел → 11+0=11 Промах / враг 8+2=10 Успех урон 2 → нарратив корректный, но с отравлением/паникой

    B-15 — Три стрелы (исправлен). Без цены.     B-16 — Повтор (исправлен). Фикс: единый предикат — если active_effects уже содержит set_trap или текст идентичен одному из 3 последних ходов → no_roll «ловушка уже стоит / ты уже целился тремя стрелами» (не «либо/либо»), тест на active_effects и историю.

    B-17 — Смерть при 0 HP (исправлен, снято противоречие). hp in 0..maxHp клипается в 0, критерий hp==0 (не ≤0). Фикс: hp==0 → status=Без сознания; обычный режим — не «стабилизация DC10» автоматом, а спасброски каждый ход d20: 10+ успех, <10 провал, 1=2 провала, 20=1HP (SRD) — 3 успеха → Стабилен (0 HP, без сознания, броски стоп), 3 провала → isDead=true; хардкор permadeath=true → сразу isDead. processTurn при hp==0 отклоняет обычное действие и принимает только death_save (или Medicine от союзника — вне MVP). applyEnemyTurn проверяет итоговое hp после Damage и не бьёт лежачего. Длительность Без сознания — indefinite до стабилизации.

    B-18 — Урон без модификатора (исправлен, SRD). Фикс: урон без prof (SRD: prof только к атаке/проверке, brief §2.2 верно, B-18 текст поправлен); ввести Enemy.damageBonus отдельно от attackBonus (волк +5 to hit, 2d6+3 — не путать); крит — двойной бросок кубов roll(2,sides)+mod (а не *2), TurnResolver.kt:78 поправить; консистентность longbow 1d8 (бриф) vs B-18 пример d6 — использовать 1d8.

    B-19 — итог ≥ AC. Код уже total>=ac (TurnResolver.kt:76,305), nat20/1 — ок. Фикс: закрыть component-тестом 10 vs AC10 = хит + проверка карточки AC до броска (B-03), исторический лог — артефакт.

    B-20 — Иерархический каталог действий (critical, ability-checks-brief.md)¶

    Проблема: TurnResolver классифицирует regex (ATTACK_PATTERN, NO_ROLL_PATTERN) — ломается на лук→Сила (B-12), иду→no_roll (B-11), бесконечных заклинаниях/бластерах/катанах. Попытка перечислить всё в коде — не масштабируется (sci-fi/ориентал/энергетика) и снова «стрельнёт».

    Решение: трехуровневый справочник в БД (0015-action-catalog): - weapon_categories (7, исчерпывающие: kinetic_melee/ranged/energy/oriental/throwable/finesse/unarmed + is_finesse/clamp) - weapons (13 seed, наследуют attack_stat/damage_dice из категории; keywords \w* с приоритетом длинного токена) - weapon_traits (6: flaming/frost/poisoned/cursed — extra_dice + status + save + duration, clamp ≤2 трейта, ≤+2d6 включая DoT) - spell_families (4 семейства direct_damage/save_debuff/control/summon_heal — любое новое заклинание маппится LLM-классификатором в семейство) - effect_templates (duration_type rounds/indefinite/condition, tick_dice, save, max_stacks=1) - skill_checks (18 навыков с dc_easy/medium/hard и keywords)

    Матчинг: exact keywords → категория; miss → CatalogClassifier (LLM, temp 0, только category_key из списка) → default_weapon 1d4+str (никогда null). Логика «одно действие за ход» (B-05/B-15) и «ловушка уже стоит» (B-16) — через active_effects.

    Критерий: TurnResolver.resolve() без regex (кроме токенизации \b\w*), все attack_stat/dc/skill — из БД; default фолбэк гарантирует расчёт; unknown_action логируется.

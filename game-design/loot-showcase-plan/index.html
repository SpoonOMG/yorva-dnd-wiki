    Витрина лута: план реализации (handoff для новой сессии)¶

    Дизайн-документ: loot-showcase.md — читать первым, там все согласованные решения (кривая редкости, триггеры, GRANT_UNIQUE, иконки, объём справочника). Ниже только план работ и технический контекст.

    Что уже сделано (в main)¶

    • Миграция 0028-loot-catalog.yaml: таблица loot_items (id, genre, level, category, rarity, name_ru, description_ru, icon_key, stat_factor 0.9–1.2, properties — резерв), индекс (genre, level), колонка sessions.loot_genre.
    • Иконотека расширена до 160 иконок (frontend/public/icons/items/, манифест manifest.json; ключи иконок — фиксированный список для генератора).
    • Механика бросков/атрибутов и гейт GRANT_ITEM — зелёные (313/313 тестов, LLM-харнесс 20/20).

    Оставшиеся шаги¶

    Шаг 2. Генератор справочника [flash, прогон [pro]]¶

    • Офлайн LLM-скрипт (Python/Node на выбор, запуск вручную, не часть рантайма): генерирует 10 жанров × 10 уровней × 35 предметов (20 WEAPON / 10 ARMOR / 5 CONSUMABLE) = 3500 предметов → YAML-миграция сидов (например серия 0029-loot-items-<genre>.yaml) или SQL-дамп.
    • В промпт генератора передаётся полный список 160 icon_key из манифеста — LLM выбирает иконку только из него.
    • Генерируются ТОЛЬКО: id, name_ru, description_ru, category, rarity, level, icon_key. stat_factor проставляет скрипт (рандом 0.9–1.2). Статы — НЕТ.
    • Скрипт-валидатор: уникальность id/имён внутри жанра, icon_key ∈ манифеста (иначе дефолт категории), распределение редкости внутри уровня.
    • Модель для генерации: дешёвая (flash-класс), батчами по уровню/жанру.
    • После генерации — вычитка выборки человеком.

    Шаг 3. Движок витрины [pro]¶

    • LootShowcaseService (backend): выбор 3 предметов из loot_items по (genre, level персонажа) с RNG по кривой редкости из дизайн-дока (ур.1: 90/10; ур.2: 70/20/10; ур.3: 40/30/20/10; 4-5 — плавный сдвиг; LEGENDARY 1-2% с 6 ур., максимум 1 за сессию — счётчик в state сессии).
    • Дедуп: исключить id предметов, уже выданных в этой сессии (state).
    • Таблица силы «уровень × редкость × категория» × stat_factor → статы предмета (урон/AC/эффект расходника). Значения выверить при реализации.
    • Выбор жанра: при старте сессии LLM получает список 10 ключей жанров, возвращает ключ → sessions.loot_genre; fallback world.genre → generic.

    Шаг 4. Интеграция в SessionService [pro]¶

    • Триггеры: старт сессии (витрина 1 ур.), победа в бою (шанс 30-50%), контейнер/обыск, награда за квест (гарант), тег [REQUEST_LOOT] от LLM.
    • Витрина подкладывается в контекст LLM (скрыто от игрока); LLM отвечает тегом выбора (напр. [TAKE_LOOT:<id>] или «ни одного») и обыгрывает в нарративе. Чистый нарратив — витрина в UI не показывается.
    • GRANT_UNIQUE: переименовать/расширить текущий GRANT_ITEM для сюжетно- уникальных предметов; промах архетипа → статы из таблицы «категория × редкость» × коэффициент. Гейт упоминания в сцене сохранить.
    • Не ломать текущий поток: SessionService.kt (GRANT_ITEM ~434-470, buildNarrativeItem ~939-960, lootGrantJustified ~972-1017).

    Шаг 5. Тесты [flash]¶

    • Gherkin component tests (component-tests/): старт сессии выдаёт витрину, кривая редкости, квота легендарки, дедуп, GRANT_UNIQUE fallback.
    • Детерминированный матричный харнесс (по образцу AttributeMatrixHarnessTest.kt) + живой LLM-харнесс (по образцу AttributeLlmHarnessTest.kt, @EnabledIfEnvironmentVariable NORDROUTER_API_KEY).

    Технический контекст для новой сессии¶

    • Worktree-ветка: spoonomg-verbose-train, репо SpoonOMG/yorva-dnd.
    • Бэкенд: ./gradlew :app:bootRun из backend/ (порт 8088), env — ~/.copilot/session-state/4504421c-f74f-453d-a947-e14580f29762/files/backend.env.
    • БД: PGPASSWORD=dnd psql -h localhost -p 5433 -U dnd -d dnd.
    • Миграции подхватываются через includeAll — просто добавить файл в db/changelog/changes/.
    • Ключ API для LLM-харнесса: из env живого бэкенда (ps eww <PID> | tr ' ' '\n' | grep NORDROUTER_API_KEY).
    • Прод-модели: gemini-3.7-flash → gpt-5.4-mini → minimax-m3, память — 3.7-flash. Другие модели не использовать.
    • Правила: помечать класс задачи [pro]/[flash]/[lite]; коммит — после показа результата; Conventional Commits.

    Отложено (не делать в этой вехе)¶

    • Доп. свойства rare+ (механические эффекты) — с фазой противников.
    • Повышенные шансы лута у элиты/боссов — с фазой противников.
    • Еженедельная перегенерация названий предметов — «на подумать».
    • Диагностика: портрет персонажа не генерируется на проде (лог /tmp/yorva-backend.log, сессия 6504991f) — отдельная задача.

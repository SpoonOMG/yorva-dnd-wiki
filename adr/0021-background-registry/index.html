    ADR-0021: Реестр предысторий (BackgroundRegistry) — оживление backgrounds.yml¶

    Status¶

    Accepted

    Context¶

    backgrounds.yml существует (92 строки, все 13 фонов PHB), но загрузчика нет — фон применяется двумя when-хардкодами в SessionService. Собранные факты (файл:строка):

    Фон сегодня¶

    # Файл:строка Что найдено
    1 resources/backgrounds.yml:1-92 Все 13 фонов PHB: acolyte, charlatan, criminal, entertainer, folk_hero, guild_artisan, hermit, noble, outlander, sage, sailor, soldier, urchin. Схема на фон: id/name/skills/tools/languages(feature-строка). Комментариев/дат нет — давность не установить; содержание канонично (не legacy по данным).
    2 resources/backgrounds.yml (отсутствует) Нет vs PHB гл.4: equipment (стартовое снаряжение), suggestedCharacteristics (Traits/Ideal/Bond/Flaw), механической формы feature (только строка: «Приют верующих», «Криминальные связи», «Привилегия положения»…). Структурно неполный — факт для G1.
    3 sessions/SessionService.kt:88-104 getBackgroundProficiencies: when на 13 фонов (skills + tools). Дублирует данные факта #1. Дрейф уже есть: guild_artisan tools в коде [smith_tools] (:95), в YAML [artisan_tools] (backgrounds.yml:41).
    4 sessions/SessionService.kt:453-461, :495 backgroundId → skills/tools (:454-456, факт #4 из 0025); языки — второй when (:457-461: acolyte/sage → Common+Elvish; hermit/guild_artisan/noble/outlander → Common+Dwarvish; иначе пусто); запись backgroundId/toolProficiencies/languages в state (:495).
    5 rules/GameState.kt:446-450 backgroundId: String? (:446); toolProficiencies: List<String> (:448); languages: List<String> (:450). Типизации фона нет.
    6 sessions/SessionDtos.kt:32-34 backgroundId: String? (@Size(max=64)) — строкой с клиента.
    7 Языки: racial / class Racial languages — отсутствуют (ADR-0020 не реализован; grep racialLanguages → 0). Class languages — отсутствуют (hardcode только background, факт #4). Мержить нечего — пересечение с ADR-0020 фиксируется как open question (см. Риски).
    8 BackgroundRegistry / backgrounds.json / BackgroundId Отсутствуют (grep kt → 0). backgrounds.yml в коде не упоминается (факт #8 из ADR-0020: docs/adr/0020-race-registry.md:23).
    9 БД (resources/db) Таблицы backgrounds — нет (grep background → 0). Фон — только поле backgroundId в JSON состояния.
    10 Equipment фона → инвентарь Связок нет (grep background.*equipment/inventory/item → 0). При создании inventory = emptyList() (SessionService.kt:492). Equipment не выдаётся вообще — факт для шва к ФАЗЕ 4.
    11 Personality / Ideal / Bond / Flaw Ноль (grep → 0 в kt). Черты/идеалы/узы/изъяны нигде не упоминаются — факт для H1.

    Список фонов: backgrounds.yml vs PHB гл.4¶

    backgrounds.yml PHB гл.4 Статус
    acolyte (Послушник) Acolyte ✓ есть
    charlatan (Шарлатан) Charlatan ✓ есть
    criminal (Преступник) Criminal (+ Criminal Variant: Spy) ✓ есть (вариант Spy — вне scope, см. I1)
    entertainer (Артист) Entertainer (+ Gladiator variant) ✓ есть (вариант — вне scope)
    folk_hero (Народный герой) Folk Hero ✓ есть
    guild_artisan (Гильдейский ремесленник) Guild Artisan (+ Guild Merchant variant) ✓ есть, дрейф tools (факт #3)
    hermit (Отшельник) Hermit ✓ есть
    noble (Дворянин) Noble (+ Knight variant, retainers) ✓ есть (retainers — вне scope)
    outlander (Чужеземец) Outlander ✓ есть
    sage (Мудрец) Sage ✓ есть
    sailor (Моряк) Sailor (+ Pirate variant) ✓ есть (вариант — вне scope)
    soldier (Солдат) Soldier ✓ есть
    urchin (Беспризорник) Urchin ✓ есть

    13/13 — расхождения набора нет (стоп-условие #1 не сработало); варианты фонов (Spy/Gladiator/Knight/Pirate) — вне scope, как Custom Background (I1).

    Проблема¶

    Фон — мёртвые данные + живой хардкод: backgrounds.yml никто не читает (факт #8), а SessionService дублирует те же 13 фонов двумя when (факты #3–4) — дрейф уже начался (факт #3). Фичи фонов («Приют верующих», «Криминальные связи») — строки без механики; equipment/characteristics — вне модели (факты #2, #10, #11). Нужны: оживление YAML + BackgroundRegistry + типизация + резолвер применения + регистрация дубля.

    Прецеденты¶

    • ADR-0020 A2/E1/F1 — races.yml + реестр, RaceId, RaceResolver (образцы для A2/D1/E1); урок backgrounds.yml-синдрома (0020-race-registry.md:23, :66, :199, :278) — реестр вводится вместе с данными, не после.
    • ADR-0023 B1 — sealed ClassFeature (образец для C1 BackgroundFeature).
    • ADR-0025 C1 — CharacterCreationService (создаётся там; E1 ложится на него).
    • ADR-0024 A2 — секция + реестр (образец для A2).

    Канон D&D 5e (PHB гл.4 «Personality and Backgrounds»)¶

    13 фонов; каждый: 2 skill proficiency + tools (+ языки 0–2) + equipment + feature (Shelter of the Faithful, False Identity, Criminal Contact, By Popular Demand, Rustic Hospitality, Guild Membership, Discovery, Position of Privilege, Wanderer, Researcher, Ship's Passage, Military Rank, City Secrets) + suggested characteristics (d8 Personality Traits / d6 Ideal / d6 Bond / d6 Flaw) — подсказки ролеплея, не механика. Custom Background — опция (свои 2 навыка + 2 инструмента/языка + equipment).

    Decision¶

    1. Место хранения (A2)¶

    Оживить backgrounds.yml + BackgroundRegistry.kt. Файл уже существует (факт #1), загрузчик отсутствует — вводится вместе с реестром (урок backgrounds.yml-синдрома из ADR-0020 A2: данные без регистра = мёртвый файл). Содержимое канонично, но структурно неполно (факт #2) — миграция данных (добивка equipment/feature/suggestedCharacteristics) входит в цикл 3.4 (см. G1).

    2. Форма Background (B1)¶

    data class — НЕ sealed. Обоснование: фон — данные (13 записей PHB), у всех одна природа. Отличие от ClassFeature (B1 sealed в 0023): там природа принципиально разная (пассив/актив/триггер/выбор), здесь — все фоны однотипны (навыки + инструменты + языки + снаряжение + фича):

    data class Background(
    val id: BackgroundId,
    val name: String,
    val skillProficiencies: List<String>,
    val toolProficiencies: List<String>,
    val languages: Int,              // сколько языков на выбор (обычно 0/1/2)
    val equipment: List<String>,     // стартовое снаряжение (шов к ФАЗЕ 4)
    val feature: BackgroundFeature?, // уникальная фича фона (C1)
    val suggestedCharacteristics: SuggestedCharacteristics?,
)

    languages: Int (счётчик «сколько на выбор»), а не список — фактический выбор языков делает CharacterCreationService (см. Риски: три источника).

    3. Фича фона (C1)¶

    BackgroundFeature — sealed interface (Passive/Triggered). Симметрично RacialTrait (0020 B1) / ClassFeature (0023 B1). Примеры: Acolyte «Приют верующих» (пассивная), Criminal «Криминальные связи» (пассивная), Noble «Привилегия положения» (пассивная), Soldier «Воинское звание» (пассивная). Триггерные фичи фона в PHB — редкость, но форма закладывается (как RacialTrigger в 0020 — на вырост, без YAGNI-нагрузки: 2 подтипа).

    4. Интеграция с состоянием (D1)¶

    CharacterState.backgroundId: String → BackgroundId enum. Симметрия RaceId (E1 из 0020). Breaking change; сессии тестовые — миграция не требуется. CreateSessionRequest.backgroundId (SessionDtos.kt:34) принимает строку, резолвер валидирует в enum (невалидный → 400, прецедент F1 из 0025).

    5. Применение при создании (E1)¶

    CharacterCreationService (создаётся в ADR-0025 C1) + BackgroundResolver.apply(state, background) — stateless object, симметрично RaceResolver (0020 F1). Не сваливать в SessionService (там уже 3983 строки; факты #3–4 — два when оттуда уходят, см. F1). Порядок применения в создании: race → class → background (аддитивные proficiency/languages складываются; см. Риски).

    6. Удаление хардкода (F1)¶

    SessionService.kt:89 (getBackgroundProficiencies) и :457-461 (языки) заменяются обращением к BackgroundRegistry. Дублирующий when — источник рассинхрона (дрейф guild_artisan уже зафиксирован, факт #3: канон — выбор artisan-инструмента, YAML — заглушка artisan_tools, код — smith_tools; при миграции побеждает канон с выбором).

    7. Миграция мёртвого файла (G1)¶

    Содержимое 92 строк канонично (факт #1), но структура неполна (факт #2: нет equipment/feature-формы/suggestedCharacteristics). ADR фиксирует целевую схему (B1+C1+H1); добивка данных — цикл 3.4. Разведка показала: legacy по давности не установить (комментариев нет), legacy по содержанию — нет; это «скелет», а не «мусор».

    8. Черты характера (H1)¶

    SuggestedCharacteristics (Personality Traits / Ideal / Bond / Flaw) — данные для narrative. Механики нет (PHB: подсказки ролеплея). Поля в data class, использование — LLM narrative. Явная пометка «не механика» (см. Риски: LLM не должен давать бонусы за черты).

    9. Custom Background (I1)¶

    PHB-optional (игрок сам собирает фон: 2 навыка + инструменты/языки + equipment) — НЕ поддерживаем (post-MVP). Варианты фонов (Spy, Gladiator, Knight, Pirate — см. таблицу) — туда же. Форма Background custom не запрещает технически — решение продуктовое.

    10. Дубль фона (J1)¶

    Фон в state (backgroundId, факт #5) vs реестр — новый дубль #9 (после #8 из 0025; O занят). Запись в ADR-0011 — отдельным циклом после реализации (аналогично 0020 J1 / 0023 J1 / 0024 H1 / 0025 J1). Правило ADR-0011: новый дубль — с пометкой Resolved in ADR-0021.

    11. Объём цикла (K1)¶

    Только ADR. Реализация (BackgroundRegistry.kt, BackgroundResolver.kt, миграция хардкода фактов #3–4, оживление backgrounds.yml по схеме G1) — цикл 3.4.

    Proposed Options¶

    A. Место хранения. - A1: новый backgrounds.json/другой файл — второй источник при живом backgrounds.yml (тот же аргумент, что отклонил features.yml/resources.yml). - A2: оживить backgrounds.yml + BackgroundRegistry.kt — рекомендация архитектора. Файл каноничен (факт #1); реестр — сразу (урок 0020). - A3: фон только в коде (enum + таблицы) — данные PHB в коде, правка = релиз.

    B. Форма Background. - B1: data class (НЕ sealed) — рекомендация архитектора. Одна природа — одна форма; 13 записей. - B2: sealed по фонам (AcolyteBackground, …) — взрыв типов: 13 классов без поведенческих различий. - B3: оставить строки (backgroundId: String + when) — сегодня так (факты #3–5); дрейф уже есть.

    C. Фича фона. - C1: sealed BackgroundFeature (Passive/Triggered) — рекомендация архитектора. Симметрия 0020/0023; механика фич — позже, форма — сейчас. - C2: строка как сегодня (факт #1: feature: "Приют верующих") — фичи остаются ярлыками навсегда. - C3: фичи фонов — сразу с механикой в 0021 — тянет 13 реализаций (контакты/приюты/ранги — преимущественно narrative).

    D. Тип backgroundId. - D1: BackgroundId enum (breaking change) — рекомендация архитектора. Симметрия RaceId; опечатки ловятся компилятором. - D2: оставить String — валидация только рантайм; рассинхрон с реестром. - D3: String + валидация в резолвере без enum — половина типизации.

    E. Точка применения. - E1: CharacterCreationService + BackgroundResolver.apply — рекомендация архитектора. Порядок race → class → background. - E2: оставить в SessionService — файл 3983 строки, when остаются. - E3: применение в BackgroundRegistry (реестр + логика) — нарушение границ (реестр — данные, резолвер — применение; прецедент 0020 F1).

    F. Хардкод. - F1: удалить оба when, обращение к реестру — рекомендация архитектора. Дрейф guild_artisan резолвится каноном. - F2: оставить хардкод + реестр рядом — два источника (новый дубль). - F3: удалить только skills-when, языки оставить — половина миграции.

    G. Миграция файла. - G1: целевую схему — сейчас, добивку данных — 3.4 — рекомендация архитектора. Скелет каноничен, readings достаточно. - G2: добить данные в этом цикле (без кода) — данные без регистра = второй backgrounds.yml-синдром (K2 из 0020). - G3: признать файл legacy и переписать с нуля — не требуется: содержание канонично (факт #1).

    H. Characteristics. - H1: данные для narrative, без механики — рекомендация архитектора. - H2: механика вдохновения за отыгрыш черт — отдельная подсистема, не PHB-ядро. - H3: не включать вообще — теряем ролеплей-контекст для LLM.

    I. Custom Background. - I1: не поддерживать (post-MVP) — рекомендация архитектора. - I2: поддержать сразу — тянет конструктор фонов + валидацию комбинаций. - I3: умолчать — реализатор угадывает.

    J. Дубль. - J1: регистрировать (#9, Resolved in ADR-0021, запись после реализации) — рекомендация архитектора. Аналогично 0020/0023/0024/0025. - J2: не регистрировать — нарушение правила ADR-0011. - J3: резолвить записью сейчас — преждевременно, реестра нет.

    K. Объём. - K1: только ADR; реализация — 3.4 — рекомендация архитектора. - K2: ADR + реестр без миграции хардкода — два источника (вариант F2). - K3: полный цикл с реализацией — нарушает «один цикл = один фокусный шаг».

    Consequences¶

    Плюсы¶

    • Мёртвый backgrounds.yml оживает (устраняется backgrounds.yml-синдром из ADR-0020 — тот самый файл, на котором урок был сформулирован).
    • Фон как сущность формализуется (13 фонов PHB, таблица сверки — 13/13).
    • Симметрия с ADR-0020 (RaceRegistry): оба — реестры данных PHB (A2/D1/E1 зеркальны).
    • Удаляется хардкод when в SessionService (факты #3–4, 16 строк).
    • Ложится на CharacterCreationService (ADR-0025 C1): порядок race → class → background.

    Минусы¶

    • Breaking change backgroundId: String → BackgroundId (D1).
    • BackgroundRegistry — восьмой регистр по паттерну.
    • Миграция 92 строк backgrounds.yml (добивка equipment/feature/ characteristics; дрейф guild_artisan резолвится каноном).
    • Equipment фона — шов к ФАЗЕ 4 (Inventory), в 3.4 не применяется.
    • Языки фона: temporary regression в 3.2 (state.languages = emptyList() до LanguageResolver).

    Риски¶

    • Файл может содержать скрытые неточности (комментариев/истории нет, факт #1). Митигация: G1 (сверка с PHB гл.4 при миграции; skills/tools/ languages уже сверены — 13/13; осталась equipment-добивка).
    • Languages: racial + class + background — три источника. Сегодня мёржить нечего (факт #7: racial/class отсутствуют). Митигация: BackgroundResolver возвращает «сколько на выбор» (languages: Int, B1); фактический выбор — CharacterCreationService (или отдельный LanguageResolver в 3.4). Пересечение с языками ADR-0020 — open question 3.4.
    • Languages фона: temporary regression (3.2). До 3.2 languages применялись hardcoded ([Common, Elvish] для acolyte/sage; [Common, Dwarvish] для hermit/guild_artisan/noble/outlander). В 3.2 hardcoded-применение удалено (BackgroundResolver languages не трогает, state.languages = emptyList()). Обоснование: PHB для этих фонов говорит «one/two languages of your choice» — hardcoded был уже неточен. Восстановление — LanguageResolver в 3.3/3.4 (правильный choice-механизм по PHB). До тех пор — известное ограничение. Архитектор подтвердил Вариант A (temporary, не stopgap).
    • Equipment → InventoryItem (ФАЗА 4). До тех пор equipment — данные без применения (факт #10: инвентарь при создании пуст). Митигация: зафиксировано в Отложено; схема хранит список строк, не объектов.
    • SuggestedCharacteristics как механика. Риск: LLM начнёт давать бонусы за черты. Митигация: H1 — только narrative, явная пометка «не механика» в схеме и промпте (цикл 3.4 — пометка, промпт — позже).
    • Дрейф guild_artisan (факт #3). Митигация: F1 — при миграции побеждает канон (выбор artisan-инструмента), обе записи заменяются.

    Отложено¶

    • Реализация (BackgroundRegistry, BackgroundResolver) — цикл 3.4.
    • Миграция backgrounds.yml (equipment/feature/characteristics) — 3.4.
    • Equipment → инвентарь — ФАЗА 4 (шов в B1).
    • LanguageResolver — цикл 3.3/3.4. Покрывает choice-языки (race/class/background). Заменяет temporary regression 3.2.
    • Custom Background + варианты фонов (Spy/Gladiator/Knight/Pirate) — post-MVP.
    • Frontend (wizard выбора фона) — ФАЗА 6.
    • Запись дубля #9 в ADR-0011 — после реализации (J1).

    Чек-лист решений A–K¶

    • A = A2 — оживить backgrounds.yml + BackgroundRegistry.kt (реестр сразу).
    • B = B1 — data class Background (НЕ sealed; languages: Int, equipment, feature?, suggestedCharacteristics?).
    • C = C1 — sealed BackgroundFeature (Passive/Triggered).
    • D = D1 — backgroundId → BackgroundId enum (breaking change).
    • E = E1 — CharacterCreationService + BackgroundResolver.apply (порядок race → class → background).
    • F = F1 — удалить оба when (:89, :457-461); дрейф guild_artisan — канон.
    • G = G1 — схема сейчас, добивка данных — 3.4 (скелет, не мусор).
    • H = H1 — characteristics для narrative, без механики.
    • I = I1 — Custom Background не поддерживаем (post-MVP).
    • J = J1 — дубль #9 (Resolved in ADR-0021), запись после реализации.
    • K = K1 — только ADR; реализация — 3.4.

    Untouched in this ADR¶

    • Код (BackgroundRegistry.kt, BackgroundResolver.kt, backgrounds.yml, CharacterState, SessionService.kt:89, :457-461) — цикл 3.4.
    • Equipment → Inventory — ФАЗА 4 (шов, не реализация).
    • Custom Background + варианты фонов — post-MVP (I1).
    • ADR-0011 — запись дубля #9 после реализации (J1; в этом цикле НЕ правим).

    ADR-0020: Реестр рас (RaceRegistry) — races.yml + RaceId/SubraceId + racial ASI/traits¶

    Status¶

    Accepted

    Context¶

    Раса персонажа сейчас — нигде: ни поля в состоянии, ни реестра, ни механики. Собранные факты (файл:строка):

    Где сейчас «раса» (разведка)¶

    # Файл:строка Что найдено
    1 rules/GameState.kt:340-507 CharacterState: полей race/subrace нет. Есть backgroundId (:446), languages (:450), feats (:452), canonicalClassId (:426), subclassId (:487, null-задел). Поля speed тоже нет.
    2 sessions/SessionDtos.kt:16-41 CreateSessionRequest: поля raceId/subraceId нет. Есть backgroundId (:34), characterClass: String (:24), l1Choices (:40).
    3 sessions/SessionService.kt:490-501 Конструирование CharacterState при создании сессии: раса не присваивается, racial ASI не применяется.
    4 rules/SavingThrowResolver.kt:25-26, :100-102 Единственные семантические упоминания: «Источники save-adv (race features) появятся в ФАЗЕ 3». Реализации нет.
    5 scene/ScenePromptBuilder.kt:56 «preserve exact race/species…» — только LLM-промпт визуальных якорей, не механика.
    6 resources/subclasses.yml:203 «Darkvision» — только текст description ки-фичи монаха, не механика расы.
    7 resources/db/changelog/changes/0004-characters.yaml:33-35 characters.character_json TEXT; колонки race нет; таблицы races нет (grep race по resources/db → 0 совпадений).
    8 resources/backgrounds.yml (92 строки) Файл существует, но загрузчика нет: grep backgrounds.yml по *.kt → 0. Мёртвые данные. Фон применяется хардкодом: SessionService.kt:89 (getBackgroundProficiencies, when) и :457-461 (языки, when). Предостережение для races.yml: файл без регистра = мёртвый файл.
    9 Остальные совпадения grep race\|Race Ложные срабатывания: IntentTrace* (trace), pass-without-trace (заклинание), closeBrace (парсер). Не расы.

    Итого: RaceRegistry отсутствует, races.yml/races.json отсутствуют, racial ASI отсутствует, racial traits отсутствуют (Darkvision, Breath Weapon, Relentless Endurance — 0 реализаций), подрас нет.

    Проблема¶

    Раса — отсутствует как сущность: racial traits не реализованы, racial ASI не применяется, подрас нет. Класс — просто ярлык (Rage, Sneak Attack не работают) — это контекст всей мини-ФАЗЫ 0, но ADR-0020 про расы, не про классы.

    Прецеденты реестров (база для A2)¶

    Реестр YAML Загрузка
    classes/ClassRegistry.kt:11-47 classes.yml (1220 строк, корневой ключ classes:) @Component + ResourceLoader + SnakeYAML + warn/fallback (12 классов, :166-210)
    skills/SkillRegistry.kt:37-61 skills.yml (263 строки, skills: + id/ability/label/description) тот же паттерн, warn при отсутствии
    classes/FeatRegistry.kt:27-48 feats.yml тот же паттерн
    classes/SubclassRegistry.kt:27-58 subclasses.yml тот же паттерн

    Канон D&D 5e (PHB гл.2 «Races», p.17–42)¶

    9 рас × 9 подрас: Dwarf (Hill, Mountain), Elf (High, Wood, Drow), Halfling (Lightfoot, Stout), Human, Dragonborn, Gnome (Forest, Rock), Half-Elf, Half-Orc, Tiefling. Racial ASI — фиксированные (+2/+1) и на выбор (Half-Elf: +2 CHA + 2×+1 на выбор; Variant Human: 2×+1 на выбор + feat + skill). Racial traits — пассивные (Darkvision), активные (Breath Weapon: действие + DC), триггерные (Savage Attacks — на крит; Relentless Endurance — на падение до 0). Плюс size, speed (30, у Dwarf/Halfling/Gnome — 25), languages.

    ADR-0010 §5 (0010-turn-and-round-model.md:84-85) уже anticipates races.yml («SpeedResolver.baseSpeed — временная SRD-таблица рас до races.yml Блока 2.3»), но speed в CharacterState отсутствует, SpeedResolver не существует — §5 ADR-0010 Proposed, не реализован.

    Decision¶

    1. Место хранения реестра (A2)¶

    YAML (races.yml) + Kotlin-обёртка (RaceRegistry.kt). Обоснование: прецедент classes.yml/skills.yml (см. Context); данные (9 рас, 9 подрас, 40+ черт) удобнее в YAML; поведение — в Kotlin. Урок backgrounds.yml (мёртвый файл без загрузчика, факт #8): YAML вводится только вместе с регистром.

    @Component
class RaceRegistry(private val resourceLoader: ResourceLoader) {
    fun getRace(id: RaceId): Race?
    fun getAllRaces(): List<Race>
}

    2. Форма RacialTrait (B1)¶

    sealed interface RacialTrait + подтипы (PassiveRacialTrait / ActiveRacialTrait / TriggeredRacialTrait). Обоснование: разная природа — Darkvision (пассивная), Breath Weapon (активная), Savage Attacks (триггер на crit), Relentless Endurance (триггер на hp=0). Enum не справится.

    sealed interface RacialTrait {
    val id: String
    val name: String
    val description: String
}
data class PassiveRacialTrait(/* … */) : RacialTrait
data class ActiveRacialTrait(/* … activatableId → ADR-0019 … */) : RacialTrait
data class TriggeredRacialTrait(val trigger: RacialTrigger /* CRIT, DROP_TO_ZERO … */) : RacialTrait

    3. Racial ASI (C1)¶

    sealed AbilityBonus (FixedAbilityBonus / ChoiceAbilityBonus). Обоснование: Half-Elf (2×+1 на выбор) и Variant Human — принципиально другой тип, чем Dwarf (+2 CON, +1 WIS).

    sealed interface AbilityBonus
data class FixedAbilityBonus(val ability: Ability, val amount: Int) : AbilityBonus
data class ChoiceAbilityBonus(val count: Int, val amount: Int, val from: List<Ability> = emptyList()) : AbilityBonus

    Ability — enum из ADR-0019 I1, консистентно с AbilityResolver/AbilityParser (типобезопасная способность, а не строка).

    4. Подрасы (D1)¶

    Вложенно: Race.subraces. Обоснование: Dwarf Hill/Mountain, Elf High/Wood/Drow — «родительская раса + модификатор», не отдельные расы.

    data class Race(
    val id: RaceId,
    val name: String,
    val abilityBonuses: List<AbilityBonus> = emptyList(),
    val traits: List<RacialTrait> = emptyList(),
    val speed: Int = 30,
    val size: CreatureSize = CreatureSize.MEDIUM,
    val languages: List<String> = emptyList(),
    val subraces: List<Subrace> = emptyList(),
)
data class Subrace(
    val id: SubraceId,
    val name: String,
    val abilityBonuses: List<AbilityBonus> = emptyList(),
    val traits: List<RacialTrait> = emptyList(),
)

    5. Интеграция с CharacterState (E1)¶

    race: RaceId? (enum, nullable), subrace: SubraceId? (nullable). Nullable — потому что сессии без расы валидны (тестовые/legacy): API принимает строку (raceId/subraceId), резолвер валидирует её в enum или null; отсутствие расы не ломает создание персонажа. Breaking change (прецедент ADR-0013: String → StatusId), сессии тестовые — миграция не требуется. Уточнение разведки: поля сейчас нет вообще (факт #1), т.е. это добавление полей, а не замена типа — но контракт состояния/API меняется, правки в тестах/фронте потребуются (см. Минусы). E2 (слить расу и подрасу в один ID) отклонён — теряется Race.subraces. E3 (параллельное поле-строка) отклонён — два источника истины.

    enum class RaceId { DWARF, ELF, HALFLING, HUMAN, DRAGONBORN, GNOME, HALF_ELF, HALF_ORC, TIEFLING }
enum class SubraceId { HILL_DWARF, MOUNTAIN_DWARF, HIGH_ELF, WOOD_ELF, DROW, LIGHTFOOT, STOUT, FOREST_GNOME, ROCK_GNOME }

    6. Применение racial ASI (F1)¶

    RaceResolver.applyRacialBonuses(state) — stateless object, симметрично DamageResolver/ConditionResolver. Вызывается при создании персонажа (SessionService, рядом с фактом #3). F3 (часть AbilityResolver) отклонён — AbilityResolver про активации, не про создание персонажа.

    object RaceResolver {
    fun applyRacialBonuses(
        state: CharacterState,
        race: Race,
        subrace: Subrace? = null,
        choiceASI: Map<Ability, Int> = emptyMap(),
    ): CharacterState

    // внутреннее ядро — применяет ASI к Attributes без CharacterState
    fun applyToAttributes(
        attributes: Attributes,
        race: Race,
        subrace: Subrace? = null,
        choiceASI: Map<Ability, Int> = emptyMap(),
    ): Attributes
}

    Порядок применения: applyRacialBonuses вызывает applyToAttributes(attrs, race, subrace, choiceASI) ДО расчёта производных (HP/AC). Иначе Dwarf CON+2 не поднимает HP, Elf DEX+2 не поднимает AC. Публичное API — applyRacialBonuses(state, race, subrace, choiceASI); внутреннее ядро — applyToAttributes.

    7. Half-Elf / Half-Orc / Variant Human (G1)¶

    Все три в ADR-0020. Обоснование: Half-Elf (choice ASI) и Half-Orc (Relentless Endurance) уже ломают простую модель — решать сейчас. Variant Human — в ту же развилку (choice ASI + feat + skill).

    8. Активные трейты (H1a + H1b)¶

    H разбит на два: - H1a (Activatable): Breath Weapon (действие + DC) → через ADR-0019 Activatable. Dragonborn. Активный трейт регистрируется как activatableId (CharacterState уже хранит только id, GameState.kt:458). - H1b (state-hook): Relentless Endurance (реакция на hp=0, не активируемая) → hook в damage-resolution (SessionService/TurnResolver). Half-Orc. Обоснование: разная природа, разные механизмы.

    9. Размер/скорость (I1)¶

    Включить в Race как статические поля (speed = 30, size = MEDIUM; у Dwarf/Halfling/Gnome speed = 25 по канону). Применение в движении — ФАЗА 5 (ADR-0010 §5). CharacterState.speed вводится в цикле 3.1 как хранимое поле (источник — Race.speed), логика движения — только ФАЗА 5.

    10. Совместимость с ADR-0011 (J1)¶

    RaceRegistry — новый живой реестр; зарегистрировать в ADR-0011 как потенциальный дубль (race в CharacterState vs race в реестре). Правило ADR-0011: «при появлении нового дубля — добавить с пометкой». Сама запись в ADR-0011 — отдельным циклом, когда ADR-0020 будет принят и реализован (не в этом ADR).

    11. Объём цикла (K1)¶

    Только ADR (design, без кода). Реализация — отдельный цикл 3.1.

    Proposed Options¶

    Развилки сформулированы, рекомендация архитектора помечена явно.

    A. Место хранения реестра. - A1: только Kotlin (enum + data-объекты, без YAML) — проще, но 9 рас × 9 подрас × 40+ черт в коде; данные и поведение смешаны. - A2: YAML (races.yml) + Kotlin-обёртка (RaceRegistry.kt) — рекомендация архитектора. Прецедент classes.yml/skills.yml; данные в YAML, поведение в Kotlin. Обязательно вместе с регистром (урок backgrounds.yml). - A3: БД-таблица races + Liquibase (как каталоги лута/опасностей) — версионирование через миграции, но расы статичны (PHB), оверхед миграций не оправдан.

    B. Форма RacialTrait. - B1: sealed interface RacialTrait + подтипы (Passive/Active/Triggered) — рекомендация архитектора. Разная природа требует разных типов; enum не справится. - B2: единый data class RacialTrait(kind: TraitKind, …) — плоская модель, но kind-флаги расползаются по when в вызывающем коде. - B3: enum RacialTraitId + логика в резолверах — дублирование логики вне реестра, реестр превращается в справочник id.

    C. Racial ASI. - C1: sealed AbilityBonus (Fixed/Choice) — рекомендация архитектора. Half-Elf и Variant Human принципиально choice-тип. - C2: Map<String, Int> + отдельное choiceASI-поле — два параллельных механизма вместо одного типа. - C3: только fixed (Half-Elf/Variant обрезать до фиксированных) — неканонично, ломает PHB.

    D. Подрасы. - D1: вложенно Race.subraces — рекомендация архитектора. «Родительская раса + модификатор». - D2: плоский список (подраса = отдельная раса) — дублирование общих черт родителя в каждой подрасе. - D3: отдельный реестр подрас со ссылкой parentRaceId — оправдано при общем пуле подрас, но пулы disjoint (Hill/Mountain только у Dwarf).

    E. Интеграция с CharacterState. - E1: race: RaceId (enum) + subrace: SubraceId? — рекомендация архитектора. Прецедент ADR-0013 (String → StatusId). - E2: один составной ID (раса+подраса слиты) — теряется Race.subraces, иерархия схлопывается. - E3: параллельное поле-строка рядом — два источника истины.

    F. Применение racial ASI. - F1: RaceResolver.applyRacialBonuses(state) (stateless object) — рекомендация архитектора. Симметрия DamageResolver/ConditionResolver; вызывается при создании. - F2: метод реестра (RaceRegistry.applyTo) — смешивает хранение данных и применение. - F3: часть AbilityResolver — отклонён: AbilityResolver про активации, не про создание персонажа.

    G. Half-Elf / Half-Orc / Variant Human. - G1: все три в ADR-0020 — рекомендация архитектора. Half-Elf (choice ASI) и Half-Orc (Relentless Endurance) уже ломают простую модель — решать сейчас; Variant Human — та же развилка. - G2: только простые расы сейчас, сложные отложить — модель придётся ломать позже, двойная работа. - G3: Half-Elf/Half-Orc сейчас, Variant Human отложить (нужна feat-система) — но choice-ASI для Variant Human уже покрыт C1, откладывать нечего.

    H. Активные трейты. - H1a: Breath Weapon → через ADR-0019 Activatable — рекомендация архитектора (действие + DC, Dragonborn). - H1b: Relentless Endurance → hook в damage-resolution — рекомендация архитектора (реакция на hp=0, не активируемая, Half-Orc). - H2: всё через Activatable (и Relentless тоже) — неверно по природе: Relentless не активируется игроком, срабатывает сам. - H3: всё хуками без Activatable — Breath Weapon теряет DC/uses-инфраструктуру ADR-0019. - H4: отложить активные трейты — Dragonborn/Half-Orc остаются ярлыками (контекст мини-ФАЗЫ 0 против).

    I. Размер/скорость. - I1: статические поля Race (speed, size), применение в движении — ФАЗА 5 — рекомендация архитектора. ADR-0010 §5 уже ждёт races.yml. - I2: сразу с движением (тянуть ADR-0010 §5 целиком) — раздувает цикл 3.1. - I3: не хранить вообще — ADR-0010 §5 останется без источника данных.

    J. Совместимость с ADR-0011. - J1: новый живой реестр + пометка потенциального дубля в ADR-0011 (отдельным циклом) — рекомендация архитектора. Правило ADR-0011: новый дубль — добавить с пометкой. - J2: не регистрировать — нарушение правила ADR-0011. - J3: заморозить как character_json — неверно: реестр живой, замораживать нечего.

    K. Объём цикла. - K1: только ADR (design, без кода); реализация — цикл 3.1 — рекомендация архитектора. - K2: ADR + races.yml данные без кода — данные без регистра = второй backgrounds.yml (факт #8). - K3: полный цикл с реализацией — нарушает «один цикл = один фокусный шаг».

    Consequences¶

    Плюсы¶

    • Реестр рас — единый источник истины (данные в races.yml, поведение в Kotlin).
    • Racial ASI, traits, подрасы — формализованы (sealed-типы покрывают и fixed, и choice).
    • Half-Elf/Half-Orc/Variant Human — учтены сразу, модель не придётся ломать позже.
    • Breaking change CharacterState.race — прецедент ADR-0013 (String → StatusId).

    Минусы¶

    • Изменение контракта CharacterState/CreateSessionRequest — правки в тестах/фронте (поле добавляется, факт #1–2: сейчас его нет вообще).
    • races.yml + RaceRegistry — новая инфраструктура (пятый регистр по паттерну ClassRegistry).
    • Активные трейты (H1a) зависят от ADR-0019 Activatable.

    Риски¶

    • Relentless Endurance (H1b) — hook в damage-resolution, может конфликтовать с G-006 (stabilization). Митигация: канон 5e — Relentless Endurance срабатывает В МОМЕНТ падения до 0, ДО death saves. Не путать со стабилизацией.
    • races.yml schema drift при добавлении новых рас. Митигация: парсинг с per-race try/catch и warn (паттерн ClassRegistry.kt:34-40), fallback при пустом реестре (:42, :166-210).
    • backgrounds.yml-синдром (факт #8): данные без загрузчика. Митигация: K1 — файл и регистр вводятся только вместе, в цикле 3.1 (K2 отклонён именно поэтому).

    Отложено¶

    • Реализация RaceRegistry — цикл 3.1.
    • Speed/size в движении — ФАЗА 5 (ADR-0010 §5).
    • Racial feats (если есть в PHB) — ФАЗА 3.5 (FeatEffect).

    Чек-лист решений A–K¶

    • A = A2 — YAML (races.yml) + Kotlin-обёртка (RaceRegistry.kt).
    • B = B1 — sealed interface RacialTrait (Passive/Active/Triggered).
    • C = C1 — sealed AbilityBonus (Fixed/Choice).
    • D = D1 — подрасы вложенно (Race.subraces).
    • E = E1 — race: RaceId + subrace: SubraceId? (E2/E3 отклонены).
    • F = F1 — RaceResolver.applyRacialBonuses (stateless object; F3 отклонён).
    • G = G1 — Half-Elf/Half-Orc/Variant Human в ADR-0020.
    • H = H1a + H1b — Breath Weapon через ADR-0019; Relentless Endurance hook в damage-resolution.
    • I = I1 — speed/size статически, движение — ФАЗА 5.
    • J = J1 — живой реестр + пометка дубля в ADR-0011 отдельным циклом.
    • K = K1 — только ADR; реализация — цикл 3.1.

    Untouched in this ADR¶

    • Код (RaceRegistry.kt, races.yml, CharacterState, CreateSessionRequest) — цикл 3.1.
    • BackgroundRegistry, FeatEffect, классовые фичи — отдельные ADR мини-ФАЗЫ 0 (ADR-0021, ADR-0022, ADR-0023). Мёртвый backgrounds.yml (факт #8) — не оживлять здесь.
    • ADR-0011 — запись про J1 отдельным циклом, когда ADR-0020 будет принят и реализован.
    • Frontend (wizard выбора расы) — ФАЗА 6.

    ADR-0028: SpellDeep — расширение модели заклинания (upcast, components, range, area, targets, ritual)¶

    Status¶

    Accepted

    Context¶

    Заклинания сегодня — это урезанная модель Spell (spells/Spell.kt): базовый урон/ лечение/бафф/дебафф + спасбросок, без upcast, area-геометрии, ritual и полноценных компонентов. Собранные факты (файл:строка):

    Заклинания сегодня¶

    Чего НЕ найдено (grep → 0)¶

    • UpcastEffect / upcast / PerLevelUpcast / FixedUpcast — ноль (base-level только).
    • SpellRange (sealed) / SpellArea / Sphere / Cone / Line / Cube / Cylinder — ноль. range только Int.
    • ritual — ноль (ни в модели, ни в JSON).
    • materialConsumed / materialCost — ноль (в Components только строка-описание).
    • Top-level duration / concentration у Spell — ноль (только внутри Buff/Debuff, факт #6).
    • targetCount в модели Spell — ноль (maxTargets есть в JSON, но не парсится, факт #9).
    • Пересечение Range/Aoe с ActionTemplate/Catalog — ноль (см. J1).

    Проблема¶

    Spell — урезан до «урон/лечение/бафф/дебафф + спасбросок». Нет upcast (Fireball при касте слотом 4-го уровня не растёт), нет area-геометрии (нельзя задать сферу/конус), нет ritual, компоненты не полны (нет consumed/cost), range — «голое» число без семантики Self/Touch/Special. Каждое новое правило (upcast, area) потребует расширения модели и реестра. Нужен полный PHB-контракт заклинания как расширение существующей модели (не greenfield — Spell/SpellRegistry/spells.json уже есть).

    Важно: данных 90 заклинаний L0–L3 (факт #24), а не полный PHB 300+. ADR закладывает полную форму на будущее, но реализация в 3.6 наполняет её только для текущих 90 — расширение справочника до полного PHB — отдельная data-задача.

    Прецеденты¶

    • ADR-0016 (remove mana → spell slots only) — прецедент «поля слота», форма расширения Spell.
    • ADR-0017 (CastingStats, fixedDc) — прецедент добавления вычисляемого поля + fallback.
    • ADR-0014 (ConcentrationManager) — концентрация уже реализована (H1 не трогает).
    • ADR-0022 (FeatEffect sealed: Passive/Active/Triggered) — прецедент sealed-иерархии эффектов (для B1/F1).
    • ADR-0027 (SkillResolver) — образец design-ADR (формат, чек-лист A–K).

    Канон D&D 5e (PHB гл.10 «Spellcasting», гл.11 «Spells»)¶

    • Upcast: заклинание кастуется слотом выше базового — растёт урон (+1d6/уровень), цели (+1/уровень) или длительность; фикс-апкаст (напр. «на 4-м уровне — 2 цели»).
    • Components: V (verbal, нужен голос), S (somatic, нужны свободные руки), M (material; если есть cost/consumed — тратится; focus/component pouch заменяет M без cost).
    • Range: Self / Touch / Ranged (в футах) / Special (описание) / Sight / Unlimited.
    • Area: sphere (radius), cone (length, 53°), line (length×width), cube (side), cylinder (radius×height).
    • Targets: fixed count (Magic Missile 3, Scorching Ray 3, Eldritch Blast 1 beam + scaling).
    • Ritual: каст без слота, +10 минут; только если заклинание имеет тег ritual.
    • Cantrip scaling: растёт с уровнем персонажа (Fire Bolt 1d10→4d10, Eldritch Blast 2/3/4 луча на L5/11/17) — не тратит слот (отдельно от upcast).

    Ссылка: https://dungeonsanddragons.ru/bookfull/5ed/5e%20Players%20Handbook%20-%20Книга%20игрока%20RUS.pdf

    Decision¶

    1. Место хранения (A2)¶

    Расширяем существующий spells.json + SpellRegistry (факты #8-9). Отдельного файла не вводим — второй источник. SpellRegistry.parseSpell дочитывает новые поля (upcast/components-consumed/range-sealed/area/targetCount/ritual); отсутствующие в JSON ключи → значения по умолчанию (backward-compatible).

    2. Upcast (B1)¶

    sealed interface UpcastEffect (симметрия FeatEffect, ADR-0022):

    sealed interface UpcastEffect

data class PerLevelUpcast(
    val damagePerLevel: Dice? = null,      // +1d6 fire per level
    val targetsPerLevel: Int = 0,          // +1 target per level
    val durationPerLevel: Int = 0,
    val other: String? = null,             // narrative
) : UpcastEffect

data class FixedUpcast(val atLevel: Int, val effect: String) : UpcastEffect

// В Spell: upcast: UpcastEffect? = null

    Примечание: Dice? в скетче — условное обозначение «значения кубика» (diceCount + diceType, как в SpellEffect.Damage). Не roller-класс com.yorva.rules.Dice (TurnResolver.kt:32). Имя типа значения зафиксировать в 3.6 (напр. DiceValue/DiceExpr).

    3. Components (C1)¶

    Расширение существующего Components (факт #2) — V/S/M уже есть, добавляем cost/ consumed:

    enum class ComponentType { V, S, M }

data class SpellComponents(
    val types: Set<ComponentType>,
    val material: String? = null,          // «a tiny ball of bat guano»
    val materialConsumed: Boolean = false, // Fireball — no, Revivify — yes
    val materialCost: Int? = null,         // gp, если указано
)

// В Spell: components: SpellComponents? = null  (заменяет Components)

    4. Material consumed (D1)¶

    Только флаг materialConsumed + materialCost (данные). Механика потребления (трата предмета из inventory) — future (ФАЗА 4 Inventory). canCast (:80) пока остаётся «MVP: материал не проверяем».

    5. SpellRange (E1)¶

    range: Int (факт #7) → sealed SpellRange:

    sealed interface SpellRange
data object SelfRange : SpellRange
data object TouchRange : SpellRange
data class Ranged(val feet: Int) : SpellRange        // 30/60/120/...
data class Special(val description: String) : SpellRange
// SightRange, UnlimitedRange — не SRD-канон (нет в PHB), но форма закладывается.

    Миграция: range: 0 → TouchRange; range: N>0 → Ranged(N); self-таргетинг (targets = SELF) не тождественен SelfRange (канон: range-self ≠ target-self).

    6. SpellArea (F1)¶

    sealed interface SpellArea
data class Sphere(val radiusFeet: Int) : SpellArea
data class Cone(val lengthFeet: Int, val widthFeet: Int = 5) : SpellArea
data class Line(val lengthFeet: Int, val widthFeet: Int = 5) : SpellArea
data class Cube(val sideFeet: Int) : SpellArea
data class Cylinder(val radiusFeet: Int, val heightFeet: Int) : SpellArea
// В Spell: area: SpellArea? = null

    7. Target count (G1)¶

    maxTargets (JSON, не парсится — факт #9) → targetCount в модели:

    // В Spell: targetCount: Int = 1
// Magic Missile: 3 (+1 per upcast level, cap 11)
// Scorching Ray: 3 (upcast +1)
// Eldritch Blast: 1 (cantrip, 2/3/4 beams at L5/11/17 — особый случай, через cantripScaling)

    MULTIPLE_ENEMIES требует targetCount > 1; ALL_ENEMIES/SELF — targetCount нерелевантен (=1). Валидация в 3.6.

    8. Concentration (H1)¶

    Не трогаем. Концентрация уже реализована (ADR-0014 K1, факт #19); признак concentration сегодня живёт внутри SpellEffect.Buff/Debuff (факт #6). Вынос top-level concentration: Boolean в Spell — не часть этого ADR (отдельное решение при рефакторинге SpellEffect в будущем).

    9. Ritual (I1)¶

    // В Spell: ritual: Boolean = false
// Механика (ритуал-каст без слота, +10 min) — future.

    10. Пересечение Range/Aoe с ActionTemplate (J1)¶

    Проверено: ActionTemplateRow (catalog/CatalogService.kt:42-51) — поля code/category/nameRu/attribute/skill/dcMedium/description/keywords. Таблица action_templates (changelog 0015) — нет колонок range/area/radius. Единственное «range» в каталоге — категория оружия RANGED_WEAPON и weapons.properties JSON (ammo/heavy/burst) — это не общий словарь дальности/зоны. Пересечения нет: SpellRange/SpellArea остаются Spell-local, новый дубль #14 в ADR-0011 НЕ регистрируем.

    11. Объём (K1)¶

    Только ADR (design, без кода). Реализация — цикл 3.6.

    Скетчи (минимальные)¶

data class Spell(

    val level: Int,
    val school: String,

    val range: SpellRange,                    // E1 (было Int)

    Примечание к скетчу: типы SpellComponents/SpellRange/SpellArea/UpcastEffect вводятся в 3.6; Components (старый) становится deprecated-алиасом или удаляется (решение в 3.6 по миграции 90 записей). Финальные сигнатуры — цикл 3.6.

    Proposed Options¶

    Развилки с вариантами, рекомендация архитектора помечена.

    A. Место. - A1: отдельный spells_deep.json + новый реестр — второй источник, рассинхрон. - A2: расширить spells.json + SpellRegistry — рекомендация архитектора. Единый источник, backward-compatible (дефолты для отсутствующих ключей).

    B. Upcast. - B1: sealed UpcastEffect (PerLevel/Fixed) — рекомендация архитектора. Типизировано, симметрия FeatEffect. - B2: строковое поле upcast: String? — не типизировано, парсинг руками. - B3: не делать — upcast недоступен (теряем каноничный рост Fireball/Magic Missile).

    C. Components. - C1: расширить Components → SpellComponents (types + material + consumed + cost) — рекомендация архитектора. V/S/M уже есть (факт #2), добавляем cost/consumed. - C2: оставить Components как есть — нет consumed/cost (Revivify нельзя отличить). - C3: строковый JSON-блоб — не типизировано.

    D. Material consumed. - D1: флаг materialConsumed + materialCost (данные) — рекомендация архитектора. Механика — ФАЗА 4 (Inventory). - D2: сразу механика траты из inventory — преждевременно (inventory ещё нет).

    E. Range. - E1: sealed SpellRange (Self/Touch/Ranged/Special) — рекомендация архитектора. Заменяет range: Int (факт #7); Sight/Unlimited — резерв. - E2: оставить Int + строковый rangeDescription — смешение, не типизировано.

    F. Area. - F1: sealed SpellArea (Sphere/Cone/Line/Cube/Cylinder) — рекомендация архитектора. Типизировано, таргетинг зоны — 3.6 + ФАЗА 5 (Grid). - F2: строковое area: String? — не типизировано, таргетинг невозможно валидировать.

    G. Target count. - G1: targetCount: Int = 1 (поверх maxTargets из JSON) — рекомендация архитектора. - G2: оставить только TargetType — Magic Missile (3 дротика) невыразим.

    H. Concentration. - H1: не трогать (ADR-0014 уже реализован) — рекомендация архитектора. - H2: выносить top-level concentration — преждевременный рефакторинг SpellEffect.

    I. Ritual. - I1: ritual: Boolean = false (данные) — рекомендация архитектора. Механика — future. - I2: сразу механика ритуал-каста (+10 min без слота) — объём вне 3.6.

    J. Пересечение с ActionRange. - J1: пересечения нет — SpellRange/SpellArea остаются Spell-local, дубль #14 НЕ регистрируем — рекомендация архитектора. (Каталог action_templates не имеет range/area; RANGED_WEAPON — категория оружия, не общий словарь.) - J2: зарегистрировать #14 в ADR-0011 — преждевременно (нет реального пересечения).

    K. Объём. - K1: только ADR; реализация — цикл 3.6 — рекомендация архитектора. - K2: ADR + частичная реализация — нарушает «один цикл = один фокусный шаг».

    Consequences¶

    Плюсы¶

    • Spell расширяется до полной PHB-модели (upcast, components, range, area, targets, ritual) — основа для 3.6.
    • Sealed-формы UpcastEffect/SpellRange/SpellArea типизированы (симметрия FeatEffect, ADR-0022).
    • Compatible с ADR-0016 (mana removal — поля слота), ADR-0017 (DC от кастера), ADR-0014 (концентрация, H1 не трогает).
    • Backward-compatible: отсутствующие в JSON ключи → дефолты, 90 записей не ломаются.

    Минусы¶

    • spells.json растёт (для 90 заклинаний — upcast/components/range/area; для полного PHB 300+ — объём кратно больше).
    • V/S/M — механика компонентов (вербальный при silence, somatic при restraint) — future, но поля вводятся сейчас.
    • Material consumed — без inventory (ФАЗА 4) не работает; только флаг.

    Риски¶

    • Upcast damage: ScalingDice (1d6/level) vs fixed (2d6 → 4d6). Форма PerLevelUpcast покрывает, но требует валидации в 3.6 (какое заклинание какой вариант использует).
    • Area: PHB не даёт единой формулы (sphere — radius, cone — length+угол 53°). Форма закладывает, детали (кто в зоне) — 3.6.
    • Cantrip scaling (Eldritch Blast beams, Fire Bolt 1d10→4d10) — отдельно от upcast (не тратит слот). Форма в этом ADR не фиксируется (cantripScaling — уточнить отдельным решением в 3.6).
    • Components: PHB требует вербальный/соматический для каста — если у персонажа нет голоса/рук, каст невозможен. Механика — future, но флаг нужен сейчас.
    • Ritual: каст без слота — механика (10 min extra) — future.
    • Коллизия имени Dice: в скетче B1 Dice? — «значение кубика», а com.yorva.rules.Dice (TurnResolver.kt:32) — roller-класс. В 3.6 зафиксировать имя типа значения (DiceValue/DiceExpr) во избежание путаницы.
    • Upcast wiring (стоп 3.6 #2): canCast/castSpell поддерживают upcastLevel, но ActionRequest не несёт уровень слота — интент приходит сырой строкой ("cast <spell_id>"). Реальная активация upcast требует расширения контракта интента (LLM-промпт + парсер/классификатор). Backend-логика готова, wiring — отдельная задача (зона LLM Engineer). В реальном геймплее пока upcast «спит» (upcastLevel = null).
    • SpellDto range format (стоп 3.6 #3): исходная human-readable миграция (Touch/Self) сломала frontend-эвристику Number(range)===0 (SpellDetailModal.tsx:54, SelectionSpellCard.tsx:110). Правка: range остаётся numeric-совместимым ("0 фт"), семантика — в новом поле rangeType. Frontend мигрирует на rangeType — ФАЗА 6.

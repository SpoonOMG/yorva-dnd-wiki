    ADR-0039: Герой между сессиями (кампания: «Продолжить историю» и «Новое приключение»)¶

    • Статус: Accepted
    • Дата: 2026-10-31
    • Контекст: soak-прогон v5 показал, что история героя заканчивается вместе с сессией — прогрессия (уровень, снаряжение, репутация) теряется. Для RPG-аудитории это блокер retention: герой должен жить между сессиями.

    Решение¶

    Герой становится долгоживущей сущностью (оживляется ранее мёртвая таблица characters), сессия — одной главой его истории.

    Модель данных¶

    • characters.character_json — сериализованный Participant (включая CharacterState): источник состояния героя между сессиями.
    • characters.last_session_id — последняя сессия героя (для кнопки «Продолжить историю» на фронте).
    • sessions.continued_from_session_id — ссылка на сессию-предшественницу (null — обычная сессия).

    Два режима (POST /api/v1/sessions)¶

    1. Новое приключение тем же героем: characterId без continueFromSessionId. Герой переносится в новую сессию того же мира с «междусессионным отдыхом» состояния; канва — свежая, без памяти прошлой истории. Точка входа — секция «Герои этого мира» в модале сессий мира.
    2. Продолжить историю: characterId + continueFromSessionId. Канва новой сессии получает блок «ПРОШЛАЯ ИСТОРИЯ» (резюме прошлой сессии из summaries) и обязана подхватывать её нити (gm-spine-prompt). Точка входа — финал канвы (ADR-0038): когда все биты сыграны (currentBeat >= beatCount), GET /sessions/{id} возвращает spineCompleted: true, и страница сессии показывает баннер «Продолжить историю», создающий сессию-продолжение.

    Write-through синк¶

    Источник правды о текущем состоянии — participantsJson активной сессии. После каждой записи participantsJson (ход, реакция, opening, allocate*, levelUp, prepareSpells, debug-хуки, grantStarterEquipment, backfill visualAnchor) SessionService.syncHeroSnapshot переписывает characters.character_json + last_session_id. Синк non-fatal: сбой логируется, ход не откатывается.

    Междусессионный отдых (CharacterService.resetForNewSession)¶

    Сильнее long rest: полные hp/хит-кости/слоты, классовые ресурсы по ClassResourceHelper.restore(LONG), снятие статусов/концентрации/баффов/истощения, сброс боевых флагов, сцен (currentScene → scene_1), droppedItems и сессионных счётчиков — xpTriggers (иначе ключи milestone@scene_1 прошлой сессии заблокируют milestone новой), рейт-лимитов лута (issuedLootItemIds, legendaryLootGranted, criticalGrantCount, dropItemSessionCount).

    Сохраняется прогресс: level/xp/атрибуты/maxHp/инвентарь/заклинания/репутации/квесты/черты/подкласс/pending-выборы.

    Ограничения¶

    • Мёртвый герой (isDead) не возобновляется — 400, permadeath сохраняется как ставка.
    • Герой привязан к миру создания (worldId): возобновление в другом мире запрещено (400).
    • Мультиплеерные сессии вне скоупа: синк берёт первого PLAYER-участника.

    Альтернативы¶

    • Snapshot в sessions + копирование при создании (без таблицы characters) — не даёт списка героев мира и «кем я играл» вне сессии; фронту нужен отдельный endpoint.
    • Полная нормализация состояния героя в отдельные таблицы — преждевременно: состояние уже сериализуется в Participant, дублирование схемы удвоит миграционный вес.

    Последствия¶

    • CreateSessionRequest.characterName/gender/attributes стали опциональными (обязательны только для нового героя — валидация в SessionService.create, 400).
    • GET /api/v1/characters?worldId= — список героев (HeroSummary).
    • Новая миграция: 0048-hero-continuation.
    • CharacterRepository параметризован UUID, не CharacterId: Hibernate после AttributeConverter видит @Id как UUID и отклоняет findById/merge с value-классом (TypeMismatchException: Supplied id had wrong type). Lookup-сервисы переводят CharacterId → .value на границе репозитория.

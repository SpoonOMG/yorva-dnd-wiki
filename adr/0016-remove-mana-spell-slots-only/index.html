    ADR-0016: Удаление mana — переход на spell slots как единственный ресурс заклинаний (канон 5e)¶

    Status¶

    Accepted

    Context¶

    В движке сосуществуют две параллельные модели ресурса заклинаний:

    1. Mana (homebrew-модель) — плоский пул очков, константная цена любого заклинания, расход только в NORMAL/HARDCORE, без восстановления.
    2. Spell slots (канон 5e) — уже полностью реализованы и работают (прогрессии full/half/pact, трата SpendSpellSlot, canCast, restore на отдыхе).

    Mana — это отход от канона 5e (PHB p.201-202), где единственным ресурсом заклинаний являются spell slots: уровень слота = уровень заклинания (1..9), upcast = трата слота выше уровня, full/half/pact прогрессии, long rest восстанавливает все слоты (pact — short rest). Продукт позиционируется на оригинальные миры на русском языке, механика канонична SRD — параллельная mana-модель дробит консистентность (audit: REG-1, NEW-1, NEW-2, NEW-3).

    Факты (файл:строка)¶

    Mana (homebrew-модель)¶

    # Место Что
    1 GameState.kt:352-353 CharacterState.mana: Int = 10, maxMana: Int = 10
    2 GameState.kt:517-518 require(mana in 0..maxMana), require(maxMana >= 0)
    3 GameState.kt:75,93,104,115 MechanicsProfile.resourcesEnabled: EASY=false, NORMAL=true, HARDCORE=true
    4 TurnResolver.kt:98 SPELL_MANA_COST = 3 — константная цена любого заклинания ≥1 уровня
    5 TurnResolver.kt:108-109 TurnMechanics.manaInsufficient / manaCost (поля ответа)
    6 TurnResolver.kt:947,1902 эмиссия StateChange.SpendMana
    7 SessionService.kt:2539 применение SpendMana: mana = (mana - amount).coerceAtLeast(0)
    8 GameState.kt:211 ItemBonuses.manaBonus: Int = 0
    9 ItemCatalogService.kt:274 чтение mana_bonus из БД → manaBonus
    10 SessionService.kt:777,955; ActionParser.kt:84 гейт hasSpellSlots = slots.values.any{it>0} || mana >= 3

    Ключевые наблюдения про mana: - manaBonus читается из БД, но нигде не применяется (grep manaBonus = только GameState.kt:211 + ItemCatalogService.kt:274; в расчёте ресурсов не участвует) — мёртвое поле. - Восстановление mana отсутствует: grep mana в RestService.kt = 0; LevelUpService mana не трогает (grep maxMana = только определение + тесты). → mana — фиксированный пул 10, который только убывает (≈3 каста за всю карьеру в NORMAL/HARDCORE). - Уровень слота при резолве выводится из manaCost, а не из spell.level (TurnResolver.kt:885-888, :938-941) — дублирующая/конфликтующая логика.

    Spell slots (канон 5e, уже реализовано и работает)¶

    # Место Что
    1 GameState.kt:362-364 spellSlots / maxSpellSlots: SpellSlots
    2 GameState.kt:1014-1043 data class SpellSlots: slots: Map<Int,Int>, hasSlot, lowestAvailable, spend(level), restore(maxSlots), forLevel(level) (full caster SRD)
    3 GameState.kt:1199 StateChange.SpendSpellSlot(level) — уже существует
    4 SessionService.kt:2540 применение SpendSpellSlot: spellSlots = spellSlots.spend(change.level)
    5 TurnResolver.kt:945,1998; ReactionResolver.kt:62,86,116 эмиссия SpendSpellSlot
    6 LevelUpService.kt:310-358 spellSlotsFor: FULL→forLevel, HALF→halfSlotsFor (:321-343), PACT→pactSlotsFor (:345-358)
    7 LevelUpService.kt:204,268-269 назначение maxSpellSlots/spellSlots на level-up
    8 SpellService.kt (canCast) level 0 (заговоры) без слота; warlock→pactSlots; иначе spellSlots.slots[spell.level]
    9 SpellService.kt:75 StateChange.CastSpell(level = spell.level) — уровень слота = уровень заклинания

    Pact Magic (отдельная модель, канон, НЕ трогать)¶

    # Место Что
    1 GameState.kt:1377-1402 PactSlots: count/level/used, forWarlockLevel, spend, restore
    2 ClassResourceHelper.kt:59,113-116,141 инициализация/level-up/restore pact slots
    3 ClassFeatureHelper.kt:64; SessionService.kt:2777,2795 spend/restore PACT_SLOTS
    4 TurnResolver.kt:1996 SpendClassResource("PACT_SLOTS") для warlock

    Upcast — отсутствует¶

    • grep upcast|higherLevel по backend = 0; поле upcast в Spell.kt нет; CastSpell.level = spell.level (SpellService.kt:75). Каноничный upcast (слот выше уровня) не поддержан.

    Mana в контракте/UI¶

    Слой Место Что
    OpenAPI openapi.yaml:356-358 manaInsufficient
    OpenAPI openapi.yaml:536-539 mana, maxMana
    OpenAPI openapi.yaml:1117-1118 spellSlotsBefore/After (уже есть)
    Frontend lib/api.ts:139,169,253 manaInsufficient, manaBonus, mana
    Frontend CharacterPanel.tsx:225-228; CharacterStaticPanel.tsx:113-114 mana-бар
    Frontend MechanicsStrip.tsx:25,45-46 предупреждение «Недостаточно маны»
    Frontend FunctionalPanel.tsx:46,69; LootDropCard.tsx:152 manaBonus в луте

    Ключевые ограничения для вариантов¶

    1. Pact Magic ≠ mana. Pact Magic (колдун) — отдельная каноничная модель (PactSlots + ClassResources.pactSlots), НЕ трогается. Смешивание запрещено (D1 = no-op).
    2. Спека-первая: изменение API-контракта — только через api-specification/openapi.yaml (AGENTS).
    3. StateChange.SpendSpellSlot(level) уже есть — перехода «mana → slots» в основном требует удаления, а не добавления новой механики.
    4. Уровень слота сейчас в mana-ветке выводится из manaCost; в slots-ветке — из spell.level. После удаления mana источник уровня один — spell.level.

    Decision¶

    Решения (A–M)¶

    • A = A1 — удалить CharacterState.mana / maxMana (GameState.kt:352-353) вместе с require(mana in 0..maxMana) / require(maxMana >= 0) (GameState.kt:517-518).
    • B = B1 — удалить ItemBonuses.manaBonus (GameState.kt:211) и чтение mana_bonus (ItemCatalogService.kt:274). Колонку БД item_archetypes.mana_bonus — оставить или drop'нуть, уточнить при реализации.
    • C = C1 — удалить StateChange.SpendMana + эмиссии (TurnResolver.kt:947,1902) + применение (SessionService.kt:2539).
    • D = D1 — единственный источник уровня слота — spell.level. Вывод из manaCost (TurnResolver.kt:885-888,938-941) удаляется.
    • E = E2 + резолвер — каталог spell_families и таблица БД (миграция 0017) ОСТАЮТСЯ (для статус-заклинаний); поле manaCost игнорируется. Удаляется только mana-путь resolveSpellCatalog (TurnResolver.kt:878-949). Канонический путь остаётся: SpellService.castSpell (SpellService.kt:60) + TurnResolver.resolveCastSpell (TurnResolver.kt:1954) / resolveSpellOrSummon (TurnResolver.kt:1872), из которых убираются mana-ветки (SpendMana, гейты resourcesEnabled).
    • F = F1 — удалить MechanicsProfile.resourcesEnabled (GameState.kt:75,93,104,115) и все гейты (TurnResolver.kt:879,935,1881,1902,1944). EASY-режим — отдельная game-design задача.
    • G = G2 — upcast отложен в ФАЗУ 3 (отдельный ADR).
    • H = H1 — canCast — slots-only: warlock→pact, level 0 free, иначе spellSlots.slots[level] (SpellService.kt:26-54 уже каноничен; mana не участвует).
    • I = I1 — Pact Magic no-op, не трогаем.
    • J = J2 — legacy mana в ledgerJson игнорируется. Обязательное требование: проверка shared/infrastructure/JsonConfig.kt выполнена — FAIL_ON_UNKNOWN_PROPERTIES НЕ отключён (strict). Поэтому J2 требует @JsonIgnoreProperties(ignoreUnknown = true) на CharacterState ИЛИ глобального .configure(FAIL_ON_UNKNOWN_PROPERTIES, false) в JsonConfig.kt — иначе старые сессии упадут на десериализации. Правка .kt — отдельным шагом, после явного подтверждения.
    • K = K1 — spec-first: сначала openapi.yaml, затем backend, затем frontend.
    • L = L1 — hasSpellSlots → canCastAnything = slots>0 || cantripsKnown>0 (cantrip-only кастер сохраняет возможность; нужен источник «есть ли known cantrips»).
    • M = M1 — удалить TurnMechanics.manaInsufficient/manaCost (GameState.kt:1112,1114) синхронно с openapi.yaml:356-358 и frontend/lib/api.ts. Если нужен API-сигнал об отказе — M2 (slotInsufficient/slotLevel).

    Обязательные уточнения¶

    • Mana — мёртвая механика (нет регена: grep mana в RestService.kt = 0). ADR-0016 = удаление, не переделка.
    • Pact Magic не затрагивается (I1).
    • resolveSpellCatalog удаляется; каталог spell_families остаётся (E).
    • J требует проверки JsonConfig.kt — она выполнена: strict (см. J выше).

    Proposed Options¶

    A. Судьба CharacterState.mana / maxMana (GameState.kt:352-353)¶

    • A1 — удалить поля полностью.
    • + Чистая модель, один ресурс; устраняет require (:517-518) и мёртвое состояние.
    • − Ломает сериализацию старых ledgerJson (ObjectMapper не знает об удалённом поле — см. J); правки всех мест чтения (гейты :777,955, ActionParser.kt:84).
    • A2 — оставить как @Deprecated (legacy-десериализация), не читать в логике.
    • + Старые сессии читаются без миграции; постепенный вывод из эксплуатации.
    • − Мёртвое поле живёт в DTO/модели; риск случайного использования.
    • A3 — оставить как homebrew-опцию (не удалять).
    • − Противоречит цели ADR (единственный ресурс); сохраняет конфликт двух моделей. НЕ РЕКОМЕНДУЕТСЯ.

    B. Судьба ItemBonuses.manaBonus (GameState.kt:211)¶

    • B1 — удалить поле + колонку чтения (ItemCatalogService.kt:274).
    • + Убирает мёртвый код; симметрично A1.
    • − Миграция БД (колонка mana_bonus в item_archetypes) либо оставить колонку без чтения.
    • B2 — оставить @Deprecated, не читать.
    • + Без миграции данных.
    • − Второе мёртвое поле.
    • B3 — переименовать в spellSlotBonus (предмет даёт доп. слот).
    • + Сохраняет «предмет → ресурс заклинаний» как фичу.
    • − Новая механика, канон SRD не знает «бонус слота от предмета» — преждевременно.

    C. Судьба StateChange.SpendMana¶

    • C1 — удалить SpendMana (эмиссия TurnResolver.kt:947,1902; применение SessionService.kt:2539).
    • + Один путь траты ресурса (SpendSpellSlot).
    • − Правки двух точек эмиссии + ветки применения; старые StateChange в истории ходов.
    • C2 — оставить как deprecated no-op.
    • + История ходов с SpendMana не ломается при чтении.
    • − Мёртвый вариант в sealed-иерархии StateChange.

    D. Источник уровня слота заклинания¶

    • D1 — всегда spell.level (канон).
    • + Единственный источник; соответствует PHB; CastSpell(level=spell.level) уже так работает (SpellService.kt:75).
    • − Требует удаления вывода из manaCost (TurnResolver.kt:885-888,938-941).
    • D2 — оставить вывод из manaCost (текущий mana-путь).
    • − Неканонично; сохраняет зависимость от mana. НЕ РЕКОМЕНДУЕТСЯ.
    • D3 — оба источника с флагом режима.
    • − Дублирование логики; конфликт источников. НЕ РЕКОМЕНДУЕТСЯ.

    E. Каталог spell_families + manaCost (CatalogService.kt:19,29-33; миграции 0015, 0017)¶

    • E1 — удалить каталог/резолв spell_families (альтернативный mana-резолв).
    • + Один путь резолва заклинаний.
    • − Удаление seed-данных (0017-status-spell-families.yaml) и SpellFamilyRow.manaCost.
    • E2 — оставить каталог, игнорировать manaCost.
    • + Каталог статус-заклинаний остаётся для прочих полей; без переезда данных.
    • − Мёртвая колонка mana_cost.
    • E3 — переписать manaCost → slotLevel.
    • + Каталог несёт каноничный уровень слота.
    • − Миграция колонки; дублирует Spell.level (см. D).

    F. MechanicsProfile.resourcesEnabled (GameState.kt:75,93,104,115)¶

    • F1 — удалить гейт (расход ресурсов всегда по канону).
    • + Устраняет расхождение сложности (audit NEW-3: «EASY не расходует ресурсы» — не канон).
    • − Теряется «облегчённый» режим; надо решить, чем заменить (если вообще).
    • F2 — оставить гейт только для EASY (в NORMAL/HARDCORE всегда канон).
    • + Минимальное изменение; EASY остаётся «бесплатным» для новичков.
    • − Гейт всё ещё неканоничен по сути.
    • F3 — переосмыслить (напр. EASY = больше слотов, а не бесплатно).
    • + Дизайн-решение сложности, а не ресурса.
    • − Вне объёма ADR-0016; требует game-design.

    G. Upcast¶

    • G1 — поддержать сейчас (слот выше уровня заклинания).
    • + Полный канон; SpendSpellSlot уже параметризован уровнем.
    • − Нужен выбор слота (какой слот тратить), отсутствует Spell.upcast-поле.
    • G2 — отложить до ФАЗЫ 3 (не блокирует удаление mana).
    • + Не строим преждевременно; удаление mana от upcast независимо.
    • − Upcast временно недоступен.
    • G3 — не поддерживать.
    • − Неполный канон. НЕ РЕКОМЕНДУЕТСЯ (но допустимо как сознательный скоуп).

    H. canCast (SpellService.kt)¶

    • H1 — slots-only (warlock→pact, остальные→spellSlots.slots[spell.level], level 0 free).
    • + Уже фактически так (mana в canCast не участвует); чистый канон.
    • − Удалить упоминания mana из hasSpellSlots-гейтов (SessionService.kt:777,955, ActionParser.kt:84).
    • H2 — hybrid (slots || pact || mana).
    • − Сохраняет третью ветку. НЕ РЕКОМЕНДУЕТСЯ.
    • H3 — как есть до ФАЗЫ 2.
    • − Откладывает устранение конфликта. НЕ РЕКОМЕНДУЕТСЯ.

    I. Pact Magic¶

    • I1 — подтвердить no-op (Pact Magic НЕ трогаем; PactSlots, PACT_SLOTS, ClassResourceHelper остаются как есть).
    • + Каноничная отдельная модель; смешивание с mana отсутствует уже сейчас.
    • − (none) — это фиксация границы, а не изменение.

    J. Legacy-сессии с mana в ledgerJson¶

    • J1 — мигрировать mana → spell slots при десериализации.
    • + Старые персонажи не теряют ресурс заклинаний.
    • − Нужна логика конвертации (сложно сопоставить 1:1).
    • J2 — игнорировать/сбрасывать mana (десериализация без mana, слоты как есть).
    • + Просто; незнакомый ключ Jackson игнорирует/сбрасывает в дефолт.
    • − Старые персонажи получают «пустой» ресурс до первого long rest.
    • J3 — @Deprecated поле с сохранением значения (совместимо с A2).
    • + Без потери данных; плавный вывод.
    • − Мёртвое поле живёт до ФАЗЫ 2+.

    K. Контракт/UI (OpenAPI + frontend)¶

    • K1 — spec-first (сначала openapi.yaml, затем код и frontend).
    • + Соблюдает AGENTS (spec-first); spellSlotsBefore/After уже в контракте (:1117-1118).
    • − Объём правок шире (openapi + frontend + backend одновременно).
    • K2 — отложить фронт/контракт до отдельной задачи (сейчас только backend).
    • + Меньше за один шаг; backend-модель чистится первой.
    • − Временно рассинхрон: UI рисует mana-бар при его отсутствии в модели.

    L. Формула «может кастовать» после удаления mana¶

    Сейчас hasSpellSlots = slots>0 || mana>=3 (SessionService.kt:777,955; ActionParser.kt:84). После A1 mana уходит.

    • L1 — переименовать в canCastAnything = slots>0 || cantripsKnown>0 — cantrip-only кастер (level 0, нет слотов) сохраняет возможность.
    • + Семантически верно; не блокирует bard/sorcerer/warlock на ранних уровнях.
    • − Нужен способ определить «есть ли cantrips» (grep known spells level 0).
    • L2 — оставить slots>0 без cantrip-ветки.
    • − Блокирует cantrip-only кастеров. НЕ РЕКОМЕНДУЕТСЯ.
    • L3 — slots>0 || pactSlots.used < pactSlots.count (покрывает warlock отдельно).
    • + Симметрично H1.
    • − cantrip-only кастер всё равно блокируется. НЕ РЕКОМЕНДУЕТСЯ без L1.

    M. TurnMechanics.manaInsufficient / manaCost (поля ответа)¶

    • M1 — удалить поля (GameState.kt:1112,1114) синхронно с openapi.yaml:356-358 и frontend/lib/api.ts.
    • + Чистый контракт.
    • − Ломает API-клиентов, если поле используется.
    • M2 — переименовать в slotInsufficient / slotLevel.
    • + Сохраняет сигнал клиенту (какой слот запрошен / почему отказ).
    • − Миграция DTO + UI.
    • M3 — оставить как есть (мёртвые поля).
    • − Противоречит A1/C1. НЕ РЕКОМЕНДУЕТСЯ.

    Consequences¶

    Плюсы¶

    • Устранён конфликт двух параллельных моделей ресурса заклинаний (mana vs spell slots).
    • Один источник уровня слота — spell.level (D1).
    • Единый путь траты ресурса — SpendSpellSlot (C1); mana-ветки (SpendMana, resourcesEnabled) удалены.
    • canCast → canCastAnything (L1) чинит cantrip-only кастеров (bard/sorcerer/warlock без слотов).
    • Контракт и UI чистые: manaInsufficient/manaCost/mana/maxMana/manaBonus уходят из OpenAPI и frontend (K1, M1).
    • Pact Magic не затронут (I1); upcast явно отложен (G2).

    Минусы¶

    • Legacy-сессии требуют проверки Jackson (J) — strict-маппер ломает десериализацию старых ledgerJson с mana.
    • EASY-режим без ресурсного гейта — отдельная game-design задача (F1 → F3).
    • Frontend mana-бар и api.ts требуют правок (K1, M1).
    • Spec-first расширяет объём одного шага (K1).

    Риски¶

    • J — strict Jackson ломает старые сессии. Митигация: @JsonIgnoreProperties(ignoreUnknown=true) на CharacterState + тест десериализации сессии с mana=7.
    • L1 — cantripsKnown требует источника данных. Митигация: known spells level 0 через SpellRegistry/canonicalClassId.
    • E — удаление resolveSpellCatalog может задеть существующие тесты. Митигация: grep тестов на resolveSpellCatalog/spell_families, отдельный коммит.

    Отложено¶

    • G2 — upcast, ФАЗА 3 (отдельный ADR).
    • F3 — EASY-режим, game-design.
    • Миграция mana → slots (J1) — только если откажемся от J2.

    Untouched in this ADR¶

    • Pact Magic — PactSlots (GameState.kt:1377-1402), PACT_SLOTS, ClassResourceHelper, ClassFeatureHelper — не меняются (I1).
    • Spell save DC / difficulty class — отдельная ADR-0017, вне объёма.
    • Conditions/duration/exhaustion — закрыты ADR-0013/0014/0015, не затрагиваются.
    • Upcast (G2) — ФАЗА 3, отдельный ADR.
    • EASY-режим без ресурсного гейта — отдельная game-design задача (F1 → F3).
    • Миграция legacy-сессий — при J2 mana сознательно сбрасывается (данные теряются); J1-миграция mana → slots не выполняется (соотношение неочевидно).
    • Колонка item_archetypes.mana_bonus — остаётся или drop'ается (уточнить при реализации B1).

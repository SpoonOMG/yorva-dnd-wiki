    ADR-0014: Длительность и жизненный цикл состояний (duration & lifecycle)¶

    Status¶

    Accepted

    Context¶

    ADR-0013 (Accepted) ввёл ядро состояний: enum StatusId (+ kind), ConditionRegistry, ConditionResolver, флаги гейтов, alias-таблицу и AdvDisadvantageResolver. Но ядро сознательно не отвечает на вопросы сколько живёт состояние и как оно снимается. Эта ADR закрывает duration/lifecycle: длительности, источник/уровень наложения, порядок tick↔save, Dispel Magic, save-модификаторы от состояний (вкл. auto-fail STR/DEX для Petrified).

    Из ADR-0013 уже решено (не переизобретать): - Enemy.statusDurations: Map<StatusId, Int> (D1 из 0013) — у врага поле появится. - StateChange + target + applyEnemyStateChanges (D1 из 0013). - H2 из 0013: DC берётся из источника наложения (spell/item), дефолт — из реестра, прокидывается через StateChange. Данный ADR — именно про то, как прокидывается. - J1 из 0013: auto-fail STR/DEX для Petrified → реализуется здесь (save-модификаторы). - kind (CONDITION/COMBAT_STATE/CLASS_EFFECT/HOMEBREW) в 0013 не используется в гейтах — ждёт именно этой ADR (какие состояния тикают, какие снимаются спасброском, какие имеют источник).

    Собранные факты (файл:строка):

    Модель длительности сейчас¶

    • CharacterState.statusDurations: Map<String, Int> (GameState.kt:463) — длительность в раундах. Поля statusSources / statusSpellLevels отсутствуют (grep = 0).
    • Enemy (GameState.kt:682-725) — есть statuses: List<String> (:691), но нет statusDurations (длительность врага не хранится; статусы врага бессрочны).
    • CharacterState.concentrationSpell: String? (GameState.kt:416) + activeModifiers: List<StatModifier> (:421); у StatModifier есть durationRounds: Int (spells/Spell.kt:123).

    Длительность в данных заклинаний¶

    • У Spell нет поля duration — длительность только внутри SpellEffect: SpellEffect.Buff.durationRounds: Int (spells/Spell.kt:91), SpellEffect.Debuff.durationRounds: Int (:101), флаг concentration: Boolean (:92, :102).
    • Форматы: только durationRounds (раунды). Значения в spells.json: 1 / 10 / 80 / 100. Нет «instant» / «minutes» / «hours» / «until save» / «until dispelled».
    • castingTime: ACTION/BONUS_ACTION/REACTION (spells/Spell.kt:37-41) — про скорость, не длительность.

    Как применяется/снимается длительность¶

    • StateChange.ApplyStatus(status, target, durationRounds = 1) (GameState.kt:1159) — target есть, duration есть.
    • StateChange.AddCondition(condition) (:1161) — без target, без duration.
    • StateChange.ApplyDebuff(condition, durationRounds) (:1238) — без target, duration есть, но не пишется.
    • applyStateChanges (SessionService.kt:2324+):
    • ApplyStatus — statusDurations[status] = durationRounds пишется только при durationRounds > 0 (:2443-2445), причём вне гейта target == PLAYER (:2437) → длительность статуса врага попадает в statusDurations игрока (баг, уже зафиксирован в 0013, D1).
    • AddCondition — только statuses.add (:2657-2661), duration не пишется.
    • ApplyDebuff — только statuses.add (:2686-2691), durationRounds игнорируется.
    • RemoveStatus — только statuses.remove(status) (:2447-2449), statusDurations не чистится (остаётся устаревший ключ).
    • SpellService.kt:235-239 при провале спасброска эмитит и AddCondition и ApplyDebuff — двойное добавление + потеря длительности (баг, зафиксирован в 0013).

    Порядок pass в конце хода¶

    • SessionService.kt:982 applyStateChanges → :986 tickDurations → :987-990 resolveSaveEnds. То есть tick ДО save (канон: спасбросок конца хода должен идти до тика длительности).

    tickDurations¶

    • tickDurations(state: CharacterState) (SessionService.kt:2824-2844):
    • декрементирует activeModifiers (удаляет при <= 0) и statusDurations (v - 1, удаляет при <= 0);
    • удаляет из statuses все статусы, чей duration истёк;
    • тикает только игрока (CharacterState); tickEnemyDurations не существует (grep = 0).
    • НЕ трогает concentrationSpell — если концентрационный бафф истёк, concentrationSpell остаётся «зависшим» (см. K).

    resolveSaveEnds (save-end)¶

    • resolveSaveEnds(state, dice, dc: Int = 12) (TurnResolver.kt:50) — DC захардкожен 12.
    • Применяется только к статусам, одновременно присутствующим в statuses, statusDurations и SAVE_END_STATUSES (:51-53). Бессрочные статусы (без ключа в statusDurations) никогда не снимаются спасброском.
    • Спасбросок CON с бонусом мастерства по уровню (2/3) (:57, :63); успех (nat 20, или non-1 и total >= dc) снимает статус и его длительность (:75-79).
    • Вызывается только в SessionService.kt:987-990 — для игрока. Для врага отдельного resolveSaveEnds нет.

    Спасброски врага против статуса¶

    • applyEnemyTurn (TurnResolver.kt:2682-2711): если враг isIncapacitated, спас saveDc = 13 + dcOffset (:2684), saveTotal = saveRoll + character.effectiveAttributes.conMod + enemy.statusSaveBonus (:2687) — использует CON игрока, а не врага (у Enemy нет conMod). Снимает только из Enemy.INCAPACITATING_STATUSES (:2691), DC хардкод.

    Save-модификаторы от состояний¶

    • SavingThrowResolver.resolvePlayerSave (SavingThrowResolver.kt:22-53) читает только способность + владение; модификаторов от состояний нет. resolveEnemySave (:62-86) — только statusSaveBonus.
    • Adv/disadv в TurnResolver.kt:2312-2322 применяются к проверкам/атакам, но не к спасброскам. Правил «Restrained → помеха DEX-спасброскам», «Petrified → авто-провал STR/DEX» нет.

    Dispel Magic¶

    • В spells.json:2533-2567 dispel-magic — это Debuff с condition: "Рассеяно" и INT-спасом DC 15, durationRounds: 1 — т.е. фейковое «рассеивание» как статус, а не канонический Dispel Magic.
    • Whitelist-заглушка DISPEL_MAGIC (action-whitelist-magic.yaml:84-86) ссылается на ключи knowsDispelMagic / target.hasMagic, которых нет в ctx (SessionService.kt:952-962 — только hasEnemy, enemy, hasSpellSlots, hasRangedWeapon, inCombat, hasSpell, isConcentrating, hasReaction). Механики Dispel Magic по источнику/уровню не существует (для этого и нужны statusSources/statusSpellLevels).

    DC наложения vs DC save-end¶

    • DC save-end — хардкод 12 (TurnResolver.kt:50); DC спас врага — 13 + offset (:2684).
    • DC наложения заклинания есть в данных (spell.savingThrow.dc, напр. spells.json:19 dc 13; SpellEffect.Debuff.savingThrow.dc), но не прокидывается в StateChange.ApplyStatus/ApplyDebuff (у них нет поля DC) — это и есть дельта H2 из 0013.

    Legacy-десериализация¶

    • CharacterState сериализуется Jackson'ом в ledgerJson (SessionService.kt:636, :1175). statusDurations имеет default emptyMap() (GameState.kt:463), кастомного десериализатора нет. Старые сессии: statuses (строки) сохраняются, statusDurations отсутствует → emptyMap() → статусы становятся бессрочными (не тикают, не save-end).

    Канон 5e (PHB p.203-204, 290-292)¶

    • Duration: instant / rounds / minutes / hours / until save / until dispelled / special.
    • Concentration: 1 эффект за раз; прерывается при incapacitated или провале CON-спасброска (DC 10 или половина урона).
    • Repeat save: в конце каждого хода (некоторые эффекты).
    • Dispel Magic: автоматически снимает эффект ≤ уровня слота; для более высокого — ability check DC 10 + spell level.
    • Petrified: auto-fail STR/DEX save (полностью парализует физически).

    Decision¶

    Принятые решения по развилкам A–M.

    A = A3. Map<StatusId, StatusInstance>, где StatusInstance(statusId, remaining: Int, source: SourceId? = null, spellLevel: Int? = null). ADR-0014 пересматривает D1 из ADR-0013 в части формы хранения: statusDurations: Map<String, Int> → Map<StatusId, StatusInstance>. Enemy.statusDurations тоже меняется на Map<StatusId, StatusInstance>. statuses: List<StatusId> остаётся. Семантика D1 сохранена (хранение длительности у носителя, включая врага); меняется только форма значения — со скалярного Int на структуру StatusInstance. Бессрочный статус — StatusInstance(remaining = Int.MAX_VALUE) (null оставлен для «без источника» — поле source). Проверка бессрочности — через ConditionRegistry (StatusId.kind, isPermanent flag).

    B = B1. Длительность в данных — только раунды (durationRounds). Minutes/hours (typed Duration) — ФАЗА 3, отдельный ADR.

    C = C3. Три pass в processTurn: apply → resolveSaveEnds (для kind == SAVE_END) → tick (для kind == TIMER). Использует kind из 0013. C3 меняет только ПОРЯДОК pass: apply → resolveSaveEnds → tick. Это устраняет списание раунда длительности до спасброска. Фикс NEW_GAP «бессрочные статусы не снимаются спасброском» — в C3-fix (отдельный пункт Decision).

    C3-fix (fix NEW_GAP). resolveSaveEnds изменяется — итерирует по всем статусам с kind == SAVE_END (через ConditionRegistry), а не по пересечению statuses ∩ statusDurations ∩ SAVE_END_STATUSES. Бессрочный статус из SAVE_END-набора теперь снимается спасброском. Текущая фильтрация (TurnResolver.kt:51-53) удаляется.

    D = D2. source хранится внутри StatusInstance.

    E = E2. spellLevel хранится внутри StatusInstance.

    F = F3. Dispel Magic отложен в отдельный ADR (ФАЗА 3). Фейковый «Рассеяно» в spells.json — зафиксировать как gap, не чинить здесь. Поля D2/E2 (source/spellLevel) в StatusInstance остаются — готовы под будущий ADR. Открытые gaps зафиксированы: «dispel-magic фейковый» и «DISPEL_MAGIC whitelist-заглушка мёртвая» (ключи ctx knowsDispelMagic/target.hasMagic не прокинуты) — для будущего ADR про Dispel Magic.

    G = G1. Отдельный SaveModifierResolver поверх StatusId. AdvDisadvantageResolver из 0013 не трогаем — он про проверки/атаки, не про спасброски.

    H = H1. Явное правило auto-fail (Petrified → STR/DEX) в SaveModifierResolver.

    I = I1. Симметричный tickEnemyDurations для Enemy.statusDurations.

    J = J1. ConditionLifecycle.removeAll(target, statusId) — атомарная чистка statuses + statusDurations + source + spellLevel разом.

    K = K1. Отдельный ConcentrationManager (владеет concentrationSpell + drop при уроне/incapacitated + тик длительности концентрации). NEW_GAP «tickDurations не чистит concentrationSpell» чинится здесь: ConcentrationManager тикает и drop'ает.

    L = L1. Fallback DC (если DC не передан через StateChange) — дефолт из ConditionRegistry (закрывает хардкод dc = 12 из TurnResolver.kt:50).

    M = M1. Legacy statusDurations: Map<String, Int> мигрируется через alias-таблицу (L1 из ADR-0013, Map<String, StatusId> в ConditionRegistry). Legacy статус без ключа в statusDurations мигрирует в StatusInstance(remaining = Int.MAX_VALUE) — сохраняет семантику «бессрочный».

    Proposed Options¶

    Развилки A–M. Ниже варианты с плюсами/минусами; выбор за архитектором.

    A. Модель duration (как хранить оставшуюся длительность). - A1: оставить Map<StatusId, Int> (rounds) из 0013 + добавить Enemy.statusDurations. +: минимальная дельта; совместимо с D1 0013; простая сериализация. −: не хранит source/spellLevel (придётся рядом держать параллельные Map — см. D/E); «один статус = один экземпляр» (нельзя иметь два «Очарован» от разных источников). - A2: новый StatusInstance(statusId, remaining: Int, source: SourceId?, spellLevel: Int?), statuses: List<StatusInstance>, statusDurations удаляется. +: полный lifecycle-объект (источник/уровень/остаток в одном месте), готов под Dispel Magic и множественные наложения одного состояния. −: ломает контракт 0013 (там List<StatusId> + Map<StatusId, Int>), миграция сессий сложнее, statuses.any { it == X } → statuses.any { it.statusId == X } по всему коду. - A3: гибрид — Map<StatusId, StatusInstance> (ключ StatusId, значение с remaining/source/spellLevel). +: сохраняет «один StatusId на носителя», добавляет метаданные без отдельной Map. −: всё ещё «один экземпляр на состояние» (тот же предел, что A1).

    B. Формат duration в данных. - B1: rounds-only (как сейчас). Минуты/часы записываются уже пересчитанными в раунды. +: ноль изменений в data; одна единица в рантайме. −: «1 hour = 600 rounds», «10 min = 100 rounds» — в данных это магические числа (80/100 уже так); потеря информации «это была минута, а не 10 раундов». - B2: typed Duration(value, unit: ROUNDS/MINUTES/HOURS) + конвертация в rounds в рантайме. +: сохраняет канонический смысл («Concentration, до 1 часа»), Dispel/дисплей могут показывать человекочитаемую длительность. −: нужен парсер + конвертер (1 min = 10, 1 hour = 600), правки spells.json и Spell.kt. - B3: «native» минуты/часы в данных, конвертация только при тике. +: данные читаются человеком. −: конвертация на каждом тике (или кэш), риск рассинхрона; избыточно для MVP (все заклинания уже в раундах).

    C. Порядок pass в конце хода. - C1: текущий apply → tick → save (оставить). +: ноль изменений. −: баг канона — длительность декрементится до спасброска конца хода. - C2: канон apply → save → tick (спасбросок конца хода, затем тик длительностей). +: соответствует «repeat save в конце каждого хода»; устраняет двойное списание раунда. −: нужно разделить pass для SAVE_END-статусов и timer-статусов (см. C3). - C3: три pass — apply → save (для SAVE_END) → tick (для timers) → resolveSaveEnds (как сейчас, но save-статусы не тикаются до спасброска). +: точное разделение семантик (kind: SAVE_END vs TIMER), канон для обоих. −: сложнее; требует, чтобы resolveSaveEnds и tickDurations не пересекались по наборам.

    D. statusSources (источник наложения). - D1: Map<StatusId, SourceId> рядом с statusDurations. +: минимальная дельта поверх A1; источник доступен для Dispel Magic. −: ещё одна параллельная Map (третий контейнер после statuses/statusDurations), риск рассинхрона при RemoveStatus. - D2: поле source внутри StatusInstance (только при A2/A3). +: атомарность (source живёт вместе с duration), нет параллельных Map. −: тянет A2/A3 (ломает контракт 0013). - D3: не хранить в 0014 — отложить statusSources до отдельного ADR про Dispel Magic. +: меньше объёма сейчас. −: Dispel Magic остаётся нереализуемым; дублирует «отложить» из 0013.

    E. statusSpellLevels (уровень заклинания для Dispel Magic). - E1: Map<StatusId, Int> (spell level; null/отсутствие = не заклинание/предмет). +: прямой вход для канон-проверки Dispel Magic (сравнение уровня слота). −: ещё одна Map; заполнение из spell.level / item.level нужно в точке наложения. - E2: spellLevel внутри StatusInstance (только при A2/A3). +: атомарность с D2. −: тянет A2/A3. - E3: не хранить в 0014 (отложить вместе с Dispel Magic). +: меньше объёма. −: Dispel Magic по уровню невозможен.

    F. Dispel Magic (механика). - F1: канон — снимает все эффекты ≤ уровня слота; для выше — ability check DC 10 + spellLevel. +: полный канон; использует D/E. −: требует statusSources/statusSpellLevels + резолвер dispel; заметный объём. - F2: упрощённо — снимает все эффекты ≤ уровня слота (без ability check). +: проще; покрывает частый случай. −: неполный канон (нет «пробивания» выше уровня). - F3: отложить Dispel Magic целиком (убрать фейковый «Рассеяно»-дебафф из spells.json или оставить). +: разгружает 0014. −: заклинание в каталоге остаётся фейковым; whitelist-заглушка DISPEL_MAGIC остаётся мёртвой.

    G. Save-модификаторы от состояний. - G1: единый SaveModifierResolver поверх StatusId (как AdvDisadvantageResolver F1 из 0013), применяется в SavingThrowResolver.resolvePlayerSave (и для врага). +: один источник истины для помех/авто-провалов; устраняет будущее дублирование. −: нужно описать, какие состояния дают помеху каким спасброскам (Restrained→DEX и т.д.). - G2: расширить существующий AdvDisadvantageResolver (F1 из 0013) спасбросками. +: переиспользует уже принятый резолвер. −: смешивает проверки/атаки/спасброски в одном резолвере (семантически шире). - G3: инлайн в точках спасброска (без отдельного резолвера). −: риск расхождения (то же, что 0013 хотел устранить); НЕ РЕКОМЕНДУЕТСЯ.

    H. Petrified auto-fail STR/DEX. - H1: явное правило «auto-fail» в SaveModifierResolver (PETRIFIED → STR/DEX = авто-провал). +: декларативно, читается в одном месте. −: резолвер должен уметь отличать «авто-провал» от «помехи». - H2: sentinel-значение модификатора (напр. Int.MIN_VALUE → авто-провал). +: простая модель данных. −: магическое число, хрупко. - H3: особенность ConditionResolver (не save-резолвер) — отдельная проверка isPetrified перед спасброском. +: изолирует Petrified. −: размазывает логику (Petrified — и в гейтах, и в save, и в damage).

    I. tickEnemyDurations. - I1: симметричный tickDurations(enemy: Enemy) (тик Enemy.statusDurations в конце хода). +: статусы врага истекают; симметрия с игроком. −: нужен pass для врага в processTurn (сейчас враг обрабатывается в applyEnemyTurn, не в pass). - I2: единый tick(statuses, target) (обобщить под обоих носителей). +: меньше дублирования. −: требует общего интерфейса носителя статусов (пересекается с D3 из 0013). - I3: тикать на каждом End-of-turn врага (не отдельный pass, а внутри applyEnemyTurn). +: минимум изменений структуры. −: семантика «чей ход кончается — того и тик» может разъехаться с игроком.

    J. Чистка метаданных при RemoveStatus / истечении. - J1: атомарная ConditionLifecycle.removeAll(target, statusId) — снимает statuses + statusDurations + statusSources + statusSpellLevels разом. +: исключает «забытый» ключ; единая точка. −: нужен единый lifecycle-объект (K). - J2: отдельные RemoveStatus/RemoveDuration/RemoveSource (оставить как есть + дописать чистку). +: минимальная дельта. −: риск рассинхрона (как текущий баг RemoveStatus не чистит statusDurations).

    K. Concentration ↔ status. - K1: отдельный ConcentrationManager (владеет concentrationSpell + drop при уроне/incapacitated + тик длительности концентрации). +: чистая ответственность; лечит «зависший» concentrationSpell при истечении баффа. −: ещё один компонент. - K2: сложить в ConditionLifecycle (сюда же, вместе с тиком длительностей). +: один lifecycle-объект для состояний и концентрации. −: смешивает две механики. - K3: не связывать — оставить concentrationSpell отдельной строкой, только дописать очистку при истечении баффа в tickDurations. +: минимум. −: концентрация остаётся «вне» lifecycle, риск новых расхождений.

    L. Fallback DC, не переданного через StateChange (H2 из 0013). - L1: дефолт из ConditionRegistry (базовый DC состояния). +: устраняет хардкод 12; единый источник. −: нужен источник данных «DC по умолчанию» в реестре. - L2: оставить 12 (текущий dc: Int = 12). +: ноль изменений. −: хардкод сохраняется. - L3: 13 + dcOffset (как в спасе врага) — унифицировать с вражеским. +: консистентность с врагом. −: всё ещё формула, не канон per-condition.

    M. Legacy statusDurations: Map<String, Int> миграция. - M1: мигрировать через alias (L1 из 0013) + та же логика rounds. +: старые сессии не теряют длительности; консистентно с миграцией statuses. −: нужна миграция ключей String→StatusId. - M2: сбросить в 0/пусто (старые статусы становятся бессрочными). +: просто. −: потеря длительности; статусы «зависнут» навсегда. - M3: тикнуть при первой возможности (запустить tickDurations при загрузке сессии). +: старые таймеры продолжают «идти». −: неоднозначно (неизвестно, сколько раундов прошло); риск неожиданного снятия.

    Consequences¶

    Плюсы¶

    • Единый lifecycle: StatusInstance собирает длительность + источник + уровень в одном значении (нет параллельных Map, риск рассинхрона уходит).
    • Канон-порядок pass (apply → resolveSaveEnds → tick): SAVE_END-статусы снимаются спасброском до списания раунда; TIMER-статусы тикаются как раньше.
    • Save-модификаторы впервые: SaveModifierResolver вводит помехи/авто-провалы от состояний (Restrained → DEX, Petrified → auto-fail STR/DEX) — ранее отсутствовали.
    • tickEnemyDurations: статусы врага теперь истекают (симметрия с игроком).
    • Атомарная чистка (ConditionLifecycle.removeAll): устраняет баг «RemoveStatus не чистит statusDurations» и будущие рассинхроны source/spellLevel.
    • Концентрация починена: ConcentrationManager тикает и drop'ает concentrationSpell, устраняя «зависшую» концентрацию при истечении баффа.
    • Legacy-миграция (M1): старые сессии не теряют длительности через alias-таблицу.

    Минусы¶

    • A3 меняет контракт 0013: statusDurations: Map<String, Int> → Map<StatusId, StatusInstance> — нужна явная отсылка на пересмотр D1 (см. Decision A). Код, читающий statusDurations как Map<String, Int>, придётся обновить.
    • C3 сложнее одного pass: три pass + разделение по kind (SAVE_END vs TIMER) вместо линейного apply → tick → save.
    • Два новых компонента: SaveModifierResolver + ConcentrationManager — расширяют ядро.
    • source/spellLevel не используются до Dispel Magic ADR: поля D2/E2 заполняются, но не потребляются, пока Dispel Magic не реализован (F3, ФАЗА 3).

    Риски¶

    • A3 ломает тесты/glue вокруг statusDurations: код и Gherkin-glue, читающие statusDurations как Map<String, Int>, потребуют правок. Митигация: alias-таблица + поэтапная миграция.
    • Миграция legacy statusDurations: риск потери при неполной alias-таблице. Митигация: тест «каждый String из аудита-09 имеет alias в ConditionRegistry».
    • C3 — риск двойного срабатывания SAVE_END-статуса в обоих pass. Митигация: SAVE_END и TIMER не пересекаются (наборы взаимоисключающие, по kind из 0013).

    Отложено¶

    • F3 — Dispel Magic механика (отдельный ADR, ФАЗА 3).
    • B2 — typed Duration (minutes/hours) — отдельный ADR, ФАЗА 3.

    Untouched in this ADR¶

    • Exhaustion (ADR-0015): поле CharacterState.exhaustion: Int (GameState.kt:374) уже есть, шкала 0..6, штрафы уровней и смерть на 6 — НЕ реализуются через StatusId здесь.
    • Dispel Magic механика (F3) — отдельный ADR (ФАЗА 3).
    • Typed Duration (B2) — отдельный ADR / ФАЗА 3.
    • REST-эндпоинты conditions/apply|remove (SessionController) — API-layer, ФАЗА 2+, вне рамок.
    • Фейковый dispel-magic в spells.json — зафиксирован как gap, не чинить здесь.
    • legendaryResistance — отдельная механика Monsters (ФАЗА 2), вне ядра состояний.
    • creatureType/targetCreatureTypes — отложено в 0013 (G2), не в этой ADR.
    • race/background/class features — не относятся к duration/lifecycle.

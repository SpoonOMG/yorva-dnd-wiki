    ADR-0036: Monster Catalog — реальные statblock'и + contested checks (ФАЗА 4.2)¶

    Status¶

    Accepted

    Context¶

    ФАЗА 4 core (ADR-0035) дала Enemy.creatureType/damageType, но враги остаются generic-архетипами rank×level (46 строк, миграция 0036) + legacy creatures (4 строки) + defaultEnemy хардкод (12 имён). Атрибутов/навыков у врага нет — contested checks (канон для shove/grapple) невозможны (ADR-0035 D6 Deferred).

    Факты (файл:строка, разведка 2026-10-02):

    # Файл:строка Факт
    1 changes/0015-action-catalog.yaml:182-200 legacy creatures: 4 строки (boar/plague_boar/wolf/goblin), только боевые числа.
    2 TurnResolver.kt:3692-3719 defaultEnemy: 12 keyword-монстров, боевые числа, без типа/атрибутов/XP.
    3 SessionService.kt:1337-1356, 3755 Спавн: structured SPAWN_ENEMY-effect (LLM выбирает archetype-код из секции промпта) + legacy regex-тег. Неизвестный код → эффект отброшен, врага нет.
    4 ContextBuilder.kt:243-254 LLM видит список архетипов (code
    5 beasts.yml + beasts/BeastRegistry.kt Прецедент YAML+Registry для существ (3 зверя Дикого облика: hp/ac/attack/damage/STR/DEX/CON/speed). INT/WIS/CHA, навыков, типа нет.
    6 TurnResolver.kt:1354-1402 resolveActionTemplate: shove/grapple/trip → фиксированный DC, статус без ответного броска врага. enemy доступен.
    7 GameState.kt:133-161, 773-822 Attributes — data class с дефолтами 10 (init-валидация 8..20); Enemy — Jackson, добавление nullable-полей с дефолтами backward-compat (прецедент G-048).
    8 audit-16-monsters.md Известные долги: pack_tactics/aura_fear/summon_minions/resist_element не реализованы; allowed_features не валидируется.

    Канон 5e: shove/grapple — contested: атлетика атакующего против атлетики или акробатики цели (цель выбирает). PB монстра — по CR (CR 0-4 → +2).

    Proposed Options¶

    По хранилищу statblock'ов:

    Вариант A: monsters.yml + MonsterRegistry (YAML+реестр) — принято. - Плюсы: конвенция кодовой базы (races/classes/beasts — YAML+Registry, ADR-0011); diff-friendly; не нужна Liquibase-миграция данных (46→N строк монстров в миграциях — анти-паттерн, данные уже мигрируют в yml-каталоги). - Минусы: вторая система рядом с creature_archetypes (см. D5 — архетипы остаются fallback'ом). - Решение архитектора.

    Вариант B: таблица monsters через Liquibase — отклонено. Данные монстров — контент, а не состояние; миграции для контента раздувают changelog и пересекаются с YAML-конвенцией реестров.

    По contested (когда у врага нет statblock'а):

    Вариант A: fallback на фиксированный DC (текущее поведение) — принято. Legacy-архетипы/defaultEnemy без атрибутов → старый путь. Statblock-враг → contested. Нет регрессии, постепенная миграция контента. - Решение архитектора.

    Вариант B: прокси-модификатор из attackBonus — отклонено (изобретённая семантика, ADR-0035 D6).

    Decision¶

    1. D1. monsters.yml + MonsterRegistry (симметрия BeastRegistry). Statblock: id, name, type (CreatureType, ADR-0035), size, cr (строка), xp (из CR по канон-таблице — данными, явно), hp, ac, attackBonus, damageDice, damageType, attributes (6), skills (список id: athletics, acrobatics, …), resistances/immunities/vulnerabilities/conditionImmunities, features (существующие движковые: regeneration/enrage/multiattack/…), speed, narrativeHint.
    2. D2. Enemy += attributes: Attributes? = null, skills: List<String> = emptyList() (nullable/default — backward-compat, факт #7). CR — не дублируем (XP несёт).
    3. D3. Спавн: instantiateMonsterEnemy(monsterId) — полный statblock (включая creatureType/damageType/XP/features). SPAWN_ENEMY-путь: код резолвится сначала как monster id, потом как archetype (fallback, факт #3 не ломается). ContextBuilder-секция архетипов += компактный список монстров по уровню игрока (CR-фильтр: xp ≤ XP-порога уровня).
    4. D4. Contested checks (shove/grapple): в resolveActionTemplate для манёврных кодов при enemy.attributes != null: бросок атакующего (атлетика, SkillResolver) против броска врага d20 + max(athletics, acrobatics) (модификатор атрибута + PB от CR при proficiency в skills; PB(CR 0-4) = +2). Успех атакующего = его total > врага. Без атрибутов — fallback DC (Вариант A). trip остаётся template-check (канон trip — не contested, а манёвр BM/шаблон).
    5. D5. Стартовый набор — 18 монстров SRD 5.1 (CR 0–2): bandit, cultist, guard, commoner, kobold, goblin, skeleton, zombie, giant_rat, wolf, giant_spider, orc, acolyte, scout, bugbear, ghoul, goblin_boss, ogre. (CR 0–2, покрытие low-level; источник — SRD, CC-BY.)
    6. D6. Не входит: миграция legacy creatures/defaultEnemy (fallback остаётся), реализация новых features (pack_tactics и пр. — аудит 16, отдельный цикл), удаление архетипов.

    Consequences¶

    Плюсы¶

    • Contested checks каноничны для statblock-врагов; универсальные манёвры (shove/grapple) наконец отличаются от skill-check'а по существу.
    • LLM получает реальный контент врагов (имена/CR/тип), а не абстрактные rank×level — лучше нарратив и баланс.
    • Единый каталог существ: beasts.yml (форма друида) и monsters.yml — один формат-прецедент, расширяемо.

    Минусы¶

    • Два контура врагов (monsters + archetypes-legacy) до миграции контента (осознанно: fallback, D6).
    • Дублирование wolf/giant_rat в beasts.yml и monsters.yml — принято (разные потребители: форма друида vs враг; консолидация — отдельный вопрос).

    Риски¶

    • LLM начнёт спавнить монстров по новым id — нужна секция промпта (D3) и fallback на архетип при неизвестном id (есть).
    • Contested меняет баланс shove/grapple (сильный враг реально сопротивляется) — канон, принято; тесты на границы.

    Отложено¶

    • Миграция/удаление legacy creatures, defaultEnemy, архетипов (после покрытия контентом). Features pack_tactics/aura_fear/summon_minions (аудит 16). Учёт size в манёврах (канон: shove/grapple — не больше чем на размер крупнее; данных size у Enemy нет — со statblock'ами появится, отдельный цикл).

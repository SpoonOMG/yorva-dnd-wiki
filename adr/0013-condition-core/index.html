    ADR-0013: Ядро состояний — StatusId, реестр, резолвер, гейты, иммунитеты¶

    Status¶

    Accepted

    Context¶

    Состояния (conditions) сейчас — свободные русские строки List<String> без типизации, реестра и единого резолвера. Логика «какие состояния что блокируют / дают помеху» захардкожена в наборах строк, размазана по GameState, TurnResolver, SessionService и расходится между игроком и врагом. ADR-0012 (Accepted) уже ввёл DamageType + DamageResolver + Damageable и флаг resistanceToAll (D1) под Petrified — данное ADR опирается на D1, а не переизобретает «сопротивление всему».

    Собранные факты (файл:строка):

    Модель состояния¶

    • CharacterState.statuses: List<String> — свободные русские строки (GameState.kt:345).
    • Enemy.statuses: List<String> (GameState.kt:691), NpcState.statuses: List<String> (:947).
    • CharacterState.statusDurations: Map<String, Int> (GameState.kt:463) — длительности статусов. Поля statusSources / statusSpellLevels отсутствуют (0 вхождений) — это территория ADR-0014.
    • Файла conditions.yml нет. Справочный словарь conditions: (24 English-кода) лежит в action-whitelist-core.yaml:240-264, но код его не читает — ActionWhitelist.kt:27 (dsl/ActionWhitelist.kt) грузит только root["action_whitelist"].
    • ConditionId / ConditionRegistry / ConditionResolver — 0 вхождений в коде.

    Наборы статусов (хардкод-строки, расходятся игрок/враг)¶

    CharacterState.companion (GameState.kt:644-668): - INCAPACITATING_STATUSES = {Заморожен, Ошеломлён, Парализован, Оглушён, Сон, Недееспособен} (:646) — Оглушён (Deafened) здесь ошибочно (канон: Deafened не лишает действий). - CONCENTRATION_BREAK_STATUSES = INCAPACITATING + {Без сознания, Окаменел, Окаменевший} (:652-653). - NO_MOVE_STATUSES (:656), NO_SPEAK_STATUSES (:659), NO_ATTACK_STATUSES (:662), NO_PERCEPTION_STATUSES = {Ослеплён, Оглушён, Глух} (:665), SAVE_END_STATUSES (:668).

    Дубликаты и расхождения: - CharacterState.isIncapacitated (:531) инлайн-дублирует набор INCAPACITATING (setOf("Ошеломлён","Парализован","Оглушён","Сон","Заморожен","Недееспособен")), не ссылаясь на константу. - Enemy.INCAPACITATING_STATUSES (:723) = {Заморожен, Ошеломлён, Парализован, Оглушён, Сон} — без Недееспособен, то есть расходится с игроком. - Геттеры isProne/isRestrained/isBlinded дублируют наборы строк (:534,537,540), у Enemy — isProne/isRestrained (:717,720).

    Гейты возможностей¶

    • Геттеры canAct/canMove/canSpeak/canAttack/canPerceive + blockedCapabilityReason есть (GameState.kt:544-579), но проверяются только canAct и canAttack в TurnResolver.kt:210 (if (!character.canAct)) и :223 (if (!character.canAttack && req.type in ATTACK_INTENTS)).
    • canMove/canSpeak/canPerceive — не гейтятся нигде в resolve.

    Adv/disadv (хардкод-наборы)¶

    TurnResolver.kt: - hasDisadvantageOnChecks = {Отравлен, Ошеломлён, Испуган, Связан, Опутанный, Оглушён, Ослеплён} (:2312-2313). - hasAdvantageOnSkill — только stealth && "Скрыт" (:2315-2316). - hasDisadvantageOnAttacks = {Отравлен, Ошеломлён, Испуган, Связан, Опутанный, Ослеплён, Сбит с ног} + isProne (:2318-2319). - targetGrantsAdvantage = {Связан, Опутанный, Без сознания, Парализован, Ошеломлён, Сон, Заморожен, Ослеплён, Сбит с ног} + isIncapacitated + isProne (:2321-2322). - Враг: enemyHasDisadv = {Отравлен, Ошеломлён, Испуган} (:2746) — набор уже, чем у игрока.

    Применение/снятие состояния¶

    • StateChange.ApplyStatus(status, target, durationRounds=1) (GameState.kt:1159) — target есть.
    • StateChange.RemoveStatus(status, target) (:1160).
    • StateChange.AddCondition(condition) (:1161) — без target.
    • StateChange.ApplyDebuff(condition, durationRounds) (:1238) — без target, durationRounds не пишется.
    • applyStateChanges (SessionService.kt:2324+):
    • ApplyStatus — if (target == PLAYER) statuses.add(...) + концентрация (:2436-2445); но statusDurations[change.status] = change.durationRounds пишется вне гейта target (:2443-2445) → длительность статуса врага попадает в statusDurations игрока.
    • AddCondition — безусловно statuses.add(condition) + концентрация (:2657-2661) → всегда на игрока.
    • ApplyDebuff — безусловно statuses.add(condition) + концентрация (:2686-2691); durationRounds игнорируется.
    • ApplyStatus(..., StateTarget.ENEMY) эмитится в манёврах (TurnResolver.kt:969,1168-1171), но applyEnemyStateChanges не существует → статусы на врага теряются.
    • SpellService.kt:235-239 при провале спасброска эмитит и AddCondition(effect.condition) и ApplyDebuff(condition, durationRounds) — двойное добавление + потеря длительности.

    Спасброски и DC¶

    • resolveSaveEnds(state, dice, dc: Int = 12) (TurnResolver.kt:50) — DC захардкожен 12; спасбросок только по статусам, присутствующим одновременно в statuses, statusDurations и SAVE_END_STATUSES (:51-53).
    • Спас врага против статуса: saveDc = 13 + profile.mechanics.dcOffset (TurnResolver.kt:2684), saveTotal = saveRoll + character.effectiveAttributes.conMod + enemy.statusSaveBonus (:2687) — использует CON игрока, а не врага (у Enemy нет собственного conMod).
    • У Enemy (GameState.kt:682-704): resistances/immunities только по урону; поля conditionImmunities нет (0 вхождений), creatureType/targetCreatureTypes нет (0 вхождений), legendaryResistance нет.

    Whitelist ctx¶

    • ctx для whitelist (SessionService.kt:952-962) содержит только: hasEnemy, enemy, hasSpellSlots, hasRangedWeapon, inCombat, hasSpell, isConcentrating, hasReaction. Статусных ключей нет (нет isPoisoned/isBlinded/isGrappled/isRestrained/…), хотя в action-whitelist-*.yaml они встречаются (hasCondition, hasParalysisAbility, isGrappled, isRestrained, isRaging и т.п.).

    Канон 5e (PHB Appendix A, p.290-292)¶

    15 состояний: blinded, charmed, deafened, exhaustion*, frightened, grappled, incapacitated, invisible, paralyzed, petrified, poisoned, prone, restrained, stunned, unconscious. (* Exhaustion — выносится в ADR-0015.) В коде состояния используются как русские строки-алиасы; полная таблица «русский ↔ канон ↔ где встречается» — в _REPORT-0013.md.

    Decision¶

    Утверждено архитектором (развилки A–L):

    • A = A1 — единый enum class StatusId (имя окончательное из K1), каждый элемент несёт nameRu.
    • B = B2 — Kotlin-реестр: флаги и метаданные у элементов enum (без conditions.yml, без Spring).
    • C = C1 — object ConditionResolver — чистая функция поверх реестра (как DamageResolver, ADR-0012 B1).
    • D = D1 — расширить StateChange полем target (добавить в AddCondition/ApplyDebuff), ввести applyEnemyStateChanges (симметрично applyStateChanges); Enemy получает statusDurations: Map<StatusId, Int>.
    • E = E1 — флаги у StatusId: blocksAct / blocksMove / blocksSpeak / blocksAttack / blocksPerceive. Геттеры canAct/canMove/canSpeak/canAttack/canPerceive вычисляются из statuses через флаги; хардкод-наборы строк (GameState.kt:644-668) удаляются.
    • F = F1 — единый AdvDisadvantageResolver поверх реестра; устраняет 5 хардкод-наборов (TurnResolver.kt:2312-2322, :2746) и расхождение игрок/враг.
    • G = G2 — Enemy.conditionImmunities: List<StatusId>; creatureType → ФАЗА 2.
    • H = H2 — DC из источника наложения (spell/item); дефолт — из реестра; DC прокидывается через StateChange (связь с ADR-0014).
    • I = I2 — типизированный StatusContext + extension toWhitelistCtx(): Map<String, Boolean> (обратная совместимость с текущим ctx: Map<String, Any>).
    • J = J1 — StatusId.PETRIFIED + флаги «недееспособен + immune к poison» в 0013; resistanceToAll — из ADR-0012 (D1, применяет DamageResolver, не здесь); auto-fail STR/DEX — в 0014.
    • K = K1 — единый StatusId enum с полем kind.
    • L = L1 — Kotlin-таблица алиасов Map<String, StatusId> внутри ConditionRegistry.

    Тип StatusId и kind¶

    Единый enum StatusId (результат A1 + K1): поле nameRu: String, поле kind: StatusKind, флаги E1 (blocksAct/blocksMove/blocksSpeak/blocksAttack/blocksPerceive) и метаданные F/G (источник помехи/преимущества, «immune to poison» для PETRIFIED). Один список statuses: List<StatusId>, один ConditionResolver, один whitelist-ctx.

    enum class StatusKind { CONDITION, COMBAT_STATE, CLASS_EFFECT, HOMEBREW }

    kind не используется в гейтах 0013 — гейты читают только флаги E1. kind — дискриминатор, заложенный заранее под duration-семантику ADR-0014 (какие состояния тикают, какие снимаются спасброском, какие имеют источник/уровень заклинания).

    Состав StatusId в 0013¶

    CONDITION (14 канонических — все кроме Exhaustion): BLINDED, CHARMED, DEAFENED, FRIGHTENED, GRAPPLED, INCAPACITATED, INVISIBLE, PARALYZED, PETRIFIED, POISONED, PRONE, RESTRAINED, STUNNED, UNCONSCIOUS.

    COMBAT_STATE: HIDDEN («Скрыт»), SURPRISED («Врасплох»/«Удивлён»), DODGE («Уклонение»), STABLE («Стабилен»).

    CLASS_EFFECT: RAGE («Ярость»), INSPIRED («Вдохновение»).

    HOMEBREW: FROZEN («Заморожен»), ASLEEP («Сон»), MUTE («Немота»).

    Вне StatusId: Exhaustion (числовое поле → ADR-0015); «Союзник» (ALLY) — это disposition (ReputationTier, NpcDisposition), а не запись statuses.

    Примечание: точная принадлежность «Стабилен» (COMBAT_STATE vs HOMEBREW) — на усмотрение реализации; зафиксирован предварительный вариант, kind важен только для 0014.

    Миграция statuses: List<String> → List<StatusId>¶

    При десериализации старых сессий строки из statuses маппятся через L1-таблицу алиасов (ConditionRegistry.alias(ru: String): StatusId?): «Сбит с ног»/«Сбита с ног»/«Лежит»/«Ничком» → PRONE, «Опутан»/«Опутанный»/«Связан» → RESTRAINED, «Захвачен»/«Грапплинг»/«Удержан» → GRAPPLED, «Оглушён»/«Глух» → DEAFENED и т.п. Неизвестная строка пропускается (не падает); полнота таблицы проверяется тестом (см. Consequences → Risks).

    Target-aware statusDurations¶

    statusDurations пишется только в target-aware ветке — фиксирует баг SessionService.kt:2443-2445 (длительность статуса врага попадала в игрока). Длительность статуса врага пишется в Enemy.statusDurations: Map<StatusId, Int>.

    Proposed Options¶

    Развилки A–L с вариантами и плюсами/минусами; итоговый выбор — в ## Decision.

    A. Типизация ConditionId. - A1: enum class ConditionId (15 канонических + служебные, каждый несёт nameRu). +: типобезопасность, как DamageType (ADR-0012 A1), exhaustiveness в when. −: требует маппинга легаси-строк и алиасов при загрузке. - A2: sealed class Condition (состояния с разной внутренней структурой, напр. Charmed→source). +: гибкость под состояния с параметрами (source для Charmed/Frightened). −: сложнее для сериализации и списков; избыточно для MVP. - A3: строковый ID (String) + реестр. +: минимальная миграция. −: сохраняет главный риск (строки), не даёт exhaustiveness; противоречит тренду ADR-0012.

    B. Источник данных реестра (ConditionRegistry). - B1: conditions.yml (дописать/вынести из action-whitelist-core.yaml:240-264) + загрузка в @PostConstruct. +: data-driven, правки без перекомпиляции, симметрия с classes.yml/feats.yml. −: нужен парсер + маппинг; риск рассинхрона enum↔yaml. - B2: Kotlin-реестр в коде (enum + свойства-флаги). +: типобезопасно, компилируемо, нет парсера. −: правки требуют релиза; дублирует enum в коде. - B3: таблица БД. −: преждевременно (данные статичны, MVP-нагрузки нет).

    C. Форма ConditionResolver. - C1: object ConditionResolver — чистая функция (как DamageResolver, ADR-0012 B1). +: детерминированный rules-engine, без состояния, легко тестировать. −: нет DI/конфига (не требуется для MVP). - C2: Spring-бин (@Component). +: инъекция реестра, переопределение в тестах. −: избыточно для чистой функции; противоречит паттерну ADR-0012.

    D. Target-aware применение состояния. - D1: расширить существующие StateChange полем target (ApplyStatus уже имеет; добавить в AddCondition/ApplyDebuff) + ввести applyEnemyStateChanges (симметрично applyStateChanges). +: минимальная дельта, единый тип изменения. −: нужно продумать, кто владеет длительностями врага. - D2: новый StateChange.ApplyConditionTo(target, condition, durationRounds) + унификация. +: явный сигнал «на цель», без размазывания по трём типам. −: ломает контракт, миграция эмиссии. - D3: унифицировать с Damageable-паттерном (общий интерфейс носителя состояний). +: симметрия Player/Enemy/Npc как в ADR-0012 C1. −: крупнее по объёму, тянет рефактор NpcState/Enemy.

    E. Гейты canMove/canSpeak/canPerceive. - E1: флаги у ConditionId (каждое состояние описывает, что блокирует: blocksMove/blocksSpeak/…). +: единственный источник истины, геттеры вычисляются из статусов, наборы-строки исчезают. −: требует полноты описания всех состояний. - E2: правила через ConditionRegistry (data-driven флаги). +: правится yaml'ом. −: те же минусы B1. - E3: оставить хардкод-наборы, но вынести в реестр (промежуточный). −: не решает расхождение наборов.

    F. Adv/disadv. - F1: единый AdvDisadvantageResolver поверх ConditionRegistry (источник помехи/преимущества = флаг состояния). +: устраняет 4+1 хардкод-наборов (TurnResolver.kt:2312-2322, :2746) и расхождение игрок/враг. −: объёмная миграция вызовов в resolveCheck/resolveAttack/applyEnemyTurn. - F2: оставить 4 функции, но вынести их данные в реестр. +: меньше риска. −: всё ещё 5 точек вызова, расхождение возможно вернуться.

    G. Иммунитеты к состояниям и тип существа. - G1: Enemy.conditionImmunities: List<ConditionId> + учёт в ConditionResolver.apply; creatureType как enum. +: канон (конструкт → immune poisoned), расширяемость. −: требуется источник данных (creature_archetypes 0036). - G2: только conditionImmunities без creatureType. +: минимальный шаг. −: creatureType откладывается (частичный канон). - G3: отложить оба (ФАЗА 2 Monsters). −: иммунитеты не работают.

    H. Save DC per condition. - H1: из ConditionRegistry (condition → DC formula/базовый DC). +: устраняет хардкод 12/13+offset. −: нужен источник; «DC от источника наложения» (spell/item) каноничнее. - H2: из источника наложения (spell/item DC) + дефолт из реестра. +: канон. −: требует прокидывать DC через StateChange (связь с ADR-0014).

    I. Whitelist ctx — статусные ключи. - I1: плоский Map<String, Boolean> (isPoisoned=true, isBlinded=false, …), вычисляется из statuses. +: минимальная дельта, whitelist уже работает с Map. −: опечатки в ключах не ловятся компилятором. - I2: типизированный объект StatusContext (поля-флаги). +: типобезопасно. −: больше кода, ломает текущий ctx: Map<String, Any>.

    J. Граница Petrified (D1 из ADR-0012) — что в 0013, что в 0014. - J1: в 0013 — ConditionId.PETRIFIED + «недееспособен + immune к poison» как флаги реестра; resistanceToAll — уже флаг D1 (ADR-0012), его применяет DamageResolver (не 0013). Auto-fail STR/DEX (save-модификатор) — в 0014 (вместе с save-модификаторами от состояний). - J2: в 0013 — всё, включая save-модификаторы. −: тянет 0014-territory. - J3: Petrified целиком в 0014. −: «resistance to all» уже решено в 0012, условие-ядро остаётся без учёта.

    K. Единая типизация статусов или разделение классов сущностей. - K1: единый StatusId enum с полем kind: CONDITION / COMBAT_STATE / CLASS_EFFECT / HOMEBREW. Один список statuses: List<StatusId>, один resolver, один whitelist-ctx. +: минимальная миграция; kind используется в 0014 для duration-семантики. −: семантически смешаны разные сущности. - K2: раздельно ConditionId (14 канонов) + отдельные подсистемы для combat states (Hidden, Surprised) + class effects (Rage, Inspired). +: чистота семантики. −: три списка на CharacterState, три resolver, три ctx; большой рефактор. - K3: ConditionId только для канонов; остальное остаётся String. +: минимум изменений. −: сохраняет хардкод-строки; противоречит цели.

    L. Alias-резолвер для легаси-строк. - L1: Kotlin-таблица Map<String, StatusId> внутри ConditionRegistry (алиасы: «Сбит с ног»/«Сбита с ног»/«Лежит»/«Ничком» → PRONE, «Опутан»/«Опутанный»/«Связан» → RESTRAINED, «Захвачен»/«Грапплинг»/«Удержан» → GRAPPLED, «Оглушён»/«Глух» → DEAFENED и т.п.). +: один источник истины; типобезопасно; тестируется. −: правки в коде при новых алиасах. - L2: YAML-таблица (в conditions.yml, если B1) — не наш выбор при B2, но оставить как вариант. - L3: без alias-резолвера (старые сессии теряют состояния). −: НЕ РЕКОМЕНДУЕТСЯ.

    Consequences¶

    Плюсы: - Единая типизация StatusId — нет расхождения игрок/враг (Enemy.INCAPACITATING_STATUSES :723 и enemyHasDisadv :2746 унифицируются с игроком). - Alias-миграция (L1) — старые сессии не теряют состояния. - resistanceToAll (D1) из ADR-0012 переиспользован, не дублируется. - Whitelist-ctx типизирован (StatusContext + toWhitelistCtx()), опечатки ключей ловятся компилятором. - Хардкод-наборы строк (adv/disadv, INCAPACITATING, NO_*) удаляются — один источник истины.

    Минусы: - Миграция statuses: List<String> → List<StatusId> в старых сессиях (десериализация). - Расширение StateChange полем target + applyEnemyStateChanges ломает тесты/glue (component-tests). - Прокидывание DC через StateChange (H2) — дельта контракта, тянет связь с 0014.

    Риски: - Homebrew-статусы могут потребовать пересмотра kind в 0014 (напр. FROZEN/ASLEEP семантически близки к CONDITION). - Неполная alias-таблица → потеря состояния при миграции. Митигация — тест «каждый уникальный String-статус из аудита имеет alias в реестре». - StatusContext (I2) ломает текущий ctx: Map<String, Any> — нужен extension для обратной совместимости.

    Отложено: F2 «магическое оружие» — уже в ADR-0012 (не часть ADR-0013).

    Untouched in this ADR¶

    НЕ входит в ADR-0013 (территория 0014/0015): - Duration/lifecycle (0014): statusSources, statusSpellLevels, Dispel Magic, tickEnemyDurations, порядок tick↔save, save-модификаторы от состояний (вкл. auto-fail STR/DEX для Petrified — J1 выносит это в 0014). - Exhaustion (0015): поле CharacterState.exhaustion: Int (GameState.kt:374) уже есть, но шкала 0..6, штрафы уровней и смерть на 6 — НЕ реализуются через ConditionId здесь. - legendaryResistance (отдельная механика Monsters, вне ядра состояний). - REST-эндпоинты conditions/apply|remove (SessionController) — вне рамок ядра. - Alias-миграция (L1) реализуется в 0013, но тесты миграции старых сессий — отдельно (не в этом ADR).

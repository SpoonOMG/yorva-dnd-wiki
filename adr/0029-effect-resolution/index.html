    ADR-0029: Effect Resolution — механизм «фича → StateChange»¶

    Status¶

    Accepted

    Context¶

    Фичи сегодня хранят эффект текстом (description: String) или семантическими строками-заготовками (condition/effect: String?), а FeatureActivator эмитит только трейс StateChange.ActivateFeature(featureName). Детерминированного механизма «фича → StateChange» нет: урон Sneak Attack, лечение Second Wind, выдача действия Action Surge, бафф Rage, кубики Bardic Inspiration — невыразимы как данные. Каждая из ~20 фич требует inline-when в движке. Нужен единый EffectSpec (данные) + резолвер (поведение), симметричный SkillResolver (ADR-0027) / RaceResolver (ADR-0020) / SpellEffect (ADR-0028).

    Собранные факты (файл:строка):

    Фичи, эффекты, StateChange сегодня¶

    Чего НЕ найдено (grep → 0)¶

    • EffectSpec / FeatureEffectResolver / EffectCondition / ScalingSpec / ScalingBy — ноль.
    • DiceBonus / GrantAction / GrantInspiration StateChange — ноль (кубик вдохновения на цель невыразим).
    • Структурный effect: у фичи в classes.yml — ноль (только description).
    • Поле «выданный кубик вдохновения на цель» в CharacterState — ноль (только BardicInspiration.dieSize у ресурса, факт #13).

    Проблема¶

    Механический эффект фичи закодирован в свободном тексте или в хардкоде (activateFeatureResource, факт #19). Каждая из ~20 фич (Sneak Attack, Second Wind, Action Surge, Rage, Bardic Inspiration, Superiority, …) потребует своего when-блока в движке — 20 инлайн-путей вместо одного резолвера. Нужен типизированный EffectSpec (данные в classes.yml + sealed-форма в Kotlin) и stateless-резолвер, эмитирующий List<StateChange> через существующую StateChange-машину. Это закладывает основу для циклов 3.7a/b/c.

    Прецеденты¶

    • ADR-0020 (RaceResolver) / ADR-0021 (BackgroundResolver) / ADR-0027 (SkillResolver) — stateless object как слой поведения поверх реестра данных.
    • ADR-0028 (SpellEffect sealed + DiceValue + UpcastEffect scaling) — образец sealed-иерархии эффектов и ScalingSpec.
    • ADR-0022 (FeatEffect sealed: Passive/Active/Triggered) / ADR-0023 (ClassFeature sealed) — образец типизации природы фичи.
    • ADR-0024 (ClassResource data-driven, PoolType.DICE) — Superiority уже есть как DICE-пул.
    • ADR-0019 (AbilityResolver) — контракт List<StateChange> активации.

    Канон D&D 5e (PHB гл.3 «Classes»)¶

    • Sneak Attack: +Nd6 к урону при advantage или союзнике в 5 фт от цели.
    • Second Wind: бонусным действием 1d10 + уровень HP.
    • Action Surge: +1 действие в ходу, 1/короткий отдых.
    • Rage: +2 к урону силой, сопротивление b/p/s, нельзя в тяжёлой броне.
    • Bardic Inspiration: дать d6 (растёт d8/d10/d12) на следующую проверку/атаку.
    • Fighting Style: пассивные модификаторы (+2 к урону, +1 AC, …).

    Ссылка: PHB 5e, гл.3 (Class features).

    Proposed Options¶

    Развилки с вариантами, рекомендация архитектора помечена.

    A. Место хранения EffectSpec. - A1: отдельный effects.yml + реестр — второй источник, рассинхрон с фичами. - A2: classes.yml (данные, поле effect:) + sealed-форма в Kotlin; трейсы ActivateFeature расширяются — рекомендация архитектора. Единый источник рядом с фичей.

    B. Форма EffectSpec. - B1: sealed interface EffectSpec (Damage/Heal/Buff/Debuff/GrantAction/ Resource/DiceBonus/Composite) — рекомендация архитектора. Типизировано, симметрия SpellEffect (ADR-0028) / FeatEffect (ADR-0022). - B2: строковый блоб (effect: String) — не типизировано, парсинг руками.

    C. Резолвер. - C1: FeatureEffectResolver — stateless object, резолвит EffectSpec → List<StateChange> — рекомендация архитектора. Симметрия Race/Skill/SpellResolver. - C2: методы прямо в FeatureActivator — смешение активации (стоимость) и резолва эффекта.

    D. Возврат. - D1: List<StateChange> — переиспользуем StateChange-машину; новые типы — минимум (только неизбежное: DiceBonus) — рекомендация архитектора. - D2: собственный тип результата EffectResolutionResult — второй параллельный контракт.

    E. Scaling. - E1: scaling: ScalingSpec? — sealed (PerLevel / Fixed / ByResource); прецедент UpcastEffect (ADR-0028) — рекомендация архитектора. Фичи скейлятся по уровню/ресурсу, не по слоту. - E2: переиспользовать UpcastEffect как есть — семантика слота ≠ уровня/ресурса.

    F. Многосоставные фичи. - F1: CompositeEffect(effects: List<EffectSpec>) — Rage = активация + Buff + Triggered — рекомендация архитектора. - F2: несколько полей effect1/effect2 — ad-hoc, не типизировано.

    G. Triggered-фичи. - G1: TriggeredClassFeature.effect: EffectSpec? — тот же резолвер при срабатывании FeatureTrigger — рекомендация архитектора. - G2: отдельный резолвер для триггеров — дублирование логики.

    H. Условия. - H1: EffectCondition? — опциональное условие (Rage без тяжёлой брони; Sneak Attack при advantage/союзнике) — рекомендация архитектора. Проверяется в резолвере. - H2: без условий — фичи применяются безусловно (неверно для Rage/Sneak Attack).

    I. SpellEffect vs EffectSpec. - I1: частичное совпадение (Damage/Healing/Buff/Debuff 4/4) — зафиксировать как potential дубль #14 ADR-0011, унификацию НЕ проводить сейчас — рекомендация архитектора. (Разведка: формы зеркальны, но представление полей разное — см. Consequences → Риски.) - I2: сразу унифицировать EffectSpec и SpellEffect — преждевременный рефакторинг Spell-слоя (завязки на SavingThrow/concentration/StatModifier).

    J. Объём. - J1: только ADR (design); реализация — 3.7a/b/c — рекомендация архитектора. - J2: ADR + частичная реализация — нарушает «один цикл = один фокусный шаг».

    Decision¶

    A. Место хранения (A2)¶

    EffectSpec — данные в classes.yml (поле effect: у фичи) + sealed-форма в Kotlin (rules/feature/EffectSpec.kt). Существующие трейсы ActivateFeature расширяются (резолвер читает эффект из реестра), не заменяются — обратная совместимость для фич без effect: (только трейс).

    B. Форма EffectSpec (B1)¶

    sealed interface EffectSpec

data class DamageEffect(
    val dice: DiceValue,                 // ADR-0028 (spells/SpellDeepTypes.kt:67)
    val damageType: DamageType? = null,
    val scaling: ScalingSpec? = null,
) : EffectSpec

data class HealEffect(
    val dice: DiceValue,
    val scaling: ScalingSpec? = null,
) : EffectSpec

data class BuffEffect(
    val statModifiers: Map<String, Int>, // "attack_roll"->+2, "ac"->+1
    val duration: Int,
    val scaling: ScalingSpec? = null,
) : EffectSpec

data class DebuffEffect(
    val condition: StatusId,             // ADR-0013 (не строка)
    val saveDc: Int? = null,
    val duration: Int,
) : EffectSpec

data class GrantActionEffect(
    val actionType: FeatureActionType,   // Action Surge
) : EffectSpec

data class ResourceEffect(
    val resourceId: String,              // Arcane Recovery
    val amount: Int,
) : EffectSpec

data class DiceBonusEffect(
    val dice: DiceValue,                 // Bardic Inspiration
    val appliesTo: String,               // "next_attack" / "next_check"
) : EffectSpec

data class CompositeEffect(
    val effects: List<EffectSpec>,       // F1: Rage = Buff + Triggered
) : EffectSpec

    C. Резолвер (C1)¶

    FeatureEffectResolver — stateless object, резолвит EffectSpec в List<StateChange>. Симметрия RaceResolver / SkillResolver / SpellResolver. Не смешивать с FeatureActivator (активация = стоимость + экономия + делегирование).

    D. Возврат (D1)¶

    Возвращает List<StateChange> — переиспользует существующую StateChange-машину (SessionService.applyStateChanges, факт #19). Новых StateChange-типов — минимум: только DiceBonusEffect требует нового типа (см. Risks). GrantActionEffect ложится на существующий GrantExtraAction (GameState.kt:1325).

    E. Scaling (E1)¶

    scaling: ScalingSpec? — sealed:

    sealed interface ScalingSpec
data class PerLevelScaling(val perLevel: DiceValue) : ScalingSpec   // +1d6/уровень (Sneak Attack)
data class FixedScaling(val atLevel: Int, val effect: String) : ScalingSpec
data class ByResourceScaling(val resourceId: String, val perUnit: DiceValue) : ScalingSpec // Ki/Pact

    Прецедент — UpcastEffect (ADR-0028), но с семантикой уровня/ресурса, а не слота.

    F. CompositeEffect (F1)¶

    CompositeEffect — одна фича даёт несколько EffectSpec. Rage: активация (SpendClassResource + ApplyBuff) + Triggered (сопротивление при ON_DAMAGE_TAKEN).

    G. Triggered-фичи (G1)¶

    TriggeredClassFeature.effect: EffectSpec? — тот же FeatureEffectResolver при срабатывании FeatureTrigger. Строковое поле effect: String? (факт #4) заменяется типизированным.

    H. EffectCondition (H1)¶

    EffectCondition? — опциональное условие, проверяемое в резолвере до эмиссии StateChange. Примеры: Rage — «без тяжёлой брони»; Sneak Attack — «advantage || союзник в 5 фт». Форма — закрытый набор предикатов (или ссылка на AdvDisadvantageResolver, ADR-0013) — уточняется в 3.7a.

    I. SpellEffect vs EffectSpec (I1)¶

    Разведка: SpellEffect (Spell.kt:67-106) и EffectSpec частично совпадают — 4 из 4 базовых вариантов (Damage/Healing/Buff/Debuff) зеркальны, но представление полей разное: diceCount+diceType (inline) vs DiceValue; List<StatModifier> vs Map<String,Int>; condition: String vs StatusId; плюс у EffectSpec 4 дополнительных варианта (GrantAction/Resource/DiceBonus/Composite) и scaling. Фиксируем как potential дубль #14 ADR-0011 (два параллельных набора Damage/Heal/Buff/Debuff + двойное представление кубика). Унификацию НЕ проводим в этом ADR — отдельный рефакторинг 3.7+ после подтверждения пересечения.

    J. Объём (J1)¶

    Только ADR (design, без кода). Реализация — циклы 3.7a/b/c.

    Consequences¶

    Плюсы¶

    • Единый механизм «фича → StateChange» вместо ~20 inline-when (Sneak Attack, Second Wind, Action Surge, Rage, Bardic Inspiration, …).
    • Симметрия SpellEffect (ADR-0028) / SkillResolver (ADR-0027) / RaceResolver (ADR-0020): данные (sealed EffectSpec) + поведение (stateless резолвер).
    • CompositeEffect покрывает многосоставные фичи (Rage = активация + Buff + Triggered).
    • Готово для 3.7a (данные + резолвер), 3.7b (StateChange-расширения), 3.7c (Wild Shape/Metamagic).
    • Переиспользование существующей StateChange-машины (D1): GrantExtraAction, SpendClassResource, ApplyBuff уже есть.

    Минусы¶

    • Ещё один stateless-резолвер (10-й по счёту после Race/Background/Damage/ Condition/Ability/Skill/Spell/…).
    • Расширение classes.yml (поле effect: на ~20 фич) — миграция данных.
    • Возможный дубль со SpellEffect (I) — два параллельных Damage/Heal/Buff/Debuff.

    Риски¶

    • EffectSpec vs SpellEffect — два параллельных DiceValue/Damage. Митигация: зафиксирован potential дубль #14 (I); унификация — отдельным циклом 3.7+.
    • ScalingSpec: фичи скейлятся по уровню/ресурсу, не по слоту. UpcastEffect (ADR-0028) не подходит 1:1 — введён отдельный ScalingSpec (E1) с ByResourceScaling для Ki/Pact.
    • GrantAction требует расширения ActionEconomy. GrantExtraAction уже есть (GameState.kt:1325), но GrantActionEffect для Action Surge потребует связки с resourceId = ACTION_SURGE (трата 1/отдых) — уточняется в 3.7a.
    • DiceBonus (Bardic Inspiration) — кто хранит d6..d12 и как применяется к следующему броску. Требует нового StateChange (напр. GrantInspirationDie) и нового поля в CharacterState (pending die на цель). Сегодня есть только BardicInspiration.dieSize у ресурса (GameState.kt:1440-1444) — нет «выданного кубика». Отдельный тип состояния в 3.7b.
    • ResistanceEffect — расширение B1 после 3.7a. Введён EffectSpec.ResistanceEffect (damageTypes) (симметрия DamageEffect) + StateChange.AddResistance(damageTypes) для Rage-resistance (b/p/s). ApplyBuff несёт один StatModifier и не покрывает список типов урона — потребовался отдельный StateChange (D1: новые типы — только неизбежное). Потребитель в SessionService.applyStateChanges дополняет CharacterState.resistances; хендлер Damage читает актуальные резисты из мутируемого снапшота.
    • FormulaScaling — расширение E1 после 3.7a. Sneak Attack скейлится как ceil(level/2)d6 (1d6 L1, 2d6 L3, 3d6 L5…), что PerLevelScaling (аддитивный +Nd6/уровень) не выражает. Введён ScalingSpec.FormulaScaling(formula) — замкнутая формула, НЕ eval: интерпретируется только маркер ceil(level/2) в FeatureEffectResolver (безопасный fallback → 1).

    Отложено¶

    • Реализация фич — циклы 3.7a (данные + резолвер) / 3.7b (StateChange-расширения) / 3.7c (Wild Shape, Metamagic).
    • Wild Shape / Metamagic — 3.7c.
    • Унификация SpellEffect ↔ EffectSpec — отдельный рефакторинг (после 3.7).
    • Полная миграция хардкода activateFeatureResource (SessionService.kt:3073-3078) на EffectSpec — 3.7a.

    Чек-лист решений A–J¶

    • A = A2 — EffectSpec в classes.yml + sealed-форма в Kotlin; трейсы ActivateFeature расширяются.
    • B = B1 — sealed interface EffectSpec (8 вариантов, включая CompositeEffect).
    • C = C1 — FeatureEffectResolver (stateless object), симметрия Race/Skill/SpellResolver.
    • D = D1 — возврат List<StateChange>, переиспользование StateChange-машины; новых типов — минимум.
    • E = E1 — scaling: ScalingSpec? (PerLevel / Fixed / ByResource); прецедент UpcastEffect.
    • F = F1 — CompositeEffect для многосоставных фич (Rage).
    • G = G1 — TriggeredClassFeature.effect: EffectSpec?, тот же резолвер по FeatureTrigger.
    • H = H1 — EffectCondition?, проверяется в резолвере.
    • I = I1 — SpellEffect ↔ EffectSpec частично совпадают → potential дубль #14 ADR-0011; унификация отложена.
    • J = J1 — только ADR (design); реализация — 3.7a/b/c.

    Untouched in this ADR¶

    • Код: ClassFeature.kt, FeatureActivator.kt, ClassFeatureActivatable.kt, AbilityResolver.kt, FeatureTrigger.kt, SpellEffect (Spell.kt), DiceValue/ UpcastEffect (SpellDeepTypes.kt), GameState.kt (StateChange/CharacterState), SessionService.kt, classes.yml — циклы 3.7a/b/c.
    • ActivateFeature-трейс (обратная совместимость) — расширяется, не удаляется.
    • ADR-0011/0013/0019/0022/0023/0024/0027/0028 — не меняются (I: запись в ADR-0011 #14 — отдельным циклом после реализации, по правилу ADR-0011).
    • SpellEffect / SpellService — не трогаем (унификация — отдельный цикл).

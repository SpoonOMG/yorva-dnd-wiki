    ADR-0027: SkillResolver — единый слой проверок навыков (skill/tool/passive/contested/group)¶

    Status¶

    Accepted

    Context¶

    Проверки навыков сейчас — это разбросанные по TurnResolver инлайн-формулы, а не отдельный слой. SkillRegistry есть (данные), SkillResolver — нет (поведение). Собранные факты (файл:строка):

    Навыки и проверки сегодня¶

    Чего НЕ найдено (grep → 0)¶

    • SkillResolver / SkillCheckResult — ноль.
    • Contested checks / group checks (resolveContested, resolveGroup, contested, group check) — ноль.
    • Passive Perception (пассивные проверки) — ноль (passive встречается только как PassiveRacialTrait, races/RaceRegistry.kt:143).
    • Jack of All Trades / Reliable Talent — ноль; хардкода if (class == BARD/ROGUE) для этого нет.
    • ToolRegistry — ноль (данные в tools.yml есть, реестра нет).

    Проблема¶

    Проверка навыка — это 5 инлайн-формул в TurnResolver, каждая копирует d20 + mod + prof + adv/disadv + dc + nat20/1: resolveCheckCatalog (#6), resolveActionTemplate (#7), resolveHide (#8) + bonus-action stealth (TurnResolver.kt:762-775, найден в 3.3), resolveSocialCheck (#11). Нет типа результата, нет contested/group/passive-проверок; Jack of All Trades и Reliable Talent непредставимы (только экспертиза ×2 захардкожена в skillProficiencyBonus). Каждое новое правило = новый if. Нужен единый SkillResolver (поведение) поверх существующего SkillRegistry (данные).

    Вне scope (не skill checks, остаются inline): resolveHazard (#9, спасбросок), resolveCheck generic (#10, attribute check через detectAttribute regex) и resolveNpcInteraction (#11, отдельная структура hasChaProf/negotiationDc).

    Прецеденты¶

    • ADR-0020 (RaceResolver) / ADR-0021 (BackgroundResolver) — stateless object как слой поведения поверх реестра данных (образец для A1).
    • ADR-0013 (AdvDisadvantageResolver) — переиспользуем (I1), не дублируем.
    • ADR-0017 (ProficiencyBonus) — единый PB, уже переиспользуется (H2).
    • ADR-0019 (Ability enum + AbilityParser + AbilityResolver) — Ability enum и AbilityParser общие; AbilityResolver (активации) разделяем (H2).
    • ADR-0023 (ClassFeature sealed, PassiveClassFeature E2) — источник для типизации Jack of All Trades / Reliable Talent (E1/F1).
    • ADR-0015 (effectiveMaxHp — вычисляемый getter, без кэша) — прецедент для passive perception (B1).

    Канон D&D 5e (PHB гл.7 «Using Ability Scores»)¶

    • Ability check: d20 + ability modifier + PB (if proficient).
    • Passive check: 10 + модификатор (восприятие — WIS) — результат без броска.
    • Contests: два участника, сравниваются d20 + mod (grapple/shove: Athletics; stealth vs perception; deception vs insight).
    • Group check: группа бросает, успех если половина или больше успешны.
    • Jack of All Trades (Bard L2): +½ PB (округление вниз) к проверкам навыков, которыми персонаж не владеет.
    • Reliable Talent (Rogue L11): на проверках навыков, которыми владеет, бросок d20 меньше 10 считается как 10.

    Ссылка: https://dungeonsanddragons.ru/bookfull/5ed/5e%20Players%20Handbook%20-%20Книга%20игрока%20RUS.pdf

    Decision¶

    1. Место: реестр + резолвер (A1)¶

    SkillRegistry остаётся источником данных (факт #1), SkillResolver — stateless object поведения. Симметрия RaceResolver/BackgroundResolver (ADR-0020/0021). Данные (SkillDef) и поведение (resolve*) разделены; SkillRegistry не переписывается.

    2. Passive Perception (B1)¶

    Вычисляемый результат, без кэша (прецедент effectiveMaxHp, ADR-0015):

    fun passivePerception(state: CharacterState): Int =
    10 + Ability.WIS.modifierOf(state.effectiveAttributes) +
        (if ("perception" in state.proficiencies) ProficiencyBonus.of(state.level) else 0)

    Derived getter, не поле — всегда актуален при росте уровня/WIS.

    3. Contested checks (C1)¶

    Отдельный метод resolveContested. Возвращает результат с двумя бросками и победителем:

    data class ContestedCheckResult(
    val actorRoll: SkillCheckResult,
    val targetRoll: SkillCheckResult,
    val winner: Winner, // ACTOR / TARGET / TIE
)

    4. Group checks (D1)¶

    Отдельный метод resolveGroup — успех, если половина или больше участников успешны (PHB гл.7):

    data class GroupCheckResult(val successes: Int, val failures: Int, val success: Boolean)

    5. Jack of All Trades (E1)¶

    Типизированный модификатор halfProficiencyBonusOnUntrained — применяется в SkillResolver, если у персонажа нет владения навыком. Источник — ClassFeature (PassiveClassFeature, ADR-0023 E2). НЕ хардкод if (class == BARD) — признак читается из фичи. Округление вниз: ½ от +2 = +1.

    6. Reliable Talent (F1)¶

    Модификатор minRollOnD20: Int = 10 (в CharacterState или через PassiveClassFeature). Применяется в SkillResolver к результату d20: если бросок < 10 и навык «с владением» — считаем 10. Источник — ClassFeature (PassiveClassFeature). НЕ хардкод if (class == ROGUE).

    7. Tool checks (G2)¶

    Инструменты — часть системы владений (state.toolProficiencies, факт #15). tools.yml уже существует (27 инструментов с ability, факт #16) — данные есть, ToolRegistry не вводим (overkill). SkillResolver принимает ability как вход (гибко: для tool-проверок ability берётся из tools.yml вызывающей стороной или лениво читается резолвером). Отдельный skills.yml -секции не нужен. Если позже понадобится реестр инструментов — ADR-lite.

    8. Ability-резолвер — отдельный слой (H2)¶

    SkillResolver — отдельный слой проверок. AbilityResolver (ADR-0019 B1) — про активации (факт #17), не сливать. Общая зависимость: Ability enum (ADR-0019 I1) + AbilityParser (abilityMod/abilityForSkill/abilityScore).

    9. Adv/Disadv — переиспользовать (I1)¶

    AdvDisadvantageResolver (ADR-0013 F1) переиспользуем, не дублируем. SkillResolver.resolve принимает вычисленные adv/disadv как вход (или AdvDisadv enum — ввести в 3.3; сегодня adv/disadv — две булевы).

    10. Дубль ADR-0011 (J2)¶

    Дубль #5 («Skill ability — 7 резолверов») закрыт в 2.8 (Ability enum + AbilityParser; attributeForSkill/getAbilityScore уже удалены из кода, факты #10, #12). Новый дубль не регистрируем. Если в 3.3 attributeForSkill/ detectAttribute останутся рядом с SkillResolver как живые параллельные пути — зарегистрировать дубль отдельным циклом.

    11. Объём (K1)¶

    Только ADR (design, без кода). Реализация SkillResolver — цикл 3.3.

    Скетчи (минимальные)¶

    enum class AdvDisadv { NONE, ADVANTAGE, DISADVANTAGE } // ввести в 3.3 (сегодня булевы)

data class SkillCheckResult(
    val roll: Int,            // итоговый d20 после adv/disadv (или minRoll для Reliable Talent)
    val modifier: Int,        // ability mod + PB (+ expertise ×2, + ½ PB untrained)
    val total: Int,           // roll + modifier
    val dc: Int,
    val success: Boolean,     // nat20 = успех, nat1 = провал (PHB гл.7)
    val advDisadv: AdvDisadv,
)

enum class Winner { ACTOR, TARGET, TIE }

data class ContestedCheckResult(
    val actorRoll: SkillCheckResult,
    val targetRoll: SkillCheckResult,
    val winner: Winner,
)

data class GroupCheckResult(val successes: Int, val failures: Int, val success: Boolean)

object SkillResolver {
    fun resolve(
        state: CharacterState,
        skill: String?,
        ability: Ability,
        dc: Int,
        dice: Dice,
        advDisadv: AdvDisadv = AdvDisadv.NONE,
    ): SkillCheckResult

    fun resolveContested(
        actor: CharacterState,
        target: CharacterState,
        skill: String,
        dice: Dice,
    ): ContestedCheckResult

    fun resolveGroup(
        actors: List<CharacterState>,
        skill: String,
        dc: Int,
        dice: Dice,
    ): GroupCheckResult

    fun passivePerception(state: CharacterState): Int
}

    Примечание к скетчу: resolve принимает ability явно (гибко для tool-проверок, G2) — вызывающая сторона может взять его из SkillDef.ability или tools.yml; финальные сигнатуры — в цикле 3.3.

    Proposed Options¶

    Развилки с вариантами, рекомендация архитектора помечена.

    A. Место. - A1: SkillRegistry (данные) + SkillResolver (поведение, stateless) — рекомендация архитектора. Симметрия RaceResolver/BackgroundResolver. - A2: всё в SkillRegistry (данные + методы проверок) — смешение данных и поведения. - A3: @Component-бин с инъекциями — поведение stateless, бин не нужен.

    B. Passive Perception. - B1: вычисляемый getter, без кэша — рекомендация архитектора. Прецедент effectiveMaxHp (ADR-0015); всегда актуален. - B2: кэшированное поле в CharacterState — второй источник истины, рассинхрон. - B3: только в нарративе (LLM считает) — не детерминировано.

    C. Contested checks. - C1: отдельный метод resolveContested → ContestedCheckResult — рекомендация архитектора. - C2: сравнивать через два вызова resolve в вызывающем коде — размазывает логику «кто победил» (tie-правило) по вызывающим. - C3: не делать (contested в 3.4) — теряем grapple/shove/stealth-vs-perception.

    D. Group checks. - D1: отдельный метод resolveGroup (успех ≥ половины) — рекомендация архитектора. PHB гл.7. - D2: агрегация в вызывающем коде — логика порога дублируется. - D3: не делать — group checks недоступны.

    E. Jack of All Trades. - E1: типизированный модификатор halfProficiencyBonusOnUntrained, источник — ClassFeature (PassiveClassFeature) — рекомендация архитектора. - E2: хардкод if (class == BARD && level >= 2) — возврат к строковым спецслучаям. - E3: не делать — Bard-фича не работает.

    F. Reliable Talent. - F1: модификатор minRollOnD20 = 10 (в state или ClassFeature), применяется на d20 при владении — рекомендация архитектора. - F2: хардкод if (class == ROGUE && level >= 11) — строковый спецслучай. - F3: не делать — Rogue-фича не работает.

    G. Tool checks. - G1: отдельный tools.yml + ToolRegistry — второй реестр под 27 записей, overkill. - G2: tools как часть владений; tools.yml (уже есть) — данные без реестра; SkillResolver принимает ability гибко — рекомендация архитектора. - G3: инструменты не проверяются вообще — теряем thieves' tools / herbalism.

    H. Связь с AbilityResolver. - H1: слить SkillResolver и AbilityResolver — смешение активаций и проверок (разные контракты). - H2: отдельный слой SkillResolver; общее — Ability enum + AbilityParser — рекомендация архитектора.

    I. Adv/Disadv. - I1: переиспользовать AdvDisadvantageResolver (ADR-0013 F1) — рекомендация архитектора. - I2: своя логика adv/disadv в SkillResolver — дублирование ADR-0013.

    J. ADR-0011. - J1: зарегистрировать новый дубль сейчас — преждевременно (#5 уже закрыт, резолвера ещё нет). - J2: новый дубль НЕ регистрируем; при появлении параллельного пути в 3.3 — зарегистрировать отдельным циклом — рекомендация архитектора.

    K. Объём. - K1: только ADR; реализация — цикл 3.3 — рекомендация архитектора. - K2: ADR + частичная реализация — нарушает «один цикл = один фокусный шаг».

    Consequences¶

    Плюсы¶

    • Единый SkillResolver устраняет разбросанные инлайн-формулы проверок навыков (resolveCheckCatalog, resolveActionTemplate, resolveHide + bonus-action stealth, resolveSocialCheck) — остатки дубля #5, если остались.
    • Contested/group checks формализованы (ContestedCheckResult/GroupCheckResult).
    • Jack of All Trades / Reliable Talent типизированы через ClassFeature (ADR-0023 E2), без хардкода if (class == ...).
    • Passive Perception — derived, без кэша (прецедент effectiveMaxHp).
    • Переиспользование AdvDisadvantageResolver (I1), Ability enum + AbilityParser (H2), ProficiencyBonus (ADR-0017).

    Минусы¶

    • SkillResolver — очередной stateless object по паттерну (после RaceResolver/BackgroundResolver/DamageResolver/ConditionResolver/AbilityResolver).
    • Миграция 5 инлайн-путей TurnResolver на SkillResolver (объём 3.3): catalog, actionTemplate, hide, bonus-action stealth, social.
    • tools.yml остаётся «данными без реестра» — чтение ability ложится на вызывающую сторону (G2) до возможного ADR-lite.

    Риски¶

    • resolveHazard (спасбросок) и resolveCheck (generic, attribute check через detectAttribute regex) — вне scope ADR-0027 (не skill checks). Остаются inline в TurnResolver. detectAttribute используется в 1 месте (факт #10). Потенциальный кандидат на отдельный ADR (check-resolver) при рефакторинге спасбросков/attribute-checks в будущих фазах.
    • Contested checks: PHB не даёт единого списка применений (grapple, shove, stealth vs perception, deception vs insight). Митигация: форма закладывается (C1), конкретные применения — 3.3/3.4.
    • Jack of All Trades (½ PB на untrained) — округление вниз (PHB): ½ от +2 = +1. Уточнить в скетче E1.
    • Reliable Talent: min d20 = 10 применим не ко всем броскам (PHB: только на skill checks с владением). Уточнить в скетче F1.
    • Tool checks: PHB не даёт чёткого ability для каждого инструмента (thieves' tools — DEX, herbalism kit — INT/WIS). Митигация: форма гибкая (ability в данных tools.yml), конкретика — 3.3.
    • Passive perception (B1) не учитывает: adv на пассивную проверку (+5) и disadv (−5) по PHB гл.7; expertise в Perception (Rogue/Bard) удваивает PB. Форма готова, детали — 3.3.

    Отложено¶

    • Реализация SkillResolver — цикл 3.3.
    • LanguageResolver — 3.3/3.4 (из ADR-0021).
    • Multiclass-скиллы — post-MVP.

    Чек-лист решений A–K¶

    • A = A1 — SkillRegistry (данные) + SkillResolver (поведение, stateless).
    • B = B1 — Passive Perception: вычисляемый, без кэша (прецедент effectiveMaxHp).
    • C = C1 — Contested: resolveContested → ContestedCheckResult.
    • D = D1 — Group: resolveGroup (успех ≥ половины).
    • E = E1 — Jack of All Trades: halfProficiencyBonusOnUntrained через ClassFeature.
    • F = F1 — Reliable Talent: minRollOnD20 = 10 через ClassFeature.
    • G = G2 — Tool checks: часть владений; tools.yml (без реестра); ability гибко.
    • H = H2 — SkillResolver отдельный слой; общее — Ability + AbilityParser.
    • I = I1 — Adv/Disadv: переиспользовать AdvDisadvantageResolver (ADR-0013).
    • J = J2 — дубль ADR-0011 не регистрируем; при появлении — отдельным циклом.
    • K = K1 — только ADR; реализация — цикл 3.3.

    Untouched in this ADR¶

    • Код (SkillResolver.kt, SkillRegistry.kt, skills.yml, tools.yml, TurnResolver.kt, GameState.kt) — цикл 3.3.
    • LanguageResolver — отдельный цикл (из ADR-0021).
    • ADR-0011/0013/0017/0019/0020/0021/0022/0023 — не меняются.
    • Frontend — ФАЗА 6.

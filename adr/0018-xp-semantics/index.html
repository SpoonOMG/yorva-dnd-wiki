    ADR-0018: Семантика XP — устранение расхождения авто-каскада и ручного level-up¶

    Status¶

    Accepted

    Context¶

    Суть проблемы¶

    В движке один и тот же CharacterState.xp трактуется двумя несовместимыми способами:

    1. Авто-каскад (SessionService.applyChanges, обработчик StateChange.GainXp) — как остаток XP внутри уровня: при переходе вычитает xpForNextLevel(level) и сохраняет остаток.
    2. Ручной путь (LevelUpService + LevelTableRegistry + фронт/превью) — как кумулятивный итог: уровень повышается при xp >= xpFor(level+1) (абсолютный порог из таблицы).

    Расхождение прямо нарушает ADR-0004, где зафиксирована каноничная таблица xp -> level (кумулятив, SRD [0,300,900,2700,6500,14000,...]), и ломает прогрессию: один и тот же персонаж на одном уровне имеет разные пороги в зависимости от того, каким путём получен XP.

    Канон 5e (PHB p.15, 163-165)¶

    • XP накапливается кумулятивно (суммарно за всю игру).
    • Порог следующего уровня — из таблицы: L2=300, L3=900, L4=2700, … L20=355000.
    • Level-up происходит при достижении порога; избыток XP сохраняется (не обнуляется).
    • Proficiency bonus растёт по уровню (1-4:+2 … 17-20:+6).
    • HP при level-up — среднее по кубику (d6=4, d8=5, d10=6, d12=7) + CON mod (после возможного роста CON).

    Факты (файл:строка)¶

    Два трактования xp¶

    Путь Семантика Место
    Авто-каскад остаток внутри уровня SessionService.kt:2491-2494 (xp += amount; xp -= xpForNextLevel(level))
    Ручной кумулятив LevelTableRegistry.kt:61-65 (canLevelUp: xp >= forLevel(level+1).xpRequired)
    Фронт кумулятив levelUp.ts:12 (xp >= xpFor(level+1)); CharacterPanel.tsx:161-166
    Таблица кумулятив (пороги) level-table.yml; LevelTableRegistry.kt:52-53,57-65

    Авто-каскад GainXp (SessionService.kt:2490-2521)¶

    • xp += change.amount (:2491), затем while (xp >= xpForNextLevel(level)) { xp -= xpForNextLevel(level); level++ } (:2492-2494).
    • xpForNextLevel (:2850-2871) — дельта-таблица (L1→300, L2→600, L3→1800, … L19→50000). Значения — корректные разности кумулятивных порогов, но семантика «остаток» конфликтует с остальным кодом.
    • HP: hpIncrease = (hitDie / 2) + 1 + conMod (:2499), conMod = state.effectiveAttributes.conMod (до ASI); hp = maxHp = newMaxHp (:2500-2502) — полное восстановление до нового максимума.
    • Слоты: только если canonical.spellcastingAbility != null, SpellSlots.forLevel(level) (:2507-2512) — полная таблица full caster для любого заклинателя (не учитывает half/pact).
    • pendingASI += 1 при level in {4,8,12,16,19} (:2513-2515) — хардкод, игнорирует cls.asiLevels.
    • На 20 уровне xp = 0 (:2517-2520).
    • Не обрабатывает: features, subclass, ASI-выбор, classResources, classLevels (нет ни одного вызова LevelUpService/ClassResourceHelper/resourcesForLevelUp).

    Ручной LevelUpService (LevelUpService.kt:94-277)¶

    • canLevelUp → levelTable.canLevelUp (:92, кумулятив).
    • needsAsi = cls.asiLevels.contains(nextLevel) (:100-101) — из classes.yml, не хардкод.
    • ASI xor Feat (:108): require(hasAsi xor hasFeat).
    • HP: avg = avgHitDie(cls.hitDie) (:178), hpDelta = avg + conModAfter (:179, после ASI), ретро-CON (conModAfter - conModBefore) * state.level (:182-186), tough +2*nextLevel (:188-189); newHp = state.hp + hpDelta (:199) — частичное восстановление (сохраняет полученный урон).
    • classResources = ClassResourceHelper.resourcesForLevelUp(...) (:254).
    • classLevels обновляется (:207-213).
    • pendingASI = 0 — потребляется (:270); инкремента pendingASI здесь нет.
    • features/subclass/featureChoices/spellChoices — обрабатываются (:124-173,215-247).

    Конкретное расхождение¶

    • Авто L2→L3: вычитает xpForNextLevel(2) = 600 (:2852).
    • Таблица/ручной: L3 требует 900 кумулятивно (level-table.yml, LevelTableRegistry.kt:53).
    • Отсюда «L2→L3 авто = 600, таблица = 900».

    Прочие точки XP¶

    • Квест-XP: CompleteQuest пишет xp += change.xpReward ?: q.xpReward напрямую (SessionService.kt:2473-2474), минуя авто-каскад (не триггерит level-up).
    • Milestone-XP за сцену: SessionService.kt:2367-2380 — на SetScene, если milestone@scene не в xpTriggers, эмитит AddXpTrigger("milestone@$scene") + GainXp(50 * (1 + level/4)). База XpRules.MILESTONE_BASE = 50 (XpRules.kt:17).
    • Источники GainXp: ReactionResolver.kt:87; TurnResolver.kt (много: :858,963,971,975,1087,1112,1290,1319,1378,1554,1641,1792,1913,1915,2178,2194,2588,2625,3011,3018); SessionService.kt:2377.
    • xpTriggers: CharacterState.xpTriggers (GameState.kt:431), читается в TurnResolver.kt:1083,1085,3003. AddXpTrigger (GameState.kt:1174) эмитится в TurnResolver.kt:1088,1089,3012,3019 и SessionService.kt:2376. ClearXpTriggers (GameState.kt:1175) обрабатывается (SessionService.kt:2722-2724), но нигде не эмитится → сброс разовых триггеров по смене сцены отсутствует (audit 14.13).
    • HP формулы — три места: авто SessionService.kt:2499; ручной LevelUpService.kt:176-201; превью LevelUpService.kt:360-363 (avgHitDie + effectiveAttributes.conMod, без ретро и без ASI).

    API (openapi.yaml)¶

    • CharacterState.xp (:498), pendingASI (:562-565), classLevels (:587-591).
    • POST /levelup (:2166), GET /levelup/preview (:2200), POST /levelup/asi (:1604).

    Decision¶

    A. Семантика xp¶

    A1 — кумулятив (канон). CharacterState.xp — суммарный XP за всю игру. Авто-каскад переписывается под кумулятив: level определяется из LevelTableRegistry (абсолютные пороги), xp не вычитается. Совпадает с ADR-0004, ручным путём, фронтом и таблицей. Отвергнуто: A2 (остаток — противоречит канону и остальному коду), A3 (два режима — преждевременно).

    B. Единый путь level-up¶

    B2 — два пути с общим ядром. Общее ядро — LevelUpApplier.applyLevelUp(state, classDef, toLevel) применяет HP/слоты/resources/пассивные features без выборов. Выборы (ASI/feat/subclass/ featureChoices/spellChoices) — обязательный ручной шаг (LevelUpService + LevelUpModal). Отвергнуто: B1 (единый LevelUpService — авто не может сделать выбор), B3 (дублирование логики).

    C. Формула HP при level-up¶

    C3 — единая формула avgHitDie + conModAfter + ретро-CON (без броска, ADR-0003 clockwork). avgHitDie: d6=4, d8=5, d10=6, d12=7. conModAfter — после применения ASI; ретро-CON (conModAfter - conModBefore) * level. Отвергнуто: C1 (игнорирует рост CON), C2 (оставляет расхождение с авто). Heal-семантика вынесена в L.

    D. pendingASI¶

    D1 — инкремент из cls.asiLevels (канон: warrior [4,6,8,12,14,16,19], rogue [4,8,10,12,16,19]). Авто-каскад читает asiLevels класса, хардкод {4,8,12,16,19} удаляется. Отвергнуто: D2 (хардкод неверен для warrior/rogue), D3 (совпадает с D1).

    E. ASI-выбор vs Feat в авто-каскаде¶

    E1 — авто останавливается на ASI-уровне с pendingASI++ и уведомлением игроку (UI). Авто-каскад НЕ проскакивает ASI-уровни: на ASI-уровне останавливается, UI обязан показать модал выбора. Отвергнуто: E2 (копит без выбора — рассинхрон с превью), E3 (запрет — лишнее ограничение UX).

    F. classResources при level-up¶

    F1 — авто вызывает resourcesForLevelUp (ClassResourceHelper), унификация с ручным путём. Отвергнуто: F2 (персонаж на авто-каскаде не получит прироста ресурсов).

    G. Features/subclass¶

    G2 — авто НЕ обрабатывает features/subclass. Авто применяет только пассивные features (без choice/options); features с choice и subclass — только ручным путём. Список пассивных features определяется по ClassFeature (отсутствие choice/options). Отвергнуто: G1 (выбор подкласса не автоматизируем).

    H. Milestone-XP за сцену¶

    H2 — milestone-XP через единый путь начисления (GainXp), без отдельной ветки применения. Отвергнуто: H1 (отдельная механика), H3 (milestone-as-leveling — смена парадигмы, не сейчас).

    I. ClearXpTriggers¶

    I1 — эмитить ClearXpTriggers на смену сцены (SetScene). Закрывает audit 14.13. Отвергнуто: I2 (триггеры копятся навсегда), I3 (рефактор модели xpTriggers).

    J. Мультикласс-casting (classLevels)¶

    J1 — отдельный ADR (0017 G2). Отвергнуто: J2 (смешивает два вопроса), J3 (отложить).

    K. Legacy-сессии (xp как остаток)¶

    K1 — миграция реконструкцией: cumulative = xpFor(level) + remainder. Если результат не сходится с level-table.yml — предупреждение + сброс остатка. Отвергнуто: K2 (потеря прогресса), K3 (расхождение для активных сессий).

    L. Heal-семантика при level-up¶

    L2 — частичное восстановление HP (канон): HP растёт на hpDelta, полученный урон сохраняется. Отвергнуто: L1 (полное — не канон, расходится с ручным), L3 (два поведения — рассинхрон).

    M. Level 20 — что с xp¶

    M2 — xp копится, level не растёт (канон 5e, нет cap на xp). Сброс отсутствует. Отвергнуто: M1 (сброс в 0 — не канон), M3 (блокировка — теряются источники XP).

    N. Spell slots при level-up в авто¶

    N1 — унифицировать через spellSlotsFor(classId, level) (full/half/pact), симметрия с ручным. Отвергнуто: N2 (full для любого заклинателя — неверно для half/pact).

    Обязательные фиксации¶

    • Авто-каскад НЕ проскакивает ASI-уровни (E1): на ASI-уровне останавливается с pendingASI++, UI обязан показать модал выбора.
    • Features с choice и subclass — только ручным путём (G2): авто применяет только пассивные features (без choice/options).
    • Heal-семантика — частичная (L2): урон сохраняется, HP растёт на hpDelta.
    • Level 20: xp копится (M2), сброс отсутствует.
    • Legacy-миграция K1: реконструкция cumulative = xpFor(level) + remainder; при расхождении с level-table.yml — предупреждение + сброс остатка.
    • CompleteQuest (SessionService.kt:2473-2474) использует общий путь начисления (GainXp), не пишет xp напрямую — фикс NEW_GAP.

    Proposed Options¶

    A. Семантика xp¶

    • A1 — кумулятив (канон, как ручной/фронт/таблица).
    • + Совпадает с PHB, ADR-0004, ручным путём, фронтом, превью; минимальное изменение — только авто-каскад.
    • − Нужна миграция legacy-сессий, где xp копил остаток (см. K).
    • A2 — остаток (текущий авто).
    • + Совпадает с авто-каскадом; не трогает xpForNextLevel.
    • − Противоречит PHB, ADR-0004, ручному пути, фронту, таблице; требует переписать XP-бар/превью/таблицу.
    • A3 — оба с флагом (world-level режим).
    • + Гибкость для будущих режимов (milestone vs XP).
    • − Два пути в рантайме, двойное сопровождение; преждевременно.

    B. Единый путь level-up¶

    • B1 — один LevelUpService для обоих.
    • + Один источник правды (ADR-0011).
    • − Авто-каскад не может сделать выбор ASI/feat/subclass → всё равно нужен ручной шаг.
    • B2 — два пути с общим ядром (применить level-up без выбора) + ручной выбор.
    • + Авто применяет HP/слоты/resources/features без выбора; выборы — ручным путём.
    • − Ядро нужно вынести (общий «applyLevelUp»), часть логики делится.
    • B3 — оставить оба, унифицировать формулы (HP/pendingASI/classResources) по месту.
    • + Минимальный объём; быстрый фикс расхождения.
    • − Дублирование level-up-логики остаётся (риск нового расхождения).

    C. Формула HP при level-up¶

    • C1 — (hitDie/2)+1+conMod (авто; эквивалент avgHitDie + conMod(before)).
    • + Просто; идентично среднему для всех hitDie (6→4, 8→5, 10→6, 12→7).
    • − Игнорирует рост CON от ASI/фита (нет ретро), полное восстановление HP.
    • C2 — avgHitDie + conModAfter + ретро-CON (ручной, канон).
    • + Учитывает ASI/фит в CON, ретро-рост HP (SRD); частичное восстановление.
    • − Сложнее (ретро по всем предыдущим уровням), расходится с авто по heal-семантике.
    • C3 — зафиксировать единый выбор: среднее (без броска) + conModAfter + ретро, единая heal-семантика.
    • + Детерминированность (ADR-0003, реплей), один алгоритм.
    • − Требует отдельного соглашения о heal (полное vs частичное).

    D. pendingASI¶

    • D1 — инкремент из cls.asiLevels (канон: warrior +6, rogue +10).
    • + Соответствует classes.yml и ручному пути.
    • − Нужно, чтобы авто-каскад читал asiLevels класса.
    • D2 — хардкод {4,8,12,16,19} (авто, текущее).
    • + Ноль зависимостей.
    • − Неверно для warrior (6,14) и rogue (10); рассинхрон с ручным.
    • D3 — унификация: единый источник asiLevels для авто и ручного.
    • + Устраняет дубль источника.
    • − Совпадает с D1 по сути, требует рефактор.

    E. ASI-выбор vs Feat в авто-каскаде¶

    • E1 — авто на ASI-уровне останавливается: pendingASI++, игрок выбирает позже (/levelup/asi / модал).
    • + Канон (выбор — действие игрока); xor уже есть (LevelUpService.kt:108).
    • − Авто-каскад не может «проскочить» ASI-уровень без UI.
    • E2 — авто продолжает без выбора, копит pendingASI.
    • + Просто, не блокирует прогресс.
    • − ASI/фит откладываются, возможен рассинхрон с превью.
    • E3 — авто-каскад запрещён на ASI-уровне (обязательный ручной шаг).
    • + Явная семантика.
    • − Дополнительное ограничение UX.

    F. classResources при level-up¶

    • F1 — авто вызывает resourcesForLevelUp (унификация).
    • + Единый расчёт ресурсов; устраняет audit 14.12.
    • − Авто-каскад получает зависимость от ClassResourceHelper.
    • F2 — авто не трогает (текущее); только ручной.
    • + Минимально.
    • − Персонаж, качающийся только авто-каскадом, не получит прироста ресурсов.

    G. Features/subclass¶

    • G1 — авто обрабатывает (нужен UI для подкласса на 3).
    • + Полный канон для авто-пути.
    • − Выбор подкласса/фич не автоматизируем → всё равно ручной шаг.
    • G2 — авто не обрабатывает (текущее); features/subclass только ручным путём.
    • + Просто; авто = «голая» прокачка HP/слотов/level.
    • − Расхождение итогов авто vs ручного уровня сохраняется.

    H. Milestone-XP за сцену¶

    • H1 — оставить как есть (отдельная эмиссия GainXp).
    • + Не трогаем; работает.
    • − Остаётся отдельная механика начисления, вне общего контура XP.
    • H2 — включить в общий контур XP (единый путь начисления/применения).
    • + Консистентность начисления.
    • − Больше изменений поверхности.
    • H3 — отдельная механика (milestone leveling, не XP).
    • + Чистое разделение «XP vs milestone».
    • − Выходит за объём ADR (смена парадигмы прокачки).

    I. ClearXpTriggers¶

    • I1 — эмитить ClearXpTriggers на смену сцены (сброс разовых per-location триггеров).
    • + Закрывает audit 14.13; XpRules-контракт «сброс сменой сцены» начинает работать.
    • − Нужно определить точку эмиссии (SetScene vs ENTER_SCENE).
    • I2 — не эмитить (текущее).
    • + Ноль изменений.
    • − Разовые триггеры копятся навсегда (фарм заблокирован, но память растёт).
    • I3 — другая триггерная модель (per-scene раздельные set'ы).
    • + Точное разделение по локациям.
    • − Рефактор модели xpTriggers.

    J. Мультикласс-casting (classLevels)¶

    • J1 — отдельный ADR (0017 G2).
    • + Не раздувает этот ADR.
    • − — (фиксация границы).
    • J2 — в этом ADR.
    • − Смешивает два вопроса (семантика XP и мультикласс).
    • J3 — отложить.

    K. Legacy-сессии (xp как остаток)¶

    • K1 — миграция xp из остатка в кумулятив (пересчёт для существующих сессий).
    • + Сохраняет прогресс.
    • − Нужна миграция + тест на граничные случаи.
    • K2 — сброс xp в 0.
    • + Просто; консистентно с новой семантикой.
    • − Потеря прогресса игроков.
    • K3 — игнор (старые сессии как есть; новая семантика только для новых).
    • + Ноль миграции.
    • − Расхождение для активных сессий остаётся.

    L. Heal-семантика при level-up¶

    • L1 — полное восстановление HP (авто, текущее).
    • + Удобно.
    • − Не канон 5e; расходится с ручным.
    • L2 — частичное: HP растёт на delta, урон сохраняется (канон, ручной).
    • + Канон.
    • − Игрок должен сам лечиться после level-up.
    • L3 — выбор per-mode (EASY=full, NORMAL/HARDCORE=partial).
    • − Два поведения, рассинхрон.

    M. Level 20 — что с xp¶

    • M1 — xp сбрасывается в 0 (авто, текущее).
    • − Не канон.
    • M2 — xp копится, level не растёт (канон).
    • + Канон 5e (нет cap на xp).
    • M3 — xp блокируется, не начисляется.
    • − Теряются источники XP.

    N. Spell slots при level-up в авто¶

    • N1 — унифицировать через spellSlotsFor(classId, level) — full/half/pact.
    • + Канон; симметрия с ручным.
    • N2 — оставить full для любого заклинателя (авто, текущее).
    • − Неверно для half/pact.

    Consequences¶

    Плюсы¶

    • Единая семантика xp (кумулятив) для авто/ручного/фронта/таблицы (A1).
    • Единый путь level-up с общим ядром LevelUpApplier (B2) — один источник формул HP/слотов/resources.
    • pendingASI из cls.asiLevels (D1) — канон для warrior/rogue.
    • Унификация classResources (F1), spell slots (N1), HP-формулы (C3).
    • ClearXpTriggers работает (I1) — разовые триггеры сбрасываются сменой сцены.
    • Level 20 — канон: xp копится (M2).
    • Частичный heal — канон (L2).
    • CompleteQuest через GainXp (NEW_GAP) — квест-XP идёт общим контуром.

    Минусы¶

    • Миграция legacy xp (реконструкция K1) — дополнительный шаг + тесты на граничные случаи.
    • Авто-каскад теперь может «останавливаться» на ASI-уровне (E1) — обязательство для UI.
    • G2 требует явного списка пассивных features (по ClassFeature без choice/options).
    • Ядро LevelUpApplier — новый компонент.

    Риски и митигация¶

    • K1 — реконструкция может не сойтись → предупреждение + сброс остатка.
    • B2 — общее ядро легко рассинхронизируется → unit-тесты ядра на всех классах.
    • I1 — эмиссия ClearXpTriggers на неверной точке → привязка к SetScene, тест.

    Отложено¶

    • J1 (мультикласс-casting) — отдельный ADR.
    • Milestone-as-leveling (H3) — не сейчас.

    Untouched in this ADR¶

    • Spell slots / mana-миграция (ADR-0016) — ресурс заклинаний не трогаем (миграция кода ещё не выполнена).
    • Spell save DC (ADR-0017) — расчёт DC не трогаем.
    • Мультикласс-casting (J1) — отдельный ADR (0017 G2, развилка J).
    • Milestone-as-leveling (H3) — не сейчас.
    • Расы/фоны/скиллы (ФАЗА 2/3) — вне объёма.
    • ClassResourceHelper / spell slots — не рефакторим.
    • Pact Magic / upcast — вне объёма.

    ADR-0034: Structured Intent + ContextBuilder abilities + utility cantrips (ФАЗА 3 closure)¶

    Status¶

    Accepted

    Context¶

    ФАЗА 3 closure по gap'ам G-007/G-009/G-032 (G-008 — ФАЗА 6, G-044 закрыт 2026-10-02). Разведка (2026-10-02) дала точные механизмы дефектов.

    Факты (файл:строка):

    # Файл:строка Факт
    1 rules/ActionParser.kt:235-246 Порядок: findSpecialAttack (:235) → findSkillCheck (:246) → широкие regex. Приоритет — по порядку, не по точности: «осматриваю ловушку» матчит set_trap (keywords ловушк\w*) раньше perception; «толкаю врага» уходит в CHECK_CATALOG (athletics) раньше action_templates shove/trip.
    2 db/changelog/changes/0031-action-templates.yaml:27,29 + TurnResolver.kt:1322 Шаблоны shove/trip с PRONE-механикой СУЩЕСТВУЮТ, но путь к ним перекрыт приоритетами (достижимы только через LLM ActionIntent.templateCode).
    3 rules/intent/IntentClassifier.kt:201-228 LLM-схема intent: 18 значений, нет SHOVE/GRAPPLE/TRIP/манёвра.
    4 TurnResolver.kt:1263,3680 resolveEnvironmentalShove (толчок в хазард) требует глагол толчка + существительное опасности в одной фразе — единственная достижимая shove-механика, без PRONE.
    5 llm/ContextBuilder.kt:76-255 Секции промпта Narrator: сеттинг/персонаж/ledger JSON/сводка/CRITICAL/история/результат… Секции способностей нет: l1Choices (манёвры/инвокации/метамагия), классовые фичи, доступные реакции — LLM не видит (только сырой ledger JSON :114-116).
    6 rules/intent/StateContextBuilder.kt:12-48 Контекст IntentClassifier: SPELLS_KNOWN есть, фич/манёвров/реакций нет.
    7 spells.json (light/mage-hand/minor-illusion) + SpellService.kt:297-347 light — фиктивный buff-стат «light» без потребителя; mage-hand — пустой buff; minor-illusion — накладывает BLINDED на врага (hallucinated-механика, канону противоречит). Маркера utility/narrative-only нет.
    8 sessions/SessionDtos.kt:61-66 TurnRequest: только action + reaction. Structured-intent поля нет (G-008 — ФАЗА 6).
    9 TurnResolver.kt:2079-2113 Манёвры Battle Master — только авто-эффекты при ON_HIT/ON_CRIT/ON_ATTACK_ROLL; отдельного действия «манёвр» нет.

    Канон 5e: shove/grapple — универсальные опции атаки (не только Battle Master): contested — атлетика атакующего против атлетики/акробатики цели; shove → PRONE или толчок. Отдельный intent от оружейной атаки.

    Proposed Options¶

    По G-007 (как чинить классификацию манёвров):

    Вариант A: приоритет «конкретное раньше общего» + расширение LLM-схемы — принято. - Детерминированный путь: findActionTemplate (манёвры shove/trip/grapple/disarm) раньше findSkillCheck (общие проверки) раньше findSpecialAttack (узкие каталожные кейсы); LLM IntentClassifier += MANEUVER intent (с параметром манёвра) → маппинг на action_templates. - Плюсы: лечит оба кейса (trip как манёвр с PRONE; «осматриваю ловушку» → perception, не set_trap) без новой инфраструктуры; LLM и детерминированный путь согласованы. - Минусы: остаётся эвристикой keyword-матчинга (полный structured intent — G-008). - Решение архитектора.

    Вариант B: только перестановка приоритетов без LLM-схемы — отклонено. - Минусы: в проде работает LLM IntentClassifier — без MANEUVER в схеме классификация манёвров продолжит зависеть от fallback-порядка; полумера.

    Вариант C: structured intent поле в TurnRequest — отложено (G-008, ФАЗА 6). - Spec-first изменение контракта + фронтенд. После него Вариант A остаётся fallback-разбором свободного текста.

    По G-032 (utility cantrips):

    Вариант A: маркер utility: true в данных + пропуск механики — принято. - Utility-заклинание: canCast/слоты — как обычно; damage/buff/debuff-резолв пропускается; mechanics получает маркер для narrative-слоя. minor-illusion — BLINDED из данных УБРАТЬ (неканон); light/mage-hand — фиктивные buff'ы убрать, заменить маркером. - Плюсы: убирает hallucinated-механику; явный контракт «это narrative-заклинание». - Решение архитектора.

    Вариант B: оставить фиктивные эффекты — отклонено. BLINDED от minor-illusion — активная ложь движка; «стат light» — мёртвые данные.

    Decision¶

    1. D1 (G-007, детерминированный путь). В ActionParser.parse порядок каталогов: findActionTemplate → findSkillCheck → findSpecialAttack. Манёвр (shove/trip/overrun/tumble из action_templates) резолвится существующим resolveActionTemplate (PRONE при успехе, :1322). Это не меняет механику манёвров Battle Master (ON_HIT-эффекты, ADR-0031) — универсальные shove/trip (любой персонаж) и манёвры BM (по выбору, на попадание) — разные слои канона. Уточнено при реализации (2026-10-02): перехват ограничен 6 манёврными кодами (shove/trip/grapple/disarm/overrun/tumble) — полный findActionTemplate-first ломал атаки: narrative-шаблоны (melee_attack и др.) резолвятся в NO_ROLL.
    2. D2 (G-007, LLM-путь). IntentClassifier: схема += MANEUVER (параметр — id шаблона: shove/trip/grapple/disarm); intentToActionRequest маппит на ActionRequest шаблона. В StateContextBuilder — секция доступных действий-манёвров (универсальные + выбранные из l1Choices).
    3. D3 (G-009). ContextBuilder += секция ## Способности персонажа: компактная (имя + одна строка), источники: активные/триггерные классовые фичи (ClassRegistry по class+level), l1Choices → имена опций (манёвры/инвокации/метамагия через реестры), доступные реакции (availableReactions-логика), spellsKnown. Без бюджета токенов — секция ограничена ~40 строками (комментарий; бюджет промпта — отдельная тема).
    4. D4 (G-032). spells.json: поле utility: true (default false). SpellService: utility → пропуск damage/buff/debuff, маркер в mechanics (utilityCast). Данные: light, mage-hand, minor-illusion → utility; у minor-illusion убрать debuff/BLINDED, у light/mage-hand — buff-пустышки.
    5. D5. Contested-семантика shove (атлетика vs атлетика/акробатика цели) — НЕ реализуется: у Enemy нет навыков; остаётся template-check против DC (отклонение, комментарий). G-008 (structured intent поле) — ФАЗА 6.

    Consequences¶

    Плюсы¶

    • «толкаю/опрокидываю врага» — канонический манёвр с PRONE вместо generic-проверки.
    • «осматриваю ловушку» — perception, а не «атака ловушкой».
    • LLM (нарратив и классификатор) знает реальные умения персонажа → меньше hallucinated-эффектов (прямая митигация класса дефектов типа minor-illusion).
    • Utility-кантрипы — честный narrative-контракт вместо фиктивной механики.

    Минусы¶

    • Приоритеты keyword-матчинга остаются эвристикой (до G-008); новые пересечения keywords возможны — митигация тестами на известные коллизии.
    • Секция способностей увеличивает промпт (~40 строк); бюджета промпта нет.

    Риски¶

    • Перестановка приоритетов ActionParser может изменить классификацию существующих фраз — митигация: прогон ActionParserTest + каталожных тестов, фикс коллизий в том же коммите.
    • Удаление BLINDED у minor-illusion — изменение поведения в бою: принято (текущее поведение неканонично).

    Отложено¶

    • G-008 (structured intent в TurnRequest + UI) — ФАЗА 6.
    • Contested checks для манёвров (нужны навыки врагов — ФАЗА 4).
    • Бюджет промпта ContextBuilder (токен-лимиты) — Observability/LLM-тема.
    • grapple/disarm механика (шаблоны есть в whitelist; PRONE-аналог для grapple — RESTRAINED? — отдельный цикл при потребности).

    ADR-0032: ChoiceOption effect/trigger/condition — сериализационная граница (@JsonIgnore)¶

    Status¶

    Accepted

    Context¶

    Цикл 3.7b2b2 (коммит de030e0 data(classes): maneuver choice options with effects) расширил ChoiceOption полями механики манёвра — effect: EffectSpec?, trigger: FeatureTrigger?, condition: EffectCondition? — и пометил их @JsonIgnore.

    Причина — полиформная сериализация EffectSpec ломает round-trip pendingChoices.

    Факты (файл:строка):

    # Файл:строка Факт
    1 rules/choice/ClassChoice.kt:18-25 ChoiceOption с полями effect/trigger/condition, помеченными @JsonIgnore (:22-24).
    2 rules/feature/EffectSpec.kt:18 sealed interface EffectSpec — без @JsonTypeInfo.
    3 rules/choice/ClassChoice.kt:39 У sealed interface ClassChoice дискриминатор kind есть (@JsonTypeInfo) — именно он делает round-trip pendingChoices рабочим.
    4 rules/GameState.kt:458 CharacterState.pendingChoices: List<ClassChoice> — сериализуется в participantsJson.
    5 sessions/SessionService.kt:2199 session.participantsJson = objectMapper.writeValueAsString(participants) — точка round-trip.
    6 rules/GameState.kt:550 l1Choices: Map<String, List<String>> — persisted-состояние хранит только id выбранных опций.
    7 rules/feature/ManeuverRegistry.kt:35 maneuverFor(id) — каталог манёвров, перечитываемый из YAML.
    8 resources/subclasses.yml Источник options «Боевое превосходство» (trip/menacing/riposte).

    Без @JsonTypeInfo на EffectSpec Jackson не знает подтип при десериализации pendingChoices → participantsJson round-trip падает. @JsonIgnore исключает effect/trigger/condition из (де)сериализации — в persisted-state остаются только сериализуемые поля ChoiceOption (id/name/description).

    Proposed Options¶

    Рекомендация архитектора помечена жирным.

    Вариант A: @JsonIgnore на effect/trigger/condition + каталог из YAML — принято. - Плюсы: persisted-state минимален (в JSON только id/name/description, без вложенного EffectSpec); единый источник механики — subclasses.yml (single source of truth, ADR-0011); доменная модель остаётся без JSON-дискриминатора (прецедент SpellEffect, см. Decision). - Минусы: state без effect → dispatch требует ManeuverRegistry.maneuverFor(id); клиент не получает механику опции напрямую (только id/name/description). - Рекомендация архитектора.

    Вариант B: @JsonTypeInfo(use=NAME, property="type") на EffectSpec — отклонено. - Плюсы: прямой round-trip EffectSpec внутри pendingChoices → participantsJson; клиент получает механику без отдельного DTO. - Минусы: вторая копия механики в persisted-state (расходится с subclasses.yml, ADR-0011); EffectSpec вкладывает sealed-типы ScalingSpec и SaveDcSpec — им тоже нужен дискриминатор (три @JsonTypeInfo вместо одного); расходится с прецедентом SpellEffect (дискриминатор там — на клиентском SpellEffectDto, не на доменной модели).

    Вариант C: @JsonIgnoreProperties на уровне CharacterState (отсечение на уровне агрегата) — отклонено. - Плюсы: одна аннотация на агрегате вместо точечных @JsonIgnore на полях. - Минусы: грубое отсечение — глушит не только effect/trigger/condition, но и любые будущие полиформные поля CharacterState; не решает восстановление механики (всё равно нужен каталог); размазывает сериализационную границу по всему агрегату.

    Decision¶

    1. @JsonIgnore на effect/trigger/condition (ClassChoice.kt:22-24) — механика опции-манёвра не сериализуется; EffectSpec не получает @JsonTypeInfo.
    2. Каталог механики — из YAML. Манёвры/эффекты читаются через ManeuverRegistry (maneuverFor(id)), источник — resources/subclasses.yml.
    3. В persisted-state — только id. l1Choices: Map<String, List<String>> (GameState.kt:550) хранит id выбранных опций; сам EffectSpec восстанавливается из каталога по id, а не из JSON.

    Обоснование выбора (Вариант A, отказ от B/C)¶

    • Меньше persisted-state. @JsonIgnore оставляет в JSON только id/name/ description — EffectSpec (с вложенными ScalingSpec/SaveDcSpec/DiceValue) в participantsJson не дублируется.
    • Единый источник механики. Каталог (subclasses.yml → ManeuverRegistry, ADR-0011) — single source of truth; @JsonTypeInfo на EffectSpec создал бы вторую копию в persisted-state, рискующих разойтись с YAML.
    • Консистентность с SpellEffect. Доменный SpellEffect (spells/Spell.kt:67) не имеет @JsonTypeInfo — дискриминатор вынесен на клиентский DTO (SpellEffectDto, spells/SpellDto.kt:50). Вариант A держит доменный EffectSpec без дискриминатора (симметрия SpellEffect); Вариант B, напротив, навесил бы @JsonTypeInfo на доменную модель и разошёлся бы с этим прецедентом. Кодовая база отдаёт клиенту механику через DTO, а не через полиформную сериализацию домена.
    • Минус A осознанно принят. State без effect требует dispatch через ManeuverRegistry.maneuverFor(id) (уже есть, ManeuverRegistry.kt:35); цена — лишний lookup по id, что допустимо для опций-манёвров.

    Consequences¶

    Плюсы¶

    • pendingChoices → participantsJson round-trip остаётся рабочим без изменений существующего @JsonTypeInfo-механизма ClassChoice (kind).
    • Нет второй копии EffectSpec в persisted-state — единственный источник механики — subclasses.yml (single source of truth, ADR-0011).
    • Граница «серверный каталог / персистируемые данные» явна: механика не утекает в JSON.

    Минусы¶

    • EffectSpec не может быть передан клиенту как есть (нет JSON-дискриминатора).
    • Опции манёвров в pendingChoices теряют детали эффекта при сериализации — клиент видит только id/name/description, не механику.

    Риски¶

    • Клиенту понадобится показывать эффекты манёвров — тогда @JsonIgnore станет узким местом. Митигация — см. Отложено (отдельный ChoiceOptionView, не сериализация EffectSpec).

    Отложено¶

    • ChoiceOptionView (DTO для клиента) — если клиенту нужно отображение эффектов манёвров/опций, ввести отдельный DTO; НЕ сериализовать EffectSpec напрямую.
    • Возврат к Варианту B (@JsonTypeInfo на EffectSpec) — отдельным циклом при выполнении хотя бы одного условия: (1) появляются ad-hoc эффекты без записи в каталоге (нет id для maneuverFor); (2) EffectSpec нужно отдавать клиенту напрямую (а не через отдельный DTO ChoiceOptionView). До этого — @JsonIgnore (Вариант A). При возврате учесть: дискриминатор потребуется не только EffectSpec, но и вложенным ScalingSpec/SaveDcSpec.

    ADR-0023: Ядро классовых фич (ClassFeature) — sealed-форма + реестр + швы к ADR-0018/0019¶

    Status¶

    Accepted

    Context¶

    Классовые фичи сейчас — плоские записи в YAML + строковые спецслучаи в коде: счётчики ресурсов есть, семантики эффектов нет. Собранные факты (файл:строка):

    Модель фичи сегодня¶

    # Файл:строка Что найдено

    Проблема¶

    Нет единой формы классовой фичи: пассивное/активное/триггерное/выборное смешано в одном плоском классе; эффекты — строковые if в TurnResolver/SessionService; ресурсы — when(classId) в ClassResourceHelper. Каждая новая фича = новый спецслучай. Нужны: sealed-форма (природа фичи — в типе), реестр «фичи по (classId, level)» и швы к level-up (ADR-0018) и активации (ADR-0019).

    Прецеденты¶

    • ADR-0020 B1: sealed interface RacialTrait (Passive/Active/Triggered) — 0023 повторяет форму для фич (симметрия раса ↔ класс).
    • ADR-0019: Activatable + AbilityCost + AbilityResolver + spendFor (единственный владелец маппинга «слот → Spend*», O3); адаптеры вместо переписывания моделей (D1); контракт не подключён к бою (N1).
    • ADR-0018: LevelUpApplier — чистое ядро; LevelTableRegistry — реестр «что на каком уровне» (образец для F2).
    • ADR-0013: StatusId — прецедент типизации строковых полей.

    Канон D&D 5e (PHB гл.3 «Classes», гл.6 «Customization» — Fighting Style)¶

    12 классов × 30+ фич: активные с ресурсом (Rage, Second Wind, Action Surge, Breath-подобные channel), триггерные (Sneak Attack — на попадание с преимуществом; Savage-подобные — на крит), пассивные (Fighting Style, Unarmored Defense), выборные (Fighting Style — выбор на L1; Expertise — выбор навыков; Metamagic, Invocations, Maneuvers — выборы при level-up, ADR-0025).

    Decision¶

    1. Место хранения (A2)¶

    Фичи остаются в classes.yml/subclasses.yml, типизация — в Kotlin. Отдельный features.yml НЕ вводим — второй источник (факт #2: 1220 строк уже есть). SubclassRegistry допарсивает actionType/resourceId/choice/usesPerLevel/recharge (сегодня теряются, факт #3) — в цикле 3.4.

    2. Форма ClassFeature (B1)¶

    sealed interface ClassFeature + подтипы — симметрично RacialTrait (ADR-0020 B1):

    sealed interface ClassFeature {
    val name: String
    val level: Int
    val description: String
}
data class PassiveClassFeature(/* … + templates: List<StateChange> … */) : ClassFeature
data class ActiveClassFeature(
    /* … + cost: AbilityCost? + resourceId: String? … */
) : ClassFeature, Activatable  // см. §3 (C1)
data class TriggeredClassFeature(
    /* … + trigger: ClassTrigger + condition? + effect … */
) : ClassFeature
data class ChoiceClassFeature(
    /* … + choice: FeatureChoice + applies: ChoiceEffect … */
) : ClassFeature

    Значения для scope: Fighting Style — ChoiceClassFeature (пассивный выбор на L1 у Fighter/Paladin/Ranger; опции defense/dueling/archery/… — те же id, что сегодня лежат в fightingStyle: String, факт #13). Expertise — ChoiceClassFeature + модификатор doubleProficiency (применяется на выбранных skills; сегодня — expertiseSkills + TurnResolver.kt:123). Spellcasting как классовая фича — НЕ включаем (пересечение с ADR-0017, см. Untouched).

    3. ActiveClassFeature реализует Activatable (C1)¶

    Симметрично Spell, минимум кода, без adapter-слоя (адаптер ClassFeatureActivatable уже существует как мост, факт #5, — в 3.4 прямые реализации вытесняют адаптер):

    // ActiveClassFeature : Activatable — id/actionType/cost напрямую,
// AbilityResolver.activate работает без изменений (факт #5: фасад по kind).

    4. Триггеры (D1)¶

    ClassTrigger enum + data class TriggeredClassFeature(trigger, condition?, effect) — симметрично RacialTrigger (ADR-0020 D1):

    enum class ClassTrigger {
    ON_CRIT, ON_HIT, ON_DAMAGE_TAKEN, ON_HP_ZERO, ON_KILL,
    ON_MISS, ON_ALLY_DOWN, ON_TURN_START, ON_TURN_END,
}

    Скрытая атака = TriggeredClassFeature(ON_HIT, condition = advantage||allyAdjacent, effect = +Xd6). Relentless Endurance (ADR-0020 H1b) использует тот же ClassTrigger.ON_HP_ZERO — не дублировать (см. Риски).

    5. Пассивные фичи (E2)¶

    PassiveClassFeature = список StateChange-шаблонов, применяемых при добавлении фичи (level-up). Ложится на LevelUpApplier (ADR-0018): ядро читает ClassDef.features уровня и применяет templates пассивных. Tough (+2 HP/level) уже работает как захардкоженный паттерн (факт #8: :32-33) — типизируем существующий паттерн, а не изобретаем новый.

    6. Реестр фич (F2)¶

    ClassFeatureRegistry отдаёт фичи по (classId, level) — единственный источник «какая фича на каком уровне». LevelUpApplier/LevelUpService вызывают реестр вместо прямого чтения cls.features (факт #9). Симметрично LevelTableRegistry:

    @Component
class ClassFeatureRegistry(private val classRegistry: ClassRegistry) {
    fun featuresFor(classId: String, level: Int): List<ClassFeature>
}

    7. Стоимость фич (G1)¶

    Фичи декларируют AbilityCost (sealed из ADR-0019). ActionEconomyRegistry.spendFor обрабатывает слоты; SpendClassResource — ресурсы. Уже сделано в ADR-0019 (AbilityResolver.spendCost, ClassFeatureActivatable.cost) — фиксируем контракт, не изобретаем. Замечание: AbilityResolver.canAfford для ClassResource/Charges сегодня всегда true (дубль #2 ADR-0011, факт #5) — лимиты закрывает ADR-0024.

    8. Шов к ресурсам (H1 + шов)¶

    ClassFeature объявляет resourceId? (nullable). Фактическое spend/restore — ADR-0024. В 0023 фиксируем только шов: «ClassFeature может потреблять ClassResource по id». when(characterClass.id) в ClassResourceHelper (факт #10) мигрирует на данные из фич в ADR-0024 (см. Риски). Не раздуваем 0023.

    9. Фичи подклассов (I1)¶

    SubclassFeature = ClassFeature (та же форма). Детали подклассов — ADR-0026 (вне мини-ФАЗЫ 0). Допарсинг полей в SubclassRegistry (§1) — необходимое условие I1, входит в цикл 3.4.

    10. Совместимость с ADR-0011 (J1)¶

    Зарегистрировать как потенциальный дубль: feature list в classes.yml vs ClassFeatureRegistry. Сама запись — отдельным циклом, когда ADR-0023 будет реализован (аналогично ADR-0020 J1).

    11. Объём цикла (K1)¶

    Только ADR (design, без кода). Реализация — цикл 3.4.

    Proposed Options¶

    Развилки сформулированы, рекомендация архитектора помечена явно.

    A. Место хранения фич. - A1: новый features.yml + регистр — чистый старт, но второй источник при живых classes.yml/subclasses.yml (1220 строк уже содержат фичи). - A2: остаются в classes.yml/subclasses.yml, типизация в Kotlin — рекомендация архитектора. Без второго источника; допарсинг SubclassRegistry в 3.4. - A3: только БД (таблица фич) — данные статичны (PHB), оверхед миграций не оправдан.

    B. Форма ClassFeature. - B1: sealed interface + 4 подтипа (Passive/Active/Triggered/Choice) — рекомендация архитектора. Симметрия ADR-0020 B1; природа фичи — в типе. - B2: плоский класс + kind-флаг — сегодня так (факт #1); флаги расползаются по when в вызывающем коде. - B3: по классу-наследнику на фичу (RageFeature, SneakAttackFeature…) — взрыв типов: 12 классов × 30+ фич.

    C. Связь с Activatable. - C1: ActiveClassFeature реализует Activatable напрямую — рекомендация архитектора. Симметрия Spell; AbilityResolver без изменений. - C2: навсегда через адаптер ClassFeatureActivatable — лишний слой при своей форме. - C3: свой контур активации мимо ADR-0019 — дублирование spendFor/cost-логики.

    D. Триггеры. - D1: ClassTrigger enum (9 значений) + TriggeredClassFeature — рекомендация архитектора. Симметрия RacialTrigger; общий ON_HP_ZERO с Relentless Endurance. - D2: строковые имена триггеров — возврат к строковым спецслучаям (факт #13). - D3: триггеры только через статусы (StatusId) — не все триггеры являются состояниями (ON_KILL, ON_MISS).

    E. Пассивные фичи. - E1: эффекты пассивок — кодом в LevelUpApplier построчно — новые if на каждую фичу (факт #8: tough, champion уже так). - E2: пассивка = список StateChange-шаблонов, применяемых при level-up — рекомендация архитектора. Типизация существующего паттерна Tough. - E3: пассивки только нарративом (как сегодня FeatureActivator, факт #6) — механика не появляется вообще.

    F. Доступ «фичи по (classId, level)». - F1: прямое чтение cls.features вызывающими (сегодня, факт #9) — логика «что на каком уровне» размазана. - F2: ClassFeatureRegistry.featuresFor(classId, level) — рекомендация архитектора. Единственный источник; симметрия LevelTableRegistry. - F3: кэш фич в CharacterState (список полученных) — второй источник истины, рассинхрон с YAML.

    G. Стоимость. - G1: декларируют AbilityCost (ADR-0019); обработка — spendFor/AbilityResolver — рекомендация архитектора. Уже работает для адаптера (факт #5). - G2: своя cost-модель для фич — дублирование sealed из ADR-0019. - G3: без стоимостей (всё Free) — ресурсы (Rage/Ki) теряют смысл.

    H. Связь с ClassResource. - H1: resourceId?-шов сейчас, spend/restore — ADR-0024 — рекомендация архитектора. Не раздуваем 0023; миграция when(classId) — в 0024 (Риски). - H2: сразу типизировать все ресурсы в 0023 — тянет ADR-0024 целиком. - H3: без шва (фичи не знают про ресурсы) — разрыв с существующими счётчиками (факт #11).

    I. Фичи подклассов. - I1: SubclassFeature = ClassFeature, детали — ADR-0026 — рекомендация архитектора. Одна форма на всё; допарсинг в 3.4 (§1). - I2: отдельная форма для подклассов — две параллельные иерархии. - I3: проектировать подклассы в 0023 — тянет ADR-0026 (12 классов × 50-80 подклассов).

    J. ADR-0011. - J1: потенциальный дубль (YAML-список vs реестр), запись — отдельным циклом после реализации — рекомендация архитектора. Аналогично ADR-0020 J1. - J2: не регистрировать — нарушение правила ADR-0011. - J3: считать дублем уже сейчас и резолвить в 0023 — преждевременно, реестра нет.

    K. Объём. - K1: только ADR; реализация — цикл 3.4 — рекомендация архитектора. - K2: ADR + частичная типизация без реестра — половина формы без источника (F2). - K3: полный цикл с реализацией — нарушает «один цикл = один фокусный шаг».

    Consequences¶

    Плюсы¶

    • Единая форма ClassFeature + реестр — единый источник истины для 12 классов × 30+ фич.
    • Типизация устраняет хардкод when(classId == ...) в ClassResourceHelper (миграция — ADR-0024, шов H1 уже фиксирует направление).
    • Ложится на существующие ADR-0018 (level-up: E2+F2) и ADR-0019 (Activatable: C1+G1).
    • Subclass-фичи используют ту же форму (I1) — задел для 0026.

    Минусы¶

    • Хардкод-фичи (факты #10, #13, #14) требуют миграции данных в YAML + переписывания строковых спецслучаев (fightingStyle, expertiseSkills, enrage у врага).
    • ClassFeatureRegistry — пятый регистр по паттерну (после Class, Skill, Feat, Subclass) — нагрузка на инфраструктуру.
    • Часть фич (Rage, Wild Shape, Sneak Attack) потребует новых StateChange-типов — это ADR-0024/0025 (не 0023).

    Риски¶

    • Хардкод-каталог фич найден (стоп-условие #3 сработало как находка): ClassResourceHelper.kt:12, :77 (when на 12 классов), SessionService.kt:80-82, :120-127, TurnResolver.kt:1913, SpellService.kt:35, :64 и др. (факт #14). Митигация: миграция данных — ADR-0024 (H1 фиксирует шов уже сейчас).
    • Rage — состояние + ресурс + триггер одновременно. Может потребовать отдельного ADR (ADR-0024 ClassResource expansion). Митигация: H1 фиксирует только шов.
    • Wild Shape — полиморф формы (трансформация CharacterState). Возможно, отдельный ADR-lite. Митигация: в 0023 — только форма Active/Triggered, детали — ADR-0025 или цикл 3.4.
    • Relentless Endurance (H1b из ADR-0020) — hook в damage-resolution. Общий паттерн с TriggeredClassFeature. Не дублировать: использовать ClassTrigger.ON_HP_ZERO для обоих.
    • backgrounds.yml-синдром: не вводить features.yml без реестра (A2 отклоняет A1 именно поэтому; SubclassRegistry допарсивается, а не дублируется).

    Отложено¶

    • ADR-0024 ClassResource expansion (Rage/Ki/Superiority/Channel + миграция when).
    • ADR-0025 Level-up choices (Metamagic, Invocations, Maneuvers).
    • ADR-0026 Subclass (12 классов × подклассы; I1 — задел формой).
    • Spellcasting как ClassFeature — пересечение с ADR-0017 (см. Decision §2).
    • Реализация — цикл 3.4.

    Чек-лист решений A–K¶

    • A = A2 — фичи остаются в classes.yml/subclasses.yml, типизация в Kotlin.
    • B = B1 — sealed interface ClassFeature (Passive/Active/Triggered/Choice).
    • C = C1 — ActiveClassFeature реализует Activatable.
    • D = D1 — ClassTrigger (9 значений) + TriggeredClassFeature.
    • E = E2 — пассивка = StateChange-шаблоны через LevelUpApplier.
    • F = F2 — ClassFeatureRegistry.featuresFor(classId, level).
    • G = G1 — AbilityCost из ADR-0019, обработка существующая.
    • H = H1 + шов — resourceId? сейчас, spend/restore — ADR-0024.
    • I = I1 — SubclassFeature = ClassFeature, детали — ADR-0026.
    • J = J1 — дубль в ADR-0011 отдельным циклом после реализации.
    • K = K1 — только ADR; реализация — цикл 3.4.

    ADR-0024: Расширение классовых ресурсов (ClassResource) — реестр + формулы + шов H1¶

    Status¶

    Accepted

    Context¶

    Классовые ресурсы сегодня — два параллельных when-каталога плюс счётчики в CharacterState: семантика «сколько и когда восстанавливается» размазана между ClassResourceHelper (по классу) и SessionService (по resourceId). Собранные факты (файл:строка):

    Ресурсы сегодня¶

    # Файл:строка Что найдено
    1 classes/ClassResourceHelper.kt:10-66 initialResources — when(characterClass.id) на 12 ветвей (barbarian/bard/cleric/druid/warrior/monk/paladin/ranger/rogue/sorcerer/warlock/wizard; ranger/rogue — пусто).
    2 classes/ClassResourceHelper.kt:68-121 resourcesForLevelUp — второй when на 12 ветвей (пересчёт max, сохранение spent). Вызывается из LevelUpApplier.kt:41 (не из LevelUpService:254 — в брифе неточность).

    Где лежат max-значения (фактура для B2)¶

    Источник Примеры
    usesPerLevel в classes.yml (через usesFor, факт #4) RAGE {1:2, 3:3, 6:4, 12:5, 17:6} (:501-506); ACTION_SURGE {2:1, 17:2} (:71-73); SECOND_WIND {1:1} (:63-64); recharge-флаги: LONG_REST (rage :507), SHORT_REST (second wind :65, action surge :74, channel :423, wild shape :702, ki :774, pact :1177), LONG_REST (arcane :204, bardic :609, sorcery :1103, lay on hands :850)
    Хардкод-формулы в ClassResourceHelper 5 * level — layOnHands (:47-48, при этом usesPerLevel: {1:5} в YAML :848-849 игнорируется); level.coerceAtLeast(2) — sorcery (:56); maxOf(1, chaModifier) + dieSize when(level) — bardic (:19-27); PactSlots.forWarlockLevel (факт #6)
    Флаги secondWindUsed/arcaneRecoveryUsed/naturalRecoveryUsed max = 1, семантика «использовано/нет» (ClassFeatureHelper.kt:67-68)

    Scope-включения: что есть сегодня¶

    Ресурс Состояние
    Superiority Dice (Battle Master) Отсутствует в коде (grep SUPERIORITY в kt → 0). Только текст: «Боевое превосходство… 4 кости d8» (subclasses.yml:18), whitelist «Кость превосходства» (action-whitelist-core.yaml:102), условия subclass == 'battle_master' (reaction_triggers.yml:53, :85). Scope: включить как PoolType.DICE, diceType=d8.
    Lay on Hands (Paladin) Счётчик + spend/restore (факты #7–8, #5). Путь «потратить N HP из пула на исцеление» — только счётчик, без связки с Heal. Scope: включить как PoolType.HP, maxFormula="5*level".
    Pact Magic (Warlock) PactSlots + spend/restore + recharge: SHORT_REST (classes.yml:1172-1177); гейт каста SpellService.kt:35-37; трата TurnResolver.kt:1996. ADR-0016 I1 подтвердил no-op для Pact как каст-пути. Scope: включить как ресурс FullOnShortRest; каст через pact slots — НЕ трогаем (граница I1, ADR-0017).
    Frenzy (Berserker) Только текст: «Путь Берсерка» (subclasses.yml:128), «Путь варвара (задел)» (classes.yml:515-517). Механики нет. НЕ в 0024 — ADR-0026 (G1).

    Итого: ClassResourceRegistry отсутствует, resources.yml отсутствует — ADR «с нуля» с переносом данных из classes.yml в секцию resources:; два when-каталога (по классу + по resourceId) + несогласованные конвенции spent/remaining; canAfford для ресурсов — заглушка true.

    Проблема¶

    Нет единого источника «какие ресурсы у класса, их max-формулы и правила восстановления»: initialResources/resourcesForLevelUp знают max по классу, spend/restoreClassResource знают трату по id, usesPerLevel в YAML знает таблицы, формулы (5*level, chaModifier, dieSize) захардкожены. Дубль #2 ADR-0011 (Partial) — прямое следствие. Нужны: resources:-секция в classes.yml + ClassResourceRegistry (max/restore по данным) + тонкий фасад вместо when-каталогов + наполнение шва H1 из ADR-0023.

    Прецеденты¶

    • ADR-0023 H1 — шов resourceId?; настоящий ADR его наполняет.
    • ADR-0018 F1 — resourcesForLevelUp уже вызывается из LevelUpApplier (факт #2); реестр подменяет источник данных, не вызывающий код (C3).
    • ADR-0019 — AbilityCost.ClassResource, spendFor (O3), AbilityResolver (лимиты — заглушка, факт #13).
    • ADR-0020 A2 — данные в YAML + реестр в Kotlin (образец для A2).
    • ADR-0011 #2 — дубль, резолвящийся здесь (H1).

    Канон D&D 5e (PHB гл.3 «Classes»)¶

    Rage (2–6/long rest), Bardic Inspiration (CHA mod/long; short с L5 — Font of Inspiration; die d6→d12), Channel Divinity (1–3/short-long), Wild Shape (2/short), Action Surge (1–2/short), Second Wind (1/short), Ki (= level/short), Lay on Hands (5×level HP/long), Sorcery Points (= level/long), Pact Magic (слоты, short rest), Arcane Recovery (1/long), Superiority Dice (4–6/short-long, d8→d12).

    Decision¶

    1. Место хранения (A2)¶

    Секция resources: в classes.yml + ClassResourceRegistry.kt. Отдельный resources.yml НЕ вводим — симметрия с ADR-0023 A2 (без второго источника). Пример записи (миграция существующих данных, факты §«max-значения»):

    resources:
  RAGE: { maxFormula: "table:1=2,3=3,6=4,12=5,17=6", restoreRule: FullOnLongRest }
  KI:   { maxFormula: "level", restoreRule: FullOnShortRest }

    usesPerLevel-таблицы переезжают как есть (table:…); хардкод-формулы (5*level, chaModifier, dieSize) становятся maxFormula-строками. SubclassRegistry-данные (Superiority — факт Scope) получают resourceId: SUPERIORITY в subclasses.yml при допарсинге из ADR-0023 §1.

    2. Форма ClassResource (B2)¶

    data class + enum ClassResourceId — НЕ sealed. Обоснование: ресурсы — данные (счётчики с формулами), не поведение; sealed провоцирует взрыв типов (13 ресурсов × варианты). Отличие от ClassFeature (B1 sealed в 0023): там природа принципиально разная (пассив/актив/триггер/выбор), здесь — все счётчики с разной maxFormula:

    data class ClassResource(
    val id: ClassResourceId,
    val name: String,
    val maxFormula: String,        // "level", "2*level", "PB", "5*level", "table:…"
    val restoreRule: RestoreRule,
    val poolType: PoolType = PoolType.COUNTER,
    val diceType: DiceType? = null, // для SUPERIORITY (d8)
)
enum class PoolType { COUNTER, DICE, HP }
enum class ClassResourceId {
    RAGE, KI, WILD_SHAPE, SORCERY_POINTS, ACTION_SURGE, SECOND_WIND,
    CHANNEL_DIVINITY, BARDIC_INSPIRATION, LAY_ON_HANDS, SUPERIORITY,
    PACT_SLOTS, ARCANE_RECOVERY, NATURAL_RECOVERY,
}

    enum DiceType { D6, D8, D10, D12 } — состав по PHB; для SUPERIORITY используется D8 (Battle Master), D6–D12 — задел под будущие пулы (Bardic Inspiration die — не пул, но dieSize есть).

    Scope: Superiority — PoolType.DICE, diceType=D8, restoreRule=FullOnShortRest. По канону superiority dice восстанавливаются и на short, и на long rest. В 0024 фиксируем ShortRest как базовое правило; в цикле 3.4 long rest вызывает short-rest-restore для всех short-capable ресурсов — тогда FullOnShortRest достаточен. Открытый вопрос 3.4: явное правило «long rest применяет short-rest-restore» (или расширение RestoreRule). Трата = «потратить 1 кубик на манёвр». Lay on Hands — PoolType.HP, maxFormula="5*level", restoreRule=FullOnLongRest; трата = «потратить N HP из пула». Манёвры/исцеление как эффекты — вне 0024 (см. Отложено).

    3. Судьба ClassResourceHelper (C3)¶

    Хелпер становится тонким фасадом над ClassResourceRegistry: те же сигнатуры (initialResources/resourcesForLevelUp/restore/usesFor), внутри — делегация в реестр. Call sites (SessionService.kt:475/:2734/:2750, LevelUpApplier.kt:41) остаются работать — минимум правок, контракт ClassResourceHelperTest сохраняется (митигация риска миграции). Удаление хелпера (фасад → прямые вызовы реестра) — отдельным шагом после миграции, в цикле 3.4.

    4. Разделение max/restore vs spend (D1 + D2)¶

    Расчёт max/restore — в ClassResourceRegistry (по maxFormula/RestoreRule из данных). Вызовы StateChange.SpendClassResource/RestoreClassResource — остаются в SessionService (:2881-2889, факт #10), но when-тела spendClassResource/restoreClassResource (факты #7–8) заменяются обращением к реестру (семантика пула по poolType). Минимальная перестройка: точка вызова та же, источник семантики — реестр. Заодно унифицируется конвенция spent/remaining (факт #8): реестр владеет направлением счётчика.

    5. Rage (E3)¶

    Rage = ActiveClassFeature с resourceId=RAGE (согласно ADR-0023 C1). RageResource(active, roundsRemaining) остаётся полем в state (GameState.kt:1378) — активное состояние ярости не сводится к счётчику. Эффекты Rage (бонус урона, resistance) — через StateChange-шаблоны PassiveClassFeature (E2 из 0023), но сама механика эффекта — цикл 3.4 (см. Риски: ресурс списывается, эффект — ярлык).

    6. Правила восстановления (F2)¶

    sealed interface RestoreRule
data object FullOnLongRest : RestoreRule
data object FullOnShortRest : RestoreRule  // Pact Magic, Ki
data object HalfOnLongRest : RestoreRule
data class FixedN(val n: Int) : RestoreRule

    Покрывает таблицу факта #3 и канон: long-only (rage, lay on hands, sorcery, arcane), short-capable (ki, pact, channel, action surge, second wind, bardic с оговоркой Font of Inspiration — нюанс L5 фиксируется в данных, не в коде), half (задел под фичи «половина на long rest»).

    7. Frenzy (G1)¶

    Frenzy (Berserker) — НЕ в 0024. Подклассовая фича, детали — ADR-0026. В 0024 только гарантия: форма TriggeredClassFeature из 0023 достаточна для Frenzy (триггер на вход в ярость), деталей не проектируем.

    8. Резолв дубля #2 (H1)¶

    Дубль #2 ADR-0011 резолвится полностью в 0024: ClassResourceRegistry — единственный источник «какие ресурсы, max, restore». Запись в ADR-0011 — в этом же цикле (коммит 2): статус #2 → Resolved (план); фактическая реализация — цикл 3.4. Направление из ADR-0011 (вариант A: хелпер — источник, SessionService делегирует) эволюционирует: источник — реестр, хелпер и spend/restore в SessionService — оба тонкие делегаты (C3+D1+D2).

    9. Pact Magic (I1, с оговоркой)¶

    Pact Magic включается как ресурс PACT_SLOTS с RestoreRule.FullOnShortRest (факт #6: PactSlots + restore() уже short-ready). НЕ трогаем «как кастуются заклинания через pact slots» (SpellService.kt:35-37, TurnResolver.kt:1996) — это ADR-0017, вне 0024. Граница: 0024 = ресурс (max/restore/трата), каст-путь = ADR-0017 (симметрично ADR-0016 I1 no-op).

    10. activatableIds (J1)¶

    CharacterState.activatableIds (факт #17) заполняется при добавлении ActiveClassFeature с resourceId. Источник данных — ClassResourceRegistry (знает все ресурсы класса), конкретная точка заполнения — LevelUpApplier (цикл 3.4; сегодня он уже трогает ресурсы — факт #2). Факт #7 из 0023 закрывается проектом, реализация — 3.4.

    11. Объём цикла (K1)¶

    Только ADR. Реализация (ClassResourceRegistry, миграция when-каталогов, заполнение activatableIds) — цикл 3.4.

    Proposed Options¶

    A. Место хранения. - A1: отдельный resources.yml — второй источник при живом classes.yml (тот же аргумент, что отклонил features.yml в 0023 A1). - A2: секция resources: в classes.yml + ClassResourceRegistry.kt — рекомендация архитектора. Симметрия ADR-0023 A2. - A3: только код (enum с формулами) — данные PHB в коде, правка = релиз.

    B. Форма ClassResource. - B1: sealed-иерархия (RageResource/KiResource/…) — взрыв типов: 13 ресурсов; поведение у всех одно (счётчик), различаются только формулы. - B2: data class + enum ClassResourceId (+ PoolType/RestoreRule) — рекомендация архитектора. Данные, не поведение; DICE/HP покрывают Superiority/Lay on Hands без новых типов. - B3: оставить ClassResources как есть (16 nullable полей) — новые ресурсы (Superiority) = новые поля + новые when-ветви (факты #5, #7–8).

    C. Судьба хелпера. - C1: удалить ClassResourceHelper сразу — ломает call sites и ClassResourceHelperTest (4 теста) в том же цикле. - C2: оставить как есть + реестр рядом — два источника (новый дубль). - C3: тонкий фасад над реестром, удаление — после миграции (3.4) — рекомендация архитектора. Контракт и тесты живы.

    D. Разделение ответственности. - D1+D2: max/restore — реестр; точки вызова Spend/Restore — SessionService (делегация в реестр) — рекомендация архитектора. Минимальная перестройка. - D3: всё в реестр (включая применение StateChange) — реестр лезет в applyStateChanges, нарушение границ слоёв. - D4: всё в SessionService — сохраняется when на 12 ветвей (факты #7–8).

    E. Rage. - E1: Rage — только счётчик (убрать active) — потеря состояния «в ярости» (ломает StatusId.RAGE-связки). - E2: Rage — только статус (убрать счётчик) — потеря лимита использований. - E3: ActiveClassFeature + resourceId=RAGE, RageResource(active) остаётся, эффекты — шаблонами в 3.4 — рекомендация архитектора. Счётчик + состояние.

    F. RestoreRule. - F1: boolean-флаги (onShort/onLong) — не выражают Half/FixedN. - F2: sealed RestoreRule (4 варианта) — рекомендация архитектора. Закрытое множество, исчерпывающий when. - F3: строка в YAML без типа — опечатки в данных не ловятся компилятором.

    G. Frenzy. - G1: НЕ в 0024 (ADR-0026) — рекомендация архитектора. - G2: включить Frenzy в 0024 — тянет подклассовую специфику (нарушение границ).

    H. Дубль #2. - H1: резолв полностью в 0024 + запись в ADR-0011 этим же циклом — рекомендация архитектора. - H2: отложить запись до реализации (3.4) — ADR-0011 врёт 2 цикла. - H3: не резолвить (оставить Partial) — дубль живёт дальше без владельца.

    I. Pact Magic. - I1: ресурс — да (FullOnShortRest), каст-путь — нет (ADR-0017) — рекомендация архитектора (с оговоркой). - I2: включить и каст-путь — пересечение с ADR-0017 шире границы (стоп-условие #5 не сработало: SpellService.kt:35-37 — только гейт наличия, каст-логики pact там нет). - I3: исключить Pact из 0024 — warlock остаётся на when-ветке (факты #1, #7).

    J. activatableIds. - J1: источник — реестр, точка — LevelUpApplier (3.4) — рекомендация архитектора. - J2: заполнять в SessionService при создании — точка создания не знает про level-up фичи. - J3: не заполнять (оставить ФАЗЕ 3) — факт #7 из 0023 висит без владельца.

    K. Объём. - K1: только ADR; реализация — 3.4 — рекомендация архитектора. - K2: ADR + реестр без миграции — второй источник рядом с when (вариант C2). - K3: полный цикл с реализацией — нарушает «один цикл = один фокусный шаг».

    Consequences¶

    Плюсы¶

    • Дубль #2 ADR-0011 резолвится полностью (H1 + коммит 2).
    • Хардкод when(classId) на 12 классов уходит из ClassResourceHelper в данные (resources: в classes.yml).
    • Шов H1 из ADR-0023 (resourceId?) наполняется.
    • activatableIds (факт #7 из 0023) находит источник заполнения (J1).
    • PoolType.DICE и PoolType.HP покрывают Superiority Dice и Lay on Hands без взрыва типов.

    Минусы¶

    • Миграция данных: 12 классов × ресурсы переезжают в classes.yml (таблицы usesPerLevel + хардкод-формулы → maxFormula-строки).
    • ClassResourceRegistry — шестой регистр по паттерну (Class/Skill/Feat/Subclass/ClassFeature).
    • Pact Magic — потенциальное пересечение с ADR-0017 (граница зафиксирована в I1: ресурс — здесь, каст — там).

    Риски¶

    • Rage остаётся частично ярлыком: ресурс списывается (active=true), эффект (бонус урона/resistance) — цикл 3.4 (E3). Не блокер 0024.
    • Миграция when(classId) может задеть ClassResourceHelperTest (4 теста: rage/ki/pact/restore). Митигация: C3 (тонкий фасад) сохраняет контракт — тесты не меняются.
    • AbilityResolver.canAfford для ClassResource всегда true (факт #13, стоп-условие #4): лимиты не проверяются — активация может тратить отсутствующий ресурс. 0024 фиксирует (реестр знает max), проверка — цикл 3.4.
    • Superiority Dice — манёвры (trip/shove) не имеют IntentClassifier (G-007): трата кубика есть, распознавание приёма — нет. Синхронизация с ФАЗОЙ 3 (Structured Intent).
    • Pact Magic — двойной источник слотов (обычные + pact): риск рассинхрона при касте. Митигация: граница I1 (0024 = ресурс, каст — ADR-0017).
    • Несогласованность spent/remaining (факт #8: ki vs layOnHands) — митигация: D1+D2 (реестр владеет направлением счётчика по poolType).
    • Bardic Inspiration в YAML recharge: LONG_REST, в коде restore и на SHORT (факты §max + #3): канонический нюанс Font of Inspiration (L5+). Митигация: RestoreRule F2 (FullOnShortRest/FullOnLongRest) НЕ выражает условное по уровню правило (L1–4: long only; L5+: long + short). Два пути: (а) расширить RestoreRule подтипом ConditionalRestoreRule(levelAtLeast, rule) в цикле 3.4; (б) развести данные classes.yml на два уровня (bardic_1_4, bardic_5_plus). Решение — open question цикла 3.4. В 0024 фиксируется как известное ограничение формы.

    Отложено¶

    • Реализация ClassResourceRegistry + миграция when-каталогов — цикл 3.4.
    • Удаление ClassResourceHelper (C3 → прямые вызовы) — после миграции.
    • Проверка лимитов в canAfford — цикл 3.4.
    • Frenzy (Berserker) — ADR-0026 (G1).
    • Pact Magic как каст-путь — ADR-0017 (I1).
    • Манёвры Superiority (trip/shove распознавание) — ФАЗА 3 (G-007).
    • Связка Lay on Hands → Heal — цикл 3.4 (эффект, не ресурс).

    Чек-лист решений A–K¶

    • A = A2 — секция resources: в classes.yml + ClassResourceRegistry.kt.
    • B = B2 — data class ClassResource + enum ClassResourceId (+ PoolType, RestoreRule); Superiority = DICE/d8, Lay on Hands = HP/5*level.
    • C = C3 — хелпер → тонкий фасад; удаление — после миграции (3.4).
    • D = D1+D2 — max/restore в реестре; точки Spend/Restore в SessionService делегируют.
    • E = E3 — Rage = ActiveClassFeature(RAGE); RageResource(active) остаётся; эффекты — 3.4.
    • F = F2 — sealed RestoreRule (FullOnLongRest/FullOnShortRest/HalfOnLongRest/FixedN).
    • G = G1 — Frenzy НЕ в 0024 (ADR-0026).

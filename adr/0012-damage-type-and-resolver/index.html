    ADR-0012: Enum DamageType и резолвер сопротивлений/иммунитетов/уязвимостей (DamageResolver)¶

    Status¶

    Accepted

    Context¶

    Сейчас тип урона — это свободная строка, а логика «сопротивление/иммунитет/уязвимость» размазана по коду и неполна. Собранные факты (файл:строка):

    Модель урона¶

    • StateChange.Damage(amount, target, damageType: String? = null) — тип урона nullable, по умолчанию null, не enum (GameState.kt:1157).
    • Тип урона заклинания — строка: SpellEffect.Damage.damageType: String (spells/Spell.kt:72).
    • Тип урона hazard — строка из БД: EnvironmentalHazardRow.damageType: String? (catalog/CatalogService.kt:260, колонка environmental_hazards.damage_type).

    Эмиссия урона (14 точек StateChange.Damage в main-коде)¶

    2 TurnResolver.kt:959 ENEMY null

    Применение resistance/immunity/vulnerability¶

    • Единственная точка учёта резистов/иммунитетов — SpellService.kt:168-173 (в resolveDamage), и только для Enemy: 
      if (effect.damageType in target.resistances) totalDamage /= 2   // 168
if (effect.damageType in target.immunities)  totalDamage = 0    // 171
      Урон уже уменьшен ДО эмиссии StateChange.Damage (SpellService.kt:175), т.е. резолвер вызывается «в вызывающем коде», а не в единой точке применения.
    • Vulnerability нигде не обрабатывается.
    • Урон по PLAYER применяется в SessionService.applyStateChanges (SessionService.kt:2385) без учёта resistance/immunity/vulnerability (только unconscious, death save, концентрация).
    • Урон по ENEMY в applyStateChanges не снижает HP — он лишь суммируется для отображения (SessionService.kt:1683-1686, :1978-1983); фактическое снижение HP врага вне этой точки.

    Модели¶

    • Enemy (GameState.kt:682): resistances: List<String> (:701), immunities: List<String> (:703). Поля vulnerabilities нет.
    • CharacterState (GameState.kt:338+): полей resistances/immunities/vulnerabilities нет.

    Канон D&D 5e (PHB p.196-197)¶

    13 типов урона: acid, bludgeoning, cold, fire, force, lightning, necrotic, piercing, poison, psychic, radiant, slashing, thunder. Resistance = ÷2 (округление вниз); immunity = 0; vulnerability = ×2; resistance + vulnerability = нормальный урон; immunity побеждает оба. В коде присутствуют 12 из 13 типов (нет slashing).

    Decision¶

    1. Enum DamageType (A1)¶

    Вводим enum в отдельном подпакете com.yorva.rules.damage (rules/damage/DamageType.kt). 13 значений D&D 5e (PHB p.196-197):

    enum class DamageType {
    ACID, BLUDGEONING, COLD, FIRE, FORCE, LIGHTNING,
    NECROTIC, PIERCING, POISON, PSYCHIC, RADIANT, SLASHING, THUNDER,
}

    Тип урона перестаёт быть строкой: StateChange.Damage.damageType меняется с String? на DamageType? (null по-прежнему означает «бестиповый», см. G3 и риски). SpellEffect.Damage.damageType (spells/Spell.kt:72) и EnvironmentalHazardRow.damageType (catalog/CatalogService.kt:260) тоже становятся DamageType — строки из JSON/БД парсятся в enum при загрузке.

    2. DamageResolver (B1)¶

    object DamageResolver — чистая функция, без Spring-бина и без состояния:

    object DamageResolver {
    fun apply(rawDamage: Int, type: DamageType?, target: Damageable): Int
}

    Правила (PHB p.196-197): - immunity → 0 (побеждает всё); - resistance → rawDamage / 2 (round down); - vulnerability → rawDamage * 2; - resistance + vulnerability → нормальный урон: сначала ÷2 (round down), затем ×2; - type == null (бестиповый урон) → без модификаций, возвращает rawDamage.

    3. Интерфейс Damageable (C1)¶

    interface Damageable {
    val resistances: List<DamageType>
    val immunities: List<DamageType>
    val vulnerabilities: List<DamageType>
}

    Реализуют CharacterState и Enemy. У Enemy существующие resistances/immunities (GameState.kt:701,703) меняют тип List<String> → List<DamageType> и добавляется vulnerabilities. У CharacterState три поля добавляются (по умолчанию пустые списки).

    4. «Сопротивление всему» (D1)¶

    Отдельное поле resistanceToAll: Boolean = false у Damageable — не значение DamageType.ALL. Обоснование: enum остаётся чистым (только 13 типов), а «сопротивление всему» — это модификатор состояния (Petrified из ADR-0013), а не тип урона.

    5. Единая точка применения (E1)¶

    Резолвер применяется в единой точке — SessionService.applyStateChanges: - StateChange.Damage хранит сырой урон (amount) и тип; резолвер вызывается при применении. - SpellService.kt:168-173 (учёт resist/immune) удаляется — вызовы перестают пред-обрабатывать урон. - E1 применяет DamageResolver в applyStateChanges к тем StateChange.Damage, которые уже приходят туда (сейчас — PLAYER). - Консолидация снижения HP ENEMY из TurnResolver.kt:1790 в applyStateChanges — ОТДЕЛЬНОЕ решение (дубль #4 ADR-0011). В ADR-0012 не входит.

    6. «Магическое vs немагическое» оружие (F2)¶

    ОТЛОЖЕНО до ФАЗЫ 2 (Monsters). В этой работе флаг isMagical не вводится.

    7. Vulnerability и типизация оружия (G1 + G3)¶

    Vulnerability (G1): vulnerabilities: List<DamageType> вводится сразу в Damageable и обрабатывается в DamageResolver.apply (×2).

    Типизация оружия (G3): базовый урон оружия получает физический тип (slashing/bludgeoning/piercing). Минимальный путь: - Источник истины — колонка damage_type (nullable) в item_archetypes (0022). - Runtime — поле damageType: DamageType? = null у InventoryItem (GameState.kt:231), заполняется из архетипа при создании предмета. - Эмиссия — TurnResolver.kt:1785 передаёт equippedItem?.damageType (объект equippedItem уже в области видимости, TurnResolver.kt:1753).

    ItemBonuses не используем — это бонусы характеристик, а не тип урона.

    Лут-предметы остаются untyped (InventoryItem.damageType = null) до отдельной задачи «типизация лута» в ФАЗЕ 2 — см. ## Untouched in this ADR.

    Legacy fallback: старые сессии без damageType → «untyped» (без resistance/immunity). Канонический тип определяется оружием (longsword=slashing, mace=bludgeoning, rapier=piercing, shortbow=piercing, sling=bludgeoning), а не «melee/ranged». Заполнение item_archetypes (G3) закрывает legacy-проблему.

    8. Gap: weapon_traits.damage_type¶

    weapon_traits.damage_type (0015) существует в БД, но WeaponTraitRow (CatalogService.kt:225-248) его не читает. Это отдельный gap вне рамок ADR-0012: он про элементальные зачарования (flaming/frost/poisoned/cursed) — дополнительный тип урона поверх базового, требующий логики применения traits (extra dice + статус), а не базового enum. Зафиксирован как открытый вопрос (отдельная работа).

    Proposed Options¶

    Развилки сформулированы, выбор за архитектором.

    A. Размещение enum DamageType. Пакет rules сейчас без подпакета damage/, но есть economy/, intent/, semantic/. - A1: com.yorva.rules.damage.DamageType — отдельный подпакет (изоляция домена урона). - A2: com.yorva.rules.DamageType — плоский пакет, рядом с GameState.

    B. Форма DamageResolver. - B1: чистая функция/object DamageResolver (детерминированный rules-engine, без состояния). - B2: Spring-бин (@Component) с инъекцией — если понадобятся конфиг/переопределения.

    C. Модель носителей resist/immune/vuln. Сейчас resist/immune есть только у Enemy (List<String>), у CharacterState их нет. - C1: общий интерфейс Damageable { resistances; immunities; vulnerabilities } — и Enemy, и CharacterState его реализуют (симметрия, один резолвер). - C2: продублировать поля в CharacterState без интерфейса. - C3: оставить только у Enemy (урон по игроку пока не учитывает сопротивления).

    D. «Сопротивление всему» (потребуется для Petrified из ADR-0013). - D1: отдельный флаг/статус «resistance to all». - D2: специальное значение DamageType.ALL в списке. - D3: не поддерживать в MVP.

    E. Точка применения резолвера. - E1: единая точка в SessionService.applyStateChanges (и для Player, и для Enemy) — резолвер применяется там, урон в StateChange.Damage хранится «сырым». - E2: оставить в вызывающем коде (как сейчас в SpellService) — риск дублирования.

    F. «Магическое vs немагическое» оружие. Канон: сопротивление к bludgeoning/piercing/slashing не распространяется на магическое оружие. - F1: флаг isMagical: Boolean у источника урона. - F2: отложить (учесть только при вводе уязвимостей к физическому урону).

    G. Vulnerability и типизация базового оружия. - G1: ввести vulnerabilities сразу (полный канон ÷2/×2/иммунитет). - G2: отложить vulnerability до отдельного шага. - G3: типизировать базовый урон оружия (slashing/bludgeoning/piercing) — сейчас он бестиповый.

    Consequences¶

    Плюсы¶

    • Симметрия Player/Enemy: оба реализуют Damageable, один резолвер на всех носителей урона.
    • Единая точка применения (E1): логика resistance/immunity/vulnerability больше не размазана по вызывающему коду.
    • Vulnerability появляется впервые (полный канон ÷2/×2/иммунитет).
    • Оружие типизировано → resistance к физическому урону (slashing/bludgeoning/piercing) заработает.

    Минусы¶

    • SpellService.kt:168-173 теряет логику резистов/иммунитетов — переезд в applyStateChanges.
    • Типизация оружия требует правок данных: колонка damage_type в item_archetypes (0022) и поле damageType в InventoryItem.

    Риски¶

    • Старые сессии без damageType на оружии — fallback untyped (без resistance/immunity). Канонический тип определяется оружием (longsword=slashing, mace=bludgeoning, rapier=piercing, shortbow=piercing, sling=bludgeoning), а не «melee/ranged». Заполнение item_archetypes (G3) закрывает legacy-проблему.
    • type == null не проходит модификацию в резолвере (без resistance/vulnerability) — поведение по умолчанию задокументировано.
    • Консолидация снижения HP ENEMY (сейчас TurnResolver.kt:1790) в applyStateChanges — дубль #4 ADR-0011, в ADR-0012 не входит (см. ADR-0011).
    • Изменение InventoryItem затрагивает лут-пайплайн. LootShowcaseService.toInventoryItem (named-args, без damageType) продолжит работать через default null. Митигация: изменение аддитивное — все существующие тесты лута (LootShowcaseServiceTest, LootPowerTableTest) должны пройти без правок. Если хоть один падает — стоп и доклад архитектору.

    Отложено¶

    • F2: «магическое vs немагическое оружие» — отложено до ФАЗЫ 2 (Monsters).

    Чек-лист решений A–G¶

    • A = A1 — enum com.yorva.rules.damage.DamageType (отдельный подпакет).
    • B = B1 — object DamageResolver, чистая функция, без Spring-бина.
    • C = C1 — общий интерфейс Damageable у CharacterState и Enemy.
    • D = D1 — resistanceToAll: Boolean (не DamageType.ALL).
    • E = E1 — единая точка applyStateChanges; SpellService.kt:168-173 удаляется.
    • F = F2 — магическое оружие отложено до ФАЗЫ 2 (Monsters).
    • G = G1 + G3 — vulnerability сразу; оружие типизируется сразу.

    Untouched in this ADR¶

    Следующие файлы НЕ изменяются в рамках ADR-0012: - loot/LootShowcaseService.kt — только конструктор InventoryItem (поле damageType добавляется с default null), логика toInventoryItem не меняется; - loot/LootTable.kt, LootPowerTable.kt, LootRarityCurve.kt; - db/changelog/changes/0028-loot-catalog.yaml, 0029-loot-items-*.yaml (все 9 файлов), 0030-loot-item-category.yaml.

    Loot-предметы остаются untyped (InventoryItem.damageType = null) до отдельной задачи «типизация лута» в ФАЗЕ 2.

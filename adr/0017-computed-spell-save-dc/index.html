    ADR-0017: Вычисляемый spell save DC (8 + proficiency bonus + spellcasting ability modifier)¶

    Status¶

    Accepted

    Context¶

    Сейчас сложность спасброска от заклинания игрока (spell save DC) жёстко зашита в spells.json как статичное число savingThrow.dc (только 13 / 14 / 15) и не зависит ни от класса, ни от характеристики, ни от уровня персонажа. Канон D&D 5e (PHB p.203-205) требует вычислять DC по формуле:

    spell save DC      = 8 + proficiency bonus + spellcasting ability modifier
spell attack bonus = proficiency bonus + spellcasting ability modifier

    где ability по классу: Wizard — INT; Cleric/Druid/Ranger — WIS; Bard/Paladin/Sorcerer/Warlock — CHA. Мультикласс — по источнику заклинания; NPC — своя DC из статблока.

    Текущая статичная DC даёт одинаковую сложность заклинания у волшебника 1-го и 20-го уровня, игнорирует ASI (росты INT/WIS/CHA) и делает прогрессию заклинателя бессмысленной для спасбросков. Это рассинхрон с уже реализованным каноном (spell slots, proficiency bonus, spellcastingAbility — всё есть в модели, но DC ими не пользуется).

    Факты (файл:строка)¶

    Где хранится и читается DC заклинания (статично)¶

    # Место Что
    1 spells/Spell.kt:57-60 data class SavingThrow(ability: String, dc: Int) — dc обязательное поле
    2 spells/Spell.kt:98-103 SpellEffect.Debuff(savingThrow: SavingThrow, ...) — вложенный DC у дебаффов
    3 spells/SpellRegistry.kt:60-66 парсинг effect.savingThrow.dc для debuff-эффекта
    4 spells/SpellRegistry.kt:81-87 парсинг верхнеуровневого savingThrow.dc (null если отсутствует)
    5 resources/spells.json фиксированные dc: только 13 / 14 / 15

    Статистика spells.json (90 заклинаний): - верхнеуровневый savingThrow не-null: 26 (14 — damage, 11 — debuff с дублем DC, 1 — sanctuary buff); - effect.savingThrow у debuff: 18 (все 18 debuff-заклинаний); - без спасброска вообще: 57; - уникальных заклинаний с ≥1 спасброском: 33 (= 26 верхн. + 7 только effect.savingThrow; не 44); - 44 = суммарное число объектов спасброска (26 верхн. + 18 effect), из них 11 дублей посчитаны дважды; - распределение dc по объектам: {13: 25, 14: 8, 15: 11} (включая 11 дублей). - Список 11 дублей (есть И верхнеуровневый, И effect.savingThrow): vicious-mockery, charm-person, command, entangle, faerie-fire, grease, hold-person, suggestion, web, hypnotic-pattern, slow.

    Где DC применяется в рантайме¶

    # Место Что
    6 rules/SavingThrowResolver.kt:22-53 resolvePlayerSave: total >= savingThrow.dc (:39)
    7 rules/SavingThrowResolver.kt:62-86 resolveEnemySave: total >= savingThrow.dc (:72)
    8 spells/SpellService.kt:153-154 damage-заклинание: resolveEnemySave(spell.savingThrow, target) → DC из справочника
    9 spells/SpellService.kt:228 debuff: resolveEnemySave(effect.savingThrow, target) → DC из справочника

    Вывод: DC нигде не вычисляется из кастера — это всегда статичное savingThrow.dc из spells.json, доставленное через объект SavingThrow.

    Поля, из которых DC можно вычислить (уже в модели)¶

    # Место Что
    10 classes/CharacterClass.kt:13 spellcastingAbility: String? — INTELLIGENCE / WISDOM / CHARISMA или null
    11 classes/CharacterClass.kt:20 casterType: String = "NONE" — FULL / HALF / PACT / NONE
    12 classes/ClassRegistry.kt:120 парсинг spellcastingAbility (uppercase) из classes.yml
    13 classes/ClassRegistry.kt:160-202 fallback-классы: wizard=INT, cleric=WIS, bard=CHA, druid=WIS, paladin=CHA, ranger=WIS, sorcerer=CHA, warlock=CHA; warrior/rogue/barbarian/monk=null
    14 rules/TurnResolver.kt:33-39 top-level fun proficiencyBonus(level: Int): Int = 2/3/4/5/6 (SRD)
    15 rules/SavingThrowResolver.kt:113 private proficiencyBonus(level) = 2 + (level-1)/4 (эквивалент SRD-таблице)
    16 rules/GameState.kt:124-152 Attributes + модификаторы intMod/wisMod/chaMod (:147,149,151)
    17 rules/GameState.kt:338-352 CharacterState.level (:342), attributes (:341)
    18 rules/GameState.kt:622-642 effectiveAttributes (атрибуты с бонусами предметов)

    Важно про два источника proficiency bonus: top-level TurnResolver.proficiencyBonus(level) (:33-39) и private SavingThrowResolver.proficiencyBonus(level) (:113) дают одинаковый результат (2/3/4/5/6), но продублированы в двух местах — см. развилку H.

    Текущая эвристика способности каста (свободный путь, regex)¶

    # Место Что

    Два пути резолва заклинаний (важно для границ ADR)¶

    # Место Что

    21 rules/TurnResolver.kt:1872-1946 resolveSpellOrSummon — свободный путь («spell»/«summon»): spellMod = ability + proficiencyBonus(level) (:1895), dc = detectDc(action, defaultDc=13) (:1893), бросок атаки d20 + spellMod >= dc

    Ключевые ограничения для вариантов¶

    1. Не путать с save-end DC состояний. ADR-0014 закрывает «спасбросок в конце хода снимает статус» (DC 12, TurnResolver.kt:42-43, SaveEndResolverTest.kt). Это другая DC — не затрагивается. Здесь — только DC заклинателя (8 + prof + ability).
    2. Pact Magic и mana — вне объёма (закрыты ADR-0016). ADR-0016 ещё не мигрирован в код (grep mana = 39 совпадений: GameState.kt:352-353, TurnResolver.kt:1881,1902 и др.), поэтому любые правки .kt здесь — только после подтверждения и не пересекаются с 0016.
    3. Spec-first (AGENTS): изменение контракта — только через api-specification/openapi.yaml.
    4. dc в spells.json — сейчас обязательное поле SavingThrow.dc (Spell.kt:59). Удаление поля ломает SpellRegistry.kt:63-66,83-86 и strict-Jackson (JsonConfig.kt).
    5. Два пути резолва (детерминированный SpellService + свободный resolveSpellOrSummon) — вычисляемый DC должен определиться, в каком из них применяется (вероятно, в детерминированном; свободный путь — см. E).

    Decision¶

    Решения по развилкам A–K (приняты архитектором):

    • A = A2 — derived-хелпер CastingStats.of(character), без кэша на CharacterState. Значения пересчитываются на лету → всегда актуальны; сериализация не трогается.
    • B = B1 + B4 — enum SpellcastingAbility { INT, WIS, CHA }; источник данных — CharacterClass.spellcastingAbility (classes.yml, парсинг в ClassRegistry.kt:120). Парсинг: INTELLIGENCE→INT, WISDOM→WIS, CHARISMA→CHA. SpellcastingAbility — только для кастера (не для SavingThrow.ability).
    • C = C2 — data class SpellcastingStats(spellSaveDc: Int, spellAttackBonus: Int).
    • D = D1 — удалить dc из SavingThrow: data class SavingThrow(ability: String). SavingThrow.ability — характеристика спасброска ЦЕЛИ (6 значений, String). НЕ перетипизировать в SpellcastingAbility. Введение enum Ability { STR, DEX, CON, INT, WIS, CHA } — territory ADR-0011, не в этом ADR.
    • E = E1 + E1a — ввести spellAttackBonus и атаку vs AC (канон PHB p.194). resolveSpellOrSummon (TurnResolver.kt:1893) переписывается: d20 + spellAttackBonus против target.ac (не против DC 13).
    • F = F2 — Enemy.spellSaveDc — ФАЗА 2 (Monsters), не сейчас.
    • G = G2 — мультикласс — отдельный ADR; сейчас берём canonicalClassId.
    • H = H2 — единый хелпер proficiencyBonus; оба потребителя (TurnResolver и SavingThrowResolver) делегируют ему.
    • I = I1 + I3 — I1: guard — кастер без spellcastingAbility не может наложить заклинание со спасброском (явный отказ). I3: legacy-fallback — dc переименовывается в fixedDc: Int?, топ-левел поле Spell (не внутри SavingThrow). Семантика: если у кастера нет spellcastingAbility, DC = fixedDc; иначе DC = 8 + PB + mod.
    • J = J1 — только DC кастера; save proficiency цели не трогаем.
    • K = K1 — ADR-0017 реализует контракт 0013 H2 → 0014 L1, не изменяет 0014: spellSaveDc кастера прокидывается как вход для DC наложения (через StateChange, 0013 H2), а 0014 L1 использует fallback DC из ConditionRegistry.

    Явные фиксации:

    • SavingThrow.ability — характеристика спасброска ЦЕЛИ (6 значений, String). НЕ SpellcastingAbility.
    • SpellcastingAbility — только для кастера (расчёт DC и spell attack).
    • fixedDc — топ-левел поле Spell (не внутри SavingThrow).
    • enum Ability { STR, DEX, CON, INT, WIS, CHA } — territory ADR-0011 (дубль #5), не 0017.
    • ADR-0017 реализует контракт 0013 H2 → 0014 L1, не изменяет 0014.
    • E1a — spell attack vs AC, не vs DC.
    • D1 — breaking change для SavingThrow.dc (Spell.kt, SpellRegistry, SpellModelTest, SpellRegistryTest).
    • H2 — консолидация дубля proficiencyBonus (0011-territory).

    Proposed Options¶

    A. Где вычислять spell save DC¶

    • A1 — кэшированное поле CharacterState.spellSaveDc (пересчитывается при level-up/ASI/смене класса).
    • + Один расчёт; прозрачно для UI/нарратива; сериализуется в ledgerJson.
    • − Новое поле в CharacterState (+strict-Jackson десериализация legacy-сессий); риск рассинхрона с атрибутами, если забыть пересчитать.
    • A2 — вычисляемый (derived) доступор/хелпер CastingStats.of(character) без хранения.
    • + Нет состояния для синхронизации; всегда актуально; не трогает сериализацию.
    • − Расчёт на каждый каст; дублирование формулы, если не сделать единый хелпер.
    • A3 — вычислять на месте каста в SpellService.castSpell (локально, без переиспользования).
    • + Минимум изменений поверхности.
    • − Логика размазана; spell attack (E) потом придётся вычислять заново.

    B. Источник spellcasting ability¶

    • B1 — CharacterClass.spellcastingAbility: String? (уже есть, CharacterClass.kt:13; значения по классам — ClassRegistry.kt:160-202).
    • + Каноничный источник; уже загружен из classes.yml; покрывает все 12 классов.
    • − null у не-кастеров (warrior/rogue/barbarian/monk) — нужен явный отказ/guard.
    • B2 — Map<classId, ability> (константа) в коде.
    • + Явно и детерминированно; не зависит от classes.yml.
    • − Дублирует источник правды; рассинхрон с classes.yml при правках.
    • B3 — regex-fallback detectCastingAttribute (как сейчас в свободном пути, TurnResolver.kt:3103).
    • + Ноль новых данных; работает без canonicalClassId.
    • − Неканонично (default INT для любого не-RU-паттерна); для детерминированного пути неприемлемо. НЕ РЕКОМЕНДУЕТСЯ для детерминированного каста.
    • B4 — enum SpellcastingAbility { INT, WIS, CHA } вместо String?.
    • + Типобезопасность; исключает опечатки.
    • − Миграция поля CharacterClass.spellcastingAbility + все места чтения (больше правок).

    C. Форма вычисленного результата¶

    • C1 — Int (только spellSaveDc).
    • + Минимально; покрывает этот ADR.
    • − Spell attack (E) потребует отдельного значения/расширения позже.
    • C2 — data class SpellcastingStats(spellSaveDc: Int, spellAttackBonus: Int).
    • + Сразу покрывает и DC, и атаку заклинанием; одна формула, два потребителя.
    • − Чуть шире объёма (spell attack ещё не в скоупе E).

    D. Судьба dc в spells.json¶

    • D1 — удалить dc из SavingThrow → SavingThrow(ability: String) (без dc); DC вычисляется. ability остаётся характеристикой спасброска ЦЕЛИ (6 значений, String), не перетипизируется.
    • + Один источник правды; исключает конфликт «статичный vs вычисляемый».
    • − Ломает SavingThrow(dc) (Spell.kt:59), парсер (SpellRegistry.kt:63-66,83-86), strict-Jackson; нужна правка модели + тестов (SpellRegistryTest:97, SpellModelTest:115-118).
    • D2 — dc остаётся, но игнорируется в рантайме (override вычисленным).
    • + Совместимость legacy-сессий/тестов; мягкий переход.
    • − Мёртвое поле в справочнике; риск случайного использования.
    • D3 — переименовать в fixedDc (fallback для legacy-миров без канона).
    • + Явная семантика «это fallback, не канон».
    • − Миграция JSON + парсера; не решает вопрос «когда fallback применяется» (см. I).

    E. Spell attack (бросок атаки заклинанием)¶

    • E1 — ввести сейчас (подварианты E1a/E1b).
    • E1a — атака сразу vs AC (канон PHB p.194): spellAttackBonus = proficiencyBonus + abilityMod; resolveSpellOrSummon (TurnResolver.kt:1893) переписывается на d20 + spellAttackBonus >= target.ac.
      • + Полный канон; убирает сломанный «атака vs DC».
      • − Меняет контракт resolveSpellOrSummon (vs DC 13 → vs AC); затрагивает тесты.
    • E1b — только spellAttackBonus, атака остаётся vs DC (текущий сломанный вариант).
      • + Меньше изменений поверхности.
      • − Сохраняет неканоничную атаку vs DC; непоследовательно с DC-решением.
    • E2 — отложить (сейчас только spell save DC; spell attack — отдельный ADR).
    • + Узкий скоуп; DC решается чисто.
    • − Временная асимметрия: DC вычисляемый, атака — нет (свободный путь живёт как есть).

    F. NPC / враги¶

    • F1 — Enemy.spellSaveDc (собственная DC из статблока/каталога).
    • + Канон (у монстров своя DC, не по классам); симметрия с statusSaveBonus.
    • − Новое поле Enemy + источник данных (архетип creature_archetypes).
    • F2 — отложить в ФАЗУ 2 (Monsters) (пока NPC не кастуют заклинания со спасбросками).
    • + Не строим преждевременно; NPC-заклинания сейчас нет в скоупе.
    • − Если NPC закастует — снова статичный DC.

    G. Мультикласс¶

    • G1 — учесть сейчас (ability по classLevels источнику заклинания).
    • + Канон для мультикласса.
    • − MulticlassService/classLevels ещё задел (GameState.kt:483, LevelUpService.kt:206); преждевременно до поддержки мультикласса.
    • G2 — отдельный ADR (сейчас один класс — берём canonicalClassId).
    • + Соответствует текущему состоянию модели (мультикласс не реализован).
    • − Позже потребуется ревизия источника ability.

    H. Источник proficiency bonus¶

    • H1 — единый top-level TurnResolver.proficiencyBonus(level) (:33-39).
    • + Уже public; одна точка правды.
    • − SavingThrowResolver использует свой private аналог (:113) — дублирование остаётся.
    • H2 — единый хелпер (общий Proficiency/LevelTableRegistry), оба потребителя.
    • + Устраняет дублирование 2 формул.
    • − Небольшой рефактор вне узкого скоупа DC.
    • H3 — из LevelTableRegistry (таблица level-table.yml).
    • + Единый data-driven источник (LevelTableEntry.proficiencyBonus).
    • − Зависимость от YAML; таблица может отличаться от hardcoded SRD.

    I. Fallback для legacy-заклинаний без вычисляемого источника¶

    • I1 — заклинания без класса/ability не кастуются со спасброском (guard → отказ).
    • + Нет скрытого fallback; честный отказ.
    • − Не-кастер с заклинанием (edge) получит отказ.
    • I2 — fallback-модификатор 0 (DC = 8 + prof + 0).
    • + Не ломает каст; детерминированно.
    • − Неканонично; заниженная DC.
    • I3 — fallback на текущий статичный dc из JSON (D3/D2).
    • + Обратная совместимость.
    • − Сохраняет статичный DC в обходном пути.

    J. Save proficiency vs spell save DC¶

    • J1 — только DC заклинателя (этот ADR); save proficiency не трогаем.
    • + Узкий скоуп; resolvePlayerSave (:31-35) уже работает корректно.
    • − (none) — фиксация границы.
    • J2 — расширить на «владение спасбросками».
    • − Вне объёма; save proficiency — отдельная тема (броски цели, а не DC кастера).

    K. Связь с ADR-0013 H2 → ADR-0014 L1¶

    • K1 — реализация контракта 0013 H2 → 0014 L1 (не изменяет 0014): spellSaveDc кастера становится входом для DC наложения — прокидывается через StateChange (0013 H2), а 0014 L1 берёт fallback DC из ConditionRegistry.
    • + Консистентность: DC наложения = DC кастера; реализует уже принятый контракт.
    • − Требует координации с реализацией 0013 H2 / 0014 L1 (ещё не в коде).
    • K2 — ADR-0014 остаётся с DC 12, связь не устанавливаем.
    • + Не трогаем закрытый ADR; минимальный риск.
    • − Расхождение «DC наложения vs DC заклинания» остаётся.

    Consequences¶

    Плюсы¶

    • Канон-DC (8 + proficiencyBonus + abilityMod) вместо статичных 13/14/15.
    • Прогрессия кастера работает: уровень/ASI реально влияют на сложность спасбросков.
    • Spell attack → vs AC (E1a): убирается сломанный «атака vs DC 13».
    • enum SpellcastingAbility (B4) — типобезопасность, исключает опечатки.
    • Единый proficiencyBonus (H2) — устраняется дубль формулы из 0011-territory.
    • Задел под мультикласс (G2): источник ability сведён к классу (canonicalClassId).

    Минусы¶

    • D1 — breaking change: SavingThrow.dc удаляется → Spell.kt:57-60, SpellRegistry.kt:60-66,81-87, SpellModelTest.kt:115-118, SpellRegistryTest.kt:97.
    • B4 — миграция String? → enum у CharacterClass.spellcastingAbility + все места чтения.
    • E1a — контракт resolveSpellOrSummon меняется (атака vs AC вместо vs DC 13).
    • A2 — вычисление на каждом касте (минимальная цена, без кэша).

    Риски и митигация¶

    • D1 — strict Jackson на legacy-сессиях с dc в JSON → митигация: I3 fixedDc: Int? (+ @JsonIgnoreProperties(ignoreUnknown=true) на CharacterState, если legacy-сессии хранят dc).
    • E1a — тесты SpellServiceTest могут ожидать «vs DC» → митигация: grep тестов перед правкой, отдельный коммит на контракт атаки.
    • H2 — рефактор с неочевидным эффектом → митигация: unit-тесты обеих формул (TurnResolver.proficiencyBonus и SavingThrowResolver.proficiencyBonus) должны давать одинаковый результат 2/3/4/5/6.

    Отложено¶

    • F2 — Enemy.spellSaveDc — ФАЗА 2 (Monsters).
    • G2 — мультикласс-casting — отдельный ADR.
    • enum Ability (6 значений) — territory ADR-0011 (дубль #5).
    • Upcast — ФАЗА 3 (ADR-0016 G2).

    Untouched in this ADR¶

    • Save-end DC состояний (ADR-0014) — DC 12, TurnResolver.kt:42-43, SaveEndResolverTest — не меняется.
    • Mana → spell slots (ADR-0016) — миграция кода не входит; правки .kt пересекающиеся с mana-ветками (TurnResolver.kt:1881,1902) — только после подтверждения и отдельно от 0017.
    • Pact Magic — PactSlots, PACT_SLOTS — не меняется.
    • Upcast — ФАЗА 3 (ADR-0016 G2), вне объёма.
    • Расы/фоны/фичи классов, подклассы — вне объёма.
    • Save proficiency (владение спасбросками цели) — работает (SavingThrowResolver.kt:31-35), не меняется.
    • enum Ability { STR, DEX, CON, INT, WIS, CHA } (6 значений) — territory ADR-0011 (дубль #5: attributeForSkill/detectAttribute/getAbilityScore/detectCastingAttribute) — не в этом ADR.
    • Spell attack для NPC/монстров — ФАЗА 2 (Monsters, F2).
    • Мультикласс-casting — отдельный ADR (G2).

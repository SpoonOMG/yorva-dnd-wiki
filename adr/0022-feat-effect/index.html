    ADR-0022: Эффекты черт (FeatEffect) — расширение FeatRegistry + prerequisites¶

    Status¶

    Accepted

    Context¶

    FeatRegistry существует и парсит feats.yml (41 черта), но механики почти нет: работает только Tough, две черты — флаги для LLM, остальные — инертные id в state.feats. Собранные факты (файл:строка):

    Черты сегодня¶

    # Файл:строка Что найдено
    1 resources/feats.yml:1-207 41 черта: 12 полных (alert, athlete, lucky, magic_initiate, healer, sharpshooter, war_caster, skilled, tavern_brawler, inspiring_leader, ritual_caster, tough) + 29 заглушек («для полноты 42», :62). Схема: id/name/description/prerequisite(строка|null)/repeatable. effects нет, category нет.
    2 resources/feats.yml (отсутствует vs PHB) Mobile («Мобильный»: +10 скорость, рывок по трудной местности, без OA после атаки) — нет в файле. Остальные 41/42 PHB на месте. Homebrew-черт нет.
    3 resources/feats.yml (prerequisites) Свободные строки: «CHA 13» (inspiring_leader :50), «INT или WIS 13» (ritual_caster :55 — or-логика уже в данных, факт для I1), «Способность творить заклинания» (war_caster :35), «Средняя/Тяжёлая/Лёгкая броня» (:116, :121, :151, :156), «Заклинание стихии» (:101), «Заговор с атакой» (:196), «STR 13» / «DEX 13» (:106, :81, :201). Формы нет.
    4 classes/FeatRegistry.kt:9-15, :27-48 Feat(id/name/description/prerequisite/repeatable); парсинг :36-45. Эффектов не парсит — факт для A2 («пересмотр + расширение», не «с нуля»).
    5 rules/GameState.kt:451-452 feats: List<String> — id выбранных черт. Типизации нет — факт для J1.
    6 Механика Tough (работает) LevelUpApplier.kt:33 (+2/уровень); LevelUpService.kt:225 (ретро 2*(nextLevel-1) при взятии); :280-282 (preview hpDeltaFor). Три точки — факт для F1 (типизация паттерна).
    7 Флаги для LLM (полуработают) SessionService.kt:802-803: hasFeatDefensiveDuelist / hasFeatShieldMaster — boolean в карте контекста реакций (:792-808), механики нет.
    8 Остальные 38 черт Инертны: только id в state.feats, ни одного чтения в движке (grep "lucky"\|"sharpshooter"\|"sentinel"… → 0 вне фактов #6–7).
    9 ASI-or-feat (частично) Ручной levelUp: asiChoice xor featId (LevelUpService.kt:108), feat-ветка :112-117 (exists/repeatable-проверки; prereq — «skip strict, just store», :114-115); pendingASI = 0 consumed (:245). Авто-каскад feat не умеет (gainXp: только ASI-стоп, факт #6 из 0025). allocateASI feat не принимает (AsiRequest — только allocations, SessionDtos.kt:108-110). Scope не сокращается.
    10 pendingFeat Отсутствует (grep → 0) — факт для G1.
    11 FeatActivatable / FeatActivator Существуют (ADR-0019 D1, адаптеры): черта как Activatable-view, эффект — трейс + narrative (прецедент факта #6 из 0023). Механики не дают — факт для C1/H1.
    12 Martial Adept × Battle Master Только текст: «2 приёма + 1d6 превосходства/отдых» (feats.yml:143-147). Связки с SUPERIORITY-пулом (ADR-0024) нет — факт для H1.

    Проблема¶

    Черты — текст без формы: эффекты не структурированы (факт #1), prerequisites — свободные строки без валидации (факты #3, #9), механика — три точки Tough (факт #6) + два LLM-флага (факт #7) на 41 черту. Новая рабочая черта = новый if в движке. Нужны: структурированные effects + формализованный prerequisite + контракт ASI-or-feat — при живом реестре (расширение, не пересоздание).

    Прецеденты¶

    • ADR-0023 B1/D1/E2 — sealed ClassFeature, ClassTrigger (9 значений), пассивка = StateChange-шаблоны (образцы для C1/F1; триггер — общий, см. §C).
    • ADR-0020 B1 / ADR-0021 C1 — sealed RacialTrait / BackgroundFeature (паттерн форм един на проект — плюс 0022).
    • ADR-0018 D1 — ASI-or-feat; allocateASI + gainXp(0) (образец для G1b).
    • ADR-0025 F1 — серверная валидация → 400 (образец для E1).

    Канон D&D 5e (PHB гл.6 «Customization» — Feats)¶

    ~42 черты: prerequisites (ability 13+, proficiency, spellcasting, уровень); ASI-уровень: +2 ASI или черта; Grappler/Great Weapon Master/Lucky/ Martial Adept/Sentinel/Sharpshooter/Tough — сложные механики (триггеры, пулы, реакции). Multiclass prerequisites — обычно ability 13 (PHB гл.6, «or»-комбинации редки).

    Decision¶

    1. Место хранения (A2)¶

    Секция feats: в feats.yml (существует, факт #1) + FeatRegistry (расширяется, НЕ создаётся — факт #4). Симметрия 0020/0021/0023/0024/ 0025 — без второго источника. Расширение реестра: парсинг effects (структурированные, C1) + формализованный prerequisite (E1). Mobile добивается в данных (факт #2) — цикл 3.5.

    Заглушки (29 черт) — полные данные без механики (описания по PHB есть), форма Feat(effects=[]) принята. Добивка effects для 29 черт — отдельная задача (данные, не архитектура), отложена. Mobile добавлен (42-я черта).

    2. Форма Feat (B1)¶

    data class, НЕ sealed. Обоснование: черта = данные + список эффектов, а не одно поведение. Одна черта — 2–3 эффекта (Tough: +2 HP/level; Lucky: 3 luck points + reroll). Sealed-по-чертам = взрыв типов (41):

    data class Feat(
    val id: String,
    val name: String,
    val category: FeatCategory,       // D1
    val prerequisite: Prerequisite?,  // E1
    val repeatable: Boolean = false,
    val description: String,
    val effects: List<FeatEffect>,    // C1
)

    id: String, не FeatId enum — 42 черты (12 полных + 29 заглушек + Mobile), enum раздуется. repeatable — для будущих (Elemental Adept с разными стихиями). Отклонение от исходного скетча, зафиксировано после 3.5.

    3. Форма FeatEffect (C1)¶

    sealed interface FeatEffect (Passive/Active/Triggered) — симметрия RacialTrait / ClassFeature / BackgroundFeature:

    sealed interface FeatEffect
data class PassiveFeatEffect(/* StateChange-шаблоны, F1 */) : FeatEffect
data class ActiveFeatEffect(/* cost + activatableId */) : FeatEffect
data class TriggeredFeatEffect(/* trigger + condition + effect */) : FeatEffect

    Триггер — общий FeatureTrigger. Решение развилки: ClassTrigger (0023 D1, 9 значений) переименовывается/расширяется в общий FeatureTrigger в цикле 3.5; отдельный FeatTrigger НЕ вводим (общий пул Trigger/Cost — митигация риска трёх иерархий). Relentless Endurance (0020 H1b) и Sneak Attack (0023 §4) используют тот же enum — единый словарь триггеров.

    4. Категории (D1)¶

    FeatCategory — enum, фиксированные 5 значений (3.5):

    enum class FeatCategory {
    COMBAT,
    GENERAL,
    MAGIC_INITIATE,
    ELEMENTAL_ADEPT,
    RACIAL,
}

    RACIAL — резерв (0 черт в SRD), форма готова. Для UI-фильтрации/валидации, на механику не влияет. PHB строго не делит — категории наши (homebrew для usability). Миграция присвоила категорию каждой из 42 черт (данные, 3.5).

    5. Prerequisites (E1)¶

    Alternatives-модель: внешний список — OR, внутри Alternative — AND. Покрывает AND, OR и комбинации. Раньше §I1 запрещал OR — отменяется (см. §9). Факт #3 разведки («INT или WIS 13», feats.yml:55) покрыт явно: [{INT:13}] OR [{WIS:13}]:

    data class Prerequisite(
    val alternatives: List<Alternative>,
)
data class Alternative(
    val conditions: List<Condition>,
)
data class Condition(
    val kind: ConditionKind,
    val value: Any,
)
enum class ConditionKind {
    ABILITY_MIN, LEVEL, RACE, CLASS, SPELLCASTING, FEATURE,
}

    Примеры: «STR 13» → одна альтернатива с одним условием; «INT или WIS 13» → две альтернативы; «Spellcasting or Pact Magic» → две альтернативы (SPELLCASTING / FEATURE: Pact Magic).

    Валидация при выборе (прецедент F1 из 0025, 400) — отдельный FeatPrerequisiteValidator (не ClassChoiceResolver): prereq-форма своя, выборы и черты — разные домены; резолвер выборов не раздуваем. Сегодня проверки нет (факт #9: «skip strict») — E1 закрывает пробел.

    6. Пассивные эффекты (F1)¶

    PassiveFeatEffect = StateChange-шаблоны (симметрия E2 в 0023). Применяются при добавлении черты (level-up / ASI-выбор). Tough — типизация существующего паттерна (факт #6: три точки схлопываются в один шаблон «+2 HP/level + ретро»). LLM-флаги факта #7 мигрируют в TriggeredFeatEffect (реакции) в 3.5.

    7. ASI-or-feat (G1b)¶

    При выборе feat на ASI-уровне — G1b: pendingASI переиспользуется (feat — вариант ASI-выбора, не отдельная очередь). Отдельное pendingFeat НЕ вводим (факт #10 подтверждает отсутствие — так и остаётся). allocateASI(featId) → применить эффект черты + gainXp(0) (зеркало факта #9/ADR-0018 E1). AsiRequest сегодня featId не принимает (факт #9) — расширение DTO входит в 3.5. Три pending-очереди (ASI/choices/feat) не возникают — митигация риска путаницы.

    8. Overlap с ClassFeature (H1)¶

    Martial Adept → манёвры (факт #12): FeatEffect — самостоятельная форма, но ссылается на ClassChoice/Activatable через id. НЕ дублировать механики — общий пул (триггеры §C, AbilityCost из 0019). Черта даёт доступ к существующему пулу (манёвры Battle Master, кости SUPERIORITY), а не копирует его. Пересечений шире Martial Adept не найдено (racial/background — ноль).

    9. Сложные prerequisites (I1)¶

    AND и OR поддерживаются через alternatives-модель (E1). Сложные условия (feature-combo, spellcasting-or-pact) — форма покрывает, конкретные черты валидируются в 3.5. Multclass-prerequisites — через ту же модель (альтернативы по классам), без отдельной формы.

    10. Дубль feats (J1)¶

    CharacterState.feats (факт #5) vs FeatRegistry — новый дубль #10 (после #9 из 0021; O занят). Запись в ADR-0011 — отдельным циклом после реализации (аналогично 0020/0023/0024/0025 J1/H1). Правило ADR-0011: новый дубль — с пометкой Resolved in ADR-0022.

    11. Объём цикла (K1)¶

    Только ADR. Реализация (расширение FeatRegistry, FeatEffect, prerequisites-валидатор, Mobile-добивка, интеграция ASI-or-feat) — цикл 3.5.

    Proposed Options¶

    A. Место хранения. - A1: новый feat-effects.yml — второй источник при живом feats.yml. - A2: feats: + расширение FeatRegistry — рекомендация архитектора. Реестр жив (факт #4); симметрия 0020–0025. - A3: эффекты только в коде — 41 черта в when, правка = релиз.

    B. Форма Feat. - B1: data class + List<FeatEffect> — рекомендация архитектора. Мультиэффектные черты без взрыва типов. - B2: sealed-по-чертам (ToughFeat, LuckyFeat, …) — 41 тип. - B3: плоский Feat + kind-флаг — возврат к строковым ветвям.

    C. Форма эффекта + триггер. - C1: sealed FeatEffect (3 подтипа) + общий FeatureTrigger (расширение ClassTrigger) — рекомендация архитектора. Единый словарь триггеров на расы/классы/черты. - C2: sealed + отдельный FeatTrigger — два параллельных словаря, рассинхрон (ON_HIT здесь vs ON_HIT там). - C3: эффекты строками (как сегодня description) — механики нет вообще.

    D. Категории. - D1: enum FeatCategory (наши, для UI) — рекомендация архитектора. - D2: без категорий — UI-фильтрация строками. - D3: категории строго по PHB — PHB не делит, делить нечего.

    E. Prerequisites. - E1: Prerequisite data class + отдельный FeatPrerequisiteValidator — рекомендация архитектора. Закрывает «skip strict» (факт #9). - E2: валидация в ClassChoiceResolver — чужой домен, раздувание. - E3: оставить строки без валидации — пробел живёт дальше.

    F. Пассивные эффекты. - F1: StateChange-шаблоны при добавлении (Tough — типизация паттерна) — рекомендация архитектора. Симметрия 0023 E2. - F2: оставить три точки Tough + флаги — новые пассивки = новые if. - F3: пассивки кодом в LevelUpApplier построчно — хардкод-каталог (урок 0024).

    G. ASI-or-feat. - G1a: отдельное pendingFeat — третья очередь, путаница. - G1b: pendingASI переиспользуется; allocateASI(featId) + gainXp(0) — рекомендация архитектора. Feat — вариант ASI. - G1c: feat только ручным levelUp (как сегодня, факт #9) — каскад и allocateASI feat не умеют навсегда.

    H. Overlap. - H1: ссылки по id на общий пул, без дублирования — рекомендация архитектора. Martial Adept → существующие манёвры/кости. - H2: копировать механику манёвров в feat-эффекты — дубль механики. - H3: запретить чертам ссылаться на классовые пулы — Martial Adept нереализуем.

    I. Сложные prerequisites. - I1: AND и OR через alternatives-модель (E1); конкретные черты валидируются в 3.5 — рекомендация архитектора. - I2: только AND, or — post-MVP — отклонено: «INT или WIS 13» уже в данных (факт #3), консервативный маппинг теряет канон. - I3: умолчать — реализатор угадывает («INT или WIS» уже в данных).

    J. Дубль. - J1: регистрировать (#10, Resolved in ADR-0022, запись после реализации) — рекомендация архитектора. - J2: не регистрировать — нарушение правила ADR-0011. - J3: резолвить записью сейчас — преждевременно, расширения нет.

    K. Объём. - K1: только ADR; реализация — 3.5 — рекомендация архитектора. - K2: ADR + парсинг effects без применения — данные без потребителя. - K3: полный цикл с реализацией — нарушает «один цикл = один фокусный шаг».

    Consequences¶

    Плюсы¶

    • 41 инертная черта получает формальную структуру (B1+C1+D1+E1).
    • Симметрия RacialTrait/ClassFeature/BackgroundFeature — единый паттерн форм на весь проект (четвёртая sealed-иерархия эффектов).
    • ASI-or-feat (ADR-0018 D1) получает чёткий контракт (G1b).
    • Tough (3 точки) и LLM-флаги типизируются (F1).
    • Общий FeatureTrigger устраняет дубли словарей (§C).

    Минусы¶

    • Расширение FeatRegistry (парсинг effects/prerequisite) — не создание, но breaking для схемы YAML.
    • 41 черта × эффекты + категории + формализованные prerequisites — миграция данных feats.yml (3.5).
    • Prerequisite-валидатор — новый слой (отдельный, не в резолвере выборов).
    • Часть черт (Lucky, Great Weapon Master) — сложные триггеры, могут потребовать новых StateChange.

    Риски¶

    • Миграция выявит неполноту данных (образец — backgrounds.yml, но здесь YAML уже парсится: риск ниже). Митигация: сверка 41/42 уже сделана (факт #2: не хватает только Mobile — добивка в 3.5).
    • Три похожие sealed-иерархии (Feat/Class/Racial). Митигация: H1 + §C — не дублировать механики, общий пул Trigger/Cost.
    • Lucky (3 очка + reroll) — уникальная механика, может потребовать отдельный StateChange. Митигация: если выйдет за B1 — в Отложено (3.5 или позже), форма это допускает (ActiveFeatEffect + новый StateChange-тип).
    • Prerequisites с «or» (факт #3: «INT или WIS 13»). Покрыто E1/I1: alternatives-модель; конкретные черты валидируются в 3.5.
    • Семантика pendingASI (:245): pendingASI = 0 consumed неоднозначно — декремент или полное обнуление. G1b (переиспользование pendingASI для feat) требует декремента. Если сейчас обнуление — баг вне scope 0022, всплывёт при интеграции feat-ветки (цикл 3.5). Митигация: верификация в 3.5; тест по образцу allocateASI.
    • Три pending-очереди (ASI/choices/feat) — риск путаницы. Митигация: G1b — feat как вариант ASI, очереди две, не три.

    Отложено¶

    • Реализация (расширение FeatRegistry, FeatEffect, валидатор, Mobile-добивка, ASI-or-feat интеграция) — цикл 3.5.
    • Сложные черты (Lucky, Great Weapon Master) — если выйдут за B1 — 3.5 или позже.
    • Multiclass prerequisites — через alternatives-модель (E1); конкретные условия — 3.5.
    • Feat retraining — post-MVP.
    • Frontend (wizard выбора черты) — ФАЗА 6.
    • Запись дубля #10 в ADR-0011 — после реализации (J1).

    Чек-лист решений A–K¶

    • A = A2 — feats: + расширение FeatRegistry (Mobile-добивка — 3.5).
    • B = B1 — data class Feat (НЕ sealed; category/prerequisite/effects).
    • C = C1 — sealed FeatEffect (3 подтипа) + общий FeatureTrigger (расширение ClassTrigger, не отдельный enum).
    • D = D1 — enum FeatCategory (наши, для UI).
    • E = E1 — alternatives-модель (Prerequisite/Alternative/Condition; внешний список OR, внутри AND) + отдельный FeatPrerequisiteValidator (закрывает «skip strict»).
    • F = F1 — пассивки = StateChange-шаблоны; Tough — типизация паттерна.
    • G = G1b — pendingASI переиспользуется; allocateASI(featId) + gainXp(0); pendingFeat не вводим.
    • H = H1 — ссылки по id на общий пул (Martial Adept → манёвры/кости).
    • I = I1 — AND и OR через alternatives-модель; конкретные черты — 3.5.
    • J = J1 — дубль #10 (Resolved in ADR-0022), запись после реализации.
    • K = K1 — только ADR; реализация — 3.5.

    Untouched in this ADR¶

    • Код (FeatRegistry.kt, feats.yml, LevelUpApplier.kt, LevelUpService.kt, SessionService.kt, SessionDtos.kt) — цикл 3.5.

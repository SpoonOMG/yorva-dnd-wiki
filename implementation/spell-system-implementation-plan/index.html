    1. Автономность: без запроса подтверждений от пользователя на каждом шаге
    2. Тестирование после фазы: после завершения каждой фазы — прогон тестов на эту фазу
    3. Финальная верификация:
    4. Фаза 8 → детерминированная симуляция (synthetic)
    5. Фаза 8 → живая симуляция с LLM
    6. Отчёт: подробный отчёт по проделанной работе и результатам симуляций
    7. Контроль контекста: после каждой фазы сверка с этим документом

    MVP-SCOPE (адаптация под нашу архитектуру)¶

    Упрощения относительно исходного брифа¶

    Аспект Исходный бриф MVP
    Типы эффектов 11 типов (damage/healing/buff/debuff/control/summon/utility/inspiration/transformation/protection/curse) 4 типа: damage, healing, buff, debuff
    Targeting Геометрия, AoE с координатами, дистанция SELF/SINGLE_ENEMY/MULTIPLE_ENEMIES(max N)/ALL_ENEMIES/SINGLE_ALLY
    Компоненты V/S/M Полная проверка + блокировка кастом при связывании Только флаги в JSON, material — метаданные
    Hot reload Динамическая догрузка custom_spells/ Загрузка resources/spells.json при старте
    Summon/Transformation Призыв NPC, морфинг модели Отложено
    Curse/Protection Сложные механики проклятий Отложено

    Ключевые архитектурные решения¶

    1. Нет сетки — TargetType без координат
    2. Концентрация — CharacterState.concentrationSpell: String? (только одно активное)
    3. Stat modifiers — CharacterState.activeModifiers: List<StatModifier>
    4. Раунды — CombatState.roundNumber: Int, персистится в SessionEntity.combatRoundNumber
    5. DamageType — StateChange.Damage(amount, source, damageType?), Enemy.resistances/immunities
    6. Интеграция с TurnResolver — префикс "cast " → делегация SpellService

    Файлы: - backend/app/src/main/kotlin/com/yorva/spells/Spell.kt - backend/app/src/main/kotlin/com/yorva/spells/SpellEffect.kt - backend/app/src/main/kotlin/com/yorva/spells/TargetType.kt - backend/app/src/main/kotlin/com/yorva/spells/Components.kt

    Структуры: 

    data class Spell(
    val id: String,
    val name: String,
    val level: Int,
    val school: String,
    val castingTime: ActionType, // ACTION, BONUS_ACTION, REACTION
    val range: Int, // футы
    val components: Components,
    val targets: TargetType,
    val savingThrow: SavingThrow?,
    val effect: SpellEffect,
    val description: String,
    val classes: List<String>
)

sealed class SpellEffect {
    data class Damage(
        val diceCount: Int,
        val diceType: String, // "d4", "d6", "d8"...
        val damageType: String, // "fire", "cold", "force"...
        val modifier: Int = 0,
        val perTarget: Boolean = true
    ) : SpellEffect()

    data class Healing(
        val diceCount: Int,
        val diceType: String,
        val modifier: Int = 0
    ) : SpellEffect()

    data class Buff(
        val statModifiers: List<StatModifier>,
        val durationRounds: Int,
        val concentration: Boolean = false
    ) : SpellEffect()

    data class Debuff(
        val condition: String, // "Отравлен", "Ослеплён"...
        val savingThrow: SavingThrow,
        val durationRounds: Int,
        val concentration: Boolean = false
    ) : SpellEffect()
}

data class StatModifier(
    val stat: String, // "attack_roll", "saving_throw", "ac"
    val value: Int,
    val durationRounds: Int,
    val source: String
)

enum class TargetType {
    SELF,
    SINGLE_ENEMY,
    MULTIPLE_ENEMIES, // + maxTargets
    ALL_ENEMIES,
    SINGLE_ALLY
}

data class Components(
    val verbal: Boolean,
    val somatic: Boolean,
    val material: String? // описание материального компонента
)

data class SavingThrow(
    val ability: String, // "dexterity", "wisdom"...
    val dc: Int
)

    Фаза 3: SpellService (4-6ч)¶

    Файлы: - backend/app/src/main/kotlin/com/yorva/spells/SpellService.kt

    Функции: 

    @Service
class SpellService(
    private val spellRegistry: SpellRegistry,
    private val dice: Dice
) {
    fun canCast(caster: CharacterState, spell: Spell): CanCastResult

    fun castSpell(
        spell: Spell,
        caster: CharacterState,
        targets: List<Enemy>,
        combatState: CombatState
    ): SpellCastResult

    private fun resolveSpellEffect(
        effect: SpellEffect,
        caster: CharacterState,
        target: Enemy,
        spell: Spell
    ): List<StateChange>
}

data class CanCastResult(
    val canCast: Boolean,
    val reason: String?
)

data class SpellCastResult(
    val spell: Spell,
    val stateChanges: List<StateChange>,
    val diceRolls: List<DiceRoll>,
    val description: String
)

    Логика: - canCast: проверка ячейки (caster.spellSlots[spell.level] > 0), castingTime vs ActionType - castSpell: списание ячейки, resolveSpellEffect для каждой цели - resolveSpellEffect: - Damage: броски урона, учёт resistances/immunities, StateChange.Damage - Healing: StateChange.Heal - Buff: StateChange.ApplyBuff - Debuff: спасбросок → StateChange.AddCondition или пропуск

    Тест: SpellServiceTest.kt — canCast, castSpell для каждого типа эффекта (Damage/Healing/Buff/Debuff).

    Фаза 5: TurnResolver интеграция (2-3ч)¶

    Файлы: - backend/app/src/main/kotlin/com/yorva/rules/TurnResolver.kt (модификация)

    Изменения: 1. Inject SpellService 2. resolve парсит префикс "cast " 3. Делегация spellService.castSpell 4. Учёт activeModifiers при бросках (attack, saving throw, checks) 5. nextTurn() → декремент durationRounds у модификаторов, удаление истёкших

    Логика: 

    if (action.startsWith("cast ")) {
    val spellId = action.removePrefix("cast ").trim()
    val spell = spellRegistry.getSpell(spellId) ?: throw IllegalStateException("Unknown spell")
    val canCastResult = spellService.canCast(char, spell)
    if (!canCastResult.canCast) {
        return Move(/* ... */, description = canCastResult.reason ?: "Заклинание недоступно")
    }
    val spellResult = spellService.castSpell(spell, char, listOf(enemy), combatState)
    return Move(/* ... */, stateChanges = spellResult.stateChanges, diceRolls = spellResult.diceRolls)
}

@RequestMapping("/api/sessions/{sessionId}/spells")
class SpellController(

    Аудит умений/заклинаний — Блок 2.5: Предыстории (backgrounds)¶

    Роль: технический аудитор. Только факты из кода. Формат — как в Блоках 1, 2.1–2.4. Если чего-то нет — «отсутствует». Пути и строки указаны.

    2.5.1. КАТАЛОГ ПРЕДЫСТОРИЙ¶

    2.5.1.1. Где хранится каталог¶

    backend/app/src/main/resources/backgrounds.yml (92 строки).

    2.5.1.2. Загрузчик¶

    Отсутствует. backgrounds.yml не читается ни одним классом:

    • grep BackgroundRegistry по kotlin — 0 совпадений (класс не существует).
    • grep backgrounds.yml по источнику — 0 совпадений (только сам файл в resources).
    • Из 8 YAML/JSON-загрузчиков (ClassRegistry.kt:19, SubclassRegistry.kt:27, LevelTableRegistry.kt:25, FeatRegistry.kt:27 — .yml; SpellRegistry.kt:19 — spells.json; ContextBuilder.kt:41; SettingReskinService.kt:38) ни один не читает backgrounds.yml.

    2.5.1.3. Структура файла¶

    YAML-корень backgrounds: (строка 1), далее 13 объектов. Каждый — 6 полей:

    backgrounds:
  acolyte:
    id: acolyte
    name: "Послушник"
    skills: [INSIGHT, RELIGION]      # имена навыков ВЕРХНИМ регистром, snake_case
    tools: []                          # список инструментов
    languages: 2                       # ЧИСЛО (не список) — количество изучаемых языков
    feature: "Приют верующих"          # строка-описание

    Поле id внутри каждого блока дублирует YAML-ключ.

    2.5.1.4. Сколько предысторий — 13.¶

    2.5.1.5. Список id¶

    acolyte, charlatan, criminal, entertainer, folk_hero, guild_artisan, hermit, noble, outlander, sage, sailor, soldier, urchin

    2.5.1.6. Fallback¶

    • Для каталога — отсутствует (файл не загружается).
    • Де-факто fallback — захардкоженный when в SessionService.getBackgroundProficiencies (SessionService.kt:69-84): для 12 известных id возвращает (skills, tools), для неизвестного — emptyList() to emptyList() (:83).

    2.5.2. МОДЕЛЬ ДАННЫХ¶

    2.5.2.1. data class Background¶

    Отсутствует. В com/yorva нет типа Background. Типов с этим именем не существует; grep по data class Background — 0 совпадений.

    2.5.2.2–2.5.2.4. Поля / feature / startingEquipment¶

    Отсутствуют как модель. Единственное поле, фиксирующее предысторию на персонаже: - com.yorva.rules.CharacterState.backgroundId: String? = null (GameState.kt:424-425, комментарий «детерминированный источник навыков/инструментов»).

    Поля feature и startingEquipment в модели отсутствуют.

    2.5.3. ПАРСИНГ¶

    2.5.3.1–2.5.3.2. Где парсятся / BackgroundRegistry¶

    Отсутствует. Загрузчика и реестра нет (см. 2.5.1.2).

    2.5.3.3. Как backgrounds.yml попадает в код¶

    Никак. Файл лежит в resources/, но ни один класс его не читает. Всё поведение идёт из захардкоженных литералов.

    2.5.3.4. Какие поля в YAML¶

    id, name, skills[], tools[], languages(int), feature — 6 полей (см. 2.5.1.3). Парсера для них нет.

    2.5.4. ВЫБОР ПРЕДЫСТОРИИ¶

    2.5.4.1–2.5.4.2. При создании — есть ли выбор / где обрабатывается¶

    Есть ввод, обработки фактической логики — захардкоженная функция. При создании сессии: - Поле входа: CreateSessionRequest.backgroundId: String? = null (SessionDtos.kt:31-33, аннотация @Size(max = 64)). - Прочтение+нормализация: SessionService.kt:358 — request.backgroundId?.trim()?.lowercase()?.takeIf { it.isNotBlank() }. - По id получаются навыки/инструменты: :359 — getBackgroundProficiencies(it). - Языки: :362-366. - Запись: :400 — backgroundId = bgId.

    2.5.4.3. Валидация¶

    • Нет валидации на существование. Если передать неизвестный id — getBackgroundProficiencies вернёт emptyList() to emptyList() (:83), языков не будет (when без else-ветки для него). Ошибки не бросается; персонаж просто не получит бонусы предыстории.
    • Единственные ограничения входа: @Size(max = 64) (SessionDtos.kt:32) и фильтр isNotBlank() (SessionService.kt:358).

    2.5.4.4. Что если не указан¶

    bgId = null → getBackgroundProficiencies не вызывается: (emptyList() to emptyList()) (:359), backgroundLanguages = emptyList() (:362-366 else). Персонаж без предыстории.

    2.5.5. ЭФФЕКТЫ¶

    2.5.5.1. Как Background влияет на CharacterState¶

    Одна точка — SessionService.create: - Навыки идут в proficiencies (:387-391, объединяются с классовыми через .union/.distinct()). - Инструменты идут в toolProficiencies (:400). - Языки идут в languages (:400). - backgroundId сохраняется (GameState.kt:425, запись :400).

    Никаких других эффектов (feature, equipment, бонусов) нет.

    2.5.5.2. Навыки — getBackgroundProficiencies целиком (SessionService.kt:69-84)¶

    internal fun getBackgroundProficiencies(backgroundId: String): Pair<List<String>, List<String>> = when (backgroundId.lowercase()) {
    "acolyte" -> listOf("insight", "religion") to emptyList()
    "charlatan" -> listOf("deception", "sleight_of_hand") to listOf("disguise_kit", "forgery_kit")
    "criminal" -> listOf("deception", "stealth") to listOf("playing_card_set", "thieves_tools")
    "entertainer" -> listOf("acrobatics", "performance") to listOf("disguise_kit", "musical_instrument")
    "folk_hero" -> listOf("animal_handling", "survival") to listOf("smith_tools", "land_vehicles")
    "guild_artisan" -> listOf("insight", "persuasion") to listOf("smith_tools")
    "hermit" -> listOf("medicine", "religion") to listOf("herbalism_kit")
    "noble" -> listOf("history", "persuasion") to listOf("playing_card_set")
    "outlander" -> listOf("athletics", "survival") to listOf("musical_instrument")
    "sage" -> listOf("arcana", "history") to emptyList()
    "sailor" -> listOf("athletics", "perception") to listOf("navigator_tools", "water_vehicles")
    "soldier" -> listOf("athletics", "intimidation") to listOf("playing_card_set", "land_vehicles")
    "urchin" -> listOf("sleight_of_hand", "stealth") to listOf("disguise_kit", "thieves_tools")
    else -> emptyList<String>() to emptyList()
}
    - Возвращает пару (навыки, инструменты). Возвращаемые имена в lowercase. - Используется ровно один раз — SessionService.kt:359 (вызовов всего 2: определение :69, вызов :359).

    2.5.5.3. Инструменты¶

    Вторая часть пары из 2.5.5.2 (правая колонка). Хардкод-строки инструментов: disguise_kit, forgery_kit, playing_card_set, thieves_tools, musical_instrument, smith_tools, land_vehicles, herbalism_kit, navigator_tools, water_vehicles. Попадают в CharacterState.toolProficiencies (:400).

    2.5.5.4. Языки — SessionService.kt:362-366 целиком¶

    val backgroundLanguages = when (bgId) {
    "acolyte", "sage" -> listOf("Common", "Elvish")
    "hermit", "guild_artisan", "noble", "outlander" -> listOf("Common", "Dwarvish")
    else -> emptyList()
}
    - Захардкожено: acolyte/sage → ["Common","Elvish"]; hermit/guild_artisan/noble/outlander → ["Common","Dwarvish"]; остальные → emptyList(). - Не использует languages из YAML (а там число: acolyte=2, sage=2, hermit=1, guild_artisan=1, noble=1, outlander=1 — см. 2.5.1.3). - Языки попадают в CharacterState.languages (:400).

    2.5.5.5. Feature¶

    Отсутствует. Поле feature в backgrounds.yml не парсится и не применяется никуда. В CharacterState нет поля фичи предыстории.

    2.5.5.6. Equipment¶

    Нет связи с предысторией. Единственная выдача стартового снаряжения — SessionService.grantStarterEquipment (SessionService.kt:1481-1506), она не зависит от backgroundId: - sword = "Стальной меч" (1d8, +2 damage) :1489-1494. - armor = "Кожаная броня" (ac +2) :1495-1499. - Условие: if (state.inventory.any { it.equipped }) return (:1488). - startingEquipment поля в YAML нет; в DTO нет.

    2.5.6. ЗАХАРДКОЖЕННАЯ ЛОГИКА¶

    2.5.6.1. getBackgroundProficiencies — список id¶

    12 id: acolyte, charlatan, criminal, entertainer, folk_hero, guild_artisan, hermit, noble, outlander, sage, sailor, soldier, urchin (13-я — отсутствует в when, попадает в else). Все 13 YAML-id покрыты, но 12 — явными ветками, urchin — тоже явной (:82). Фактически в when 13 явных веток, все id покрыты.

    2.5.6.2. Языки — какие background¶

    acolyte, sage, hermit, guild_artisan, noble, outlander (6 из 13). Остальные 7 — emptyList().

    2.5.6.3. Другие захардкоженные эффекты¶

    • Нет feature-эффектов, equipment-эффектов, бонусов, skill-choice. Влияние ограничено навыками + инструментами + языками.

    2.5.6.4. Сравни: YAML vs хардкод¶

    Расхождения: | Поле | YAML (backgrounds.yml) | Хардкод (SessionService.kt) | | :--- | :--- | :--- | | skills | ВЕРХНИЕ (INSIGHT, RELIGION) | lowercase (insight, religion) | | tools | guild_artisan: [artisan_tools] (:41) | guild_artisan: [smith_tools] (:75) — расходится | | languages | число (acolyte=2, sage=2, …) | список строк: acolyte/sage→Common+Elvish, 4→Common+Dwarvish | | feature | строка-описание (у всех 13) | не используется | | id | 13 | 13 (12+else) |

    guild_artisan в YAML даёт tools: [artisan_tools] (backgrounds.yml:41), в хардкоде — smith_tools (SessionService.kt:75). Единственное расхождение в данных (навыки/инструменты) между YAML и хардкодом.

    2.5.7. BACKGROUND FEATURE¶

    2.5.7.1. Тип поля feature в YAML¶

    Строка (имя фичи, например «Приют верующих» :8, «Ложная личность» :15). Описаний нет, только заголовок.

    2.5.7.2. Механическая реализация¶

    Отсутствует. feature не читается и не применяется (см. 2.5.5.5).

    2.5.7.3. Как обрабатывается в игре¶

    Никак. На LLM-контекст и в механику не передаётся. Единственное место, где предыстория фигурирует после создания — CharacterState.backgroundId (персист в participantsJson), но он нигде не читается в правилах (rules/GameState.kt:424-425 — только объявление; grep по rules/ на использование backgroundId — 0 совпадений, кроме объявления).

    2.5.8. REST API¶

    2.5.8.1. Endpoint¶

    Отдельного endpoint для предысторий нет. backgroundId передаётся как поле CreateSessionRequest в POST /api/v1/sessions (создание сессии).

    2.5.8.2. DTO¶

    • Вход: CreateSessionRequest.backgroundId: String? = null (SessionDtos.kt:31-33).
    • Хранение: CharacterState.backgroundId: String? = null (GameState.kt:425).
    • Отдельного DTO BackgroundDto/каталога нет.

    2.5.8.3. Endpoint выбора¶

    Нет. Нет GET /api/backgrounds, нет перечисления каталога, нет отдельного endpoint применения после создания. Выбор возможен только как поле тела POST /api/v1/sessions при создании.

    2.5.9. ВЗАИМОДЕЙСТВИЕ¶

    2.5.9.1. С расами (языки)¶

    Нет взаимодействия — рас отсутствуют. В коде raceId/raceLanguages/RaceRegistry/RacialTrait — 0 совпадений в main (единственный race в тексте — строка промпта арт-генератора NordRouterSceneImageGenerator.kt:185). Языки персонажа при создании — только из предыстории (SessionService.kt:362-366), расового вклада в языки нет.

    2.5.9.2. С классами (навыки)¶

    • profificiencies = (classProficiencies + bgSkills).distinct() (SessionService.kt:360), затем объединение с L1-выборами (:387-391).
    • Источник классовых навыков: ClassRegistry.getClass(...)?.proficiencies.skills (:354-356) либо fallback proficienciesForClass(...) (SessionService.kt:59-66, захардкожено по классу).
    • Конфликт дубликатов между классовыми и фоновыми навыками не разрешается выбором — просто .distinct() (:360).

    2.5.9.3. С чертами (prerequisite)¶

    Нет взаимодействия. Background не участвует ни в prerequisite, ни в выборе черт. FeatRegistry не ссылается на background; черты не используют backgroundId.

    2.5.10. ОТСУТСТВУЮЩИЕ¶

    2.5.10.1. SRD-канон (13)¶

    Файл содержит ровно 13 предысторий (см. 2.5.1.4), совпадает с количеством SRD-набора, но это независимо — загрузчика и сверки с каноном нет.

    2.5.10.2. Реализовано¶

    Через хардкод getBackgroundProficiencies — навыки и инструменты для всех 13 (12 явных веток + else), языки для 6 (в т.ч. только 2 набора: Common+Elvish / Common+Dwarvish).

    2.5.10.3. Отсутствуют¶

    • Загрузчик backgrounds.yml.
    • Модель Background / BackgroundRegistry.
    • Фичи предысторий (feature).
    • Стартовое снаряжение предысторий (startingEquipment).
    • Перечисление каталога через API.
    • Проверка существования id.
    • Валидация «выбрал 2/1 языков из SRD-набора» (в YAML языки — число, но выбора нет вообще).
    • Мультипредысторийная механика (skill-choice из фона).

    2.5.11. КАСТОМНЫЕ¶

    2.5.11.1. Поддержка¶

    Отсутствует. Нет механизма пользовательских предысторий.

    2.5.11.2. Создание¶

    Нет. Кастомную предысторию нельзя создать/добавить в рантайме.

    2.5.11.3. Builder¶

    Нет. CharacterState создаётся только в create (SessionService.kt:395-406), поля жёстко задаются; механизма builder/кастомизации предыстории нет.

    2.5.12. МУЛЬТИКЛАСС¶

    2.5.12.1. Влияние¶

    Нет. Предыстория применяется только один раз при создании персонажа (SessionService.create, :358-400). В level-up и мультиклассировании (LevelUpService) предыстория не участвует: grep backgroundId по LevelUpService.kt — 0 совпадений.

    2.5.12.2. Требования¶

    Нет. Предыстория не задаёт никаких требований и не влияет на требования мультикласса.

    Примечания по процессу / класс модели¶

    • Любая реализация BackgroundRegistry + переход с хардкода на YAML — архитектурный класс, [pro] (по AGENTS.md), переключение модели перед кодом обязательно.

    Аудит состояний — Блок 2.8: Состояния (conditions) (facts)¶

    Только факты из кода, без оценок. «Отсутствует» — если нет в коде. Паттерны: состояния хранятся как свободные строки List<String> в CharacterState/Enemy и statusDurations: Map<String, Int>. Системные наборы статусов — companion-константы GameState.kt. Справочный словарь (не загружается) — whitelist/action-whitelist-core.yaml. DSL-категория CONDITION — dsl-registry.yml. Заклинания — spells.json (effect.condition).

    2.8.1: РЕЕСТР СОСТОЯНИЙ¶

    2.8.1.1. Файл-каталог состояний — отсутствует. Нет conditions.yml, conditions.json или иного реестра/справочника состояний, который читал бы движок. Состояния — строковые литералы, разбросанные по Kotlin-коду (см. 2.8.1.6).

    2.8.1.2. Загрузчик — отсутствует. Нет ConditionRegistry, @PostConstruct load() для состояний, нет get(id)/getAll(). Единственное вхождение ключа conditions: — backend/app/src/main/resources/whitelist/action-whitelist-core.yaml:240-264, но загрузчик ActionWhitelist (com.yorva.dsl.ActionWhitelist.kt:22-81) читает только ключ root["action_whitelist"] (:27) и ключ conditions не обрабатывает. То есть этот список в движок не попадает и остаётся справочной документацией (комментарий «СЛОВАРЬ СОСТОЯНИЙ»).

    2.8.1.3. Модель/enum Condition — отсутствует. Нет enum class Condition, data class Condition, интерфейса или фабрики. Хранение состояний: | Где | Тип | Файл | |---|---|---| | CharacterState.statuses | List<String> (свободные строки) | rules/GameState.kt | | CharacterState.statusDurations | Map<String, Int> (раунды до снятия) | rules/GameState.kt | | Enemy.statuses | List<String> | rules/GameState.kt:643 | | NpcState/CombatState | statuses (:909 — isIncapacitated = "Недееспособен") | rules/GameState.kt | | exhaustion | Int 0..6, отдельное поле, не элемент statuses | rules/GameState.kt:363,484 |

    Операции над состояниями — через sealed StateChange (rules/GameState.kt): ApplyStatus(status: String, target, durationRounds), RemoveStatus(status, target), AddCondition(condition: String) (:1112), ApplyDebuff(condition: String, durationRounds: Int) (:1184), Stabilized (:1161).

    2.8.2: НАЛОЖЕНИЕ СОСТОЯНИЙ¶

    2.8.2.1. Каналы наложения — StateChange (rules/GameState.kt:1107-1211): | StateChange | Поля | Файл:строка | |---|---|---| | ApplyStatus | status: String, target: String, durationRounds: Int = 1 | GameState.kt:1110 | | RemoveStatus | status, target | GameState.kt:1111 | | AddCondition | condition: String (нет target, нет длительности) | GameState.kt:1112 | | ApplyDebuff | condition: String, durationRounds: Int (нет target) | GameState.kt:1184 | | ApplyBuff | modifier: StatModifier, requiresConcentration: Boolean | GameState.kt:1177-1182 | | Stabilized | — | GameState.kt:1161 |

    2.8.2.2. Применение в SessionService.applyStateChanges — SessionService.kt:1712-2190: - ApplyStatus (:1808-1815): добавляет строку в statuses, только если target == PLAYER и статуса ещё нет. Запись длительности в statusDurations[status] = durationRounds не гейтится по target (:1813-1815): при target == ENEMY строка в statuses не добавится, но длительность в карту игрока всё равно попадёт (загрязнение statusDurations). При durationRounds <= 0 длительность не пишется (трактуется как «бесконечный / до long rest»). - RemoveStatus (:1817-1819): statuses.remove только при target == PLAYER. - AddCondition (:2031-2033): if (condition !in statuses) statuses.add(condition) — всегда игроку, target отсутствует, длительность не пишется. - ApplyDebuff (:2055-2057): if (condition !in statuses) statuses.add(condition) — всегда игроку; поле durationRounds не читается (не влияет ни на statuses, ни на statusDurations). - ApplyBuff (:2041-2053): добавляет modifier в activeModifiers; при requiresConcentration снимает предыдущую концентрацию (activeModifiers.removeAll { it.source == concentrationSpell }) и выставляет concentrationSpell = change.modifier.source. - CastSpell (:2034-2039): безусловно concentrationSpell = null (комментарий «MVP: заглушка»).

    2.8.2.3. Наложение на Enemy — через ApplyStatus/ApplyDebuff не работает (StateTarget.ENEMY в applyStateChanges не обрабатывается — :1809,1818; change.target проверяется только для PLAYER). Враг обновляется только прямыми enemy.copy(statuses = ...) в TurnResolver: - Врасплох — накладывается (:1128 — провал инициативы, :2261 — успешная Скрытность) и снимается (:594,1469,2287); - Ярость — enemy.copy(statuses + "Ярость", ac-2, damageBonus+2) (:2347); - статус от statusNameForFamily при стихийной атаке (:757).

    2.8.2.3.1. Дефект: боевые приёмы на врага теряются. trip/shove/overrun/tumble → ApplyStatus("Сбит с ног", StateTarget.ENEMY) (TurnResolver.kt:933), grapple → "Связан" (:934), dirty_trick → "Ослеплён" (:935), feint → "Испуган" (:936). В applyStateChanges эти StateChange не применяются ни к игроку (target != PLAYER), ни к врагу — эффект приёма фактически отсутствует (описание есть, статус не накладывается).

    2.8.2.4. Критическая находка — дебафф заклинания уходит игроку, а не врагу. SpellService.resolveDebuff (spells/SpellService.kt:214-238) резолвится для target: Enemy, но при провале спасброска создаёт: 

    stateChanges.add(StateChange.AddCondition(effect.condition))        // :230
stateChanges.add(StateChange.ApplyDebuff(effect.condition, effect.durationRounds)) // :231-234
    Оба варианта в SessionService применяются к CharacterState.statuses игрока (:2031-2033, :2055-2057), Enemy не изменяется. То есть cast <debuff> накладывает состояние на игрока, а не на цель.

    2.8.2.5. Стек/дубликаты. Повторное наложение того же статуса не создаёт второй элемент (if (... !in statuses)), но durationRounds перезаписывается. Для ApplyStatus перезапись происходит даже если статус уже был. Счётчиков стаков (stacks) нет — исключение exhaustion: Int.

    2.8.2.6. Валидация. Строка статуса нигде не проверяется по реестру/enum — принимается любая произвольная строка (см. 2.8.1.3).

    2.8.3: СНЯТИЕ СОСТОЯНИЙ¶

    2.8.3.1. Явное снятие — только StateChange.RemoveStatus (SessionService.kt:1817-1819) и statuses.remove(...) в обработчиках: - Heal (:1800-1805): при переходе hp 0 → >0 снимаются Без сознания и Стабилен, сбрасываются deathSaveSuccess/deathSaveFail. - DeathSaveSuccess (:1912-1921): при 3 успехах снимается Без сознания, добавляется Стабилен, hp = 1. - Stabilized (:1930-1937): то же + сброс счётчиков. - Long rest (TurnResolver.kt:1794-1795): RemoveStatus("Стабилен") и, если hp > 0, RemoveStatus("Без сознания"). - Уклонение (TurnResolver.kt:2366): RemoveStatus("Уклонение") в конце хода врага.

    2.8.3.2. Дефект: RemoveStatus не чистит statusDurations. В :1817-1819 удаляется только строка из statuses; запись в statusDurations остаётся и продолжает тикать до истечения.

    2.8.3.3. Автоснятие по длительности — tickDurations (см. 2.8.4).

    2.8.3.4. Снятие заклинанием — обработчика нет. REMOVE_CONDITION присутствует в dsl-registry.yml:120, но в ActionParser не разобран (см. 2.8.14).

    2.8.3.5. End-условия типа «спасбросок в конце хода» — resolveSaveEnds (см. 2.8.5).

    2.8.4: ДЛИТЕЛЬНОСТЬ И ТИК¶

    2.8.4.1. Хранилище — CharacterState.statusDurations: Map<String, Int> (GameState.kt:441, комментарий «когда значение <= 0, статус удаляется из statuses в tickDurations»). У Enemy поля statusDurations нет — вражеские статусы бессрочны.

    2.8.4.2. Тик — SessionService.tickDurations (:2188-2208), вызывается в :844 после applyStateChanges и до resolveSaveEnds: 

    val updatedDurations = state.statusDurations.mapValues { (_, v) -> v - 1 }
val expired = updatedDurations.filter { (_, v) -> v <= 0 }.keys
val remainingStatuses = state.statuses.filter { it !in expired }
    Заодно уменьшает activeModifiers.durationRounds и удаляет истёкшие модификаторы (:2189-2196).

    2.8.4.3. Единица тика — 1 ход игрока (вызов в конце resolve). Тик происходит даже если состояние наложено в этом же ходу с durationRounds = 1: ApplyStatus пишет 1, затем tickDurations уменьшает до 0 и снимает — статус живёт до конца текущего хода.

    2.8.4.4. Источники длительности: - ApplyStatus — durationRounds из StateChange (по умолчанию 1). - ApplyDebuff — durationRounds игнорируется (SessionService.kt:2055-2057). - AddCondition — длительность не задаётся вовсе. - spells.json — поле durationRounds у debuff-эффектов (SpellService.kt:233), но путь обрывается дефектом 2.8.2.4.

    2.8.4.5. «Бесконечные» статусы — те, у которых нет записи в statusDurations (durationRounds <= 0): тик их не удаляет. Снимаются только явно.

    2.8.5: SAVE-END¶

    2.8.5.1. Игрок — TurnResolver.resolveSaveEnds (TurnResolver.kt:49-82): - Отбор: status in statuses и status in statusDurations и status in SAVE_END_STATUSES. - Спасбросок Телосложения, DC 12 (параметр dc: Int = 12). - Бонус: effectiveAttributes.conMod + proficiencyBonus (уровневая заглушка: >=5 → 3, >=1 → 2, иначе 0). - d20 == 20 — автоуспех; d20 == 1 — автопровал; иначе total >= 12. - При успехе снимаются и statuses, и statusDurations. - Вызов — SessionService.kt:845-848 после tickDurations; броски уходят в mechanics.diceRolls/нарратив. - Статусы с длительностью, но без записи в statusDurations (бесконечные) спасбросок не проходят.

    2.8.5.2. Враг — TurnResolver.applyEnemyTurn (TurnResolver.kt:2291-2320): - Срабатывает в начале хода врага при enemy.isIncapacitated. - saveDc = 13 + profile.mechanics.dcOffset. - Бросок d20 + character.effectiveAttributes.conMod + enemy.statusSaveBonus (используется модификатор игрока, а не врага). - 20 — автоуспех, 1 — автопровал. - При успехе снимаются статусы из Enemy.INCAPACITATING_STATUSES, пересечённые с enemy.statuses. - statusSaveBonus задаётся архетипом (SavingThrowResolver.kt:68, TurnResolver.kt:1127).

    2.8.5.3. SAVE_END_STATUSES (GameState.kt:620): Парализован, Ошеломлён, Заморожен, Ослеплён, Испуган, Отравлен, Опутанный, Опутан.

    2.8.5.4. Отдельные спасброски по видам (SAVE_DEATH/POISON/FIRE/FEAR/CHARM) — маппятся в ActionType.CHECK (ActionParser.kt:517), специализированной логики снятия состояния нет (см. 2.8.14).

    2.8.6: ADVANTAGE / DISADVANTAGE ОТ СОСТОЯНИЙ¶

    2.8.6.2. Точки применения: атака по врагу — :592-593, :1467-1468; проверки навыков — :815-816, :908-909, :1194, :2001, :2110.

    2.8.6.3. Атака врага по игроку — :2352-2360: playerGrantsAdv = character.isIncapacitated; помеха врагу при Отравлен/Ошеломлён/Испуган у врага (:2353) или при Dodge (isDodge). Расхождение: у врага отсутствуют Связан/Опутанный/Ослеплён в наборе помехи атаки (:2353), хотя у игрока они есть (:1985).

    2.8.6.4. Правила SRD, отсутствующие: преимущество атакующих по Paralyzed/Unconscious реализовано через targetGrantsAdvantage; advantage на спасброски от состояний (напр. Restrained → disadvantage на DEX saves) не реализовано; авто-провал DEX/STR save у Paralyzed/Stunned/Unconscious — отсутствует; Blinded → disadvantage на проверки, зависящие от зрения — отдельно не выделено (входит в общий hasDisadvantageOnChecks).

    2.8.7: МОДЕЛЬ ВОЗМОЖНОСТЕЙ (canAct / canMove / canSpeak / canAttack / canPerceive)¶

    2.8.7.1. Геттеры CharacterState (GameState.kt:507-540): | Геттер | Формула | |---|---| | canAct | !isIncapacitated (:507); isIncapacitated = isUnconscious \|\| statuses.any { it in {"Ошеломлён","Парализован","Оглушён","Сон","Заморожен","Недееспособен"} } (:492) | | canMove | !isIncapacitated && statuses.none { it in NO_MOVE_STATUSES } (:511) | | canSpeak | !isIncapacitated && statuses.none { it in NO_SPEAK_STATUSES } (:515) | | canAttack | canAct && statuses.none { it in NO_ATTACK_STATUSES } (:519) | | canPerceive | !isIncapacitated && statuses.none { it in NO_PERCEPTION_STATUSES } (:523) | | blockedCapabilityReason | первая причина из INCAPACITATING_STATUSES/NO_ATTACK/NO_MOVE (:530-540) |

    2.8.7.2. Геттеры Enemy (GameState.kt:666-672): isIncapacitated (по Enemy.INCAPACITATING_STATUSES), isProne, isRestrained. Модели canMove/canSpeak/canAttack/ canPerceive у врага нет — только isIncapacitated/isProne/isRestrained.

    2.8.7.3. Единственная точка блокировки действия игрока — TurnResolver.kt:184: if (!character.canAct || !character.canAttack) → no_roll с причиной. Проверка isUnconscious идёт раньше (:179) и уводит в death save. canMove/canSpeak/canPerceive в диспетчеризации действий не используются (нет отдельного гейта на движение/речь/восприятие).

    2.8.7.4. Наборы CharacterState (GameState.kt:605-620): INCAPACITATING_STATUSES, NO_MOVE_STATUSES, NO_SPEAK_STATUSES, NO_ATTACK_STATUSES, NO_PERCEPTION_STATUSES, SAVE_END_STATUSES (см. 2.8.1.4).

    2.8.8: SRD-СОСТОЯНИЯ: РЕЕСТР И СОПОСТАВЛЕНИЕ¶

    2.8.8.1. Канонические 15 состояний SRD 5e сопоставлены со строками кода — таблица в 2.8.1 («Соответствие 15 каноническим состояниям SRD 5e»).

    2.8.8.2. Полностью отсутствуют в движке: Invisible (нет статуса/геттера; есть только заклинание «Невидимость»), Petrified (только PETRIFIED/Окаменел в справочном whitelist-словаре).

    2.8.8.3. Частично реализованы: - Charmed — строки Очарован/Зачарован, только как дебафф заклинаний и NO_SPEAK; отдельного геттера/логики нет. - Grappled — строки Грапплинг/Захвачен/Удержан, только NO_MOVE без геттера. - Exhaustion — отдельное поле Int, не элемент statuses (см. 2.8.9). - Deafened — Оглушён/Глух, но Оглушён дополнительно в INCAPACITATING_STATUSES/SAVE_END.

    2.8.8.4. Маппинг English-код ↔ русская строка — отсутствует (см. 2.8.1.5).

    2.8.9: ИСТОЩЕНИЕ (exhaustion)¶

    2.8.9.1. Поле CharacterState.exhaustion: Int = 0 (GameState.kt:363) с инвариантом require(exhaustion in 0..6) (:484). Комментарий: «6 уровней = смерть» (:361).

    2.8.9.2. Снятие: только long rest exhaustionRemoved = minOf(1, exhaustion) — RestService.kt:90,97,107.

    2.8.9.3. Механические штрафы отсутствуют. Уровень истощения не влияет на броски, HP, скорость, преимущества/помехи — в TurnResolver нет чтений character.exhaustion (кроме long rest). Проверка смерти при exhaustion == 6 не реализована.

    2.8.9.4. Статус Истощён (русская строка) — отдельный флаг из statusNameForFamily (TurnResolver.kt:1152-1153, necrotic), не связан с полем exhaustion.

    2.8.10: НЕДЕЕСПОСОБНОСТЬ¶

    2.8.10.1. CharacterState.isIncapacitated (GameState.kt:492): isUnconscious || statuses.any { it in setOf("Ошеломлён","Парализован","Оглушён","Сон","Заморожен","Недееспособен") }.

    2.8.10.2. Enemy.isIncapacitated (GameState.kt:666) — по Enemy.INCAPACITATING_STATUSES (:675: Заморожен, Ошеломлён, Парализован, Оглушён, Сон; без Недееспособен). Наборы игрока и врага различаются.

    2.8.10.3. Блокировка. Игрок: TurnResolver.kt:184 (!canAct || !canAttack → no_roll). Враг: TurnResolver.kt:2293 — при enemy.isIncapacitated враг не атакует, проходит спасбросок (2.8.5.2).

    2.8.10.4. Unconscious — isUnconscious = hp == 0 && !isDead && deathSaveFail < 3 && "Стабилен" !in statuses (GameState.kt:489). При isUnconscious доступен только death save (TurnResolver.kt:179-180).

    2.8.11: ОЧАРОВАНИЕ / ИСПУГ¶

    2.8.11.1. Charmed. Строки Очарован/Зачарован приходят из spells.json (Очарован — 3 вхождения: :917,2161,2793) и участвуют только в NO_SPEAK_STATUSES (GameState.kt:611). Иммунитет к атаке от источника очарования, запрет атак по очарователю (SRD-механика Charmed), геттер/снятие по урону — отсутствуют.

    2.8.11.2. Frightened. Строка Испуган: - помеха проверкам — hasDisadvantageOnChecks (TurnResolver.kt:1979); - помеха атакам — hasDisadvantageOnAttacks (:1985); - помеха атакам врага — :2353; - SAVE_END (GameState.kt:620). Запрет приближаться к источнику страха и disadvantage атак, пока источник в поле зрения, не реализованы.

    2.8.11.3. Иммунитеты к очарованию/страху — только текстовые описания фич сабклассов (subclasses.yml:132,175,225,299, classes.yml:878,890), в коде не применяются.

    2.8.12: СМЕРТЬ, БЕЗ СОЗНАНИЯ И СТАБИЛИЗАЦИЯ¶

    2.8.12.1. Death saves — TurnResolver.resolveDeathSave (TurnResolver.kt:427-455): - d20 == 20 → Heal(1) + снятие Без сознания; - d20 == 1 → два DeathSaveFail; - >= 10 → DeathSaveSuccess; иначе DeathSaveFail. Автовызов при isUnconscious (:179-180) и по ActionType.DEATH_SAVE (:330).

    2.8.12.2. Обработка счётчиков — SessionService.kt:1912-1928: - 3 успеха → снять Без сознания, добавить Стабилен, hp = 1, сброс счётчиков (:1912-1921); - 3 провала → isDead = true (:1922-1927).

    2.8.12.3. Урон по бессознательному (SessionService.kt:1757-1775): - урон доводит hp до 0, добавляется Без сознания; - massiveDeath = change.amount >= state.maxHp → мгновенная смерть; - при повторном попадании по уже бессознательному — deathFail += 2 (автокрит), >= 3 → смерть. - profile.mechanics.permadeath — флаг постоянной смерти.

    2.8.12.4. Стабилизация — StateChange.Stabilized (SessionService.kt:1930-1937): снимает Без сознания, добавляет Стабилен, hp = 1, сбрасывает счётчики. Кто и когда эмитит Stabilized (кроме заклинаний/эндпоинта) — отдельной ветки в TurnResolver нет. При смерти permadeath=false восстановление идёт через checkpoint (RestoreCheckpoint, no-op в applyStateChanges).

    2.8.12.5. Восстановление из бессознательного лекарством — Heal при hp > 0 снимает Без сознания/Стабилен (SessionService.kt:1800-1805).

    2.8.12.6. Long rest — снятие Стабилен/Без сознания в TurnResolver.kt:1794-1795, восстановление HP через RestService.applyLongRest.

    2.8.13: ИММУНИТЕТЫ И КОНТРСПАСБРОСКИ¶

    2.8.13.1. Enemy.immunities: List<String> (GameState.kt:654-655) — иммунитеты только к типам урона (no damage): проверяются в SpellService.resolveDamage (SpellService.kt:163-168) и в уроне TurnResolver. Аналогично resistances.

    2.8.13.2. conditionImmunities / иммунитеты к состояниям — отсутствуют. Аналог statusSaveBonus (бонус к спасброску против статуса, TurnResolver.kt:1127, SavingThrowResolver.kt:68) — не иммунитет.

    2.8.13.3. Легендарные сопротивления — отсутствуют.

    2.8.13.4. Creed/тип существа (creatureType) — отсутствует; из-за этого нет иммунитетов по типу (напр. undead vs charm).

    2.8.13.5. Иммунитеты рас/классов — файлы рас отсутствуют; в YAML — только текст фич (см. 2.8.11.3).

    2.8.14: REST API / DSL / WHITELIST ПО СОСТОЯНИЯМ¶

    2.8.14.1. DSL-категория CONDITION — dsl-registry.yml:114-121, 7 команд: SAVE_DEATH, SAVE_POISON, SAVE_FIRE, SAVE_FEAR, SAVE_CHARM, REMOVE_CONDITION, APPLY_CONDITION.

    2.8.14.2. Разбор в ActionParser (ActionParser.kt:517): пять SAVE_* маппятся в ActionType.CHECK. REMOVE_CONDITION и APPLY_CONDITION не разобраны — попадают в else-ветку (ActionType.NO_ROLL, :523). Отдельных обработчиков/StateChange под них нет.

    2.8.14.3. Справочный словарь — whitelist/action-whitelist-core.yaml:240-264 (24 English-кода состояний) не загружается (ActionWhitelist читает только root["action_whitelist"], ActionWhitelist.kt:22-81). Проверок whitelist на конкретные состояния (кроме косвенных условий) нет.

    2.8.14.4. Контекст whitelist-условий — SessionService.kt:818-826: hasEnemy, enemy, hasSpellSlots, hasRangedWeapon, inCombat, hasSpell, isConcentrating, hasReaction. Ключей под состояния (isStunned, isProne, isGrappled, isRestrained, isBlinded, isCharmed, isFrightened) в контексте нет, хотя action-whitelist-core.yaml ссылается на isGrappled, isRestrained (:137), isRaging, hasCover, hasConcealment, hasAdvantage. В eval-парсере (ActionWhitelist.kt:263-328) неизвестная переменная даёт false; !var при отсутствии ключа тоже false (:282) — то есть условия с несуществующими ключами не выполняются.

    2.8.14.5. Капкан для DEFEND_DODGE/HIDE и т.п. Негативные условия (DISARM, GRAPPLE, MOVE_*) читают enemy.size, player.size, hasClimbSpeed, strength — часть из них в контексте отсутствует.

    2.8.14.6. REST-эндпоинты. В SessionController.kt (мапинги :21-192) и SpellController нет эндпоинтов управления состояниями/длительностями. Наружу отдаётся isConcentrating (SessionService.kt:817); statuses/statusDurations видны через characterState в TurnResponse. Отдельного API «наложить/снять состояние» нет.

    Аудит умений/заклинаний — Блок 2.6: Скиллы и проверки (facts)¶

    Только факты из кода, без оценок. «Отсутствует» — если нет в коде. Паттерны: SkillRegistry/SkillDef от skills.yml; проверки — skill_checks/action_templates таблицы (БД) + TurnResolver; whitelist — whitelist/action-whitelist-skills.yaml.

    2.6.1: КАТАЛОГ НАВЫКОВ¶

    2.6.1.1. skills.yml — backend/app/src/main/resources/skills.yml.

    2.6.1.2. Загрузчик — SkillRegistry (com.yorva.skills.SkillRegistry.kt:29-59): @Component, @PostConstruct fun load(), ResourceLoader.getResource("classpath:skills.yml"), snakeyaml Yaml(), ключ data["skills"] as? Map<String, Map<String, Any>>. Есть getAll() (:61), get(id) (:62).

    2.6.1.3. Структура — ключ skills:, далее по одному id на навык: 

    skills:
  athletics:
    id: athletics
    ability: STRENGTH
    level: 1
    classes: [warrior, barbarian, monk, paladin, ranger, rogue, bard]
    label: { fantasy: "Атлетика", dark_fantasy: "Выносливость", ... }
    description: "Бег, прыжки, лазание, плавание"

    2.6.1.4. Записей — 37 топ-уровневых id (skills.yml).

    2.6.1.5. Список id: athletics, acrobatics, sleight_of_hand, stealth, arcana, history, investigation, nature, religion, animal_handling, insight, medicine, perception, survival, deception, intimidation, performance, persuasion — 18 канонических; + second_wind, action_surge, sneak_attack, cunning_action, rage, bardic_inspiration, wild_shape, ki, divine_channel, lay_on_hands, hunters_mark, arcane_recovery, sorcery_points, pact_magic, power_strike, shield_bash, double_shot, help_action, ready_action — 19 активных классовых способностей.

    2.6.1.6. Fallback — SkillRegistry load(): при !res.exists() → logger.warn("skills.yml not found"); return (пустой реестр, без loadFallback, :38); при ошибке парсинга записи — logger.warn("Failed to parse skill $key") и пропуск (:55); при падении YAML — logger.error (:58).

    2.6.2: МОДЕЛЬ ДАННЫХ SkillDef¶

    2.6.2.1. SkillDef целиком (SkillRegistry.kt:9-16): 

    data class SkillDef(
    val id: String,
    val ability: String,
    val level: Int,
    val classes: List<String>,
    val labels: Map<String,String>, // genre -> displayName
    val description: String,
)

    2.6.2.2. Поля: id, ability (строка, напр. STRENGTH), level (Int), classes (List), labels (Map genre→label), description. Доп. DTO SkillDto (:18-27): id, name, ability, level, classes, description, displayName, flavor.

    2.6.2.3. Связь с 18 D&D-навыками — да, все 18 канонических присутствуют как id (см. 2.6.3.1).

    2.6.2.4. Активные способности (rage, second_wind) — да, в skills.yml (см. 2.6.1.5). Поле level задаёт уровень получения (L1/L2).

    2.6.3: 18 НАВЫКОВ D&D 5E¶

    2.6.3.1. Все 18 канонических навыков реализованы в skills.yml (id-ом и ability): | Навык | ability (skills.yml) | attribute (attributeForSkill) | |---|---|---| | athletics | STRENGTH | str | | acrobatics | DEXTERITY | dex | | sleight_of_hand | DEXTERITY | dex | | stealth | DEXTERITY | dex | | arcana | INTELLIGENCE | int | | history | INTELLIGENCE | int | | investigation | INTELLIGENCE | int | | nature | INTELLIGENCE | int | | religion | INTELLIGENCE | int | | animal_handling | WISDOM | wis | | insight | WISDOM | wis | | medicine | WISDOM | wis | | perception | WISDOM | wis | | survival | WISDOM | wis | | deception | CHARISMA | cha | | intimidation | CHARISMA | cha | | performance | CHARISMA | cha | | persuasion | CHARISMA | cha |

    2.6.3.2. Отсутствуют из канона SRD — ни одного: все 18 есть.

    2.6.3.3. Связь с abilities — два независимых пути: - SkillDef.ability (skills.yml) — декларативная строка (STRENGTH/DEXTERITY/INTELLIGENCE/WISDOM/CHARISMA). - TurnResolver.attributeForSkill(skill) (TurnResolver.kt:985-993) — жёсткий маппинг skill→str/dex/int/wis/cha для расчёта модификатора; else -> "dex". Констант-способности (CONSTITUTION) и SkillDef.ability здесь не используются.

    2.6.4: ФОРМУЛА ПРОВЕРКИ¶

    2.6.4.1. Где обрабатывается CHECK{skill} — маршрутизация в ActionParser (ActionParser.kt:346-349, 453-459): CHECK→ если catalog.findSkillCheck(lower)!=null → ActionType.CHECK_CATALOG, иначе CHECK. Собственно проверки: - resolveSkillCheck (skill_checks) — TurnResolver.kt (CHECK_CATALOG, вызов на :342). - resolveCheck (generic CHECK, хардкод) — TurnResolver.kt:1956 (см. 2.6.3, detectAttribute/detectDc). - resolveActionTemplate (action_templates) — :847 (CHECK). - resolveSocialCheck (social_checks) — :915 (SOCIAL_CHECK).

    2.6.4.2. Формула d20 + abilityMod + proficiencyBonus — реализована в resolveSkillCheck (:767-802): 

    val baseMod = when (sc.attribute) { "str"->strMod; "dex"->dexMod; "con"->conMod; "int"->intMod; "wis"->wisMod; "cha"->chaMod; else->dexMod }
val profBonus = skillProficiencyBonus(character, sc.skill)
val mod = baseMod + profBonus
val roll = ... // d20 / advantage / disadvantage
val total = roll + mod
val dc = (sc.dcMedium + profile.mechanics.dcOffset).coerceIn(5, 30)
val success = roll == 20 || (roll != 1 && total >= dc)
    Generic resolveCheck (:1965-...): mod из detectAttribute, total = applyModifiers(baseTotal, "ability_check", character), DC из detectDc. resolveActionTemplate (:851-884): attribute или attributeForSkill(template.skill), profBonus, crit/fumble.

    2.6.4.3. abilityMod — character.effectiveAttributes.{str,dex,con,int,wis,cha}Mod (в resolveSkillCheck/resolveActionTemplate); detectAttribute использует те же effectiveAttributes по regex-паттернам (Сила/Ловкость/Телосложение/Интеллект/Мудрость/Харизма).

    2.6.4.4. proficiencyBonus — fun proficiencyBonus(level: Int) (TurnResolver.kt:32-38): level≤4→2, ≤8→3, ≤12→4, ≤16→5, else→6. Применяется только если навык в character.proficiencies (через skillProficiencyBonus).

    2.6.4.5. expertise — да: skillProficiencyBonus (TurnResolver.kt:41-47): 

    if (!character.proficiencies.contains(skill)) return 0
val base = proficiencyBonus(character.level)
return if (character.expertiseSkills.contains(skill)) base * 2 else base
    expertiseSkills — поле CharacterState (GameState.kt:468), заполняется из l1Result.expertiseSkills (SessionService.kt:250,404).

    2.6.5: ADVANTAGE / DISADVANTAGE¶

    2.6.5.1/2.6.5.2. Механика: Dice.d20WithAdvantage()/d20WithDisadvantage() (TurnResolver.kt:11-20) — два d20, max/min. Применяется в: - resolveSkillCheck (:770-775): advantage = hasAdvantageOnSkill(character, sc.skill); disadvantage = hasDisadvantageOnChecks(character); advantage && !disadvantage → adv, disadvantage && !advantage → disadv, иначе d20. - resolveActionTemplate (:863-868) — аналогично. - resolveCheck (generic, :1965-1967) — только disadvantage (if (disadvantage) d20WithDisadvantage()). - resolveHazard (TurnResolver.kt:1145-1153): disadvantage + advantage = "Уклонение" in character.statuses && attributeCode=="dex".

    2.6.5.3. DSL/whitelist — механизм броска в resolve-функциях TurnResolver (не в DSL). Whitelist: CHECK_*/SOCIAL_* разрешают действие, а не бросок.

    2.6.5.4. Взаимодействие с состояниями — хардкод в хелперах TurnResolver.kt:1933-1940: - hasDisadvantageOnChecks: статусы {Отравлен, Ошеломлён, Испуган, Связан, Опутанный, Оглушён, Ослеплён}. - hasAdvantageOnSkill: skill=="stealth" && "Скрыт" in statuses. - hasDisadvantageOnAttacks (:1937): {Отравлен, Ошеломлён, Испуган, Связан, Опутанный, Ослеплён, Сбит с ног} + isProne. - targetGrantsAdvantage (:1940): статусы цели {Связан, Опутанный, Без сознания, Парализован, Ошеломлён, Сон, Заморожен, Ослеплён, Сбит с ног} + incapacitated/prone.

    2.6.6: DC ПРОВЕРОК¶

    2.6.6.1/2.6.6.2. Три источника: - skill_checks (БД): колонки dc_easy=10, dc_medium=15, dc_hard=20 (0015-action-catalog.yaml:172-174). В resolveSkillCheck DC берётся из sc.dcMedium (колонка dc_medium), далее + profile.mechanics.dcOffset (:778). DC задан в БД (миграции), не LLM. - action_templates (БД): template.dcMedium ?: 15 (:882), + dcOffset. - generic CHECK (detectDc, TurnResolver.kt:2664-2669): HARD_PATTERN→20, MEDIUM_PATTERN→15, else defaultDc=10; (base + dcOffset).coerceIn(5,30). - social_checks / hazards: sc.dcMedium + dcOffset; hazard.saveDc ?: 12 (:1150).

    2.6.6.3. Таблица DC (5/10/15/20/25/30) — отсутствует как единая таблица. Есть только колонки dc_easy=10/dc_medium=15/dc_hard=20 + жёсткие ветки HARD_PATTERN→20, MEDIUM_PATTERN→15 в detectDc. Делений 5/10/15/20/25/30 в коде нет.

    2.6.6.4. Кто решает DC — движок + БД. LLM не задаёт DC; DC берётся из таблиц skill_checks/action_templates (колонки dc_*) и хардкод-веток detectDc; DC ограничен .coerceIn(5,30) и сдвигается profile.mechanics.dcOffset.

    2.6.7: ПАССИВНЫЕ ПРОВЕРКИ¶

    2.6.7.1. Passive Perception — отсутствует. Поиск по коду passive находит только FeatureActionType.PASSIVE (классовые фичи, ClassFeatureHelper.kt, GameState.kt:1195), не пассивную проверку навыка.

    2.6.7.2. Формула 10 + WIS mod + PB — отсутствует.

    2.6.7.3. Где применяется — отсутствует.

    2.6.7.4. Другие пассивные — отсутствуют.

    2.6.8: ПРОТИВОПОСТАВЛЕННЫЕ ПРОВЕРКИ¶

    2.6.8.1/2.6.8.2. Contested checks (Stealth vs Perception) — отсутствует. Скрытность (resolveSkillCheck stealth :448-495) — одиночный бросок против dc (фикс. DC), нет сравнения двух проверок/целей.

    2.6.8.3. Grapple vs Athletics/Acrobatics — отсутствует как противопоставление. grapple есть в resolveActionTemplate (:870: при успехе ApplyStatus("Связан", ENEMY)), но это одиночная проверка dc = template.dcMedium, не contested.

    2.6.8.4. Как обрабатывается — противопоставленные проверки не реализованы; все проверки — одиночные против фикс. DC.

    2.6.9: ГРУППОВЫЕ ПРОВЕРКИ¶

    2.6.9.1/2.6.9.2/2.6.9.3. Group checks — отсутствует. Поиск group/группов в контексте проверок не находит реализации. Все проверки — индивидуальные (один character).

    2.6.10: SKILLS В CharacterState¶

    2.6.10.1. Три поля CharacterState (GameState.kt): - skills: List<String> (:336) — список навыков персонажа. - proficiencies: List<String> (:338) — коды навыков и спасбросков (STR/DEX/...); дают бонус мастерства. - expertiseSkills: List<String> (:468) — навыки с экспертизой (удвоенный PB).

    2.6.10.2 Проficient vs non = наличие в proficiencies: skillProficiencyBonus возвращает 0, если not in proficiencies (TurnResolver.kt:42).

    2.6.10.3. Expertise — да, expertiseSkills (см. 2.6.4.5).

    2.6.10.4. Связь с class/background/race — формируется при создании (SessionService.kt): :360 val proficiencies = (classProficiencies + bgSkills.map{it.lowercase()}).distinct(), :397 proficiencies = finalProficiencies, :404 expertiseSkills = l1Result.expertiseSkills. skills (:336) декларативное поле. Связь с расой — расы отсутствуют (Блок 2.3).

    2.6.11: REST API¶

    2.6.11.1. Endpoint навыков — SkillController (com.yorva.skills.SkillController.kt): - GET /api/skills (@GetMapping, :11-25) — List<SkillDto>, параметр setting (reskin). - GET /api/skills/{id} (:27-35) — SkillDto или 404 (ResponseStatusException(NOT_FOUND)).

    2.6.11.2. DTO — SkillDto (SkillRegistry.kt:18-27): id, name, ability, level, classes, description, displayName, flavor. Рескин через SettingReskinService.reskin(def.id, "skill", name, setting).

    2.6.11.3. Endpoint проверок — отсутствует отдельный endpoint для выполнения проверок (нет /checks); проверки исполняются внутри хода через ActionType.CHECK/CHECK_CATALOG/SOCIAL_CHECK.

    2.6.12: ПРОВЕРКИ В WHITELIST/DSL¶

    2.6.12.1. CHECK → whitelist — ActionWhitelist.resolveConcreteId (ActionWhitelist.kt:115-122): "CHECK" -> "CHECK_${skill.uppercase()}" (skill = param ?: inferCheckSkill(lower)). canExecute (:103-112): 25 шаблонных TEMPLATE_IDS допускаются всегда; конкретные — по whitelist.

    2.6.12.2. CHECK_ / SOCIAL_ в whitelist (whitelist/action-whitelist-skills.yaml): - CHECK_ в ALWAYS (строки 12-25): ACROBATICS, ATHLETICS, PERCEPTION, STEALTH, INVESTIGATION, INSIGHT, HISTORY, ARCANA, NATURE, RELIGION, MEDICINE, SURVIVAL, ANIMAL_HANDLING, PERFORMANCE. - CHECK_ в CONDITIONAL (28-77): PERSUASION, DECEPTION, INTIMIDATION, SLEIGHT_OF_HAND, PICKPOCKET, LOCKPICK, DISARM_TRAP, FORGERY, DISGUISE, POISONER, HERBALISM, NAVIGATION, TRACKING, FORAGING + условия (напр. CHECK_LOCKPICK: "lock == null || !hasThievesTools"). - SOCIAL_* (core 459-470; skills 83-121): TALK, ASK, ANSWER, LISTEN, OBSERVE, GREET, FAREWELL, THANK, PERSUADE, DECEIVE, INTIMIDATE, COMMAND, INTIMIDATE_GROUP, TRADE, NEGOTIATE, BRIBE, SEDUCE, INSPIRE, REWARD.

    2.6.12.3. Валидация CHECK — canExecute (:103-112): NO_ROLL→true; NEVER/neverConditional→блок; ALWAYS→true; conditional→evalCondition; иначе true только если in TEMPLATE_IDS. CHECK_* конкретика резолвится через resolveConcreteId, и если её нет в whitelist и не в 25 шаблонах → false (блок). SOCIAL→приоритет SOCIAL_ над CHECK_${skill} если известен (:125-127).

    РЕШЕНИЯ¶

    2.5.A · Создать BackgroundRegistry по паттерну ClassRegistry — ✅ РЕШЕНО¶

    - Копия-схема ClassRegistry (com.yorva.classes.ClassRegistry.kt:14-49): @Component, ResourceLoader, @PostConstruct, org.yaml.snakeyaml.Yaml, resourceLoader.getResource("classpath:backgrounds.yml"), корневой ключ backgrounds (в YAML это Map<String, Map<String, Any>>, а не List — см. 2.5.1.3). - Методы: get(id): Background?, getAll(): List<Background>. - Новый файл com.yorva.classes.BackgroundRegistry + в него же — data class Background (см. 2.5.B).

    2.5.B · Модель Background — ✅ РЕШЕНО¶

    data class Background в com/yorva/classes/CharacterClass.kt-рядом (новый файл Background.kt в com.yorva.classes), зеркалит CharacterClass/StartingItem/ClassFeature. Поля:

    data class Background(
    val id: String,
    val name: String,
    val description: String,                 // опционально; в YAML нет — пусто/заглушка
    val skills: List<String>,                // lowercase, фикс. 2 навыка (SRD)
    val tools: List<String>,                 // lowercase
    val languageChoices: Int,                // = числа из YAML `languages` (acolyte=2, hermit=1, ...)
    val languageOptions: List<String> = defaultLanguages(),  // пул доступных языков для выбора
    val feature: BackgroundFeature? = null,  // см. 2.5.G
    val startingEquipment: List<StartingItem> = emptyList(), // переиспользуем StartingItem (CharacterClass.kt:32)
)
    • languageOptions по умолчанию = SRD-набор языков (Common, Dwarvish, Elvish, Giant, Gnomish, Goblin, Halfling, Orc, Abyssal, Celestial, Draconic, Deep Speech, Infernal, Primordial, Sylvan, Undercommon).
    • defaultLanguages() — детерминированный SRD-констант.

    2.5.C · BackgroundRegistry — ✅ РЕШЕНО¶

    См. 2.5.A. Методов getForSetting() не добавляем (reskin — сквозь SettingReskinService, как ClassController). Fallback — см. 2.5.M.

    2.5.D · Валидация backgroundId — ✅ РЕШЕНО (отклоняющий вариант)¶

    • В SessionService.create заменить прямую getBackgroundProficiencies на обращение к реестру (см. 2.5.E).
    • Если bgId != null и backgroundRegistry.get(bgId) == null → throw NoSuchElementException("Background $bgId not found") ( паттерн — ClassController.kt:25, SessionService.kt:496,628).
    • Т.е. ошибка + сообщение, НЕ тихий fallback на пусто. Это поведенчески меняется с текущего «молча без бонусов».

    2.5.E · Убрать хардкод, читать из BackgroundRegistry — ✅ РЕШЕНО¶

    • Удалить getBackgroundProficiencies (SessionService.kt:69-84).
    • В create: val bg = backgroundRegistry?.get(bgId); bgSkills = bg?.skills; bgTools = bg?.tools.
    • Единственная точка истины — backgrounds.yml. Это закрывает и 2.5.N.

    2.5.F · Языки — канон: N языков на выбор — ✅ РЕШЕНО (вариант B из рекомендации)¶

    • Решение: вариант B — languageChoices: Int (число из YAML languages, уже есть) + languageOptions: List<String> (SRD-пул).

    • Механика выбора: в CreateSessionRequest добавить languageChoices: List<String>? (как skillsKnown/l1Choices).¶

      В create: val finalLanguages = if (bg == null) emptyList() else (request.languageChoices ?: pickDefaultLanguages(bg)); валидировать size == bg.languageChoices и all { it in bg.languageOptions }.
    • Заменить хардкод SessionService.kt:362-366 на выбор из пула. Common в SRD даётся всегда, но включать его в выбор — по канону (Common+выбранные).
    • Зависимость: это уже-есть в CreateSessionRequest? — нет, добавить поле.
    • Примечание: текущий дефолт Common+Elvish/Common+Dwarvish противоречит YAML (acolyte/sage=2, но hermit/noble=1, а код даёт обоим по 2) — расхождение закрывается автоматически.

    2.5.G · Background feature — ✅ РЕШЕНО (sealed, дескриптивный статус-эффект)¶

    • sealed class BackgroundFeature, по образцу RacialTraitEffect (блок 2.3).
    • Дескриптивная реализация (нет системного «приюта в храме»): фича хранится как строковый идентификатор + подсказка для LLM-нарратива, а не как числовая механика.
    sealed class BackgroundFeature(val id: String, val name: String, val description: String) {
    object ShelterOfTheFaithful : BackgroundFeature("shelter", "Приют верующих", "Кров и еда в храмах своей веры.")
    object PositionOfPrivilege :
        BackgroundFeature("privilege", "Привилегия положения", "Благородное имя открывает двери.")
    class Custom(val title: String, val text: String) : BackgroundFeature("custom_$title", title, text)
}
    • В data class Background.feature → сериализуется id; в CharacterState добавить поле backgroundFeatureId: String? (для 2.5.O — нарратив/контекст).
    • YAML feature: "Приют верующих" → маппинг feature-строки на один из объектов (или Custom).

    2.5.H · Стартовое снаряжение от background — ✅ РЕШЕНО (через YAML)¶

    • Добавить в YAML startingEquipment (список {id, quantity}, как ClassRegistry/StartingItem).
    • В data class Background.startingEquipment: List<StartingItem>.
    • В SessionService.grantStarterEquipment (SessionService.kt:1481-1506) применить background.startingEquipment, объединив с текущим фикс. sword+leather — ИЛИ заменить фикс. набор класс-аналогично. (Классовое снаряжение уже в YAML ClassRegistry.kt:63; текущий sword+leather не зависит от bg :1488.)
    • Решение по «заменить или дополнить»: дополнить — фикс. меч+броня это базовый класс, bg-снаряжение добавляется поверх.

    2.5.J · REST API — ✅ РЕШЕНО (по паттерну ClassController)¶

    • BackgroundController (паттерн ClassController.kt:6-29):
      • GET /api/backgrounds → List<Background>, опц. setting для reskin имени.
      • GET /api/backgrounds/{id} → Background или throw NoSuchElementException (:25).
    • reskin через SettingReskinService.reskin(id, "background", ...).

    2.5.K · DTO — ✅ РЕШЕНО¶

    • Финальный вариант: сериализовать Background напрямую (как это делает ClassController — List<CharacterClass> без отдельного dto, :14). Отдельный BackgroundDto не нужен, если модель публичная и flat.
    • Если хотим скрыть внутреннее (languageOptions) — тогда flat-DTO. Рекомендация: без DTO, Background уже flat (см. 2.5.B).

    2.5.L · Взаимодействие с расами — ✅ РЕШЕНО (закрывается 2.3)¶

    • Языки персонажа при создании = bg-language-выбор + (в будущем) расовые языки.
    • При создании backgroundLanguages сейчас — единственный источник (см. 2.5.5.4). Когда появятся расы (блок 2.3), объединять .distinct().
    • Дедуп: (bgLanguages + racialLanguages).distinct().

    2.5.M · Fallback — ✅ РЕШЕНО (по паттерну ClassRegistry:21)¶

    • В BackgroundRegistry.load(): если backgrounds.yml не найден / нет ключа / пуст → loadFallback() с хардкод-списком 13 предысторий (зеркало хардкода 2.5.6). Точный паттерн ClassRegistry.kt:19-49.

    2.5.N · guild_artisan tools — ✅ РЕШЕНО (YAML — канон)¶

    • Каноничное значение — YAML [artisan_tools] (backgrounds.yml:41), это «любой набор ремесленных инструментов» (SRD).
    • Так как точка истины станет YAML (2.5.E), расхождение исчезает само. Если нужен выбор конкретного — отдельный toolsChoices: Int + опции (по аналогии с 2.5.F). Рекомендация: оставить [artisan_tools] как фикс, выбор — вне текущего скоупа.

    2.5.O · backgroundId — ✅ РЕШЕНО (читаем в контексте)¶

    • Оставить CharacterState.backgroundId (GameState.kt:425) как персист.
    • Начать читать: добавить backgroundFeatureId (см. 2.5.G) и включить предысторию (+её feature-подсказку) в LLM-контекст сборщика (llm/ContextBuilder) и в getCharacterState/toSummary.
    • Использовать в prerequisite черт (блок 2.4) и в нарративе — как источник ролевой подсказки, не механики.

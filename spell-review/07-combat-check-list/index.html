    Аудит — Блок 2.7: Боевая система (чеклист решений)¶

    Фактура — 07-combat-facts.md; сверка 46 дыр (24 из ревью 1 + 22 из ревью 2) — 07-combat-holes-response.md. Канон: D&D 5e SRD. Паттерны: *Registry (YAML/JSON), sealed-эффекты (SpellEffect, FeatEffect), CharacterState/Enemy, TurnResolver.resolveXxx, StateChange, ActionIntent/ActionWhitelist.

    Фактические поправки (применены к решениям): 1. CharacterState не имеет charClass — есть canonicalClassId + classLevels (мультикласс). 2. CharacterState.resistances/immunities/vulnerabilities отсутствуют (GameState:653,655 — поля Enemy) → новые поля игрока. 3. Enemy не имеет vulnerabilities/creatureType/spellSaveDc/damageReduction; creature_archetypes не имеет creature_type/spell_save_dc → миграции. 4. CombatState.actionUsed/bonusActionUsed/reactionUsed/freeInteractionUsed уже есть (GameState:1381) → 2.7.KK закрыта фактом. 5. TurnMechanics не имеет merge/enemyHp → нужен хелпер (2.7.LL). 6. spells.json — 89 записей, 11 типов урона (BLUDGEONING/SLASHING — от оружия, не заклинаний).

    Принятые решения (фундамент Ф0–Ф3)¶

    Ф0. enum DamageType (13 типов) — подтверждено пользователем (ломающая миграция)¶

    enum class DamageType {
    ACID, BLUDGEONING, COLD, FIRE, FORCE, LIGHTNING,
    NECROTIC, PIERCING, POISON, PSYCHIC, RADIANT, SLASHING, THUNDER;
    companion object { fun from(s: String): DamageType = entries.first { it.name.equals(s, true) } }
}
    Замена String: SpellEffect.Damage.damageType, StateChange.Damage.damageType, Enemy.resistances/immunities/vulnerabilities, новые CharacterState.resistances/immunities/vulnerabilities. Миграция spells.json (11 типов в JSON) + OpenAPI. → закрывает 2.7.O/P и разблокирует 2.7.H/BB.

    Ф1. DamageResolver.apply — подтверждено¶

    immune→0, resist→÷2, vuln→×2, порядок strict. Точки вызова: SpellService.resolveDamage (уже для Enemy), новый SessionService.applyStateChanges для StateChange.Damage(PLAYER) (2.7.H/JJ). → закрывает 2.7.H/P/X.

    Ф2. SpellResolution { ATTACK, SAVE, AUTO } — подтверждено¶

    Поле в Spell + миграция 89 заклинаний (2.7.GG): скрипт/вручную, fallback (savingThrow != null → SAVE, иначе AUTO), require(resolution != null) при загрузке. → закрывает 2.7.C/D/V/GG.

    Ф3. SpellcastingStats — подтверждено¶

    fun spellSaveDc(c: CharacterState, spell: Spell): Int = 8 + proficiencyBonus(c.level) + spellMod(c, spell)
fun spellAttackBonus(c: CharacterState, spell: Spell): Int = proficiencyBonus(c.level) + spellMod(c, spell)
    spellMod — резолвинг способности (2.7.Y/TT): spell.castingAbility → classLevels → canonicalClassId, источник ClassRegistry.getClass(classId)?.spellcastingAbility. spells.json.dc — fallback монстров. → закрывает 2.7.A/Y/TT.

    • Урон и криты: 2.7.E/Z + 2.7.J + 2.7.Q + 2.7.B (условный PB).
    • Атаки за ход: 2.7.F/FF/LL (агрегация) + 2.7.G/DD/NN + 2.7.M (bonus action).
    • Сопротивления/ресурсы: 2.7.H/JJ + 2.7.P + 2.7.BB + новые поля CharacterState.
    • Классовые способности (MVP): 2.7.I + 2.7.AA + 2.7.BB + 2.7.CC + 2.7.EE.

    • Отложено: 2.7.T, 2.7.L, 2.7.W, Wild Shape, Channel Divinity.

    Примечание по процессу / класс модели¶

    • Фундаменты Ф0–Ф3, attackCount, DamageResolver-интеграция, FeatureRegistry, TurnMechanics.merge, резолвинг spellMod — [pro] (архитектурный класс, AGENTS.md); переключение перед кодом обязательно.
    • Миграции spells.json/creature_archetypes, OpenAPI, шаблоны UNARMED_STRIKE/OFFHAND_ATTACK/ IMPROVISE_WEAPON, ActionIntent-коды (MANEUVER) — [flash].
    • Ф0/Ф3/2.7.GG/2.7.PP — ломающие миграции (контракт состояния + spells.json + БД), требуют обновления OpenAPI и подтверждения перед кодом.
    • 2.7.B — перед добавлением кодов оружия grep существующие proficiencies (навыки/спасброски), формат weapon:* не конфликтует.
    • 2.7.F/FF — attackCount опирается на canonicalClassId+subclassId+features (thirsting_blade), порядок веток — от специфичного к общему.
    • 2.7.GG — классификация 89 заклинаний: ручной аудит первым (LLM-скрипт — риск шума), fallback строго для чтения.

    Аудит Action Economy — Блок 2.9 (facts)¶

    Только факты из кода, без оценок и фиксов. «Отсутствует» — если нет в коде. «Требует уточнения» — если по коду однозначно не следует. Статус документа: 2.9.1–2.9.16 — факты собраны, ожидается подтверждение.

    Паттерны из кода: - Трекинг экономии игрока — data class ActionEconomy (ActionEconomy.actionUsed/bonusActionUsed/ reactionUsed/freeInteractionUsed), поле CharacterState.actionEconomy (GameState.kt:452). - Дублирующие флаги у CombatState (GameState.kt:1387-1390) — используются тестами/glue, не движком. - StateChange.Spend* — единственный механизм простановки флагов; обрабатывается в SessionService.applyStateChanges. - Проверки — TurnResolver.checkActionEconomy + ClassFeatureHelper.canAfford.

    БЛОК 2.9.1: ACTION¶

    2.9.1.1. Где хранится флаг actionUsed.

    Где Тип/поле Файл:строка
    ActionEconomy.actionUsed Boolean = false rules/GameState.kt:1264
    CharacterState.actionEconomy ActionEconomy = ActionEconomy() rules/GameState.kt:452
    CombatState.actionUsed Boolean = false rules/GameState.kt:1387

    Факт: движок (TurnResolver, SessionService) читает/пишет только CharacterState.actionEconomy (TurnResolver.kt:288, :220; SessionService.kt:724, :2169). CombatState.actionUsed в production-коде не читается и не пишется — только тесты/glue (test/.../CombatSteps.kt:34,45).

    2.9.1.2. Когда сбрасывается.

    • SessionService.processTurn (SessionService.kt:723-724) — в начале каждого запроса хода игрока: 
      // Сброс экономии действий в начале хода персонажа (D&D 5e)
playerState = playerState.copy(actionEconomy = playerState.actionEconomy.reset())
      Сброс происходит до ветки реакции (:728), то есть и для request.reaction != null.
    • ActionEconomy.reset() = ActionEconomy() (GameState.kt:1279) — сбрасывает все 4 флага.
    • StateChange.ResetActionEconomy — определён (GameState.kt:1194) и обработан (SessionService.kt:2181-2183), но не эмитится нигде в коде (только определение + обработчик).
    • CombatState.nextTurn() (GameState.kt:1439) сбрасывает actionUsed/bonusActionUsed/ freeInteractionUsed; CombatState.nextRound() (:1436) — reactionUsed. В production-коде не вызываются — только в тестах/glue (CombatSteps.kt:134,139, TurnResolverTest.kt:543).

    2.9.1.3. Как проверяется перед действием.

    TurnResolver.checkActionEconomy(req, character) (TurnResolver.kt:264-295), вызов — в resolve (TurnResolver.kt:207-217): 

    val actionEconomyError = checkActionEconomy(req, character)
if (actionEconomyError != null) {
    return TurnMechanics(action = "no_roll", diceRolls = emptyList(),
        description = actionEconomyError, stateChanges = emptyList(), enemy = enemy)
}
    Формулировки отказа: - "Основное действие уже использовано в этом ходу" — :288; - "Бонусное действие уже использовано в этом ходу" — :289; - "Реакция уже использована в этом раунде" — :291.

    Для классовых способностей — ClassFeatureHelper.canAfford (ClassFeatureHelper.kt:42-50), вызов TurnResolver.kt:219-229: 

    FeatureActionType.ACTION       -> if (actionEconomy.actionUsed) "Основное действие уже использовано" else null
FeatureActionType.BONUS_ACTION -> if (actionEconomy.bonusActionUsed) "Бонусное действие уже использовано" else null
FeatureActionType.REACTION     -> if (actionEconomy.reactionUsed) "Реакция уже использована" else null

    2.9.1.4. Какие действия требуют Action.

    Группа в checkActionEconomy (TurnResolver.kt:266-288) — проверка actionUsed: ATTACK_CATALOG, ATTACK, SPELL, SPELL_CATALOG, CHECK_CATALOG, CHECK, SOCIAL_CHECK, USE_ITEM, HEAL, OBJECT, LOOT, SPECIAL_ATTACK, EQUIP, DASH, DISENGAGE, DODGE, HIDE, FINISHING_BLOW, AMBUSH_PREP, TEMPLATE, HAZARD, NPC_INTERACTION, QUEST_PROGRESS.

    Отдельно: - BONUS_ACTION — :289 (проверка bonusActionUsed); - OPPORTUNITY_ATTACK, REACTION — :290-291 (проверка reactionUsed); - DEATH_SAVE, NO_ROLL — :292-293 (без проверки, возвращают null).

    Полный enum — ActionType.kt:8-65 (28 значений).

    2.9.1.5. Понятие «1 Action за ход».

    Реализовано как один булев флаг actionUsed: Boolean (GameState.kt:1264) и методы hasAction()/withActionUsed() (:1270,1275). Счётчика действий нет — второй SpendAction ничего не меняет (copy(actionUsed = true) идемпотентно). Явной проверки «сколько Action потрачено» отсутствует.

    2.9.1.6. Где выставляется actionUsed = true.

    Только через StateChange.SpendAction → SessionService.applyStateChanges (SessionService.kt:2169-2171): 

    is StateChange.SpendAction -> {
    actionEconomy = actionEconomy.withActionUsed()
}
    Эмиттеры StateChange.SpendAction: - TurnResolver.buildEconomyChanges (TurnResolver.kt:297-313) — добавляется, если mechanics.consumesAction == true; для всех типов, кроме BONUS_ACTION, OPPORTUNITY_ATTACK/REACTION, DEATH_SAVE/NO_ROLL (там else -> StateChange.SpendAction). - ClassFeatureHelper.spendCost (ClassFeatureHelper.kt:76-84) — FeatureActionType.ACTION. - Тест ActionEconomyTest.kt:17 (resolver.resolve("атакую", ...) → ожидает SpendAction).

    mechanics.consumesAction по умолчанию true (TurnResolver.kt:112); выставлен в false в :1353, :1852, :1931, :2209, :2237.

    Порядок: Spend* кладётся первым в stateChanges (TurnResolver.kt:238-240: economyAndResourceChanges + mechanics.stateChanges).

    БЛОК 2.9.2: BONUS ACTION¶

    2.9.2.1. Где хранится флаг. - ActionEconomy.bonusActionUsed: Boolean = false (GameState.kt:1265). - CombatState.bonusActionUsed (GameState.kt:1388) — в production не читается. - Методы hasBonusAction()/withBonusActionUsed() (GameState.kt:1271,1276).

    2.9.2.2. Как распознаётся. - Regex BONUS_ACTION_PATTERN (ActionParser.kt:600): бонусным действием|бонусное действие|второе дыхание|second wind|дополнительное действие → ActionRequest(ActionType.BONUS_ACTION, ...) (ActionParser.kt:124-126). - DSL-шаблон BONUS_ATTACK (dsl-registry.yml:13) → ActionType.ATTACK (не BONUS_ACTION) (ActionParser.kt:480-483) — то есть бонусная атака через DSL теряет тип bonus. - Проверка/резолвер: resolveBonusAction (TurnResolver.kt:518-551).

    2.9.2.3. Что делает resolveBonusAction. - «второе дыхание / second wind» → heal 1d10 + уровень (TurnResolver.kt:520-529). - «скрыт/спрятать/stealth» → проверка Скрытности, при успехе статус «Скрыт» (TurnResolver.kt:531-544). - иначе — generic bonus_action без эффекта (TurnResolver.kt:545-550).

    2.9.2.4. Экономика. - checkActionEconomy для BONUS_ACTION проверяет bonusActionUsed (TurnResolver.kt:289), текст отказа «Бонусное действие уже использовано в этом ходу». - buildEconomyChanges: ActionType.BONUS_ACTION -> StateChange.SpendBonusAction (TurnResolver.kt:304). - Обработчик StateChange.SpendBonusAction → withBonusActionUsed() (SessionService.kt:2172-2174). - ClassFeatureHelper.spendCost: FeatureActionType.BONUS_ACTION -> SpendBonusAction (ClassFeatureHelper.kt:78); canAfford проверяет bonusActionUsed (:46-47).

    БЛОК 2.9.3: REACTION / OPPORTUNITY ATTACK¶

    2.9.3.1. Где хранится флаг. - ActionEconomy.reactionUsed (GameState.kt:1266), методы hasReaction()/withReactionUsed() (:1272,1277). - CombatState.reactionUsed (GameState.kt:1389) — production не читает; сбрасывается в CombatState.nextRound() (:1436), который в production не вызывается.

    2.9.3.2. Провокационная атака (текстовая). - Regex OPPORTUNITY_ATTACK_PATTERN (ActionParser.kt:601): провокационн|атака по возможности|реакцией.*атак|вдогонку.*уходящ|уходящего врага → ActionType.OPPORTUNITY_ATTACK (ActionParser.kt:128-130). - DSL-интент opportunity_attack → ActionType.OPPORTUNITY_ATTACK (ActionParser.kt:296). - resolveOpportunityAttack (TurnResolver.kt:554-563) вызывает resolveAttack и меняет action на "opportunity_attack"; комментарий :556 — «для MVP не трекаем персистентно», при этом SpendReaction эмитится через buildEconomyChanges.

    2.9.3.3. Общая реакция (ретроактивная, Q8.1/Q8.3). - DSL не различает общий REACTION: ActionParser не производит ActionType.REACTION (значение enum есть в TurnResolver.kt:291,305, но парсер его не выставляет). - Отдельный конвейер: SessionService.processReactionTurn (SessionService.kt:1387-1456), вызывается из processTurn при request.reaction != null (:728-737). - Валидация: реакция должна быть среди availableReactions предыдущего хода, иначе IllegalStateException (SessionService.kt:1405-1408). - ReactionResolver.resolve (ReactionResolver.kt:27-52) — 16 веток: SHIELD, HELLISH_REBUKE, ABSORB_ELEMENTS, UNCANNILY_DODGE, EVASION, DEFENSIVE_DUELIST, SHIELD_MASTER, DEFLECT_MISSILES, PARRY, RIPOSTE, CUTTING_WORDS, WARDING_FLARE, ENTROPIC_WARD, RETALIATION, FEATHER_FALL, SLOW_FALL. Каждая эмитит StateChange.SpendReaction. - Каталог триггеров: ReactionTriggerRegistry (ReactionTriggerRegistry.kt) + reaction_triggers.yml. Триггеры (ReactionTrigger): PLAYER_TAKES_DAMAGE, PLAYER_FALLS, ENEMY_ATTACK_MISSED. - Детекция триггеров и гейт: availableReactions (SessionService.kt:678-690) — при !hasReaction() возвращает пустой список; контекст условий — reactionContext (SessionService.kt:655-675, поле hasReaction). - ReactionProposal(reaction,label,description,trigger) (ReactionTriggerRegistry.kt:21-26).

    2.9.3.4. Экономика. - checkActionEconomy: OPPORTUNITY_ATTACK, REACTION → проверка reactionUsed, текст «Реакция уже использована в этом раунде» (TurnResolver.kt:290-291). - buildEconomyChanges: те же типы → StateChange.SpendReaction (TurnResolver.kt:305-306). - Обработчик SpendReaction → withReactionUsed() (SessionService.kt:2175-2177). - Особенность: processTurn сбрасывает всю экономию до ветки реакции (SessionService.kt:723-724), поэтому при обработке follow-up реакции reactionUsed заведомо false, и гейт hasReaction() в availableReactions не блокирует. - Ограничение: общего трекинга реакции за раунд нет — reactionUsed обнуляется каждым ходом игрока, а не концом раунда (нет вызова CombatState.nextRound()).

    БЛОК 2.9.4: MOVEMENT (скорость / Dash / провокация)¶

    2.9.4.1. Числовая скорость. - Отсутствует: у CharacterState нет поля speed/walkSpeed/movementLeft (в GameState.kt такие имена не встречаются). - DSL-реестр содержит только описания движения, без дистанции: MOVE_WALK, MOVE_RUN, MOVE_JUMP, MOVE_CRAWL, MOVE_CLIMB, MOVE_SWIM, MOVE_HIDE, MOVE_SNEAK, MOVE_FLEE, MOVE_TELEPORT (dsl-registry.yml:102-112). - Whitelist движения: MOVEMENT_ALWAYS = MOVE_WALK, MOVE_RUN, MOVE_CRAWL, MOVE_STAND_UP, MOVE_DROP_PRONE; MOVEMENT_CONDITIONAL — 11 записей (action-whitelist-core.yaml:128-173); MOVE_FLY, MOVE_SQUEEZE, MOVE_DIFFICULT_TERRAIN, MOVE_THROUGH_ENEMY есть только в whitelist (нет в DSL).

    2.9.4.2. Что делает MOVE-действие. - DSL MOVE → ActionType.DASH (ActionParser.kt:472). - Конкретные MOVE_JUMP/MOVE_CRAWL/MOVE_CLIMB/MOVE_SWIM/MOVE_SNEAK/MOVE_TELEPORT → ActionType.CHECK (ActionParser.kt:512-513). - DASH/MOVE_RUN/MOVE_WALK → ActionType.DASH (ActionParser.kt:488). - MOVE_HIDE → ActionType.HIDE (ActionParser.kt:489); MOVE_FLEE → ActionType.DISENGAGE (ActionParser.kt:487).

    2.9.4.3. CharacterState.canMove. - val canMove (GameState.kt:509) — только разрешение/запрет перемещения, без дистанции; численного бюджета перемещения нет.

    2.9.4.4. Провокационные атаки при движении. - Отдельной механики «выход из зоны досягаемости → провокационная атака врага» нет. - Триггер провокационной атаки у игрока — только текстовый regex (2.9.3.2).

    БЛОК 2.9.5: FREE / OBJECT INTERACTION¶

Экономика. - StateChange.SpendFreeInteraction определён (GameState.kt:1192) и обработан (SessionService.kt:2178-2180), но не эмитится нигде — grep по main/test даёт только определение + обработчик + ActionEconomy. - checkActionEconomy не проверяет freeInteractionUsed (TurnResolver.kt:264-295) — ни один ActionType не относится к свободному взаимодействию. - Объектные действия (OPEN_CONTAINER, PULL_LEVER, ...) идут как ActionType.OBJECT и тратят основное действие (TurnResolver.kt:275,309), а не free interaction.

    БЛОК 2.9.6: READY¶

    2.9.6.2. Вывод по коду. READY не реализован: ни парсинг, ни резолвер, ни хранение; есть только запись в whitelist.

    БЛОК 2.9.8: INITIATIVE / СБРОС ХОДА¶

Модель. - CombatState (GameState.kt:1379-1444): initiativeOrder, round, currentTurnIndex, roundNumber, surprisedParticipants, combatEnded. - InitiativeEntry и INITIATIVE_COMPARATOR используются resolveInitiative (TurnResolver.kt:2447+). - nextRound() сбрасывает reactionUsed (GameState.kt:1436); nextTurn() сбрасывает actionUsed/bonusActionUsed/freeInteractionUsed (:1439).

(SessionService.kt:1133) и insertIntoInitiative (:1143). - CombatState.nextRound()/nextTurn() в production не вызываются — только тесты/glue (CombatSteps.kt:134,139, TurnResolverTest.kt:543). - combatState.round/currentTurnIndex при обычных ходах не инкрементируются. - Бой завершается сбросом combatState = null при отсутствии врага (SessionService.kt:1129-1131), сохраняется в session.combatStateJson (:1305). - Сюрприз: пометка снимается после первого хода игрока (SessionService.kt:1152-1155).

    2.9.8.3. Сброс экономии (живой механизм). - playerState.actionEconomy.reset() в начале каждого processTurn (SessionService.kt:723-724) — до ветки реакции. - StateChange.ResetActionEconomy определён (GameState.kt:1194) и обработан (SessionService.kt:2181-2183), но не эмитится. - Итог: экономия сбрасывается на каждый ход игрока; раундового сброса реакции нет.

    БЛОК 2.9.9: EXTRA ATTACK¶

    2.9.9.1. Классовая доп. атака (игрок). - Whitelist: EXTRA_ATTACK — CONDITIONAL, условие class == 'Fighter' && level >= 5 && enemy != null (action-whitelist-magic.yaml:224-226). - Whitelist: ATTACK_MULTI — CONDITIONAL, условие level >= 5 && class in ['Fighter','Paladin','Ranger','Barbarian','Monk'] && enemy != null (action-whitelist-core.yaml:47-49). - ActionWhitelist.resolveConcreteId("ATTACK", "multi", ...) → ATTACK_MULTI (ActionWhitelist.kt:134). - ActionParser: ATTACK_MULTI → ActionType.ATTACK (ActionParser.kt:480-483), как обычная атака. - resolveAttack (TurnResolver.kt:1420-...) всегда выполняет один бросок атаки; цикла по числу атак/EXTRA_ATTACK/ATTACK_MULTI в коде нет (grep по level >= 5/extraAttack в TurnResolver — совпадений нет).

    2.9.9.2. Вывод по коду. У игрока фактической мультиатаки/Extra Attack нет: есть только whitelist-условия и маппинг на одиночную атаку.

    БЛОК 2.9.10: SPELLCASTING INTERACTION (casting time)¶

    2.9.10.1. Модель. - enum CastingTime { ..., BONUS_ACTION, REACTION } (spells/Spell.kt:39-40); у Spell есть castingTime: CastingTime (spells/Spell.kt:14). - SpellDto.castingTime: String (spells/SpellDto.kt:14), маппинг castingTime.name (:101). - SpellRegistry читает castingTime из JSON (SpellRegistry.kt:96). - В spells.json есть castingTime: BONUS_ACTION и REACTION (13 и 5 записей соответственно, включая 514, 800, 834, 1093, 1159, 1255, 1430, 1458, 1524, 1554, 1745, 1774, 1970, 2118, 2505).

    2.9.10.2. Использование в экономике. - grep castingTime/CastingTime вне spells/Spell.kt, SpellDto.kt, SpellRegistry.kt — совпадений нет: TurnResolver/SpellService/SessionService не читают castingTime и не выбирают SpendBonusAction/SpendReaction по нему. - Заклинания разрешаются как обычные действия: ActionType.SPELL/SPELL_CATALOG (TurnResolver.kt:268-269), механизм экономии — else -> SpendAction (TurnResolver.kt:309), если не сработал FeatureActionType. - Концентрация помечена как заглушка (SessionService.kt:2144-2163): CastSpell обнуляет concentrationSpell с TODO.

    Вывод по коду. Casting time хранится в данных, но не влияет на action economy.

    БЛОК 2.9.11: DSL / WHITELIST MAPPING¶

    2.9.11.1. Источники. - DSL-реестр: backend/app/src/main/resources/dsl-registry.yml. - Whitelist: 5 YAML в backend/app/src/main/resources/whitelist/ (action-whitelist-core.yaml, -exploration.yaml, -magic.yaml, -objects.yaml, -skills.yaml), загрузка — ActionWhitelist.init (ActionWhitelist.kt:13-81). - Луты: loot-whitelist.yml (BONUS_ATTACK: true на строке 11).

    2.9.11.2.

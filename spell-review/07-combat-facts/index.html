    Аудит умений/заклинаний — Блок 2.7: Боевая система (фактура)¶

    Фактура извлечена из кода (backend/app/src/main/kotlin/**), YAML/JSON каталогов (.yml/.yaml/.json). Метод: только факты без оценок. Пути → классы/строки → примеры. «Отсутствует» — если нет в коде. Основной файл механики: com/yorva/rules/TurnResolver.kt (2822 строки).

    2.7.1 ATTACK ROLL¶

    2.7.1.1. Где обрабатывается атака?¶

    • TurnResolver.resolveAttack(action, actionLower, character, enemy, profile) — TurnResolver.kt:1420.
    • TurnResolver.resolveAttackCatalog(weapon, ...) — TurnResolver.kt:566 (атака оружием из weapon-каталога).
    • TurnResolver.resolveSpecialAttack(sa, ...) — TurnResolver.kt:1039 (special_attacks из каталога).
    • TurnResolver.resolveOpportunityAttack — TurnResolver.kt:554 (реакция, переиспользует resolveAttack).
    • TurnResolver.resolveFinishingBlow — TurnResolver.kt:1074.
    • Диспетчеризация типа → resolve(...) в TurnResolver.kt:412 (ActionType.ATTACK), :358 (ATTACK_CATALOG), :348 (SPECIAL_ATTACK), :332 (FINISHING_BLOW), :344 (OPPORTUNITY_ATTACK).

    2.7.1.2. Формула d20 + abilityMod + PB vs AC¶

    // TurnResolver.kt:1500-1515
val attackMod = when {
    isFinesse -> maxOf(strMod, dexMod)
    isRanged -> dexMod
    else -> strMod
} + proficiencyBonus(character.level) + character.weaponAttackBonus + fsAttackBonus
val total = applyModifiers(baseTotal, "attack_roll", character)   // baseTotal = attackRoll + effectiveAttackMod
val ac = target.ac
val hit = crit || (!fumble && total >= ac)
    Реализовано. Профисиенси всегда прибавляется к атаке (нет разделения «владею/не владею оружием»).

    2.7.1.3. Где берётся AC цели¶

    • val ac = target.ac (TurnResolver.kt:1514); в catalog-варианте target.ac (:617); у атаки врага playerAc = character.effectiveAc + defenseAcBonus (:2363, defense fighting style +1).
    • Enemy.ac — поле Enemy (GameState.kt, напр. ac = row.ac при инстансархиатипе TurnResolver.kt:1120).

    2.7.1.4. Proficiency с оружием¶

    • Нет. Нет weapon-proficiencies (список «владею этим оружием»). proficiencyBonus(character.level) прибавляется безусловно к каждому броску атаки (:1504, :606-609).

    2.7.1.5. Учёт оружия (finesse/heavy/two-handed)¶

    • finesse: isFinesse = equipped FINESSE || trait finesse || FINESSE_PATTERN || имя (:1483,1487); бросок атаки и урон — maxOf(strMod, dexMod) (:1501,1524).
    • heavy: trait minStrength → штраф attackPenalty, если strength < minStr (:1491,1508-1509); в catalog — :611-615; применяется только к melee.
    • two-handed: isTwoHanded из trait two_handed/свойства TWO_HANDED (:1494-1495) — влияет только на fighting style dueling (не суммируется).
    • Атака блокируется/деградирует: если оружие каталога неизвестно и есть inventory — бьётся дефолтом 1d6 (:1426-1456, :1517).
    • Weapon traits: traitCode → catalogService.findWeaponTrait (:1481); attackPenalty/damagePenalty/minStrength (:1489-1491).

    2.7.1.6. Unarmed strike¶

    • Есть как whitelist-код ATTACK_UNARMED (action-whitelist-core.yaml:13), маппится в resolveConcreteId ("unarmed" → ATTACK_UNARMED, ActionWhitelist.kt:133). Механика: попадает в resolveAttack c дефолтным дайсом 1d6 и abilityMod, если нет оружия (:1422-1424,1517). Отдельного дайса 1+strMod (SRD 1 bludgeoning) — отсутствует.

    2.7.1.7. Spell attack roll (d20 + spellMod + PB)¶

    • Есть в resolveSpellOrSummon: spellMod = castingAttribute.second + proficiencyBonus(level), total = roll + spellMod (:1659-1660), бросок к dc = detectDc(...) (:1657), а не к AC. Сравнение с dc, не с target.ac.
    • Отсутствует в SpellService.resolveDamage (SpellService.kt:124-177): заклинание из cast <id> (SpellService) не делает броска атаки по AC — сразу применяет урон/спасбросок. Attack-roll тип заклинания реализован только в упрощённой ветке resolveSpellOrSummon.

    2.7.1.8. Где берётся spellMod¶

    • detectCastingAttribute(action, character) → (attrName, mod) (:1643), spellMod = castingAttribute.second + proficiencyBonus(level) (:1659).
    • В resolveSpellCatalog: spellMod = casterMod + proficiencyBonus(character.level) (:720), casterMod из family.casterStat.

    2.7.2 УРОН¶

    2.7.2.1. Формула урона¶

    // TurnResolver.kt:1517-1530
val diceSpec = equippedItem?.effectiveDamageDice ?: weapon?.damageDice ?: "1d6"
val (diceTimes, diceSides) = parseDice(diceSpec)
val damageRoll = if (hit) dice.roll(diceTimes, diceSides) else 0
val damage = if (hit) (damageRoll + damageMod + weaponBonus + fsDamageBonus - damagePenalty).coerceAtLeast(1) else 0
    dice + abilityMod + оружие-бонус + fighting style − штраф, минимум 1. Реализовано (:1523-1530).

    2.7.2.2. Откуда dice оружия¶

    • equippedItem?.effectiveDamageDice (инвентарь, MISC 1d4) → weapon?.damageDice (каталог) → дефолт "1d6" (:1517).
    • Парс: parseDice("1d8") → (1,8), parseDice("2d6") → (2,6).
    • В catalog-атаке: diceSpec = weapon.damageDice (:618).

    2.7.2.3. abilityMod для урона¶

    • damageMod = when { isFinesse -> maxOf(strMod,dexMod); isRanged -> dexMod; else -> strMod } (:1523-1526); в catalog :622-626.

    2.7.2.4. Two-handed STR ×1.5¶

    • Отсутствует. Только finesse/dex/str выбор (:1523-1526). Нет правила «двуручное оружие → +1×strMod».

    2.7.2.5. Off-hand без mod (two-weapon fighting)¶

    • Отсутствует. Нет two-weapon fighting: бонус BONUS_ATTACK/ATTACK_MULTI есть только как whitelist-коды (см. 2.7.9), реальной реализации off-hand атаки/бонусного действия нет («off_hand» встречается только как EquipSlot.OFF_HAND, SessionService.kt:2089).

    2.7.2.6. Типы урона¶

    • Оружие/физическая атака: урон без типа — StateChange.Damage(damage, StateTarget.ENEMY) без damageType (:1549, GameState.kt:1106 — data class Damage(amount, target, damageType: String? = null)).
    • Заклинание: StateChange.Damage(amount, ENEMY, damageType = effect.damageType) (SpellService.kt:170-174).

    2.7.2.7. Список типов урона¶

    • Отсутствует в виде enum/DamageType. Тип — строка damageType: String (SpellEffect.Damage, Spell.kt:72; StateChange.Damage, GameState.kt:1106). Примеры значений в spells.json: "fire", "cold", "force", "lightning", "necrotic", "acid", "poison", "radiant", "psychic", "piercing".

    2.7.3 КРИТИЧЕСКИЕ УДАРЫ¶

    2.7.3.1-2.7.3.2. Где проверяется, nat 20¶

    • val crit = attackRoll == 20 (:1477), :602; val hit = crit || (!fumble && total >= ac) (:1515, :617). Nat 20 → автохит (крит).
    • У заклинания: crit = roll == 20 (:1661).
    • В check/save: crit || (!fumble && total >= dc) (:2007-2009, :918-920, :2123).

    2.7.3.3. critRange (Champion 19-20)¶

    • Отсутствует. Только attackRoll == 20 (:1477, :602). Поле critRange нет в коде (решено в аудите 2.6/Блока 1 добавить в CharacterState — в коде не найдено).

    2.7.3.4. Урон при крите (×2 dice)¶

    // TurnResolver.kt:1519-1522
val critDoubles = crit && "armor_heavy" !in target.features
val damageRoll = if (hit) { if (critDoubles) dice.roll(diceTimes*2, diceSides) else dice.roll(diceTimes, diceSides) } else 0
    Крит = удвоение только дайсов (не mod). Реализовано. «armor_heavy» — фича противника, подавляет удвоение (полу-иммунитет к криту).

    2.7.3.5-6. Savage Attacks / Brutal Critical¶

    • Отсутствуют. Нет доп. дайса при крите (Half-Orc Savage Attacks, Barbarian Brutal Critical).

    2.7.3.7. Крит-эффекты от фич¶

    • Отсутствуют. Крит даёт только урон ×2 дайсов; fumble → «Ошеломлён» (:1532, :629). Нет фич-модификаторов крита.

    2.7.4 СПАСБРОСКИ ОТ ЗАКЛИНАНИЙ¶

    2.7.4.1-2.7.4.2. Где spell save DC; формула 8 + PB + spellMod¶

    • Проводится в SavingThrowResolver (com/yorva/rules/SavingThrowResolver.kt).
    • resolveEnemySave: saveBonus = enemy.statusSaveBonus; total = d20 + saveBonus (:62-86). DC приходит из savingThrow.dc.
    • resolvePlayerSave: modifier = abilityModifier; total = d20 + mod + profBonus (:22-53), DC из savingThrow.dc.
    • Формула «8 + PB + spellMod» отсутствует как вычисление DC. DC у заклинаний — фиксированные числа в spells.json (напр. "savingThrow": { "ability": "constitution", "dc": 13 }, spells.json:17-19), зашиты в каталог, а не считаются от кастера.

    2.7.4.3. Монстры — фиксированный DC¶

    • В заклинаниях: да, из spells.json. В спасбросках против статусов врага: saveDc = 13 + profile.mechanics.dcOffset (:2294), saveDc = hazard.saveDc ?: 12 (:1201), dc = 12 + profile.mechanics.dcOffset (ambush, :2257), poison_strike DC 13 (:2414). Для персонажа-кастера (SpellService) — из savingThrow.dc заклинания.

    2.7.4.4. SaveEffect (HALF/NEGATES/NONE)¶

    • Есть: enum SaveEffect { HALF, NEGATES, NONE } (SavingThrowResolver.kt:127-136).
    • Применяется в SpellService.resolveDamage (:153-159): HALF → totalDamage /= 2; NEGATES → 0; NONE → {}. Только если spell.savingThrow != null и saveResult.success.

    2.7.4.5. Spell save DC у Enemy¶

    • Отсутствует как поле Enemy (нет enemy.spellSaveDc). Бонус врага — только enemy.statusSaveBonus (GameState.kt, напр. :1127), используется в resolveEnemySave и в начале хода врага (:2297).

    2.7.5 SAVING THROWS (общие)¶

    2.7.5.1-2.7.5.2. Где saving throws; формула¶

    • TurnResolver.resolveSavingThrow(character, attribute, dc, effectName, hasProficiency, advantage, disadvantage) — :2077. 
      // :2104-2123
val hasProf = hasProficiency || character.proficiencies.any { it.equals(attribute, ignoreCase = true) }
val profBonus = if (hasProf) proficiencyBonus(character.level) else 0
val mod = attrMod + profBonus
val roll = advantage ? d20WithAdvantage / disadvantage ? d20WithDisadvantage / else d20
val total = applyModifiers(baseTotal, "saving_throw", character)
val success = crit || (!fumble && total >= dc)
      Формула d20 + abilityMod + PB реализована. Профисиенси по атрибуту берётся из character.proficiencies (по имени атрибута, напр. "dex").
    • Второй путь: SavingThrowResolver.resolvePlayerSave (:22-53) — идентичная формула.
    • Дополнительно для врага (статус-сэйвы): applyEnemyTurn :2293-2321.

    2.7.5.3. Откуда proficient¶

    • Два пути: параметр hasProficiency ИЛИ совпадение названия атрибута в character.proficiencies (:2104).
    • SavingThrowResolver: if (ability in character.proficiencies.map { it.lowercase() }) (:31-35).

    2.7.5.4. Advantage на saves (Elf charm / Dwarf poison)¶

    • Отсутствует для расовых способностей (нет racial save-advantage из 2.3).
    • Adv/disadv в resolveSavingThrow — только параметры и статусы: effectiveAdvantage = advantage || ("Уклонение" in statuses && attr=="dex"), effectiveDisadvantage = disadvantage || hasDisadvantageOnChecks(character) (:2109-2110).

    2.7.6 COVER¶

    • Отсутствует полностью. Нет half/three-quarters/total cover, нет бонуса к AC от укрытия (grep по cover/flank пуст в TurnResolver/SessionService/GameState).

    2.7.7 FLANKING¶

    • Отсутствует. Нет flanking, нет проверки позиций союзников для преимущества.
    • Единственный смежный механизм: allyAdjacentToEnemy — поле-условие в whitelist для SNEAK_ATTACK (action-whitelist-magic.yaml:314, action-whitelist-core.yaml:122), но реализации вычисления позиций в движке нет.

    2.7.8 MULTIATTACK¶

    2.7.8.1. Multiattack у Enemy.features¶

    • Есть: attackCount = (if ("multiattack" in enemy.features) 2 else 1) + legendaryExtra (:2388), повтор repeat(attackCount) бросков урона (:2396-2403). Применяется только в ответной атаке врага applyEnemyTurn.
    • Также "legendary" in enemy.features → +1 легендарная атака (:2387).

    2.7.8.2. Extra Attack у классов¶

    • Отсутствует в механике бросков. EXTRA_ATTACK есть как whitelist-код с условием class == 'Fighter' && level >= 5 (action-whitelist-magic.yaml:224-226), но резолвера, дающего второй бросок/набор урона игроку, нет (grep: ни одного вхождения в .kt).

    2.7.8.3. Стакание Extra Attack¶

    • Отсутствует (нет реализации, нет защиты от стака).

    2.7.8.4. Как обрабатывается¶

    • Для врага: через attackCount в applyEnemyTurn (:2385-2403) — несколько бросков урона (без отдельных attack-roll бросаются — 1 атак-ролл, N бросков урона). Для игрока — через ATTACK_MULTI только как whitelist-код, без множителя атак.

    2.7.9 TWO-WEAPON FIGHTING¶

    • Отсутствует. BONUS_ATTACK/ATTACK_MULTI — whitelist-коды (action-whitelist-core.yaml:47,50, ActionWhitelist.kt:134), но: нет отдельного бонусного действия, нет учёта light-оружий, нет off-hand атаки без mod, нет feat Dual Wielder.
    • Единственное упоминание off-hand — слот EquipSlot.OFF_HAND (SessionService.kt:2089).

    2.7.10 RANGED IN MELEE¶

    • Отсутствует. Нет disadvantage для ranged-атаки вблизи противника. В hasDisadvantageOnAttacks (:1984-1985) — только статусы; дистанция/близость не проверяются. Crossbow Expert — feat с 2.4, но механики «игнор дистанции» нет в коде.

    2.7.11 SPELL ATTACKS¶

    2.7.11.1-2.7.11.2. d20 + spellMod + PB где¶

    • resolveSpellOrSummon: spellMod = castingAttribute.second + proficiencyBonus(level), total = roll + spellMod, сравнение с dc (:1659-1663). НЕ против AC.
    • resolveSpellCatalog: spellMod = casterMod + proficiencyBonus(level) (:720).

    2.7.11.3. Разница с weapon attack¶

    • Weapon attack: бросок к ac (:1514). Spell attack в resolveSpellOrSummon: бросок к dc (detectDc, :1657), не к AC.
    • SpellService (cast по id, spells.json): вообще без броска — resolveDamage сразу считает урон/спасбросок (SpellService.kt:124-177). Нет ни to-hit-броска, ни attack-roll.

    2.7.11.4. Spell attack для cantrips¶

    • Отсутствует как отдельная механика. Cantrip не различается в коде боя (нет isCantrip-логики в SpellService/TurnResolver; в Spell.kt:21 поле level, без отдельного cantrip-атаки-броска).

    2.7.12 DAMAGE RESISTANCE / IMMUNITY¶

    2.7.12.1-2.7.12.2. У Enemy / Player¶

    • Enemy: val resistances: List<String>, val immunities: List<String> (GameState.kt:653,655). Нет vulnerabilities поля.
    • Player: character.resistances, character.immunities — поля в CharacterState? — grep в GameState для CharacterState дал :653,655 (это Enemy-блок; блок GameState.kt:653-655 находится между Enemy-полями). Уточнение: применить к StateChange.Damage для PLAYER код не находит применения character.resistances в TurnResolver (пусто). Player-resistance применение — отсутствует.

    2.7.12.3. Как применяется (÷2 / →0)¶

    • Только для Enemy и только в SpellService.resolveDamage: 
      // SpellService.kt:162-168
if (effect.damageType in target.resistances) totalDamage /= 2
if (effect.damageType in target.immunities) totalDamage = 0
    • Оружейный урон по врагу (resolveAttack) — без применений resistance/immunity.
    • Урон по игроку (StateChange.Damage PLAYER, SessionService.kt:1671) — без halving по типу (нет использования change.damageType для резистов игрока).

    2.7.12.4. Vulnerabilities (×2)¶

    • Отсутствует и для Enemy, и для Player (нет поля vulnerabilities, нет логики ×2).

    2.7.12.5. Где применяется¶

    • Только SpellService.resolveDamage для Enemy (:162-168). Не в TurnResolver боевых атак, не для игрока.

    2.7.13 HP И СМЕРТЬ В БОЮ¶

    2.7.13.1. HP = 0¶

    • Enemy: val isDefeated: Boolean get() = hp <= 0 (GameState.kt:663); при победе — GainXp + loot (TurnResolver.kt:1554-1556, 1142-1146).
    • Player: if (hp == 0) statuses.add("Без сознания") (SessionService.kt:1675-1676).

    2.7.13.2. Death saves¶

    • Есть: resolveDeathSave(character) (TurnResolver.kt:427-455); поля deathSaveSuccess/deathSaveFail (GameState.kt:345-346).
    • isUnconscious = hp == 0 && !isDead && deathSaveFail < 3 && "Стабилен" !in statuses (GameState.kt:489).
    • Без сознания — только death_save, действия блокируются (:178-179).

    2.7.13.3. Nat 20 / Nat 1¶

    • Nat 20 → Heal(1) + RemoveStatus Без сознания (:430-435).
    • Nat 1 → 2× DeathSaveFail (:436-441).
    • >=10 успех, иначе провал (:442-453).

    2.7.13.4. Massive damage¶

    • massiveDeath = change.amount >= state.maxHp; if (permadeath || massiveDeath) isDead = true (SessionService.kt:1678-1679).

    2.7.13.5. Урон по бессознательному¶

    • wasUnconsciousBefore = hp == 0 || "Без сознания" in statuses; при попадании по лежачему (не massive) — deathFail += 2 (автокрит), if (deathFail >= 3) isDead = true (SessionService.kt:1672-1685).
    • Врагу не атакует у applyEnemyTurn, если character.hp == 0 || unconscious || dead (:2280).
    • Концентрация при уроне: DC maxOf(10, change.amount/2), save CON (:1688-1707).

    2.7.14 ИНИЦИАТИВА¶

    2.7.14.1-2.7.14.2. rollInitiative, d20 + DEX¶

    • TurnResolver.resolveInitiative(character, enemy, playerSurprised, enemySurprised) (:2447), перегрузка (character, List<Enemy>, groupRoll, ...) (:2461).
    • playerRoll = if (playerSurprised) minOf(d20,d20) else d20; playerTotal = playerRoll + dexMod (:2468-2470). Враг: мод 0 (:2498), групповая инициатива по archetypeCode (:2492-2496).

    2.7.14.3. Порядок ходов¶

    • CombatState.initiativeOrder, сортировка INITIATIVE_COMPARATOR (GameState.kt:1377,1446), insertIntoInitiative (:1415).

    2.7.14.4-2.7.14.5. Legendary / Lair actions¶

    • Legendary: частично — "legendary" in enemy.features → +1 атака в applyEnemyTurn (:2387-2388). Отдельного типа действия/фазы «вне своего хода» нет.
    • Lair actions: отсутствует.

    2.7.15 WHITELIST / DSL ДЛЯ БОЯ¶

    2.7.15.1. ATTACK_* в whitelist¶

    • core: ATTACK_MELEE, ATTACK_UNARMED (action-whitelist-core.yaml:12-13), OPPORTUNITY_ATTACK, ATTACK_RANGED, ATTACK_SPELL_RANGED, ATTACK_SPELL_MELEE, ATTACK_SPELL_AOE, ATTACK_MULTI, BONUS_ATTACK, SNEAK_ATTACK (:32-76), ATTACK_NO_KILL (exploration :449).
    • magic: CAST_ATTACK_SPELL (:21), RECKLESS_ATTACK (:132), EXTRA_ATTACK (:224), SNEAK_ATTACK (:313).

    2.7.15.2. Как валидатор проверяет¶

    • ActionWhitelist.canExecute(dslId, context) — 4 шага: NEVER → блок; условный NEVER → блок; ALWAYS → разрешено; CONDITIONAL → eval; нет в whitelist → false (ActionWhitelist.kt:103-112).
    • 25 шаблонов LLM ↔ 150 конкр. id: resolveConcreteId(genericId, param, rawAction) (:115-...); ATTACK → melee/ranged/unarmed/multi (:129-137).
    • Условия боя (для 2.7.15.2): enemy == null, !hasRangedWeapon, !hasSpellSlots, class == 'Fighter' && level >= 5, class == 'Rogue' && (hasAdvantage || allyAdjacentToEnemy) и т.п. (action-whitelist-core.yaml:111-122, magic :224,313).

    2.7.15.3. Покрытие боем через 25 шаблонов¶

    • TEMPLATE_IDS (25) listOf("ATTACK","CAST_ATTACK","CAST_DEFEND","CAST_HEAL","CAST_BUFF","CAST_DEBUFF","CAST_UTILITY", "CHECK","SOCIAL","ACQUIRE","USE","EQUIP","UNEQUIP","OBJECT","GIVE","CAMP_REST","CAMP_FIRE","CAMP_GATHER","HEAL","MOVE","HIDE","DEFEND","MANEUVER","HAZARD","SAVE","NO_ROLL") (ActionWhitelist.kt:89-93).
    • ATTACK покрывает melee/ranged/unarmed/multi; MANEUVER → shove/grapple/disarm; CAST_ATTACK → боевые заклинания; DEFEND → DODGE; HIDE → advantage-атака.

    2.7.16 БОЕВЫЕ СПОСОБНОСТИ КЛАССОВ¶

    • Rage (Barbarian): ресурс RAGE — resources.rage (SessionService.kt:2043,2061), активация фичи «Ярость» → rage.active=true, roundsRemaining=10 (:2079). Механика бонуса к урону/резиста в бою — не найдена в resolveAttack (нет учета rage в уроне).
    • Sneak Attack (Rogue): только whitelist-условие (action-whitelist-magic.yaml:313-315, core :76,122). Резолвера-урона Sneak Attack — отсутствует.
    • Divine Smite (Paladin): отсутствует (grep no match в TurnResolver/SessionService).
    • Action Surge (Fighter): отсутствует (нет второго действия; EXTRA_ATTACK — whitelist без резолвера).
    • Ki (Monk): ресурс Resources — ki/KI_POINTS не найден (см. Resources-поля :1359-1360 arcaneRecovery/naturalRecovery; grep ki пуст).
    • Wild Shape (Druid): отсутствует (не найден). Есть resolveSpellOrSummon isSummon (:1678) — призыв существа, не Wild Shape персонажа.
    • Channel Divinity (Cleric): отсутствует.

    2.7.17 БОЕВЫЕ СОСТОЯНИЯ¶

    2.7.17.1-2.7.17.3. Применение/снятие/влияние¶

    • Применение: StateChange.ApplyStatus(статус, target, durationRounds) (SessionService.kt:1719-1727), снятие RemoveStatus (:1728-1730), statusDurations (:1724-1726).
    • Влияние на атаку — набор хардкод-статусов:
    • hasDisadvantageOnAttacks: Отравлен, Ошеломлён, Испуган, Связан, Опутанный, Ослеплён, Сбит с ног + isProne (TurnResolver.kt:1984-1985).
    • targetGrantsAdvantage: Связан, Опутанный, Без сознания, Парализован, Ошеломлён, Сон, Заморожен, Ослеплён, Сбит с ног + isIncapacitated + isProne (:1987-1988).
    • Враг: playerGrantsAdv = character.isIncapacitated; enemyHasDisadv.statuses ∩ {Отравлен, Ошеломлён, Испуган} (:2352-2355).
    • Снятие в бою: resolveSaveEnds (TurnResolver.kt:49) — топ-уровневая функция сброса save-статусов; враг — сэйв в начале хода applyEnemyTurn (:2292-2321).
    • isIncapacitated = isUnconscious || statuses ∩ {Ошеломлён, Парализован, Оглушён, Сон, Заморожен, Недееспособен} (GameState.kt:492).

    2.7.18 XP ЗА БОЙ¶

    2.7.18.1-2.7.18.3. Как начисляется, где, зависимость от ранга¶

    • private fun xpForEnemy(enemy): enemy.xpReward ?: when { maxHp>=30 -> 100; maxHp>=15 -> 75; else -> 50 } (TurnResolver.kt:1094-1098).
    • enemy.xpReward приходит из архетипа row.xp * scale (instantiateArchetypeEnemy, :1112-1125) — партийное масштабирование × (1 + 0.6×союзники).
    • GainXp добавляется при defeated (:1556, 1677) и при спец. заклинании nonCombatXp (:853, 1679, 2262).
    • От ранга (DifficultyRank) напрямую не зависят — зависят от maxHp (фикс. фолбэк) или от архетипа.

    2.7.19.1-2.7.19.3. Генерация лута, LootTable.rollForEnemy, LootWhitelist¶

    .map { StateChange.ItemDropped(it) }

StateChange.ItemDropped применяется в SessionService как лут-статус. - LootWhitelist: взаимодействие — в коде TurnResolver нет явной ссылки на LootWhitelist; сбор предметов — action == "loot" в SessionService.kt:2224-2233. «Требует уточнения» (LootWhitelist в этом файле не используется напрямую).

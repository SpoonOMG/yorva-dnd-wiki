    Аудит умений/заклинаний — Блок 1: Модель данных умений¶

    Технический аудит кодовой базы. Только факты из кода. Пути и номера строк указаны по состоянию репозитория на момент аудита.

    1.1. Как представлено «умение»¶

    В коде нет единого типа «умение». Сосуществуют пять независимых представлений:

    (а) Spell — заклинание¶

    backend/app/src/main/kotlin/com/yorva/spells/Spell.kt:9-23

    data class Spell(
    val id: String,
    val name: String,
    val level: Int,
    val school: String,
    val castingTime: CastingTime,
    val range: Int, // футы, 0 = касание/self
    val components: Components,
    val targets: TargetType,
    val savingThrow: SavingThrow?,
    val saveEffect: SaveEffect = SaveEffect.NONE,
    val effect: SpellEffect,
    val description: String,
    val classes: List<String>
)

    Вложенные типы: - Components(verbal: Boolean, somatic: Boolean, material: String?) — Spell.kt:28-32 - CastingTime enum: ACTION, BONUS_ACTION, REACTION — Spell.kt:37-41 (ритуал/минуты/часы отсутствуют) - TargetType enum: SELF, SINGLE_ENEMY, MULTIPLE_ENEMIES, ALL_ENEMIES, SINGLE_ALLY — Spell.kt:46-52 - SavingThrow(ability: String, dc: Int) — Spell.kt:57-60 - SpellEffect — sealed class с 4 подтипами Damage / Healing / Buff / Debuff — Spell.kt:65-104 - StatModifier(stat, value, type, durationRounds, source) — Spell.kt:119-125

    Пример из кода (resources/spells.json:3-34):

    {
  "id": "acid-splash",
  "name": "Брызги кислоты",
  "level": 0,
  "school": "conjuration",
  "castingTime": "ACTION",
  "range": 60,
  "components": { "verbal": true, "somatic": true, "material": null },
  "targets": "SINGLE_ENEMY",
  "maxTargets": 1,
  "savingThrow": { "ability": "dexterity", "dc": 13 },
  "effect": {
    "type": "damage", "diceCount": 1, "diceType": "d6",
    "damageType": "acid", "modifier": 0, "perTarget": true
  },
  "description": "Бросок кислоты 1d6",
  "classes": ["wizard", "sorcerer"]
}

    Важно: maxTargets присутствует в JSON, но SpellRegistry его не парсит — в модели Spell поля maxTargets нет (SpellRegistry.kt:91-104).

    1.2. Где хранятся умения¶

    Каталоги — статические файлы в classpath. Загрузчики:

    Тип Файл Загрузчик Количество
    Заклинания resources/spells.json SpellRegistry.loadSpells() — SpellRegistry.kt:17-27 89 записей
    Классы + их фичи resources/classes.yml ClassRegistry.loadClasses() — ClassRegistry.kt:16-46 12 классов; 120 фич
    Подклассы resources/subclasses.yml SubclassRegistry.load() — SubclassRegistry.kt:24-56 31 подкласс
    Черты resources/feats.yml FeatRegistry.load() — FeatRegistry.kt:24-50 41 черта
    Навыки/умения (UI) resources/skills.yml SkillRegistry.load() — SkillRegistry.kt:34-59 37 записей
    Предыстории resources/backgrounds.yml — (загрузчика в Kotlin не найдено) 13
    Инструменты resources/tools.yml — 28 строк файла

    Классы в classes.yml: warrior, wizard, rogue, cleric, barbarian, bard, druid, monk, paladin, ranger, sorcerer, warlock.

    В БД каталогов умений нет — есть только таблицы персонажей/сессий. resources/db/changelog содержит таблицу characters (0004-characters.yaml) без отдельных таблиц заклинаний/фич.

    1.3. Какие типы умений различает движок¶

    Разделение идёт по источнику/файлу, а не по единому enum:

    • Spell (заклинания) — SpellRegistry.kt, подтипы эффекта Damage/Healing/Buff/Debuff (Spell.kt:65-104).
    • ClassFeature (классовые фичи) — classes.yml; различаются по actionType (4× ACTION, 4× BONUS_ACTION, 8× FREE, 2× REACTION; остальные — пассивные/без actionType) и по resourceId.
    • Subclass features — subclasses.yml (только название/уровень/описание).
    • Feat (черты) — feats.yml (описательные).
    • SkillDef — skills.yml; смешаны проверки навыков (athletics, arcana…) и активные способности (rage, second_wind, power_strike, shield_bash, double_shot, help_action, ready_action).

    Отсутствуют как отдельные типы: - Racial traits — каталога рас нет; origin — свободный текст. resources/ не содержит race/origin/heritage файлов. Раса фигурирует только как текст: BackstoryService.kt:33 и GameState.kt:700. - Invocation / Metamagic — в classes.yml только заголовки-заделы: Мистические воззвания (задел) (classes.yml:1196), Метамагия (задел) (classes.yml:1104). - Epic Boons / Charms / Blessings / Psionics — отсутствуют.

    1.4. Как связаны умения с персонажем¶

    Список умений хранится в CharacterState (GameState.kt:326-449):

    Поле Строка Содержимое
    spellsKnown GameState.kt:411 заговоры + known (сорк/бард)
    spellbook GameState.kt:412 книга волшебника
    preparedSpells GameState.kt:413 подготовленные (wizard/cleric/druid)
    feats GameState.kt:409 id выбранных черт
    skills GameState.kt:335 навыки (коды)
    proficiencies GameState.kt:337 владения
    l1Choices GameState.kt:444 выбор L1-фич по названию фичи
    fightingStyle GameState.kt:448 боевой стиль
    expertiseSkills GameState.kt:446 экспертиза
    subclassId GameState.kt:437 id подкласса
    classLevels GameState.kt:439 List<ClassLevelEntry> (мультикласс, «задел»)
    classResources GameState.kt:435 ресурсы умений
    canonicalClassId GameState.kt:393 механический класс 
    val spellsKnown: List<String> = emptyList(),   // заговоры + known для сорка/барда
val spellbook: List<String> = emptyList(),     // книга волшебника (6 на L1 +2/ур)
val preparedSpells: List<String> = emptyList(), // подготовленные (wizard/cleric/druid)

    Хранение самих заклинаний — только id-строки, ссылки на spells.json.

    Где физически хранится состояние персонажа: - CharacterEntity (characters/CharacterEntity.kt:12-26) имеет колонку characterJson: String? (CharacterEntity.kt:20-21), но по grep characterJson вне этой entity не используется. - Фактическая сериализация CharacterState идёт в JSON сессии sessions.participants_json: SessionService.kt:432 (objectMapper.writeValueAsString(listOf(participant))), чтение/запись — SessionService.kt:479,483,1089,1238,1308 и далее. Модель Participant содержит state: CharacterState? (GameState.kt:602). - Заполнение при создании персонажа — SessionService.resolveSpellSelection(...) (SessionService.kt:372-401); при повышении — LevelUpService.kt:216-272.

    ClassLevelEntry(classId: String, level: Int) — GameState.kt:543-546; в комментарии указано «пока 1 элемент (totalLevel = sum)».

    Аудит — Блок 2.7: Боевая система (сверка дыр + решения)¶

    Фактура — 07-combat-facts.md. Ревью 1: 24 дыры (2.7.A–2.7.X). Ревью 2: ещё 22 дыры (2.7.Y–2.7.TT). Всего 46 дыр + фундаменты Ф0–Ф3. Итоговый чеклист — 07-combat-check-list.md. Канон: D&D 5e SRD. Паттерны из предыдущих блоков: *Registry (YAML/JSON), sealed-эффекты (SpellEffect, FeatEffect), CharacterState/Enemy, TurnResolver.resolveXxx, StateChange.

    Фактические поправки к коду (из верификации, применены к решениям ниже): 1. CharacterState не имеет charClass — есть canonicalClassId (str/класс) и classLevels: List<ClassLevelEntry> (12 реальных классов, для мультикласса). Все решения переведены на canonicalClassId + classLevels. 2. CharacterState.resistances/immunities/vulnerabilities отсутствуют (GameState:653,655 — это поля Enemy). Для игрока нужны новые поля CharacterState (раса/Rage/черты/предметы). 3. У Enemy нет vulnerabilities, creatureType, spellSaveDc, damageReduction; таблица creature_archetypes не имеет creature_type/spell_save_dc — нужны миграции. 4. CombatState.actionUsed/bonusActionUsed/reactionUsed/freeInteractionUsed уже есть (:1381) — 2.7.KK не требует новых полей. 5. TurnMechanics не имеет merge и enemyHp — для 2.7.LL нужен агрегирующий хелпер + поле состояния цели. 6. spells.json — 89 записей, 11 типов урона (нет BLUDGEONING/SLASHING — это оружие/unarmed, не заклинания). Ф0 «17 значений» — уточнено.

    Кросс-блочные решения (фундамент, требуется для половины дыр)¶

    Ф0. Единый enum DamageType — закрывает 2.7.O и разблокирует 2.7.H/P и валидацию. 

    enum class DamageType {
    ACID, BLUDGEONING, COLD, FIRE, FORCE, LIGHTNING,
    NECROTIC, PIERCING, POISON, PSYCHIC, RADIANT, SLASHING, THUNDER;
    companion object { fun from(s: String): DamageType = entries.first { it.name.equals(s, true) } }
}
    Заменить String в: SpellEffect.Damage.damageType, StateChange.Damage.damageType, Enemy.resistances/immunities, новых CharacterState.resistances/immunities/vulnerabilities, Enemy.vulnerabilities. spells.json — валидировать миграцией (в JSON физических типов BLUDGEONING/SLASHING нет — они приходят от оружия/unarmed; в JSON встречается 11 типов).

    Ф1. Единый резолвер урона DamageResolver — закрывает 2.7.H/P/X. 

    fun apply(amount: Int, type: DamageType, resist: List<DamageType>,
          immune: List<DamageType>, vuln: List<DamageType>): Int {
    if (type in immune) return 0
    var d = if (type in resist) amount / 2 else amount
    if (type in vuln) d *= 2
    return d
}
    Использовать в SpellService.resolveDamage (сейчас резист только у Enemy, :158-164) и в новом пути урона по игроку (сейчас его нет).

    Ф2. Единый SpellResolution — закрывает 2.7.C/D/V. 

    enum class SpellResolution { ATTACK, SAVE, AUTO }
    Добавить в Spell и в каталог/шаблоны: ATTACK (Scorching Ray, Eldritch Blast, cantrip-атаки), SAVE (Fireball, Hold Person), AUTO (Magic Missile). Устраняет двойной путь resolveSpellOrSummon (TurnResolver:1636) vs SpellService.castSpell (:1755).

    Ф3. SpellcastingStats — закрывает 2.7.A. 

    fun spellSaveDc(c: CharacterState, spell: Spell): Int = 8 + proficiencyBonus(c.level) + spellMod(c, spell)
fun spellAttackBonus(c: CharacterState, spell: Spell): Int = proficiencyBonus(c.level) + spellMod(c, spell)
    spellMod — из spell.castingAbility (добавить поле в Spell); для мультикласса и свитков/предметов — явный резолвинг (см. 2.7.TT). spells.json.dc остаётся fallback для монстров/NPC.

    🔴 Критичные дыры (2.7.A–2.7.K)¶

    2.7.A — Spell save DC фиксированный¶

    Принято: вычислять для PC, фикс — для монстров. Факт: SpellService.resolveDamage (:145) берёт spell.savingThrow.dc из JSON (dc:13). PC всегда кастует через SpellService.castSpell (TurnResolver:1755), т.е. путь один. 

    // Spell: добавить val castingAbility: String? = null
// SpellService.resolveSpellEffect: dc = spellSaveDc(caster, spell) вместо spell.savingThrow.dc
val st = spell.savingThrow!!.copy(dc = spellSaveDc(caster, spell))
savingThrowResolver.resolveEnemySave(st, target)
    В D&D 5e способности по классам различаются (Sorcerer/Warlock/Bard/Paladin — CHA, Wizard — INT, Cleric/Druid/Ranger — WIS). Резолвинг spellMod и DC — через classRegistry.getClass(classId)?.spellcastingAbility (см. 2.7.TT), а не хардкод.

    То же в resolveSpellOrSummon:1657 — заменить detectDc(..., 13) на spellSaveDc.

    2.7.B — Нет weapon proficiency¶

    Принято: закрывается метками владения (расширение CharacterState.proficiencies). Факт: proficiencyBonus(level) безусловно в resolveAttack:1504 и resolveSpellOrSummon:1659. 

    // proficiencies уже содержит коды навыков/спасбросков → расширить кодами оружия:
// "weapon:simple", "weapon:martial", "weapon:raсk", "weapon:longsword", ...
fun isProficient(c: CharacterState, weapon: WeaponDef?): Boolean {
    if (weapon == null) return false
    return weapon.category.code in c.proficiencies || weapon.code in c.proficiencies
}
val pb = if (isProficient(character, weapon)) proficiencyBonus(character.level) else 0
    Для заклинательных атак PB остаётся безусловным (владение заклинаниями класс-гейтед).

    2.7.C — Spell attack к DC, не к AC¶

    Принято: развести по SpellResolution. resolveSpellOrSummon:1657-1663 сравнивает total с dc (13) — неверно для атакующих заклинаний. 

    val success = when (resolution) {
    SpellResolution.ATTACK -> crit || (!fumble && roll + spellAttackBonus(character, spell) >= (enemy?.ac ?: return miss))
    SpellResolution.SAVE   -> /* спасбросок цели против spellSaveDc */
    SpellResolution.AUTO   -> true
}
    Урон атакующего заклинания — по AC цели; спасбросок — через SavingThrowResolver.

    2.7.D — SpellService без attack roll¶

    Принято: добавить attack roll в SpellService для ATTACK. Факт: resolveSpellEffect (:110) сразу применяет Damage. Добавить: 

    if (spell.resolution == SpellResolution.ATTACK) {
    val atk = dice.d20() + spellAttackBonus(caster, spell)
    val crit = dice.d20raw() >= critRange(caster)
    if (!crit && atk < target.ac) return noDamage
    totalDamage = if (crit) rollTwiceDice(effect) else rollDice(effect)
}
    Крит-удвоение — общий хелпер с resolveAttack. critRange общий для оружия и заклинаний (см. 2.7.MM — для spell attack Champion-снижение порога не применяется, остаётся 20).

    2.7.E — Unarmed strike = 1d6¶

    Принято: отдельный дайс. Факт: resolveAttack:1517 — фолбэк "1d6". Канон: 1 + STRmod (bludgeoning). Monk — Martial Arts die. 

    private val UNARMED_PATTERN = Regex("(?U)кулак|рукопаш|без оружи|удар рукой|пинок|ногой")
val diceSpec = when {
    UNARMED_PATTERN.containsMatchIn(actionLower) -> martialArtsDie(character) ?: "1"
    equippedItem?.effectiveDamageDice != null -> equippedItem.effectiveDamageDice
    weapon?.damageDice != null -> weapon.damageDice
    else -> "1d6"
}
    martialArtsDie(character) — Monk по уровню, точные уровни см. 2.7.Z. Добавить шаблон UNARMED_STRIKE.

    2.7.F — Extra Attack не работает¶

    Принято: attackCount из класса/уровня + последовательный резолв. Факт: whitelist EXTRA_ATTACK есть (action-whitelist-magic.yaml:224), резолвера нет (grep 0). 

    fun attackCount(c: CharacterState): Int = when {
    c.canonicalClassId == "fighter" -> when { c.level >= 20 -> 4; c.level >= 11 -> 3; c.level >= 5 -> 2; else -> 1 }
    c.canonicalClassId in listOf("barbarian", "paladin", "ranger", "monk") && c.level >= 5 -> 2
    c.canonicalClassId == "bard" && c.level >= 6 && c.subclassId in listOf("valor", "swords") -> 2
    c.canonicalClassId == "warlock" && "thirsting_blade" in c.features && c.level >= 5 -> 2
    c.canonicalClassId == "druid" && c.level >= 6 && c.subclassId == "moon" -> 2
    else -> 1
}
    Покрывает Fighter/Barbarian/Paladin/Ranger/Monk и Bard (Valor/Swords 6), Warlock (Thirsting Blade 5), Druid (Circle of Moon 6). ActionParser/SessionService: при действии ATTACK вызывать resolveAttack N раз, агрегируя TurnMechanics (один actionUsed). Агрегация с ранним выходом при смерти цели — см. 2.7.LL. Не дублировать через whitelist — EXTRA_ATTACK оставить как маркер намерения.

    2.7.G — Sneak Attack не работает¶

    Принято: дайсы по уровню плута + условие + один раз за ход. 

    fun sneakAttackDice(c: CharacterState): Int {
    val rogueLevel = c.classLevels.firstOrNull { it.classId == "rogue" }?.level ?: 0
    return (1 + (rogueLevel - 1) / 2).coerceAtMost(10)   // мультикласс: только уровни плута
}
    Применять один раз за ход (флаг CombatState.sneakAttackUsedThisTurn, см. 2.7.DD), только если есть преимущество ИЛИ рядом союзник цели, и нет помехи: 
    if (sneakDice > 0 && !hasDisadv && (hasAdv || allyAdjacentTo(enemy))) {
    damage += dice.roll(sneakDice, 6)
}
    allyAdjacentTo — заглушка (см. 2.7.L). Whitelist SNEAK_ATTACK уже есть.

    2.7.H — Player resistance отсутствует¶

    Принято: через DamageResolver (Ф1). Факт: у character нет resistances/immunities/vulnerabilities (GameState:653,655 — это поля Enemy). Требуется новые поля CharacterState (источники: раса, Rage B/P/S, черты, предметы). Урон по игроку сейчас проходит напрямую в StateChange.Damage → нужен слой apply(...) в applyStateChanges для StateChange.Damage(target == PLAYER) (см. 2.7.JJ — точка вызова): 

    // TurnResolver.resolveEnemyAttack / environmental / spell-on-player:
val finalDmg = damageResolver.apply(raw, type, c.resistances, c.immunities, c.vulnerabilities)
stateChanges += StateChange.Damage(finalDmg, StateTarget.PLAYER, type)
    Закрывает расу (Tiefling/Dwarf), Rage (B/P/S), черты.

    2.7.I — Классовые способности (6 из 7)¶

    Принято: единый FeatureRegistry (YAML) + resolveFeatureAction, ресурсы уже есть в ClassResources. Факт: поля rage/ki/channelDivinity/wildShape/actionSurge уже существуют (GameState:1343-1352), резолверов нет.

    Способность Реализация Ресурс
    Rage RageResource.active=true; +2/+3/+4 к melee-урону по уровню; resistance B/P/S rage.uses
    Divine Smite после попадания: трата слота → +2d8 radiant (+1d8 undead/fiend), max 5d8 spell slot
    Action Surge actionUsed=false (доп. действие в этом ходу); 1/отдых actionSurge
    Ki Flurry of Blows (бонус-действие, 2 атаки), Patient Defense (Dodge), Step of the Wind (Dash); 1 ki ki
    Wild Shape превращение в beast-статблок; отдельный пул HP; возврат формы wildShape
    Channel Divinity Turn Undead / Sacred Weapon / Preserve Life (по подклассу) channelDivinity
    Rage bonus урона добавить в resolveAttack: if (rage.active && isMelee) +rageDamageBonus(level) —

    Формат: Activatable { code, cost, actionType, effect } через YAML feature-actions.yaml, TurnResolver.resolveFeatureAction(code) — единая точка (по аналогии с ActionWhitelist).

    2.7.J — critRange отсутствует¶

    Принято: вычисляемый порог. Факт: crit = attackRoll == 20 (resolveAttack:1477, :602). 

    fun critRange(c: CharacterState): Int = when {
    "champion_18" in c.features -> 18
    "champion_19" in c.features -> 19
    else -> 20
}
val crit = attackRoll >= critRange(character)
    Champion (19-20 на 3 ур., 18-20 на 15 ур.) — через features/подкласс. Крит-удвоение дайсов — общий хелпер.

    2.7.K — Cover отсутствует¶

    Принято: вариант A + B. - A: Enemy.cover: Cover = Cover.NONE (цель атаки — обычно враг). - B: для PC — через activeModifiers типа "ac" (уже поддержано в applyModifiers, но AC сейчас не читает модификаторы!).

    Правка: применять applyModifiers(ac, "ac", character) для AC игрока (сейчас applyModifiers вызывается только для attack_roll/saving_throw/damage). Для врага: 

    enum class Cover(val acBonus: Int) { NONE(0), HALF(2), THREE_QUARTERS(5), TOTAL(-1) }
val ac = target.ac + target.cover.acBonus   // TOTAL → цель недосягаема
    Установка: через whitelist TAKE_COVER с параметром укрытия через ActionIntent (см. 2.7.II: { "type": "MANEUVER", "maneuver": "take_cover", "cover": "HALF" }).

    🟡 Важные дыры (2.7.L–2.7.T)¶

    2.7.L — Flanking отсутствует¶

    Принято: опционально, заглушка под тактику. Flanking — вариантное правило DMG, не базовый SRD. Без сетки координат позиционирование моделируем флагом: 

    // Enemy: val engagedByAllies: Int = 0  (0..N)
val flanking = enemy.engagedByAllies >= 1   // advantage
    Используется и для Sneak Attack (allyAdjacentTo), и как advantage-источник. Источник заполнения — ActionIntent от LLM (см. 2.7.HH); без него флаг всегда 0. Полная сетка — отложена до мультиплеера. Зафиксировать как «частично реализовано».

    2.7.M — Two-weapon fighting¶

    Принято: бонус-действие off-hand. Условие: оба оружия light. Бонусное действие → 1 атака off-hand, модификатор урона не добавляется (кроме отрицательного), если нет стиля two_weapon_fighting. 

    if (offhand && !twoWeaponFightingStyle) damageMod = min(0, damageMod)
// требует CombatState.bonusActionUsed == false → выставить true
    Шаблон OFFHAND_ATTACK; проверка ItemProperty.LIGHT.

    2.7.N — Ranged in melee¶

    Принято: помеха при враге в упор. 

    val rangedInMelee = isRanged && enemy != null && enemy.engagedInMelee
val hasDisadv = attackerDisadv || rangedInMelee
    Нужен флаг дистанции: Enemy.isEngaged (0/5 ft). Источник — ActionIntent (LLM) или scеnе (см. 2.7.HH). Полноценная модель расстояний — отложена; LLM/сцена выставляет флаг при «стреляешь в упор»/«враг рядом».

    2.7.O — Enum урона¶

    Принято: enum DamageType (Ф0). Единый источник, валидация spells.json, замена всех String. Ломающее изменение модели — фиксируется в чеклисте как миграция.

    2.7.P — Vulnerabilities¶

    Принято: добавить поле + ×2 в DamageResolver. Enemy.vulnerabilities: List<DamageType>, CharacterState.vulnerabilities. Порядок: immunity → resistance → vulnerability. Данные — из бестиария/каталога архетипов.

    2.7.Q — Savage Attacks / Brutal Critical¶

    Принято: через critBonusDice. 

    fun critBonusDice(c: CharacterState): Int = when {
    "savage_attacks" in c.features -> 1                    // Half-Orc
    c.canonicalClassId == "barbarian" && c.level >= 17 -> 3
    c.canonicalClassId == "barbarian" && c.level >= 13 -> 2
    c.canonicalClassId == "barbarian" && c.level >= 9 -> 1
    else -> 0
}
// в crit-ветке: damage += dice.roll(critBonusDice, weaponDieSides)
    Реализуется через features/класс, не отдельный FeatEffect.

    2.7.R — Stabilization¶

    Принято: добавить. 

    // CharacterState: val isStable: Boolean = false
fun resolveStabilize(character, profile): TurnMechanics  // Medicine DC 10
// успех → isStable=true, death saves остановлены; урон снова снимает стабилизацию
    Действие (обычно союзник). В соло — self-stabilize невозможен, но NPC-союзник/сцена может.

    2.7.S — Healing → 1 HP¶

    Принято: добавить с приоритетом (см. 2.7.SS). 

    // в resolveHealing / StateChange.Heal:
if (target.hp == 0) {
    hp = 1; deathSaveSuccess = 0; deathSaveFail = 0; isStable = true
    statuses.remove("Без сознания"); statuses.remove("Стабилен")
}
    Магическое лечение поднимает с 0 HP до 1 (канон), даже если цель стабилизирована; снимает «Без сознания»/«Стабилен». Stabilize не лечит (только стабилизирует).

    2.7.T — Lair actions¶

    Принято: отложить (🟡), зафиксировать крючок. Не нужно соло-MVP. В CombatState зарезервировать lairActionTriggered: Boolean и точку вызова на initiative 20 (с потерей инициативы при равенстве). Полная механика — после подтверждения retention.

    🔴 Дополнительные дыры (2.7.U–2.7.X)¶

    2.7.U — Surprise round¶

    Принято: формализовать существующую часть. CombatState.surprisedParticipants (:1394) и advantage «Врасплох» (resolveAttack:1466) уже есть. Добавить: участники из surprisedParticipants пропускают первый ход (currentTurnIndex перескакивает), и снимать "Врасплох" после первой атаки или после 1 раунда, что наступит раньше (см. 2.7.RR). Отдельный «surprise round» не вводим — в 5e это просто пропуск хода, а не отдельный раунд.

    2.7.V — Spell attack для cantrips¶

    Принято: закрывается Ф2 + Ф3. Cantrip (level 0, без слота) с SpellResolution = ATTACK → attack roll vs AC, PB + spellMod. Масштабирование кантрипов по уровню (5/11/17) — типизировано (см. 2.7.OO: DICE/BEAMS/ADDITIONAL), не просто cantripScale: Int.

    2.7.W — Improvised weapons¶

    Принято: через шаблон, без PB. 

    # action-templates: IMPROVISE_WEAPON
damageDice: "1d4"; ability: STR; proficient: false
    Урон 1d4 + STRmod bludgeoning, без PB (кроме черты Tavern Brawler → PB).

    2.7.X — armor_heavy подавляет крит¶

    Принято: убрать homebrew. Факт: critDoubles = crit && "armor_heavy" !in target.features (:1519) — не канон. Удалить условие: крит всегда удваивает дайсы. Если нужен аналог Heavy Armor Master — ввести отдельное поле Enemy.damageReduction: Int (DR против немагического B/P/S), не связанное с критами. Применение DR — отдельный шаг до/после резолвера (см. 2.7.QQ).

    🔴 Второе ревью: новые дыры (2.7.Y–2.7.TT)¶

    2.7.Y — Spell.castingAbility для мультикласса¶

    Принято: явный резолвинг способности. Для мультикласс-кастера, свитков и предметов чья-то ability должна вычисляться детерминированно: 

    fun spellMod(c: CharacterState, spell: Spell): Int {
    val ability = spell.castingAbility
        ?: c.classLevels.firstOrNull { it.classId in spell.classes }?.let {
            classRegistry.getClass(it.classId)?.spellcastingAbility
        }
        ?: c.canonicalClassId?.let { classRegistry.getClass(it)?.spellcastingAbility }
        ?: return 0
    return abilityMod(c, ability)
}
    См. также 2.7.TT (источники spellcastingAbility).

    2.7.Z — martialArtsDie точные уровни¶

    Принято: таблица SRD. | Уровень Monk | Die | | :--- | :--- | | 1–4 | d4 | | 5–10 | d6 | | 11–16 | d8 | | 17–20 | d10 | 

    fun martialArtsDie(c: CharacterState): String? {
    if (c.canonicalClassId != "monk") return null
    return when { c.level >= 17 -> "1d10"; c.level >= 11 -> "1d8"; c.level >= 5 -> "1d6"; else -> "1d4" }
}

    2.7.AA — rageDamageBonus точные уровни¶

    Принято: таблица SRD. | Уровень Barbarian | Rage Damage | | :--- | :--- | | 1–8 | +2 | | 9–15 | +3 | | 16–20 | +4 | 

    fun rageDamageBonus(c: CharacterState): Int = when {
    c.canonicalClassId != "barbarian" -> 0
    c.level >= 16 -> 4
    c.level >= 9 -> 3
    else -> 2
}

    2.7.BB — Rage resistance B/P/S агрегация¶

    Принято: добавлять/удалять три типа через activeModifiers (без DamageCategory). resistances: List<DamageType> — три типа одновременно: 

    // при активации Rage:
c.activeModifiers += listOf(
    RageResistance(BLUDGEONING), RageResistance(PIERCING), RageResistance(SLASHING)
)
// при окончании Rage: удалить те же модификаторы
    Источник модификаторов — activeModifiers (уже поддержаны в applyModifiers), тип-гейт по DamageType.

    2.7.CC — Divine Smite точная формула¶

    Принято: база + уровень слота + undead/fiend. | Слот | Урон | | :--- | :--- | | 1st | 2d8 | | 2nd | 3d8 | | 3rd | 4d8 | | 4th | 5d8 | | 5th+ | 5d8 + 1d8/уровень (max +5d8) | 

    fun divineSmiteDice(slotLevel: Int, target: Enemy?): Int {
    val base = (slotLevel + 1).coerceAtMost(5)
    val extra = if (slotLevel > 4) (slotLevel - 4).coerceAtMost(5) else 0
    val undead = if (target?.creatureType in listOf("undead", "fiend")) 1 else 0
    return base + extra + undead
}
    Требует Enemy.creatureType (миграция, см. 2.7.PP).

    2.7.DD — Sneak Attack один раз за ход¶

    Принято: флаг CombatState.sneakAttackUsedThisTurn: Boolean, сбрасывается в начале хода.

    2.7.EE — Ki Points точные уровни¶

    Принято: level при Monk ≥ 2. 

    fun kiPoints(c: CharacterState): Int =
    if (c.canonicalClassId == "monk" && c.level >= 2) c.level else 0

    2.7.FF — Extra Attack: Bard/Warlock/Druid¶

    Принято: включено в attackCount (2.7.F). Bard (Valor/Swords 6), Warlock (Thirsting Blade 5), Druid (Moon 6).

    2.7.GG — SpellResolution: миграция 89 заклинаний¶

    Принято: скрипт миграции + fallback + валидация. - Миграция данных spells.json: классификация ATTACK/SAVE/AUTO (скрипт или вручную). - Fallback при загрузке: savingThrow != null → SAVE, иначе AUTO. - Валидация: require(resolution != null) при загрузке каталога.

    2.7.HH — engagedByAllies/isEngaged: источник¶

    Принято: через ActionIntent (вариант B), движок применяет. 

    { "type": "MANEUVER", "maneuver": "engage", "target": "enemy_01" }
    Движок: enemy.engagedByAllies += 1 / enemy.isEngaged = true. LLM-нарратив сам по себе флаги не меняет.

    2.7.II — Cover: whitelist с параметром¶

    Принято: ActionIntent с параметром укрытия. 

    { "type": "MANEUVER", "maneuver": "take_cover", "cover": "HALF", "target": "enemy_01" }

    2.7.JJ — DamageResolver для PC: точка вызова¶

    Принято: в SessionService.applyStateChanges перед применением StateChange.Damage(PLAYER). 

    if (change is StateChange.Damage && change.target == StateTarget.PLAYER) {
    val final = damageResolver.apply(change.amount, change.damageType,
        pc.resistances, pc.immunities, pc.vulnerabilities)
    // применить final вместо change.amount
}
    Охватывает урон от врагов и заклинаний врага (все идут через StateChange).

    2.7.KK — bonusActionUsed поле¶

    Принято: уже есть. CombatState содержит actionUsed/bonusActionUsed/reactionUsed/freeInteractionUsed (GameState.kt:1381). Дополнительных полей не нужно.

    2.7.LL — Extra Attack: агрегация TurnMechanics¶

    Принято: хелпер merge + ранний выход при смерти цели. TurnMechanics не имеет merge и enemyHp — нужны (см. факт. поправку №5): 

    var combined = TurnMechanics.EMPTY
var targetAlive = true
repeat(attackCount(c)) {
    if (!targetAlive) return@repeat
    val result = resolveAttack(...)
    combined = combined.merge(result)
    targetAlive = result.enemyHp > 0
}

    2.7.MM — critRange для spell attack¶

    Принято: для spell attack порог 20 (Champion-фича не применима к заклинаниям). Общий хелпер critRange(c, isSpell) → 20 для isSpell, иначе Champion-порог.

    2.7.NN — sneakDice для мультикласса¶

    Принято: только уровни плута из classLevels (см. обновлённую 2.7.G). Rogue 3/Fighter 5 → 2d6, не 4d6.

    2.7.OO — Cantrip scale: типы масштабирования¶

    Принято: scalingType: DICE | BEAMS | ADDITIONAL + scaleStep, или scalesAt: List<Int> = [5,11,17]. Fire Bolt/Eldritch Blast — разная механика (дайсы vs лучи vs доп. урон GFB). Модель в SpellEffect.

    2.7.PP — Spell save DC монстров¶

    Принято: Enemy.spellSaveDc: Int? из архетипа. Миграция creature_archetypes + spell_save_dc; источник — бестиарий (Блок 2.15). Также Enemy.creatureType (нужно для 2.7.CC — Divine Smite undead/fiend).

    2.7.QQ — damageReduction применение¶

    Принято: отдельный шаг до резолвера, только B/P/S. 

    fun applyDamageReduction(raw: Int, type: DamageType, dr: Int?): Int =
    if (dr != null && type in listOf(BLUDGEONING, PIERCING, SLASHING)) (raw - dr).coerceAtLeast(0) else raw

    2.7.RR — Surprise: снятие «Врасплох»¶

    Принято: после первой атаки ИЛИ после 1 раунда, что раньше. (обновлённая 2.7.U)

    2.7.SS — Healing → 1 HP: приоритет¶

    Принято: лечение всегда возвращает сознание с 1 HP, даже если isStable. Снимать «Без сознания»/«Стабилен» (обновлённая 2.7.S).

    2.7.TT — spellcastingAbility источники¶

    Принято: через classRegistry.getClass(classId)?.spellcastingAbility. Таблица SRD (CHA: Sorcerer/Warlock/Bard/Paladin; INT: Wizard; WIS: Cleric/Druid/Ranger) — источник classes.yml/ClassRegistry, не хардкод. Для half-casters (Paladin/Ranger) в мультиклассе берём способность из того класса, который дал заклинание (см. 2.7.Y).

    Порядок реализации (предложение)¶

    1. Ф0 + Ф1 (DamageType, DamageResolver, новые поля CharacterState) — фундамент, ломающая модель → миграция.
    2. Ф3 (SpellcastingStats) → 2.7.A/Y/TT.
    3. Ф2 (SpellResolution) → 2.7.C/D/V/GG (миграция 89 заклинаний).
    4. Мелкие боевые фиксы: 2.7.B/E/Z/F/FF/LL/G/DD/NN/J/Q/M/K/MR/S/SS/U/RR/W/X/QQ/AA/BB/CC/EE.
    5. 2.7.I (MVP: Rage, Divine Smite, Action Surge, Ki) — отдельная крупная итерация после стабилизации ядра.
    6. 2.7.K/II/HH/L/N — тактика/данные, по мере наполнения каталога.
    7. Отложено: Wild Shape, Channel Divinity (2.7.I), 2.7.T (lair), 2.7.L (flanking), 2.7.PP (данные бестиария — Блок 2.15).

    Ответы пользователя (зафиксировано)¶

    1. 2.7.I — MVP-ядро: Rage, Divine Smite, Action Surge, Ki. Wild Shape — до Блока 2.15 (бестиарий), Channel Divinity — до Блока 2.2 (подклассы). Sneak Attack — отдельно в 2.7.G.
    2. Ф0 — да, подтверждена ломающая миграция StateChange.Damage + spells.json + OpenAPI (13 типов).
    3. 2.7.L/N — да, вводим минимальные флаги Enemy.isEngaged + Enemy.engagedByAllies через ActionIntent (LLM). Полная сетка — отложена до мультиплеера.
    4. 2.7.T (lair) и 2.7.L (flanking) — отложены, фиксируются в чеклисте.

    Решения по Блоку 2.9 — Action Economy¶

    Основание: факты из 09-action-economy-facts.md + ревью (28 дыр, 6 game-breaking). Связанные документы: docs/adr/0006-action-economy-class-resources.md, 07-combat-holes-response.md (2.7.F/2.7.I/2.7.LL), docs/game-design/action-economy.md. Статус: предложено к подтверждению (до реализации).

    0. Контекст и архитектурный вывод¶

    1. Живая экономия — только CharacterState.actionEconomy. Флаги CombatState — мёртвый дубль (2.9.1), подлежат удалению.
    2. «Ход» = один processTurn. Реального цикла инициативы в production нет: CombatState.nextRound()/nextTurn() не вызываются (2.9.8).
    3. Целевая модель раунда (MVP, без перестройки боя): 1 раунд = один нормальный запрос игрока (действие игрока + ответ врагов). Реакция и все «1/ход» ресурсы обновляются в начале нормального хода игрока, то есть в начале раунда. Это канон 5e («reaction refreshes at the start of your turn») и одновременно чинит «бесконечные реакции».
    4. Ответ на реакцию (request.reaction != null) — не новый ход и не должен сбрасывать экономию. Follow-up реакции обязан видеть уже потраченную реакцию.
    5. Economy как данные, а не булевы флаги по месту вызова: вводим economyCost в DSL. mechanics.consumesAction остаётся fail-closed (true по умолчанию) до миграции.
    6. Нет сетки/позиций → движение моделируется абстрактным бюджетом (футы), а не геометрией. Провокационные атаки по геометрии — отложены (см. 2.9.P).
    7. Изменения CharacterState/DTO (speed, readiedAction, ActionEconomy, MechanicsBlock) — spec-first: сначала api-specification/openapi.yaml, потом код. JSON-сессии обратно совместимы (поля с дефолтами).

    1. Уточнения формулировок ревью¶

    Дыра Уточнение
    2.9.A Сброс реакции в начале хода игрока — канон, а не баг. Реальные баги: (а) сброс на follow-up реакции → чейнинг; (б) нет понятия раунда.
    2.9.D MOVE_CLIMB/SWIM/JUMP действительно требуют проверок в 5e, но это движение с проверкой, а не Action-проверка. MOVE_CRAWL/SNEAK проверок не требуют.
    2.9.E BONUS_ATTACK (off-hand, бонусное действие) и ATTACK_MULTI (мультиатака в рамках основного Attack) — разные вещи; сейчас оба теряются в ATTACK. Исправляются по-разному.
    2.9.B Вывод «раунд не существует» верен. Не воскрешаем полный цикл инициативы (нет мультиплеера), а делаем раунд = цикл «ход игрока + ответ врагов».

    2. Решения¶

    🔴 Game-breaking¶

    2.9.A — reactionUsed сбрасывается каждый ход → бесконечные реакции¶

    Решение. Сброс экономии выполняется только на нормальном ходу игрока (request.reaction == null). Follow-up реакции не сбрасывает экономию. Реакция обновляется вместе с action/bonus/free в начале нормального хода.

    Обоснование. В 5e реакция восстанавливается в начале своего хода. Проблема не в этом, а в том, что processTurn вызывается и для follow-up реакции и там же сбрасывает флаги, позволяя чейнить реакции.

    Как. 

    // SessionService.processTurn
if (request.reaction != null) {
    // НЕ сбрасывать экономию: реакция уже была потрачена в предыдущем ходу
    return processReactionTurn(...)
}
// экономия сбрасывается один раз, перед нормальным ходом
playerState = playerState.copy(actionEconomy = playerState.actionEconomy.beginTurn())

    Зависит от 2.9.B (beginTurn синхронизирован с раундом).

    2.9.B — CombatState.nextRound()/nextTurn() не вызываются¶

    Решение. Не воскрешать цикл инициативы. Ввести единый beginPlayerTurn: инкремент CombatState.round, сброс action/bonus/free/reaction через ActionEconomy.beginTurn(), синхронизация currentTurnIndex на игрока.

    Обоснование. В соло-игре акторы — игрок и авто-враги; отдельный цикл по initiativeOrder не имеет смысла до мультиплеера. Раунд нужен только для «1/раунд» эффектов (реакция, legendary, некоторые спеллы).

    Как. 

    // GameState.kt
fun ActionEconomy.beginTurn(round: Int) =
    ActionEconomy(turnSerial = round)   // action/bonus/free/reaction = false, movementUsed = 0

// SessionService.processTurn (нормальный ход)
combatState = combatState?.beginPlayerTurn()      // round++, currentTurnIndex -> player
playerState = playerState.copy(actionEconomy = playerState.actionEconomy.beginTurn(combatState?.round ?: 0))
    CombatState.nextRound()/nextTurn() оставляем как внутренние методы beginPlayerTurn(). Если боя нет (combatState == null) — beginTurn вызывается с локальным счётчиком ходов.

    Отвергнуто: (C) отдельный CombatStateService — преждевременно.

    2.9.C — Movement без трекинга¶

    Решение. Ввести абстрактный бюджет движения, без сетки: CharacterState.speed: Int (футы) + ActionEconomy.movementUsed: Int. Дистанция приходит из намерения (ActionIntent/DSL, поле distance), движок вычитает. Dash добавляет speed к бюджету (2.9.R).

    Обоснование. Без позиций полноценная геометрия невозможна, но бюджет делает Dash осмысленным и ограничивает «бесконечное движение». Terrain/Stand Up/ranged-in-melee — поверх бюджета (2.9.S/T), позже.

    Как. 

    // CharacterState
val speed: Int = 30,
// ActionEconomy
val movementUsed: Int = 0,
fun movementRemaining(speed: Int) = (speed - movementUsed).coerceAtLeast(0)
    speed берётся из races.yml/classes.yml (dwarf 25 и т.п.), дефолт 30. Поля — spec-first в OpenAPI. JSON-сессии совместимы (дефолты).

    2.9.D — MOVE_JUMP/CRAWL/CLIMB/SWIM → CHECK¶

    Решение. Добавить ActionType.MOVE. MOVE_WALK/RUN/JUMP/CRAWL/CLIMB/SWIM/SNEAK маппить в MOVE (не CHECK). MOVE_HIDE→HIDE, MOVE_FLEE→DISENGAGE (как сейчас). Проверки (Athletics для CLIMB/SWIM, Acrobatics/STR для JUMP) — вложения внутрь resolveMove, а не отдельный Action. Движение списывает бюджет, не Action.

    Обоснование. Это разные бюджеты: CHECK тратит основное действие, движение — нет. Canon: лазание/плавание стоят доп. футов (×2), прыжок ограничен STR.

    Как. 

    // ActionParser.kt
"MOVE_WALK","MOVE_RUN","MOVE_JUMP","MOVE_CRAWL","MOVE_CLIMB","MOVE_SWIM","MOVE_SNEAK" -> ActionType.MOVE
// TurnResolver.resolveMove: списать distance из бюджета; при CLIMB/SWIM distance*2; при необходимости — roll
    MOVE_TELEPORT → отдельный ActionType.MOVE с cost=0 (спелл-источник), не проверка.

    2.9.E — DSL BONUS_ATTACK → ATTACK¶

    Решение. Развести два шаблона: - BONUS_ATTACK → новый ActionType.BONUS_ATTACK → SpendBonusAction, резолв resolveAttack. - ATTACK_MULTI → ActionType.ATTACK (это основное Attack-действие с мультиатакой, не бонус).

    Обоснование. Ревью ошибочно объединяет их. Off-hand/two-weapon/Cunning Action — бонусные; ATTACK_MULTI — основное действие с Extra Attack.

    Как. 

    // ActionParser.kt
"BONUS_ATTACK" -> ActionType.BONUS_ATTACK
"ATTACK_MULTI" -> ActionType.ATTACK
// checkActionEconomy: BONUS_ATTACK -> проверка bonusActionUsed
// buildEconomyChanges: BONUS_ATTACK -> SpendBonusAction
    Whitelist loot-whitelist.yml/dsl — уточнить economyCost (см. 2.9.K).

    2.9.F — Extra Attack не работает¶

    Решение. Не дублировать: закрывается уже принятым 2.7.F + 2.7.LL. attackCount(class+level) + N последовательных resolveAttack с TurnMechanics.merge и ранним выходом при смерти цели, один SpendAction. 2.9 лишь проводит ATTACK/ATTACK_MULTI через этот путь.

    Как. repeat(attackCount(c)) { ... resolveAttack ... combined = combined.merge(r) } (точный код — 07-combat-holes-response.md:135-151, 471-483).

    🔴 Критичные¶

    2.9.G — Casting Time не влияет на экономию¶

    Решение. Резолвить бюджет заклинания из Spell.castingTime: ACTION→SpendAction, BONUS_ACTION→SpendBonusAction, REACTION→SpendReaction, FREE/none→без списания. Точка — buildEconomyChanges/resolve при ActionType.SPELL, через SpellRegistry по id заклинания.

    Как. 

    fun StateChange.spendForCastingTime(ct: CastingTime): StateChange? = when (ct) {
    CastingTime.BONUS_ACTION -> StateChange.SpendBonusAction
    CastingTime.REACTION     -> StateChange.SpendReaction
    CastingTime.ACTION, CastingTime.ONE_MINUTE, CastingTime.TEN_MINUTES,
    CastingTime.ONE_HOUR, CastingTime.EIGHT_HOURS -> StateChange.SpendAction
    CastingTime.FREE -> null
}
    checkActionEconomy для SPELL должен знать castingTime (проверять соответствующий флаг до списания). Зависит от 2.9.Q (bonus spell ограничивает второй каст).

    2.9.H — READY не реализован¶

    Решение. ActionType.READY_ACTION + хранение CharacterState.readiedAction: ReadiedAction? (сохранённое действие + структурированный триггер). READY тратит основное действие сразу. Триггер детектируется движком автоматически (не «ручной» пункт меню): реестр триггеров расширяется, при совпадении действие исполняется как реакция (тратит reaction).

    Как. 

    data class ReadiedAction(val action: String, val trigger: ReadiedTrigger, val roundSet: Int)
enum class ReadiedTrigger { ENEMY_ENTERS_REACH, ENEMY_ATTACKS, ENEMY_CASTS, ALLY_HIT, CUSTOM }
// processTurn: "готовлю действие ... когда ..." -> parse trigger -> set readiedAction + SpendAction
// detection: в applyEnemyTurn/processTurn проверять события против readiedAction.trigger
//   (переиспользовать ReactionTrigger/ReactionTriggerRegistry)
// processReactionTurn: исполнить сохранённое действие + SpendReaction, очистить readiedAction
    Whitelist READY_ACTION уже есть — добавить DSL-шаблон, маппинг и READY_*-триггеры в reaction_triggers.yml. Зависит от 2.9.B (round) и 2.9.C (позиционные триггеры — по Enemy.isEngaged).

    2.9.I — DELAY не реализован¶

    Решение. Отложить. В соло-бою очередь = [игрок] и авто-ответ врагов; «отложить ход» не даёт игроку ничего, кроме перестановки в списке из одного элемента.

    Обоснование. Преждевременно до мультиплеера/сложной инициативы (см. AGENTS.md «не строить преждевременно»). Крючок: при мультиплеере — reorder CombatState.initiativeOrder.

    2.9.J — Free Interaction не подключён¶

    Решение. Ввести бюджет свободного взаимодействия: - первый OBJECT_INTERACTION в ходу — бесплатно (эмитит SpendFreeInteraction); - последующие объектные действия стоят основное действие.

    Как. 

    // ActionType.OBJECT_INTERACTION (или reuse OBJECT с признаком free)
// checkActionEconomy: OBJECT_INTERACTION -> if (freeInteractionUsed) check actionUsed else null
// buildEconomyChanges: OBJECT_INTERACTION -> SpendFreeInteraction
// SessionService: SpendFreeInteraction -> withFreeInteractionUsed()  (обработчик уже есть, :2178)
    Объектные действия сейчас идут как ActionType.OBJECT и тратят Action (2.9.5).

    🟡 Важные¶

    2.9.K — consumesAction = true по умолчанию¶

    Решение. consumesAction из call-site убираем. Добавляем economyCost: ACTION | BONUS_ACTION | REACTION | FREE | MOVE | NONE в dsl-registry.yml и мигрируем все 5 whitelist-файлов + DSL сразу. buildEconomyChanges читает economyCost; старый mechanics.consumesAction остаётся только как совместимый дефолт (ACTION) до полного выпиливания.

    Обоснование. Белый список «свободных» действий опасен (неизвестное действие станет бесплатным). Данные безопаснее и единообразнее bool-флагов по call-site. Полная миграция исключает двойные источники истины (в отличие от «только затронутых шаблонов»).

    Как. 

    # dsl-registry.yml / whitelist/*.yaml
ATTACK:        { economyCost: ACTION }
BONUS_ATTACK:  { economyCost: BONUS_ACTION }
OPPORTUNITY_ATTACK: { economyCost: REACTION }
MOVE_WALK:     { economyCost: MOVE }
MOVE_STAND_UP: { economyCost: MOVE }
OPEN_CONTAINER:{ economyCost: FREE }

    2.9.L — Дублирование CombatState.actionUsed / ActionEconomy.actionUsed¶

    Решение. Удалить 4 флага из CombatState (GameState.kt:1387-1390) и их методы. Единственный источник — ActionEconomy. Обновить тесты/glue (CombatSteps.kt). CombatState оставляет round, initiativeOrder, currentTurnIndex, surprisedParticipants, combatEnded.

    Обоснование. Два источника истины гарантируют рассинхрон. JSON-сессии: лишние поля просто игнорируются при десериализации.

    2.9.M — ResetActionEconomy не эмитится¶

    Решение. Разделить семантику: - StateChange.ResetActionEconomy — полный сброс; эмитить из LongRest (вместо inline- reset()), убрать дублирование. - Новый StateChange.RestoreAction — восстановить только Action (Action Surge, 2.7.I), не трогая bonus/reaction.

    Как. 

    is StateChange.RestoreAction -> actionEconomy = actionEconomy.copy(actionUsed = false)
// resolveFeatureAction(ACTION_SURGE) -> StateChange.RestoreAction + SpendClassResource(ACTION_SURGE)

    2.9.N — LongRest сбрасывает, ShortRest — нет¶

    Решение. Убрать сброс экономии из LongRest (и не добавлять в ShortRest): сброс экономии — исключительная ответственность beginPlayerTurn (2.9.B). Асимметрия исчезает по определению. Экономика вне боя не имеет смысла.

    Как. Удалить actionEconomy = actionEconomy.reset() из SessionService.kt:2065; при следующем ходу beginPlayerTurn сбросит всё сам.

    2.9.O — Нет MechanicsBlock.actionEconomy¶

    Решение. Добавить в MechanicsBlock (и OpenAPI) actionEconomy: action/bonusAction/reaction/freeInteraction (boolean), movementRemaining: Int. characterState.actionEconomy тоже остаётся, но фронту нужен компактный per-turn блок.

    Как. MechanicsBlock.actionEconomy: ActionEconomyDto — spec-first, затем DTO и заполнение в SessionService/TurnResolver.

    2.9.P — Opportunity Attack: триггер не реализован¶

    Решение. MVP-триггер привязать к движению игрока, а не к геометрии: если игрок выполняет MOVE, покидая melee (флаг enemy.isEngaged), и не использовал DISENGAGE, — предложить врагу OA (авто, через applyEnemyTurn). Провокационная атака игрока остаётся текстовым regex до появления позиций.

    Обоснование. Без сетки единственный детектируемый случай — уход из melee. Полная геометрия — отложена. Зависит от 2.9.C/D и Enemy.isEngaged (2.7.N/L).

    2.9.Q — Bonus spell + action-cantrip не ограничено¶

    Решение. Добавить ActionEconomy.bonusSpellCastThisTurn: Boolean. Если в ходу кастовали заклинание бонусным действием, основным действием можно только cantrip (уровень 0). Проверять в checkActionEconomy/резолвере заклинаний; сбрасывается beginTurn.

    Как. 

    val bonusSpellCastThisTurn: Boolean = false
// при ActionType.SPELL, spellLevel > 0 && bonusSpellCastThisTurn -> отказ

    2.9.R — Dash без speed¶

    Решение. Закрывается 2.9.C: resolveDash добавляет speed к доступному движению и помечает dashUsedThisTurn; тратит Action.

    Как. resolveDash → StateChange.SpendAction (есть) + StateChange.AddMovement(speed) или вычисляемо: movement = speed + (if dash) speed else 0.

    2.9.S — Stand Up из Prone¶

    Решение. MOVE_STAND_UP требует ≥ половины speed бюджета (округление вниз), снимает статус «Снижен»/Prone; MOVE_DROP_PRONE бесплатно. Реализуется в блоке движения (2.9.C).

    2.9.T — Difficult Terrain¶

    Решение. Без сетки — через явное намерение: MOVE_DIFFICULT_TERRAIN {distance} стоит ×2 бюджета. Автодетекция по местности — отложена вместе с сеткой.

    2.9.U — Action Surge¶

    Решение. Закрывается 2.7.I + 2.9.M: resolveFeatureAction(ACTION_SURGE) эмитит RestoreAction + списывает ClassResources.actionSurge (1/отдых). Восстанавливает только Action.

    2.9.V — Haste / Slow¶

    Решение. Реализовать через activeModifiers (не хардкод): - Haste: +2 AC, speedMultiplier=2, extraAction (ограничен Attack/одиночный каст), истощение при окончании. - Slow: actionRestriction (одно действие, без бонусной атаки), speedMultiplier=0.5, ограничение реакций. Отложено до блока эффектов заклинаний (2.7 modifiers), зафиксированы поля контракта.

    2.9.W — Legendary Actions: только +1 атака¶

    Решение. Отложить до 2.24. Целевая модель: Enemy.legendaryActions: Int (пул 3/раунд), refresh в начале раунда, трата по одному действию вне хода. Текущий legendary = +1 атака — временный костыль (2.9.12).

    2.9.X — Lair Actions¶

    Решение. Отложить до 2.24 / 2.7.T. Сейчас — только крючок (эффект по инициативе 20).

    2.9.Z — Нет тестов на free/ready/delay/extra attack¶

    Решение. Добавить: - unit (ActionEconomyTest): persist реакции на follow-up; BONUS_ATTACK→bonus; castingTime→ SpendBonus/Reaction; bonus-spell+cantrip ограничение; free interaction budget; extra attack N× и агрегация; RestoreAction. - component (Gherkin): «реакция не восстанавливается между ходами того же раунда», «бонусная атака не тратит Action», «второе объектное действие стоит Action», «READY выполняется как реакция».

    2.9.Y — Time Stop (🟢)¶

    Решение. Отложить. Не входит в MVP; помечено в чеклисте как желательное.

    data class ActionEconomy(
    val actionUsed: Boolean = false,
    val bonusActionUsed: Boolean = false,
    val reactionUsed: Boolean = false,
    val freeInteractionUsed: Boolean = false,
    val movementUsed: Int = 0,               // 2.9.C

    val dashUsedThisTurn: Boolean = false,   // 2.9.R

)

val speed: Int = 30,                         // 2.9.C/AA
val turnSerial: Int = 0,                     // глобальный счётчик ходов (2.9.JJ)
val readiedAction: ReadiedAction? = null,    // 2.9.H

// Enemy (минимально; полный ActionEconomy — не для врага)
val speed: Int = 30,                         // 2.9.BB

val distance: Int? = null,                   // 2.9.CC, футы

    val action: String,
    val trigger: ReadiedTrigger,
    val roundSet: Int,

MOVE, BONUS_ATTACK, OBJECT_INTERACTION, READY_ACTION   // 2.9.D/E/J/H

    7. Уточнения после второго ревью (2.9.AA–OO)¶

    2.9.AA — источник speed¶

    Решение. CharacterState.speed: Int = 30 — дефолт. Источник базовой скорости — единый SpeedResolver.baseSpeed(raceId, classId, features); до появления races.yml (Блок 2.3) — временная SRD-таблица рас, затем миграция в данные.

    Как. 

    fun baseSpeed(raceId: String?, features: Set<String>): Int = when (raceId) {
    "dwarf", "halfling", "gnome" -> 25
    "wood_elf" -> 35            // деревянный эльф (не всякий elf)
    else -> 30
}
// SessionService.create: speed = baseSpeed(raceId, features)
    Единая точка, без «хардкода по месту»; при 2.3 SpeedResolver читает races.yml (RacialTrait.speed), поле CharacterState.speed остаётся.

    2.9.BB — движение у Enemy¶

    Решение. Полный ActionEconomy врагу не даём. Минимально: Enemy.speed: Int = 30 (для OA/побега) и Enemy.reactionUsed: Boolean = false. Данные скорости — бестиарий (2.15). Враг двигается нарративно; отдельного бюджета движения у него нет.

    Как. Enemy.speed участвует только в детекции OA (уход из melee, 2.9.P) и в описании.

    2.9.CC — парсинг distance¶

    Решение. ActionIntent.distance: Int? — опционально, из structured output LLM (ADR-0009). Правила: - null → движение не трекаем (нарратив, свободный ход); - задано > remaining → clamp до остатка + предупреждение (не отказ — не ломаем естественно-языковую игру); - regex-fallback (на N футов) — для оффлайна/тестов.

    Как. 

    val dist = intent.distance
if (dist == null) { /* narrative move, no SpendMove */ }
else {
    val remaining = currentMovement
    val spent = minOf(dist, remaining)
    if (spent < dist) warn("Недостаточно движения: перемещение ограничено $remaining фт")
    changes += StateChange.SpendMove(spent)
}

    2.9.DD — StateChange.SpendMove¶

    Решение. Вариант A — единый паттерн Spend*: StateChange.SpendMove(distance: Int), обрабатывается в applyStateChanges (movementUsed += distance). Отдельный StateChange.MarkDash для dashUsedThisTurn.

    2.9.EE — READY + концентрация¶

    Решение. ReadiedAction.isConcentration: Boolean. Заклинание исполняется в момент триггера, и концентрация начинается тогда же; старая концентрация заменяется (канон). Концентрация сейчас — заглушка (SessionService.kt:2144-2163, TODO) → поле фиксируется, реальная замена — при реализации концентрации.

    2.9.FF — READY не сработал¶

    Решение. Если триггер не сработал до начала следующего хода — readiedAction теряется, Action не возвращается (канон).

    Как. В beginPlayerTurn/beginTurn: if (readiedAction?.roundSet ?: Int.MAX_VALUE < round) readiedAction = null.

    2.9.GG — READY и availableReactions¶

    Решение. processReactionTurn валидирует реакцию по availableReactions. При совпадении триггера READY в availableReactions синтезируется запись READIED_ACTION (тем же механизмом, что ReactionProposal). Валидация расширяется до availableReactions ∪ {READIED_ACTION}. Безопасно, без bypass.

    Как. При сборке availableReactions после applyEnemyTurn добавить READIED_ACTION, если triggerMatches(readiedAction.trigger, enemyEvents).

    2.9.HH — bonusSpellCastThisTurn и Action Surge¶

    Решение. Ограничение «bonus spell → далее только cantrip» действует весь ход. Action Surge восстанавливает только Action и не сбрасывает bonusSpellCastThisTurn. Сбрасывается исключительно beginTurn.

    2.9.II — Enemy.reactionUsed¶

    Решение. Enemy.reactionUsed: Boolean, сбрасывается в начале раунда (beginPlayerTurn — вместе с экономией игрока). OA тратит его (StateChange.EnemyReactionUsed(enemyId)); 1 OA/раунд на врага.

    2.9.JJ — beginPlayerTurn при combatState == null¶

    Решение. Глобальный счётчик CharacterState.turnSerial: Int инкрементируется на каждом нормальном ходу независимо от боя. ActionEconomy.turnSerial — его проекция для идемпотентности. Бой (combatState) влияет только на enforcement, не на счётчик.

    Как. 

    val serial = playerState.turnSerial + 1
playerState = playerState.copy(
    turnSerial = serial,
    actionEconomy = playerState.actionEconomy.beginTurn(serial),
)
combatState = combatState?.beginPlayerTurn()   // round++ (если бой)

    2.9.KK — движение вне боя¶

    Решение. Вне боя (combatState == null) MOVE — свободно/нарративно; SpendMove не эмитится, movementUsed не ограничивается. Enforcement (checkActionEconomy по движению) действует только в бою.

    2.9.LL — формула Dash¶

    Решение. movementUsed не меняется Dash'ем; меняется доступный максимум: 

    val effectiveSpeed = speed + (if (dashUsedThisTurn) speed else 0)
val remaining = (effectiveSpeed - movementUsed).coerceAtLeast(0)
    resolveDash → SpendAction + MarkDash; movementUsed всегда ≥ 0.

    2.9.MM — MOVE_TELEPORT — не движение¶

    Решение. MOVE_TELEPORT не маппится в ActionType.MOVE. Телепортация — это SPELL (Misty Step — bonus, Dimension Door — action) или предмет (USE_ITEM). Шаблон сохраняем как маркер, но economyCost берётся из источника (spell/item).

    2.9.NN — enemyShouldAct для MOVE¶

    Решение. MOVE не входит в триггеры контратаки: враг не атакует на движение. Единственное исключение — OA врага при уходе из melee без DISENGAGE (2.9.P); это отдельный путь, а не applyEnemyTurn-контратака.

    2.9.OO — назначение turnSerial¶

    Решение. Идемпотентность сброса + истечение READY. 

    fun beginTurn(serial: Int): ActionEconomy =
    if (turnSerial == serial) this else ActionEconomy(turnSerial = serial)
    Сериализуется в JSON как часть ActionEconomy; дефолт 0 → обратная совместимость старых сессий.

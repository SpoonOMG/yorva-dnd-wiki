    Аудит умений/заклинаний — Блок 2.6: Скиллы и проверки (сверка дыр + решения)¶

    Фактура — 06-skills-facts.md. Ревью пользователя: 18 дыр (2.6.A–2.6.R). Канон: D&D 5e SRD. Паттерны из предыдущих блоков: *Registry (YAML), sealed-эффекты (FeatEffect/RacialTraitEffect), CharacterState, TurnResolver.resolveXxx.

    Решения по дырам¶

    2.6.A — Passive Perception¶

    Принято: A + C. Хранить passiveSkills: Map<String, Int> в CharacterState (обновлять при создании/level-up), + метод вычисления для всех навыков. 

    // GameState.kt — в CharacterState
val passiveSkills: Map<String, Int> = emptyMap(),   // skill -> 10 + mod + PB

// SessionService — при create/levelUp:
fun computePassive(character: CharacterState, skill: String): Int {
    val mod = character.effectiveAttributes.wisMod // для perception; для других — свой ability
    val pb = if (skill in character.proficiencies) proficiencyBonus(character.level) else 0
    return 10 + mod + pb
}
    - Использовать: resolveSkillCheck/detectDc — когда действие «заметить пассивно» (no roll), сравнивать passivePerception с DC скрытности. Остальные 17 — через passiveSkill(skill) (Insight, Investigation, Stealth).

    2.6.B — Contested checks¶

    Принято: A. Универсальный resolveContestedCheck. 

    private fun resolveContestedCheck(
    attacker: CharacterState, defender: CharacterState,
    skillA: String, skillB: String, profile: DifficultyProfile
): TurnMechanics {
    val aMod = abilityMod(attributeForSkill(skillA)) + skillProficiencyBonus(attacker, skillA)
    val bMod = abilityMod(attributeForSkill(skillB)) + skillProficiencyBonus(defender, skillB)
    val aRoll = dice.d20(); val bRoll = dice.d20()
    val success = aRoll + aMod >= bRoll + bMod
    // ...
}
    - B отклонён: таблица не нужна, контекст боя определяет пару навыков (хардкод-маппинг в ActionParser/TurnResolver). - Сценарии (маппинг в resolveSkillCheck/resolveActionTemplate): Stealth vs PassivePerception (2.6.A), Grapple→Athletics/Acrobatics, Shove→Athletics/Acrobatics, Deception/Intimidation/Persuasion vs Insight. - Defender без персон-состояния → passive (10 + mod).

- column: { name: dc_very_hard, type: INT, defaultValueNumeric: 25 }

    2.6.E — Три источника ability (уточнение: не два, а три)¶

    Принято: единый источник — SkillDef.ability (skills.yml). Факт из кода: 1. resolveSkillCheck — sc.attribute (DB skill_checks, TurnResolver.kt:758-766). 2. resolveActionTemplate — template.attribute ?: attributeForSkill(template.skill) (:851). 3. SkillDef.ability — только DTO (SkillRegistry.kt:81, toDto). 4. attributeForSkill хардкод (:985-993) — 4-й путь для generic CHECK (resolveCheck → detectAttribute). 

    // Единый маппинг: skill -> attribute через SkillDef.ability (или SkillRegistry)
fun abilityMod(skill: String?, character: CharacterState): Int = when (skillRegistry.get(skill)?.ability) {
    "STRENGTH" -> character.effectiveAttributes.strMod
    "DEXTERITY" -> character.effectiveAttributes.dexMod
    "CONSTITUTION" -> character.effectiveAttributes.conMod
    "INTELLIGENCE" -> character.effectiveAttributes.intMod
    "WISDOM" -> character.effectiveAttributes.wisMod
    "CHARISMA" -> character.effectiveAttributes.chaMod
    else -> character.effectiveAttributes.dexMod
}
    - Удалить attributeForSkill/detectAttribute-хардкод; sc.attribute/template.attribute оставить как override (явно заданный в каталоге), иначе SkillDef.ability.

    2.6.F — Активные способности в skills.yml¶

    2.6.G — Generic CHECK только disadvantage¶

    Принято: добавить advantage. 

    // resolveCheck (TurnResolver.kt:1965-1967) — сейчас:
val roll = if (disadvantage) dice.d20WithDisadvantage().first else dice.d20()
// станет:
val advantage = hasAdvantageOnSkill(character, skillFromAction(lower))
val roll = when {
    advantage && !disadvantage -> dice.d20WithAdvantage().first
    disadvantage && !advantage -> dice.d20WithDisadvantage().first
    else -> dice.d20()
}
    - skillFromAction(lower) — определить навык по regex (общий с inferCheckSkill в ActionParser).

    2.6.H — Help action¶

    Принято: через activeModifiers. - Факт: HELP_ALLY (ActionWhitelist.kt:222, :488 → ActionType.SOCIAL_CHECK, socialCheckCode=persuasion) — Help работает как SOCIAL_CHECK, эффекта advantage нет. - Добавить в CharacterState activeModifiers (по образцу buff-модификаторов applyModifiers, TurnResolver.kt): Modifier(source="help", type=ADVANTAGE, targetSkill=?, durationRounds=1). - hasAdvantageOnSkill/hasAdvantageOnChecks учитывают activeModifiers. - В resolveSocialCheck/resolveCheck при коде HELP_ALLY → не бросок, а StateChange.ApplyModifier на союзника.

    2.6.I — Jack of All Trades (Bard 2)¶

    Принято: в skillProficiencyBonus. 

    fun skillProficiencyBonus(character: CharacterState, skill: String?): Int {
    if (skill == null) return 0
    val base = proficiencyBonus(character.level)
    if (character.proficiencies.contains(skill)) {
        return if (character.expertiseSkills.contains(skill)) base * 2 else base
    }
    // Jack of All Trades (Bard 2+): половина PB на все непрофильные
    if ("jack_of_all_trades" in character.activeFeatures) return base / 2
    return 0
}
    - jack_of_all_trades — id feature, добавляется через levelUp Bard 2 (Блок 2.4 LevelUpService).

    Новые дыры (ревью пользователя, 2.6.S–2.6.Y)¶

    2.6.S — passiveSkills обновление¶

    Принято: динамически passiveSkill(skill) в TurnResolver; passiveSkills в CharacterState — кэш. Обновлять в SessionService.create, LevelUpService.levelUp (ASI), SessionService.allocateASI (:1276), при получении Expertise. Факт: allocateASI есть; при изменении WIS кэш обязан пересчитываться.

    2.6.T — Contested adv/disadv¶

    Принято: rollWithModifiers. Обертка на advantage (Stealth/Скрыт), disadvantage (Blinded/statuses), activeModifiers. Применяется к обеим сторонам.

    2.6.U — Grapple/Shove vs Enemy¶

    Принято: C — примитивы. resolveContestedCheck(attackMod: Int, defenseMod: Int, advantageA, disadvantageA, advantageB, disadvantageB). Для Enemy брать enemy.attackBonus/аналогичный мод; для PC — abilityMod + skillProficiencyBonus. Не требует общего интерфейса.

    2.6.V — Help длительность¶

    Принято: trigger="NEXT_CHECK" (расходуется при следующей проверке/атаке), не durationRounds.

    2.6.W — jack_of_all_trades источник¶

    Принято: canonicalClassId == "bard" && level >= 2 (до 2.1.12). Факт: CharacterState.canonicalClassId (GameState.kt:409) есть; CharacterState НЕ имеет activeFeatures/features (поле features на :649 принадлежит Enemy); «Мастер на все руки» — classes.yml:610 (Bard, level 2). После 2.1.12 — читать из classFeatures.

    2.6.X — SkillDto источник character¶

    Принято: два endpoint. GET /api/skills — каталог (без bonus); GET /api/sessions/{id}/skills — навыки персонажа (proficient/expertise/bonus/passiveScore).

    2.6.Y — Endpoint check whitelist¶

    Принято: через валидатор. CheckRequest → ActionIntent(type=CHECK, skill) → whitelist/валидатор → resolveSkillCheck/resolveCheck. Прямой вызов резолвера запрещён.

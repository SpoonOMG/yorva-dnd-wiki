    Аудит умений/заклинаний — Блок 2.3: Расы (races)¶

    Роль: технический аудитор. Только факты из кода. Формат — как в Блоках 1, 2.1, 2.2. Если чего-то нет — «отсутствует». Пути и строки указаны.

    2.3.1. КАТАЛОГ РАС¶

    2.3.1.1. Файл каталога рас¶

    Отсутствует. В backend/app/src/main/resources/ файла races.yml/races.yaml нет. Полный список YAML в resources: subclasses.yml, level-table.yml, skills.yml, semantic-dictionary.yml, settingReskin.yml, loot-whitelist.yml, classes.yml, feats.yml, tools.yml, dsl-registry.yml, dsl-templates.yml, application.yml, backgrounds.yml, whitelist/*.yaml, llm/setting-tones.yml, db/changelog/**.

    2.3.1.2. Любой файл, связанный с расами¶

    • Поиск по именам файлов (*race*, *origin*, *ancestry*, *lineage*) в репозитории (кроме node_modules/build/.git) — совпадений нет.
    • Понятие «раса» присутствует только как свободный текст origin:
    • BackstoryService.kt:33 — "Происхождение/раса: $it. " (в промпт бэкстори).
    • frontend/components/game/CharacterCreationWizard.tsx:246 — поле ввода Происхождение / раса.
    • frontend/components/game/CharacterCreationWizard.tsx:250 — onChange={(e) => setOrigin(e.target.value)}.

    2.3.1.3. Загрузчик рас¶

    Отсутствует. Класса/метода загрузки рас нет. Для сравнения — существующие загрузчики: - classes/ClassRegistry.kt — классы (classes.yml). - classes/SubclassRegistry.kt — подклассы (subclasses.yml). - classes/FeatRegistry.kt — черты (feats.yml, FeatRegistry.kt:25-48). - classes/LevelTableRegistry.kt — таблица уровней (level-table.yml). - skills/SkillRegistry.kt — навыки (skills.yml). BackgroundRegistry тоже отсутствует: данные backgrounds.yml не читаются — getBackgroundProficiencies захардкожен в SessionService.kt:69.

    2.3.1.4. Модель Race / RacialTrait¶

    Отсутствует. Grep по class Race, data class Race, interface Race, class RacialTrait, data class RacialTrait — 0 совпадений. Слово Race/racial в Kotlin-коде — 0 совпадений.

    2.3.1.5. Количество рас¶

    0. Каталога/модели/загрузчика нет; расы не перечислены как данные.

    2.3.2. МОДЕЛЬ ДАННЫХ РАСЫ¶

    2.3.2.1. data class Race¶

    Отсутствует. Grep data class Race / class Race — 0 совпадений. Ближайшие существующие модели (не раса): Attributes (GameState.kt:123-151), CharacterState (GameState.kt:326+).

    2.3.2.2. Поля (id, name, description, traits, abilityBonuses, speed, size, languages)¶

    Отсутствуют — модели нет, полей нет. Что есть в CharacterState и может быть связано с расой по смыслу: - languages: List<String> (GameState.kt:413) — заполняется из background (см. 2.3.7.5). - proficiencies: List<String> (:337) — из класса/предыстории. - attributes: Attributes (:329) — из запроса, не из расы. Полей speed, size, abilityBonuses, traits, raceId в CharacterState нет (проверено 2.3.6/2.3.7).

    2.3.2.3. Поле subraces¶

    Отсутствует (модели нет; grep subrace = 0).

    2.3.2.4. Поле racialTraits¶

    Отсутствует (grep racial = 0).

    2.3.3. RACIAL TRAITS¶

    2.3.3.1. Модель RacialTrait¶

    Отсутствует. Grep data class RacialTrait / class RacialTrait — 0 совпадений.

    2.3.3.2. Поля (actionType, resourceId, usesPerLevel, recharge, choice)¶

    В существующей модели классовых фич ClassFeature эти поля есть (CharacterClass.kt:51-65): name, level, description, actionType: FeatureActionType?, resourceId, usesPerLevel: Map<Int,Int>?, recharge: RestType?, choice: FeatureChoice?. Для расовых traits такой модели нет. Модель Enemy.features: List<String> (GameState.kt:573) — только строковые коды, без полей.

    2.3.3.3. Какие racial traits реализованы¶

    Никакие. Grep по Darkvision/Тёмное зрение, Breath Weapon, Relentless, Fey Ancestry, Trance, Stonecunning — 0 совпадений в Kotlin-коде. Связанное наблюдение: lucky присутствует в feats.yml (черта, не раса) — см. 2.3.8.3.

    2.3.3.4. Где хранятся racial traits¶

    Отсутствует — хранилища нет. Существующий паттерн хранения аналогичных каталогов (для сравнения, не для рас): - данные: backend/app/src/main/resources/*.yml (например classes.yml, feats.yml, subclasses.yml); - загрузка: классы-реестры classes/*Registry.kt (см. 2.3.1.3); - модель фичи: ClassFeature (CharacterClass.kt:51-65).

    2.3.3.5. Как парсятся racial traits¶

    Отсутствует — парсинга нет. Для сравнения: SubclassRegistry.kt:41-47 парсит фичи подклассов только как name/level/description; FeatRegistry.kt:25-48 парсит feats.yml.

    2.3.3.6. Какие поля парсятся/игнорируются¶

    Неприменимо — racial traits не парсятся. Для сравнения (классовые фичи): ClassRegistry парсит полный ClassFeature; SubclassRegistry заполняет только name/level/description, остальные поля (actionType/resourceId/usesPerLevel/recharge/choice) остаются null/default.

    2.3.4. SUBRACES¶

    • 2.3.4.1. Подрасы (High Elf, Wood Elf, Hill Dwarf, Mountain Dwarf) — отсутствуют (grep subrace/подрас = 0).
    • 2.3.4.2. Моделирование — отсутствует.
    • 2.3.4.3. Выбор — отсутствует (в создании персонажа выбора подрас нет, CreateSessionRequest — SessionDtos.kt:15-40).
    • 2.3.4.4. Отдельные traits у подрас — отсутствуют.

    2.3.5. ABILITY SCORE INCREASES ОТ РАСЫ¶

    2.3.5.1. Поле abilityBonuses у расы¶

    Отсутствует.

    2.3.5.2. Как применяются¶

    Расовых бонусов нет. Атрибуты задаются клиентом при создании: - CreateSessionRequest.attributes: Attributes — обязательное поле (SessionDtos.kt:28). - SessionService.create: val attrs = request.attributes (SessionService.kt:325), затем валидация point-buy (:334-336). - При level-up ASI накапливается в pendingASI (GameState.kt:406), endpoint POST /sessions/{id}/levelup/asi (SessionController.kt:136).

    2.3.5.3. Учёт при расчёте модификаторов¶

    Модификаторы считаются только из Attributes (GameState.kt:137-150). Расовых бонусов в расчёт не входит.

    2.3.5.4. Custom lineage (Tasha's)¶

    Отсутствует. Полей/trait-выбора в коде нет. Существующий point-buy: - POINT_BUY_BUDGET = 27 (SessionService.kt:49); - ATTR_MIN = 8, ATTR_MAX = 15 (:50-51); - стоимость: POINT_COST = {8:0, 9:1, 10:2, 11:3, 12:4, 13:5, 14:7, 15:9} (:52); - базовый HP при отсутствии класса: BASE_HP = 10 (:53). Для сравнения, Attributes (модель) допускает диапазон 8..20 (GameState.kt:132), но при создании применяется 8..15.

    2.3.6. ORIGIN vs RACEID¶

    2.3.6.1. Где хранится origin¶

    • Тип: origin: String? — свободный текст.
    • DTO запроса: CreateSessionRequest.origin (SessionDtos.kt:20-21) с @field:Size(max = 200).
    • В состоянии: Participant.origin: String? (GameState.kt:616).
    • Сохраняется при создании: SessionService.kt:410,424 — origin = request.origin.

    2.3.6.2. Как используется origin¶

    Только нарративно/визуально, механических эффектов нет: - Participant.narrativeDescription (GameState.kt:648) — "Происхождение: $it", идёт в characterDescription промпта (SessionService.kt:549,676,875; ContextBuilder.kt:91-99). - Participant.portraitDescription (GameState.kt:674) — для портрета. - buildVisualAnchor (GameState.kt:696-722, коммент :706 — «Раса/происхождение — главный маркер внешности») — origin берётся take(80) (:707). - BackstoryService.kt:33 — «Происхождение/раса: $it. » в промпт бэкстори; :118 — добавление origin в fallback-бэкстори. - ContextBuilder.kt:97 — «линза персонажа»: учёт происхождения при описании сцены.

    2.3.6.3. Есть ли raceId¶

    Отсутствует. Grep raceId — 0 совпадений. В CreateSessionRequest, CharacterState, Participant поля raceId нет.

    2.3.6.4. Маппинг «текст origin → механический raceId»¶

    Отсутствует.

    2.3.6.5. Как origin влияет на механики (HP, AC, speed)¶

    Не влияет. HP считается как hitDie + attrs.conMod (SessionService.kt:351-352), AC — 10 + attrs.dexMod (:353), поля speed нет (см. 2.3.7.3). origin в этих расчётах не участвует.

    2.3.6.6. Валидация origin¶

    • Единственная проверка — @field:Size(max = 200) (SessionDtos.kt:20-21).
    • Проверки существования расы/соответствия каталогу — отсутствует.

    2.3.7. ВЛИЯНИЕ РАСЫ НА ПЕРСОНАЖА¶

    • 2.3.7.1. HP — не влияет. hitDie + attrs.conMod (SessionService.kt:351-352); единственный источник доп. HP — l1Result.draconicHpBonus (сорцерер, SessionService.kt:393), не раса.
    • 2.3.7.2. AC — не влияет. 10 + attrs.dexMod (:353); draconicAcFloor (:394) — сорцерер, не раса. Есть поэкипировочные бонусы (GameState.kt:503-506).
    • 2.3.7.3. speed — отсутствует. Поля speed в CharacterState нет (grep val speed = 0). В whitelist встречаются флаги hasClimbSpeed/hasSwimSpeed/hasFlySpeed (whitelist/action-whitelist-core.yaml:138-144,169-171), но их определение/вычисление в Kotlin-коде — 0 совпадений (требует уточнения, где резолвятся).
    • 2.3.7.4. size — не влияет. Поля size у персонажа нет.
    • 2.3.7.5. languages — не влияет. CharacterState.languages заполняется из предыстории захардкоженной картой: SessionService.kt:362-366 (acolyte/sage → Common, Elvish; hermit/guild_artisan/noble/outlander → Common, Dwarvish; иначе пусто). Расовых языков нет. В backgrounds.yml есть поле languages: <int>, но оно в коде не читается (getBackgroundProficiencies захардкожен, SessionService.kt:69-84).
    • 2.3.7.6. proficiencies — не влияет. Владения = класс + предыстория (SessionService.kt:354-361). Расовых владений оружием нет.
    • 2.3.7.7. saving throws — не влияет. Спасброски — из класса (proficienciesForClass, SessionService.kt:59-66). Расовых преимуществ (Elf vs charm) нет.

    2.3.8. РАСОВЫЕ СПОСОБНОСТИ В БОЮ¶

    • 2.3.8.1. Breath Weapon (Dragonborn) — отсутствует (grep = 0).
    • 2.3.8.2. Relentless Endurance (Half-Orc) — отсутствует (grep = 0).
    • 2.3.8.3. Lucky (Halfling) — расовая версия отсутствует. Есть черта lucky в feats.yml (feats.yml:14-17, «3 очка удачи/день»), но её механическая обработка в TurnResolver/GameState не найдена. Статус расового Lucky — отсутствует.
    • 2.3.8.4. Fey Ancestry (Elf) — отсутствует (grep = 0).
    • 2.3.8.5. Trance (Elf) — отсутствует (grep = 0).
    • 2.3.8.6. Darkvision — отсутствует (grep Darkvision/Тёмное зрение = 0).
    • 2.3.8.7. Stonecunning (Dwarf) — отсутствует (grep = 0).

    2.3.9. РАСЫ В REST API¶

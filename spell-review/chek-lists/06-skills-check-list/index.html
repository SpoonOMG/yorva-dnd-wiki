    Принятые решения (ядро)¶

    Passive / Contested (2.6.A/B/S/T/U)¶

    • 2.6.A+S: динамический passiveSkill(skill) в TurnResolver (10 + abilityMod + PB); passiveSkills: Map<String,Int> в CharacterState — кэш, обновляется в SessionService.create, LevelUpService.levelUp, SessionService.allocateASI (:1276), при Expertise. 
      fun passiveSkill(character: CharacterState, skill: String): Int {
    val mod = abilityMod(character, skill) // из SkillDef.ability
    val pb = if (skill in character.proficiencies) proficiencyBonus(character.level) else 0
    return 10 + mod + pb
}
    • 2.6.B+T+U: resolveContestedCheck на примитивах (вариант C), с adv/disadv обеих сторон: 
      private fun resolveContestedCheck(
    attackMod: Int, defenseMod: Int,
    attackAdv: Boolean, attackDisadv: Boolean,
    defenseAdv: Boolean, defenseDisadv: Boolean,
): TurnMechanics
    • rollWithModifiers — обёртка над d20WithAdvantage/Disadvantage; для PC — hasAdvantageOnSkill/hasDisadvantageOnChecks/activeModifiers; для Enemy — моды из Enemy (attackBonus/аналогия).
    • Сценарии: Stealth vs PassivePerception, Grapple/Shove→Athletics/Acrobatics, Deception/Intimidation/Persuasion vs Insight.

    Ability-источник (2.6.E)¶

    Единый источник — SkillDef.ability (skills.yml); override — sc.attribute/template.attribute из каталога. Удалить attributeForSkill (TurnResolver.kt:985-993) и detectAttribute-хардкод. Generic CHECK → skillFromAction → SkillDef.ability; fallback else -> "dex".

    Каталог (2.6.F/O + P/X)¶

    • 2.6.F: удалить 19 активных id из skills.yml (есть в classes.yml); skills.yml → 18 канонических. Проверить ссылки (grep по 19 id) → заменить на feature-id/ClassFeatureHelper.
    • 2.6.O: SkillRegistry.loadFallback() (18 навыков) при отсутствии/падении YAML.
    • 2.6.P+X: расширить SkillDto (proficient, expertise, bonus, passiveScore); GET /api/skills — каталог (без bonus); GET /api/sessions/{id}/skills — навыки персонажа.

    DC (2.6.D/R)¶

    • 2.6.D: добавить колонки dc_very_easy=5, dc_very_hard=25, dc_nearly_impossible=30 (default — не breaking) + Liquibase + OpenAPI.
    • 2.6.R: LLM может задавать dc в 5–30; валидируется движком, при отсутствии — из каталога.

    Advantage/Disadvantage / Help / спец-фичи (2.6.G/H/I/J/L/M/N/V/W)¶

    • 2.6.G: generic resolveCheck — добавить advantage (не только disadvantage) через skillFromAction.
    • 2.6.H+V: Help → activeModifiers с trigger="NEXT_CHECK" (расходуется при след. проверке/атаке), не durationRounds.
    • 2.6.I+W: Jack of All Trades — canonicalClassId == "bard" && level >= 2 (до 2.1.12) в skillProficiencyBonus → base/2; после 2.1.12 — classFeatures. Факт: «Мастер на все руки» classes.yml:610.
    • 2.6.J: Reliable Talent — min 10 на proficient-проверках.
    • 2.6.K: Stroke of Luck — отложено (🟢).
    • 2.6.L: adv/disadv статусов вынести в YAML-каталог (общий с 2.3 RacialTraitEffect); заменить setOf(...) в TurnResolver.kt:1933-1940.
    • 2.6.M: CHECK_TOOL_{type} + toolProficiencyBonus (LOCKPICK/DISARM_TRAP→thieves_tools, FORGERY→forgery_kit, DISGUISE→disguise_kit, HERBALISM→herbalism_kit, NAVIGATION→navigators_tools).
    • 2.6.N: proficiencies — единственный источник расчёта; skills — для UI.

    API / валидация (2.6.Q/Y)¶

    • 2.6.Q+Y: POST /api/sessions/{id}/check; CheckRequest { skill, dc?, target? }; проходит через валидатор/whitelist (ActionIntent(type=CHECK, skill)), не напрямую в резолвер; dc валидируется 5–30. Обновить OpenAPI.
    • 2.6.C: Group checks — отложено до мультиплеера.

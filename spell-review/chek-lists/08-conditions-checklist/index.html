    Чек-лист работ — Блок 2.8: Состояния (conditions)¶

    Источник решений: docs/spell-review/08-conditions-decisions.md. Канон — D&D 5e SRD. Spec-first: пункты, затрагивающие openapi.yaml, помечены 🔶. Пометка приоритета: 🔴 game-breaking/фундамент, 🟡 точность, 🟢 UX. Аудит 2026-09-15: [x] — реализовано, [~] — частично, [ ] — отсутствует. Детали и ссылки — audit-09-conditions.md.

    ⭐ ОСОБО ЦЕННЫЕ НАХОДКИ (не потерять при реализации)¶

    1. ConditionResolver с алиасами (2.8.BB) — Опутан = Опутанный = RESTRAINED, Сбит с ног = Сбита с ног = Лежит = Ничком = PRONE, Захвачен = Удержан = Грапплинг = GRAPPLED. Без маппинга алиасов вся система состояний ломается ("Опутан" не найдётся в registry).
    2. Порядок пассов в processTurn (2.8.CC) — applyStateChanges → applyEnemyStateChanges → tickDurations → tickEnemyDurations → resolveSaveEnds. Разделение Player/Enemy пассов убирает загрязнение.
    3. applyExhaustion как единая точка (2.8.EE/NN/UU) — maxHp ×0.5, мгновенная смерть на 6, помеха на проверки с 1 уровня — в одном месте.
    4. ConditionId с @JsonValue = nameRu (2.8.II) — сохраняет существующий контракт ("Ошеломлён"), frontend/LLM не ломаются.

    ⚠️ 3 МИНОРНЫХ ЗАМЕЧАНИЯ (учтены в решении)¶

    1. See Invisibility — не состояние (2.8.FF) → activeModifier типа SEE_INVISIBLE, а не ConditionRegistry.
    2. Frightened «запрет приближения» без координат (2.8.GG) → в MVP только помехи; запрет приближения отложен (опционально флаг sourceNearby).
    3. Damage(ENEMY) — без двойной обработки (2.8.PP) → applyEnemyStateChanges обрабатывает только статусы, Damage игнорирует.

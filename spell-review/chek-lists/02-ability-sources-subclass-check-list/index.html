    Принятые решения по дырам¶

    2.2.1 · subclassLevel отсутствует — Решено: Вариант A¶

    • Добавить subclassLevel в CharacterClass + YAML (согласуется с 2.1.8).
    • LevelUpService.kt:63,126 — читать cls.subclassLevel вместо хардкод == 3, fallback на 3.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — поля subclassLevel нет ни в CharacterClass.kt, ни в classes.yml (0 вхождений); LevelUpService.kt:63,126 по-прежнему хардкодят == 3]

    2.2.2 · 139 фич подкласса — только текст — Закрывается 2.1.4¶

    • Переиспользовать ClassRegistry-парсинг (ClassFeature с полными полями) для SubclassRegistry.kt:41-47.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — SubclassRegistry.kt:41-47 строит ClassFeature только с name/level/description]

    2.2.3 · Нет choice в подклассах — Решено: Вариант A (фазово)¶

    • Добавить choice в subclasses.yml для Battle Master (маневры), Hunter (тактики), Totem Warrior (тотемы), Four Elements (дисциплины).
    • Механику выбора — через общий feature-механизм (см. 2.2.2).

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — choice в subclasses.yml отсутствует (0 вхождений)]

    2.2.4 · Нет подкласс-ресурсов — Решено: Вариант C¶

    • Использовать resourceId из ClassFeature, расширить ClassResources недостающими полями (Superiority Dice и др.).
    • Без отдельного объекта SubclassResources.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — ClassResources (GameState.kt:1370-1398) без подкласс-полей; ClassResourceHelper.kt:12 ветвится только по classId]

    2.2.5 · Восстановление ресурсов не через RestService — Дыра закрыта (факт)¶

    • ClassResourceHelper.restore вызывается из SessionService при StateChange.ShortRest (SessionService.kt:1756) и LongRest (:1769).
    • Ресурсы восстанавливаются корректно. Отдельное действие не требуется.

      [ОБНОВЛЕНО: 2026-09-15: факт подтверждён, строки сместились — SessionService.kt:2266 (ShortRest) и :2282 (LongRest)]

    2.2.6 · Spell lists подкласса захардкожены — Решено: Вариант A¶

    • Вынести доп. заклинания из SessionService.kt:217-244 в subclasses.yml (spellList: [...]), парсить в Subclass.
    • Убрать хардкод из кода; добавить для школ/кругов/клятв.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано, строки сместились — хардкод в SessionService.kt:225-252 (домены :225-239, покровитель :240-246, чародей :247-252); spellList в subclasses.yml нет]

    2.2.7 · Improved Critical не работает — Решено: Вариант A¶

    • Добавить critRange в CharacterState, модифицируется фичами.
    • TurnResolver (5 мест roll == 20) использовать critRange.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — critRange отсутствует (0 вхождений); == 20 в TurnResolver.kt в 21 месте (напр. :63, :761, :1101, :1649, :2252), не 5]

    2.2.8 · Sneak Attack — только текст — Решено: добавить реальный урон¶

    • В TurnResolver ветку атаки добавить 1d6 (или sneakDice в CharacterState), не только метку :1499.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — sneakDice/реальный sneak-урон отсутствует; метка «скрытая атака» теперь TurnResolver.kt:1737 (было :1499)]

    2.2.9 · Фичи игрока в бою — Решено: отдельная ветка¶

    • Разделить features монстров и фичи-механики персонажа.
    • Подкласс-фичи применять через общий эффект-механизм.

      [ОБНОВЛЕНО: 2026-09-15: частично — реакции подкласса вынесены в reaction_triggers.yml (:53,:57,:61,:65,:69,:85) + ReactionTriggerRegistry; контекст SessionService.kt:753-773; остальные боевые фичи подкласса не подключены]

    2.2.10 · Конфликт l1Choices ↔ subclassId — Решено: Вариант C¶

    • Синхронизировать: выбор на L1 (домен/покровитель/происхождение) автоматически выставляет subclassId.
    • subclassLevel делает выбор каноничным по уровню. Устраняет дублирование.
    • Решается вместе с 2.2.1.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — resolveL1Choices (SessionService.kt:192-267) возвращает domainId, но subclassId не выставляется; выбор подкласса остаётся отдельным на L3 (LevelUpService.kt:63,126)]

    2.2.11 · Неполный SRD-каталог (31 vs ~40) — Решено: фазово¶

    • Докрутить Cleric 7/7 и Wizard 8/8; остальное — по мере реализаций механик.

      [ОБНОВЛЕНО: 2026-09-15: без изменений — 31 подкласс в subclasses.yml]

    2.2.12 · Нет resource в модели Subclass¶

    • Закрывается решением по 2.2.4 (поле в ClassFeature).

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — поля resource в Subclass (SubclassRegistry.kt:9-15) нет]

    2.2.13 · Нет spellList в модели Subclass¶

    • Закрывается решением по 2.2.6 (поле в Subclass).

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — поля spellList в Subclass (SubclassRegistry.kt:9-15) нет]

    2.2.14 · Нет fallback для subclasses.yml — Решено: добавить¶

    • Добавить хардкод-fallback (как в ClassRegistry: 12 классов). Пустой список ломает выбор подкласса всем.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — в SubclassRegistry.load() (:23-60) fallback отсутствует (warn + возврат)]

    2.2.15 · Superiority Dice — состав полей — Новая (требует уточнения)¶

    • Расширить ClassResources тремя полями: superiorityDiceSize, superiorityDiceCount, superiorityDiceRecharge.
    • В SRD: размер d8 (Battle Master), число 4 на 3 ур. (рост до 6), восстановление short rest.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — полей нет в ClassResources (GameState.kt:1370-1398); superiorityDice встречается только в whitelist-YAML (action-whitelist-core.yaml:101, action-whitelist-magic.yaml:231)]

    2.2.16 · Subclass spells — разная механика — Новая (требует уточнения)¶

    • Добавить тип списка заклинаний подкласса: alwaysPrepared: Boolean или spellListType: DOMAIN/EXPANDED/SCHOOL.
    • Разница механик: Cleric Domain / Paladin Oath / Druid Circle (Land) — всегда подготовлены, не считаются в лимите; Warlock Expanded — добавляются в known; Wizard School — добавляются в spellbook; Druid Circle (Moon) — списка нет.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — spellListType/alwaysPrepared отсутствуют (0 вхождений)]

    2.2.17 · CritRange — инициализация — Новая (уточнение к 2.2.7)¶

    • Вычислять в LevelUpService при получении фичи (Champion: 19-20 на 3 ур., 18-20 на 15 ур.) и хранить в CharacterState.
    • Не вычислять динамически в TurnResolver из subclassId.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — critRange не вычисляется в LevelUpService (поле отсутствует)]

    2.2.18 · Sneak Attack — масштабирование — Новая (уточнение к 2.2.8)¶

    • sneakDice вычислять из уровня Rogue: sneakDice = ceil(rogueLevel / 2) (1d6→1, 3→2, 5→3, ..., 19→10d6).
    • Хранить в CharacterState для производительности.

      [ОБНОВЛЕНО: 2026-09-15: не реализовано — sneakDice в CharacterState отсутствует (0 вхождений)]

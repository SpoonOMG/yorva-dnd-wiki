    Детали¶

    ADR-0010 «Turn & Round Model»¶

    • Утверждение: ADR создан, но не утверждён; решение в коде не реализовано.
    • Статус: ✅ VALID
    • Текущая реализация: docs/adr/0010-turn-and-round-model.md:5 — Status: Proposed.
    • Целевое поведение (5e): модель хода/раунда и момент сброса экономии зафиксированы до кода.
    • Расхождение: статус ADR не изменён; ссылки внутри ADR на SessionService.kt:723-724 устарели (факт SessionService.kt:845).
    • Что делать: вопрос для ADR.

    OpenAPI spec-first (Фаза 0)¶

    • Утверждение: поля/значения экономии не добавлены в api-specification/openapi.yaml.
    • Статус: ✅ VALID
    • Текущая реализация: api-specification/openapi.yaml — поиск actionEconomy|BONUS_ACTION|READY_ACTION|OBJECT_INTERACTION|turnSerial даёт 0 совпадений.
    • Целевое поведение (5e): контракт API отражает слоты экономии (spec-first).
    • Расхождение: контракт не расширен.
    • Что делать: требует решения по spec-first.

    2.9.L Удаление 4 флагов CombatState¶

    • Утверждение: флаги не удалены, помечены @Deprecated.
    • Статус: ✅ VALID
    • Текущая реализация: GameState.kt:1451-1459 (поля), участвуют в nextRound() (GameState.kt:1505) и nextTurn() (GameState.kt:1508).
    • Целевое поведение (5e): единственный источник экономии — CharacterState.actionEconomy.
    • Расхождение: дублирующие поля живут в data-классе и меняются методами.
    • Что делать: требует решения по миграции.

    2.9.B/JJ/OO beginPlayerTurn + turnSerial + beginTurn(serial)¶

    • Утверждение: методов и поля нет; сброс инлайн в начале processTurn.
    • Статус: ✅ VALID
    • Текущая реализация: SessionService.kt:845 — playerState.copy(actionEconomy = playerState.actionEconomy.reset()).
    • Целевое поведение (5e): сброс в явной точке начала хода, с серийным номером хода.
    • Расхождение: нет beginPlayerTurn/turnSerial.
    • Что делать: вопрос для ADR-0010.

    2.9.A Сброс только на нормальном ходу¶

    • Утверждение: сброс выполняется до ветки request.reaction.
    • Статус: ✅ VALID
    • Текущая реализация: SessionService.kt:845 (сброс) → SessionService.kt:849 (if (request.reaction != null)).
    • Целевое поведение (5e): follow-up реакции не обнуляет экономию текущего хода.
    • Расхождение: реакция исполняется на уже сброшенной экономии.
    • Что делать: вопрос для ADR-0010.

    2.9.E ActionType.BONUS_ATTACK¶

    • Утверждение: константы BONUS_ATTACK нет; строка классификатора идёт в общую ветку атаки.
    • Статус: ⚠️ CHANGED
    • Текущая реализация: появился ActionType.BONUS_ACTION (ActionType.kt:60), паттерн BONUS_ACTION_PATTERN (ActionParser.kt:902, ветка :217-218); строка "BONUS_ATTACK" по-прежнему в общей ветке ActionParser.kt:620.
    • Целевое поведение (5e): бонусная атака — отдельный слот BONUS_ACTION.
    • Расхождение: строка BONUS_ATTACK не маппится в BONUS_ACTION.
    • Что делать: открытый вопрос классификации.

    2.9.G castingTime → Spend*¶

    • Утверждение: castingTime при выборе слота не читается.
    • Статус: ✅ VALID
    • Текущая реализация: TurnResolver.kt:397-408 (checkActionEconomy), TurnResolver.kt:456-462 (buildEconomyChanges) — слот из ActionEconomyRegistry.slotFor(type, dslId, classId).
    • Целевое поведение (5e): время каста заклинания определяет слот (Bonus Action/Action).
    • Расхождение: castingTime не участвует в выборе слота.
    • Что делать: вопрос для ADR.

    • Что делать: открытый вопрос.

    Новые находки¶

    • NEW-1: Система ретроактивных реакций игрока (ReactionResolver.kt, reaction_triggers.yml, MechanicsBlock.availableReactions GameState.kt:1136) — новый слой экономии, не описанный в исходном аудите; проверка «реакция предлагалась» в SessionService.kt:1914-1917.

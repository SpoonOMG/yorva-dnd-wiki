    Аудит: Отдых (RestService.applyShortRest/applyLongRest, Hit Dice, spell slots, class resources, Exhaustion, состояния)¶

    Дата: 2026-09-15 База: нет (область без чек-листа)

    Фактура из кода¶

    11.1 Модель отдыха¶

    Где: rules/GameState.kt:1024-1052. Что: 

    enum class RestType { SHORT, LONG }                         // :1024
data class RestConfig(
    val shortRestDuration: Int = 60,
    val longRestDuration: Int = 480,
    val longRestIntervalMinutes: Int = 24 * 60,             // :1030
    val interruptThresholdMinutes: Int = 60,                // :1032
)
data class RestResult(..., val restoredAbilities: List<String> = emptyList(), ...)
    RestResult.restoredAbilities (:1040) в коде нигде не заполняется (результат grep пуст).

    11.2 Доступность short rest¶

    Где: rules/RestService.kt:23-27. 

    fun canShortRest(character: CharacterState): Boolean {
    if (character.hitDice <= 0) return false
    if (character.hp >= character.maxHp && character.hitDice == character.maxHitDice) return false
    return true
}
    Комментарий :20 фиксирует: «короткий отдых не ограничен числом в день».

    11.3 Short rest: Hit Dice/HP¶

    Где: rules/RestService.kt:16-17,51-74. 

    private fun hitDieFor(character: CharacterState): Int =
    character.canonicalClassId?.let { classRegistry?.getClass(it)?.hitDie } ?: 8   // :16-17

val toSpend = hitDiceToSpend.coerceIn(1, character.hitDice)                        // :53
val rolls = (1..toSpend).map { dice.roll(1, hitDie) }                              // :55
val totalHeal = rolls.sumOf { it + character.effectiveAttributes.conMod }.coerceAtLeast(1) // :56
val newHp = (character.hp + totalHeal).coerceAtMost(character.maxHp)               // :57
    Число костей из текста: parseHitDiceToSpend (TurnResolver.kt:2012-2015) — первое \d+, дефолт 1, coerceIn(1, hitDice).

    Две реализации: TurnResolver.resolveRest (:1986-2007) и TurnResolver.resolveHeal (:2045-2064) вызывают restService.applyShortRest, но берут только result (val (_, result)), а изменение состояния пересчитывают заново через StateChange.Heal + StateChange.ShortRest (:1997-1998, 2057-2058). В SessionService.applyStateChanges StateChange.ShortRest (SessionService.kt:2261-2268) списывает hitDice и инкрементирует shortRestsUsedToday, но HP уже пришёл отдельным Heal.

    11.4 Доступность long rest¶

    Где: rules/RestService.kt:33-37,43-48. 

    fun canLongRest(character: CharacterState): Boolean {
    if (character.restInterrupted) return false
    val last = character.lastLongRestAt ?: return true
    return Duration.between(last, clock.instant()).toMinutes() >= config.longRestIntervalMinutes
}
fun onInterrupt(...) = if (interruptMinutes >= config.interruptThresholdMinutes) character.copy(restInterrupted = true) else character
    onInterrupt вызывается только из теста RestServiceTest.kt:85,95; в production-коде вызовов нет.

    11.5 Long rest: HP + Hit Dice¶

    Где: rules/RestService.kt:80-111. 

    val restoredHp = character.maxHp - character.hp                          // :83
val hitDiceRestore = (character.maxHitDice / 2).coerceAtLeast(1)         // :84
val newHitDice = (character.hitDice + hitDiceRestore).coerceAtMost(character.maxHitDice) // :85
hp = character.maxHp, hitDice = newHitDice, ...                          // :92-93
    TurnResolver отбрасывает персонажа из Pair (:1965,2025) и эмитит StateChange.Heal(restoredHitPoints) + StateChange.LongRest(occurredAt) (:1967-1968,2027-2028). В SessionService.applyStateChanges long rest повторно восстанавливает Hit Dice (:2272-2273): 
    val restore = (state.maxHitDice / 2).coerceAtLeast(1)
hitDice = (hitDice + restore).coerceAtMost(state.maxHitDice)

    11.6 Spell slots¶

    Где: sessions/SessionService.kt:2274, rules/RestService.kt:87-89,94. - Long rest: spellSlots = state.maxSpellSlots (SessionService.kt:2274). - Короткий отдых: обычные spellSlots не восстанавливаются; восстанавливается только pactSlots через ClassResourceHelper.restore(..., SHORT) (:2266, ClassResourceHelper.kt:141). - RestService.applyLongRest вычисляет restoredSlots для отчёта (:87-89), но вызывающие его не используют.

    11.8 Exhaustion¶

    Где: rules/GameState.kt:359-363,484; sessions/SessionService.kt:2277; rules/RestService.kt:90,97. - Хранится: val exhaustion: Int = 0, require(exhaustion in 0..6) (GameState.kt:363,484). - Long rest: exhaustion = (exhaustion - 1).coerceAtLeast(0) (SessionService.kt:2277); то же в RestService.kt:90,97. - Инкремент exhaustion: не найден (grep по exhaustion = даёт только декремент и присваивание в буферах). - Статус "Истощён" (TurnResolver.kt:1333, statusNameForFamily) отделён от счётчика exhaustion и его не меняет.

    11.9 Снятие состояний¶

    Где: rules/TurnResolver.kt:1969-1970 и :2029-2030. 

    if ("Стабилен" in character.statuses) stateChanges += StateChange.RemoveStatus("Стабилен", StateTarget.PLAYER)
if ("Без сознания" in character.statuses && character.hp > 0) stateChanges += StateChange.RemoveStatus("Без сознания", StateTarget.PLAYER)
    Это единственные снятия статусов при long rest. Отравление не снимается (комментарий SessionService.kt:2271). resolveSaveEnds (TurnResolver.kt:49-82) снимает статусы из SAVE_END_STATUSES (GameState.kt:629) в конце хода по спасброску CON DC12 — независимо от отдыха.

    11.10 Ограничения/прерывание отдыха¶

    Где: sessions/SessionService.kt:2265,2276; поля GameState.kt:357-358. - shortRestsUsedToday++ (:2265) и longRestsUsedToday++ (:2276) — счётчики, проверок на лимит нет (grep: чтение только в буферах). - restInterrupted выставляется только в RestService.onInterrupt (не вызывается) и сбрасывается в long rest (SessionService.kt:2281, RestService.kt:99). - 24-часовое окно: lastLongRestAt устанавливается из StateChange.LongRest(occurredAt) (SessionService.kt:2279).

    11.11 Триггеры/вызывающие¶

    • ActionType.REST (ActionType.kt:71-72), парсинг ActionParser.kt:654,584, классификатор CatalogClassifier.kt:227.
    • Dispatch: TurnResolver.kt:548 → resolveRest (:1948).
    • Дублирующий путь по ключевым словам в resolveHeal (TurnResolver.kt:2020,2045): ночлег/лагерь/длинный отдых и короткий отдых/передышк/привал.
    • UI-кнопки: UiCommandWhitelist.kt:12-13 («короткий отдых», «длинный отдых»).
    • В бою отдых отклоняется: if (enemy != null) → "Нельзя отдыхать в бою" (TurnResolver.kt:1949-1958).
    • ActionType.REST не тратит действие/бонус/реакцию (TurnResolver.kt:368,414,425).

    11.12 Что НЕ восстанавливается / НЕ снимается¶

    • На short rest не восстанавливаются обычные spellSlots, layOnHands, sorceryPoints, arcaneRecoveryUsed (см. 11.7).
    • RestResult.restoredAbilities не заполняется (11.1).
    • Exhaustion не сбрасывается полностью, только −1 (11.8).
    • При long rest не снимаются прочие состояния/дебаффы, кроме «Стабилен»/«Без сознания» (11.9).
    • clock/Duration — только для long rest; RestConfig не переопределяется Spring-конфигом (используется дефолтный конструктор RestService.kt:11).

    Открытые вопросы¶

    1. exhaustion 6 = смерть (GameState.kt:361 комментарий) — реализация перехода в смерть при 6 не найдена; требует уточнения.
    2. Двойная реализация восстановления (RestService возвращает Pair, вызывающие его игнорируют) — какая считается источником истины, требует уточнения.
    3. onInterrupt без вызывающих — прерывание отдыха фактически неактивно; требуется подтверждение, что это intended.
    4. shortRestsUsedToday/longRestsUsedToday не читаются — требуется уточнить, нужны ли лимиты.
    5. lastLongRestAt — сравнение по clock; при occurredAt = null (не должно случаться) окно не обновится, требует уточнения.

    Сводка¶

    • Реализовано: RestType/RestConfig/RestResult; short rest через Hit Dice (+CON); long rest (HP до max, +половина max Hit Dice, spell slots до max); восстановление class resources по short/long; 24-часовое окно long rest; canShortRest/canLongRest; блок отдыха в бою; счётчики.
    • Частично: Exhaustion (−1 за long rest, поле не растёт); снятие состояний (только «Стабилен»/«Без сознания»); прерывание отдыха (метод есть, не вызывается); class resources (short не даёт layOnHands/sorceryPoints/arcaneRecovery); дублирование логики RestService ↔ SessionService.
    • Отсутствует: инкремент exhaustion; смерть от exhaustion 6; лимиты short/long rest по счётчикам; RestResult.restoredAbilities; восстановление обычных spell slots на short rest; снятие дебафф-статусов отдыхом.

    15.4 Резолв equip/unequip¶

    Где: rules/TurnResolver.kt:2147-2201; rules/ItemSearch.kt:13-27. 

    private fun resolveEquip(action, actionLower, character, target): TurnMechanics {
    val isUnequip = UNEQUIP_PATTERN.containsMatchIn(actionLower)
    val item = findEquipTarget(character.inventory, target, actionLower)
    if (item == null) return TurnMechanics("equip", description = "Предмет не найден в инвентаре", consumesAction = false)
    return buildEquipMechanics(item, isUnequip)
}
    buildEquipMechanics (:2166-2201): идемпотентность вместо toggle — снятие ненадетого → "«X» не надета", consumesAction=false; надевание надетого → no-op, consumesAction=false; иначе StateChange.EquipItem/UnequipItem с consumesAction=true. findEquipTarget: точное совпадение target (ignoreCase) → вхождение полного имени в текст → совпадение слова имени длиной >3 символов; частичного совпадения по target нет (комментарий ItemSearch.kt:6-11).

    15.11 Расчётные бонусы от экипировки¶

    Где: rules/GameState.kt:544-603.

    Открытые вопросы¶

    1. InventoryItem.properties нигде не заполняется, и loot_items.properties пуст по умолчанию — TWO_HANDED/FINESSE в проде не работают; нужен источник заполнения (каталог/миграция/LootShowcase)?
    2. classes.yml:startingEquipment и ItemCatalogService.startingInventory без потребителя: стартовый комплект должен выдаваться по классу, а не хардкод «меч + кожаная броня» (SessionService.kt:1911-1921)?
    3. EquipSlot.OFF_HAND не маппится ни одной ItemCategory; щит (classes.yml:28) не имеет категории — вводить SHIELD/OFF_HAND?
    4. UseAction (тип действия предмета) объявлен, но не используется ни в движке, ни в UI — использовать или удалить?
    5. Бэкенд разрешает экипировку MISC (без слота, без бонусов, без якоря), а UI не даёт кнопки — какое поведение канонично?
    6. Фронт (CharacterPanel.tsx:168-197) суммирует бонусы всех equipped, бэкенд — только со слотом (GameState.kt:560-603): расхождение отображения и механики для MISC.
    7. hpBonus/manaBonus в ItemBonuses не применяются в effectiveAc/effectiveAttributes — где они должны учитываться?
    8. Бонусы оружия берутся от первого надетого MELEE/RANGED (GameState.kt:550-552); при двух оружиях (main/off hand) правила не определены.

    Сводка¶

    • Реализовано: полная модель InventoryItem (категория, редкость, бонусы, equipped, damageDice, эффективный кубик); перечни категорий/слотов/свойств/бонусов; классификация и парсинг EQUIP (ActionParser/CatalogClassifier/IntentValidator); резолв и идемпотентный equip/unequip (ItemSearch/buildEquipMechanics); слот-эксклюзивность; выдача через GRANT_ITEM/GRANT_UNIQUE/TAKE_LOOT/PickUpItem с гейтами и дедупом; визуальные якоря экипировки (с отсечением безслотовых); action economy для EQUIP; UI инвентаря в двух панелях с кнопками «Надеть/Снять/Применить» и отображением бонусов; unit-тесты ApplyEquipToInventoryTest.
    • Частично: категоризация нарративных предметов — эвристика по имени с фолбэком в MISC; бонусы от экипировки учитывают только предметы со слотом, hpBonus/manaBonus не применяются; фронт и бэкенд по-разному суммируют бонусы equipped; ItemCategory не покрывает OFF_HAND (щиты).
    • Отсутствует: заполнение properties (TWO_HANDED/FINESSE недостижимы в проде); потребитель CharacterClass.startingEquipment и ItemCatalogService.startingInventory (классное стартовое снаряжение не выдаётся); использование UseAction; правила для двух оружий (main/off hand); категория щита.

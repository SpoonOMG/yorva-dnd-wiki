    Аудит: Монстры (Enemy.features, multiattack, legendary, creatureType, conditionImmunities, speed, reactionUsed)¶

    Дата: 2026-09-15 База: нет (область без чек-листа)

    Вердикт¶

    Подблок Статус Комментарий
    16.1 Модель Enemy и поля ⚠️ data class Enemy (GameState.kt:643-686); нет полей speed, creatureType, conditionImmunities, vulnerabilities
    16.2 Источник статблоков ✅ creature_archetypes (0036-creature-archetypes.yaml:9-26); ArchetypeRow (CatalogService.kt:297-314)
    16.3 multiattack ⚠️ один бросок атаки + N бросков урона (TurnResolver.kt:2651-2669); правило «в соло — x1.5» из драфта не реализовано
    16.4 legendary/lair ❌ легендарных действий и действий логова нет; ветка "legendary" (TurnResolver.kt:2653) недостижима — legendary нет в allowed_features каталога
    16.5 Тип существа / иммунитеты к состояниям / уязвимости ❌ creatureType, conditionImmunities, vulnerabilities отсутствуют в модели и БД; resistances/immunities есть, но нигде не заполняются
    16.6 speed / reactionUsed ❌ Enemy.speed и Enemy.reactionUsed отсутствуют; реакции врага нет (реакция только у игрока, GameState.kt:1285)
    16.7 features врага ⚠️ реализованы multiattack/regeneration/enrage/poison_strike/armor_heavy; не реализованы pack_tactics/aura_fear/summon_minions/resist_element; has_phase читается и не используется; фичи из тега не валидируются по allowed_features
    16.8 Спасброски врага ⚠️ resolveEnemySave использует только statusSaveBonus (SavingThrowResolver.kt:62-86); в контратаке к спасброску врага добавляется conMod игрока (TurnResolver.kt:2560)
    16.9 Поведение врага ⚠️ действия врага детерминированы движком (TurnResolver.kt:2535-2699, :351-364); LLM выбирает архетип/имя/фичи и нарратив (ContextBuilder.kt:195-205, SessionService.kt:1306-1321)

    Фактура из кода¶

    16.1 Модель Enemy и поля¶

    Где: rules/GameState.kt:643-686.

    Что: data class Enemy содержит поля: 

    val name: String,                                          // :644
val hp: Int, val maxHp: Int, val ac: Int,                  // :645-647
val attackBonus: Int,                                      // :648
val damageDie: String = "d6", val damageBonus: Int = 2,    // :649-650
val statuses: List<String> = emptyList(),                  // :652
val archetypeCode: String? = null,                         // :654
val xpReward: Int? = null,                                 // :656
val features: List<String> = emptyList(),                  // :658
val statusSaveBonus: Int = 0,                              // :660
val resistances: List<String> = emptyList(),               // :662
val immunities: List<String> = emptyList(),                // :664
    Валидация: require(hp in 0..maxHp), require(maxHp > 0) (:666-669). Вычисляемые свойства: isDefeated (:672), isIncapacitated (:675), isProne (:678), isRestrained (:681); INCAPACITATING_STATUSES = {Заморожен, Ошеломлён, Парализован, Оглушён, Сон} (:684).

    Пример: смежных полей speed, creatureType, conditionImmunities, vulnerabilities в классе нет — поиск по GameState.kt пуст.

    16.2 Источник статблоков¶

    Где: db/changelog/changes/0036-creature-archetypes.yaml:9-26; catalog/CatalogService.kt:297-348; db/changelog/changes/0015-action-catalog.yaml:186-196.

    Что: таблица creature_archetypes (колонки code, rank, name_ru, level, hp, ac, attack_bonus, damage_dice, damage_bonus, xp, allowed_features, has_phase, save_bonus_vs_status, loot_tier, min_player_level, narrative_hint). ArchetypeRow (CatalogService.kt:297-314) и mapArchetype (:316-333) читают эти колонки. findArchetype(code) — :336-339; listArchetypesForPlayer(level) (уровень в [playerLevel-1, playerLevel+1], min_player_level <= level) — :345-348. Legacy-таблица creatures (без level/rank/фич) — 0015-action-catalog.yaml:186-196, читается findCreature (CatalogService.kt:287) и findRandomCreature (:360).

    Пример: 

    ('elite_1', 'elite', 'Элита', 1, 30, 12, 4, '1d8', 3, 125,
 '["multiattack","aura_fear","regeneration","armor_heavy","enrage"]', FALSE, 0, 'uncommon', 1, '...')
    (0036-creature-archetypes.yaml:33). save_bonus_vs_status = 4 у ранга boss, = 6 у epic; has_phase = TRUE у boss/epic (:34,51).

    16.3 multiattack¶

    Где: rules/TurnResolver.kt:2651-2669.

    Что: в контратаке после одного успешного броска атаки врага число бросков урона задаётся: 

    val legendaryExtra = if ("legendary" in enemy.features) 1 else 0                       // :2653
val attackCount = (if ("multiattack" in enemy.features) 2 else 1) + legendaryExtra      // :2654
...
repeat(attackCount) { attackIndex ->                                                    // :2662
    val enemyDamageRoll = dice.roll(1, sides)                                           // :2663
    ...
}
    Это один бросок атаки (enemyRoll, :2622-2626) и один бросок попадания (enemyHit, :2630), затем attackCount независимых бросков урона, суммируемых в totalDamage (:2659-2669) и помечаемых (×N атаки) (:2671).

    Пример: драфт предписывает «2 атаки за ход. Только против пати >= 3 героев; в соло/дуэте — одна тяжёлая атака (урон x1.5)» (docs/game-design/creature-archetypes-draft.yml:174). В коде условия по partySize для multiattack нет — он всегда даёт 2 броска урона.

    16.4 legendary/lair¶

    Где: rules/TurnResolver.kt:2652-2653, 2672.

    Что: единственное упоминание легендарности — legendaryExtra (доп. бросок урона), комментарий «13.5: легендарное существо совершает дополнительную легендарную атаку вне своего хода» (:2652), при попадании добавляется строка «Легендарное действие!» (:2672). Системы легендарных действий (пул из 3 действий в конце чужого хода) и действий логова нет.

    Пример: строки legendary нет ни в одном allowed_features каталога (0036-creature-archetypes.yaml:31-76); ближайшее — loot_tier='legendary' у epic_* (:51). la и lair в коде monster-контекста отсутствуют.

    16.5 creatureType / conditionImmunities / resistances / immunities / vulnerabilities¶

    Где: rules/GameState.kt:643-664; spells/SpellService.kt:154,168-173,228; 0036-creature-archetypes.yaml:9-26.

    Что: - creatureType — отсутствует (нет поля, нет колонки, нет использования). - conditionImmunities — отсутствует. - vulnerabilities — отсутствует. - resistances / immunities — поля есть (GameState.kt:662,664), но в instantiateArchetypeEnemy (TurnResolver.kt:1286-1312) не заполняются: в таблице creature_archetypes нет соответствующих колонок, поля остаются emptyList(). Единственное чтение — в расчёте урона заклинанием (SpellService.kt:168-173).

    Пример: 

    if (effect.damageType in target.resistances) { ... }   // SpellService.kt:168
if (effect.damageType in target.immunities) { ... }    // SpellService.kt:171
    Фича resist_element (заявлена в allowed_features у improved_*) в коде не читается — поиск по resist_element даёт только CatalogService.kt/ContextBuilder.kt (вывод в промпт), но не движок урона.

    16.6 speed / reactionUsed¶

    Где: rules/GameState.kt:1285,1417-1418,1466; rules/TurnResolver.kt:366-415,713.

    Что: Enemy.speed отсутствует. Enemy.reactionUsed отсутствует. Реакция реализована только для игрока: ActionEconomy.reactionUsed (GameState.kt:1285), hasReaction() (:1293), withReactionUsed() (:1302); CombatState.reactionUsed помечен @Deprecated (:1417-1418), сбрасывается nextRound() (:1466). Проверка реакции игрока — TurnResolver.kt:377,408; провокационная атака игрока — resolveOpportunityAttack (:713, диспетчер :480-482).

    Пример: docs/adr/0010-turn-and-round-model.md:155 и чек-лист 09-action-economy-check-list.md:49,62,83,89 фиксируют Enemy.speed/Enemy.reactionUsed/StateChange.EnemyReactionUsed как запланированные; поиск по Enemy.speed, EnemyReactionUsed, applyEnemyStateChanges в backend/ пуст (совпадения только в docs/).

    16.7 features врага¶

    Где: rules/TurnResolver.kt:779,1691,2603-2615,2651-2684; catalog/CatalogService.kt:308-309,328; sessions/SessionService.kt:1312-1313.

    Что: формат — List<String> (GameState.kt:658), значения задаёт LLM в теге спавна или emptyList(). Реализация фич в движке:

    Фича Статус Где
    multiattack ✅ TurnResolver.kt:2654
    regeneration ✅ TurnResolver.kt:2603-2609
    enrage ✅ TurnResolver.kt:2611-2615
    poison_strike ✅ TurnResolver.kt:2674-2684
    armor_heavy ✅ TurnResolver.kt:779,1691 (крит не удваивает урон)
    legendary ⚠️ TurnResolver.kt:2653,2672; недостижим через каталог
    pack_tactics ❌ вхождений в backend/.../main нет
    aura_fear ❌ вхождений нет
    summon_minions ❌ вхождений нет
    resist_element ❌ вхождений нет

    has_phase читается в ArchetypeRow.hasPhase (CatalogService.kt:309,328), но нигде в production-коде не используется. features из тега не сверяются с allowedFeatures: SessionService.kt:1312-1313 передаёт распарсенный список напрямую в instantiateArchetypeEnemy, который принимает его без проверки (TurnResolver.kt:1289,1307). В allowed_features каталога встречаются только pack_tactics, poison_strike, resist_element (improved), multiattack, aura_fear, regeneration, armor_heavy, enrage (elite) и +summon_minions (boss/epic) (0036-creature-archetypes.yaml:32-34).

    Пример (реализация enrage): 

    if ("enrage" in enemy.features && enemy.hp < enemy.maxHp / 2 && "Ярость" !in enemy.statuses) {
    enemy = enemy.copy(statuses = enemy.statuses + "Ярость", ac = (enemy.ac - 2).coerceAtLeast(1), damageBonus = enemy.damageBonus + 2)
}
    (TurnResolver.kt:2612-2613).

    16.8 Спасброски врага¶

    Где: rules/SavingThrowResolver.kt:62-86; rules/TurnResolver.kt:2555-2584; spells/SpellService.kt:154,228; rules/TurnResolver.kt:1308.

    Что: два независимых расчёта: 1. resolveEnemySave (для заклинаний): d20 + enemy.statusSaveBonus против DC (SavingThrowResolver.kt:68-72). Вызывается из SpellService.kt:154 и :228. 2. Спасбросок против оглушающего статуса в начале хода врага: saveTotal = saveRoll + character.effectiveAttributes.conMod + enemy.statusSaveBonus (TurnResolver.kt:2560) — то есть к спасброску врага добавляется модификатор Телосложения персонажа игрока, а не врага.

    statusSaveBonus заполняется из save_bonus_vs_status при инстанцировании (TurnResolver.kt:1308): boss = 4, epic = 6, остальные 0 (0036-creature-archetypes.yaml:31-76). Атрибутивных спасбросков врага (STR/DEX/…) и proficiencies у Enemy нет.

    Пример: DiceRoll("d20", saveRoll, "Спасбросок врага", attribute = "Телосложение", modifier = character.effectiveAttributes.conMod, ...) (TurnResolver.kt:2571).

    16.9 Поведение врага¶

    Где: rules/TurnResolver.kt:2535-2699, :351-364; llm/ContextBuilder.kt:195-205; sessions/SessionService.kt:1188-1199,1306-1321,2690-2763; rules/GameState.kt:76,94-116.

    Что: действия врага выбирает движок, не LLM. - Контратака applyEnemyTurn (TurnResolver.kt:2535-2699) срабатывает, если force || isNarrationInCombat || (!isMisfire && (action == "attack" || isDodge || playerRoll?.success == false)) (:2595), и дополнительно при Random.nextDouble() <= profile.mechanics.enemyAggression (:2597-2601). - Самостоятельный ход по инициативе — resolveEnemyTurn (:351-364) с force = true. - enemyAggression: EASY 0.4, NORMAL 1.0, HARD 1.6 (GameState.kt:94,105,116); диспетчер сессии применяет инициативу — resolveInitiative (TurnResolver.kt:2759-2784). - LLM выбирает болванку и обёртку: промпт требует выбрать ОДИН код и вернуть тег [SPAWN_ENEMY:<код>|<Имя>|<фичи>] (ContextBuilder.kt:197), список доступных архетипов с allowedFeatures (:200-202). - Парсинг тега: spawnEnemyRegex (SessionService.kt:2945), применение — :1306-1321; структурированный эффект SPAWN_ENEMY — :1188-1199; нарративный спавн без тега (Q11.7) — :842-845. - Консистентность именованных врагов: registerEnemy пишет enemy_registry:<имя> в факты (:2715-2739); restoreRegisteredEnemy (:2745-2763) вызывается из :845. - Массовый спавн spawnArchetypeEnemy (:2698-2708) используется контуром самообучения (sim/selflearn/SelfLearnRunner.kt:132).

    Пример: Q11.7-фолбэк «часы» (SessionService.kt:998-1014) отключён константой if (false && ...) (:998); выбор архетипа RNG (:1003) в этом блоке мёртв. defaultEnemy (TurnResolver.kt:2994) оставляет хардкод-фолбэк на 12 имён (гоблин, волк, кабан и т.п.).

    Открытые вопросы¶

    1. Enemy.speed и Enemy.reactionUsed — запланированы в 08-conditions-checklist.md/09-action-economy-check-list.md и ADR-0010, но в коде отсутствуют. Есть ли решение по механике движения и авто-провокации врага?
    2. conditionImmunities/vulnerabilities/creatureType — отсутствуют и в модели, и в каталоге. Нужны ли они для SRD-иммунитетов и взаимодействия с условиями?
    3. resistances/immunities у Enemy не заполняются из creature_archetypes; фича resist_element выводится в промпт, но не влияет на урон. Как задумано связывать фичу и поля?
    4. legendary: ветка в коде есть, но недостижима из каталога (нет в allowed_features). Планируется ли отдельный ранг/флаг или это остаток?
    5. has_phase = TRUE у boss/epic и phase: true в драфте (creature-archetypes-draft.yml:146,161) — код фазы не читает. Это запланировано?
    6. features из тега [SPAWN_ENEMY] не сверяются с allowed_features — LLM может передать любую строку (в т.ч. legendary). Должна ли быть валидация?
    7. Спасбросок врага в контратаке использует conMod игрока (TurnResolver.kt:2560) — намеренно или опечатка вместо спасброска врага?
    8. multiattack не учитывает partySize (в соло по драфту должен быть x1.5), а также промахи между атаками — один бросок атаки на N бросков урона. Соответствует ли это задумке?

    Сводка¶

    • Реализовано: источник статблоков creature_archetypes (§16.2); фичи multiattack, regeneration, enrage, poison_strike, armor_heavy (§16.7); детерминированное поведение врага движком + выбор болванки LLM (§16.9); реестр именованных врагов (§16.9); спасбросок врага по statusSaveBonus для заклинаний (§16.8).
    • Частично: модель Enemy (§16.1); multiattack — без правила соло-режима (§16.3); спасброски врага — два несогласованных расчёта (§16.8); features из тега без валидации (§16.7).
    • Отсутствует: legendary-действия и действия логова (§16.4); creatureType, conditionImmunities, vulnerabilities (§16.5); заполнение resistances/immunities и фича resist_element (§16.5); Enemy.speed, Enemy.reactionUsed, реакции врага (§16.6); фичи pack_tactics, aura_fear, summon_minions (§16.7); has_phase/фаза босса (§16.7).

    Дата: 2026-09-15 База: нет (область без чек-листа)

    Фактура из кода¶

    13.1 Каталог и источник¶

    • Где: catalog/ItemCatalogService.kt; resources/db/changelog/changes/0022-item-archetypes.yaml; loot/LootShowcaseService.kt; loot/LootItemEntity.kt; rules/LootTable.kt; миграции 0028-loot-catalog.yaml, 0029-loot-items-*.yaml, 0030-loot-item-category.yaml.
    • Что: два независимых источника предметов.
    • Архетипы — таблица item_archetypes (миграция 0022), читается JdbcTemplate. ItemArchetype (ItemCatalogService.kt:21-43), методы findById (:48), findByCategory (:59), findByCategoryAndRarity (:77), findAll (:100), matchArchetype (:115-141). mapRow (:243-281) мапит damage_bonus, ac_bonus, str/…/cha_bonus, hp_bonus, mana_bonus, tags.
    • Лут-каталог — таблица loot_items (LootItemEntity.kt:16-52), отдаётся витриной LootShowcaseService.generateShowcase (:123-162), статы считаются LootPowerTable (LootPowerTable.kt:16-57).
    • Пример (схема каталога, миграция 0022): 
      - column: { name: damage_bonus, type: INT, defaultValueNumeric: 0 }   # 0022:16
- column: { name: hp_bonus,     type: INT, defaultValueNumeric: 0 }   # 0022:24
- column: { name: mana_bonus,   type: INT, defaultValueNumeric: 0 }   # 0022:25
- column: { name: tags,         type: VARCHAR(256), defaultValue: "" }# 0022:27
      Колонок attunement/charges/uses/requires_attunement нет.
    • Пример (магический архетип): sword-rune «Рунический меч» RARE, damage_bonus=3, str_bonus=1 (0022-item-archetypes.yaml:42-53); excalibur LEGENDARY (:55-67); amulet-arcane EPIC, hp_bonus=15, mana_bonus=10 (:334-345); scroll-fireball RARE, damage_bonus=5, tags="aoe,fire" (:400-411).
    • Пример (маппинг бонусов без attack_bonus): 
      bonuses = ItemBonuses(
    damageBonus = (row["damage_bonus"] as? Number)?.toInt() ?: 0,   // ItemCatalogService.kt:267
    acBonus     = (row["ac_bonus"] as? Number)?.toInt() ?: 0,       // :268
    ...
    manaBonus   = (row["mana_bonus"] as? Number)?.toInt() ?: 0,     // :276
)                                                                    // attackBonus не читается
    • Маппинг категорий витрины: ICON_CATEGORY_TO_ITEM (LootShowcaseService.kt:55-70), LOOT_CATEGORY_DEFAULT (:73-77), resolveItemCategory (:214-221). Заметные соответствия: "gloves" to AMULET (:62), "shield" to MISC (:66), "explosive" to EXPLOSIVE (:58).
    • Стартовый инвентарь: startingInventory (ItemCatalogService.kt:226-241) — COMMON-оружие + COMMON-броня + 2 зелья. В LootTable зелья — единственные расходники шаблонов (LootTable.kt:230-231).

    13.2 Магические бонусы¶

    • Где: rules/GameState.kt:200-215; catalog/ItemCatalogService.kt:266-277; loot/LootPowerTable.kt:16-57; rules/LootTable.kt:237-256.
    • Что: единая модель бонусов — ItemBonuses, 11 полей, все Int = 0; isEmpty (:213-214). Тип магического урона, школа, DC спасброска у предметов не моделируются. 
      data class ItemBonuses(
    val damageBonus: Int = 0, val acBonus: Int = 0, val attackBonus: Int = 0,
    val strBonus: Int = 0, val dexBonus: Int = 0, val conBonus: Int = 0,
    val intBonus: Int = 0, val wisBonus: Int = 0, val chaBonus: Int = 0,
    val hpBonus: Int = 0, val manaBonus: Int = 0,
)
    • Что (источники):
    • Каталог архетипов заполняет все поля, кроме attackBonus (нет колонки attack_bonus в 0022).
    • LootPowerTable.bonusesFor (:48-56): WEAPON → damageBonus, ARMOR → acBonus, CONSUMABLE → hpBonus.
    • LootTable.generateBonuses (:237-256): оружие/шлем/броня/сапоги/кольцо/амулет/зелье.
    • Пример (LootPowerTable): 
      "WEAPON"     -> ItemBonuses(damageBonus = damageBonus(item.level, rarity, item.statFactor)) // LootPowerTable.kt:51
"ARMOR"      -> ItemBonuses(acBonus = acBonus(...))                                        // :52
"CONSUMABLE" -> ItemBonuses(hpBonus = consumableEffect(...))                               // :53
    • Следствие: attackBonus не имеет источника ни в одной из веток (ItemBonuses создаётся без него), т.е. в проде всегда 0.

    13.3 Attunement¶

    • Где: отсутствует.
    • Что: вхождения attunement/attune/attuned/настройк в коде не найдены (grep пуст). Нет поля в InventoryItem (GameState.kt:231-267), нет колонки в item_archetypes (0022:9-27) и loot_items (LootItemEntity.kt:17-50).
    • Пример (единственный флаг состояния предмета — equipped): 
      val equipped: Boolean = false,   // GameState.kt:252
      Настройка/связь с предметом не представлена; экипировка регулируется только слотом ItemCategory.slot (GameState.kt:169-181) и EquipSlot (:186-194).

    13.4 Charges¶

    • Где: поле/таблица — отсутствуют; упоминания только в DSL-файле resources/whitelist/action-whitelist-magic.yaml.
    • Что: нет поля зарядов у InventoryItem и колонок зарядов у каталогов. Расход предметов реализован удалением по количеству — StateChange.ConsumeItem(item, quantity) (GameState.kt:1140), применяется в SessionService.kt:2229-2236.
    • Пример (whitelist ссылается на несуществующую модель): 
      WAND_USE:
  condition: "hasWand == true && wand.charges > 0"   # action-whitelist-magic.yaml:97
STAFF_USE:
  condition: "hasStaff == true && staff.charges > 0" # :100
ROD_USE:
  condition: "hasRod == true && rod.charges > 0"     # :103
      Переменные hasWand/wand.charges/hasStaff/staff.charges/hasRod/rod.charges не подкреплены ни моделью, ни контекстом.
    • Пример (нет восстановления зарядов): UseAction (GameState.kt:218-224) содержит только FREE_ACTION/ACTION/BONUS_ACTION/REACTION/NO_ACTION; механизма recharge нет.

    13.5 Potions¶

    • Где: GameState.kt:177; TurnResolver.kt:2080-2114; SessionService.kt:2229-2236; миграция 0022:347-383; LootTable.kt:252-253.
    • Что: категория POTION без слота (GameState.kt:177). Использование резолвится по имени в тексте действия: 
      val item = character.inventory.firstOrNull { actionLower.contains(it.name.lowercase()) }   // TurnResolver.kt:2081
stateChanges += StateChange.ConsumeItem(item.name, 1)                                      // :2091
val healAmount = if (item.bonuses.hpBonus > 0) item.bonuses.hpBonus else dice.roll(2, 4)   // :2098-2103
stateChanges += StateChange.Heal(healAmount, StateTarget.PLAYER)                           // :2105
stateChanges += StateChange.GainXp(nonCombatXp(10, character))                             // :2106
      Признак зелья — категория POTION или подстроки зель/эликсир/potion (:2094-2095).
    • Что (архетипы): potion-health (COMMON, hp_bonus=8, 0022:351-358), potion-great (UNCOMMON, 20, :363-370), potion-elixir (RARE, 30 + str_bonus=1, :375-383).
    • Что (лут): LootTable даёт зелью hpBonus = scaled(base=4, rarity) (:252-253); LootPowerTable — consumableEffect (:40-43,53).
    • Что НЕ применяется: str_bonus/прочие бонусы зелья при использовании игнорируются — обрабатывается только hpBonus. maxHp зельем не меняется.
    • Пример (отображение в контексте): расходники для LLM фильтруются по POTION/SCROLL/EXPLOSIVE (llm/ContextBuilder.kt:247).

    13.6 Scrolls¶

    • Где: GameState.kt:178; TurnResolver.kt:2116-2129; 0022:399-411.
    • Что: категория SCROLL без слота. При использовании расходуется и наносит фиксированный урон врагу: 
      val isScroll = item.category == ItemCategory.SCROLL || item.name.lowercase().contains("свиток") // :2117-2118
if (isScroll && item.bonuses.damageBonus > 0) {                                                // :2119
    val dmg = item.bonuses.damageBonus
    stateChanges += StateChange.Damage(dmg, StateTarget.ENEMY)                                 // :2121
    stateChanges += StateChange.GainXp(nonCombatXp(15, character))                             // :2122
}
      Заклинание не резолвится: нет обращения к SpellService/SpellRegistry, нет спасброска, DC, типа урона, школы, расхода маны. При damageBonus == 0 свиток проваливается в общую ветку «Использован предмет» (:2131-2136).
    • Что (архетип): scroll-fireball (RARE, damage_bonus=5, tags="aoe,fire", 0022:400-411) — теги aoe,fire в resolveUseItem не читаются.
    • Что (изучение/спеллы): логика «прочитать свиток → выучить/применить конкретное заклинание» не найдена (grep по scroll + spell пуст). DSL-условия SPELL_SCROLL_USE (scroll.spell.level <= maxSpellLevel) и SCROLL_USE (hasSpellScroll) — action-whitelist-magic.yaml:90-92,105-107 — не подкреплены моделью предмета.

    13.7 Wands/Staves/Rods¶

    • Где: GameState.kt:169-181 (нет категорий); sessions/ItemCategoryInference.kt:15; sessions/SessionService.kt:3072,3076; action-whitelist-magic.yaml:96-104.
    • Что: ItemCategory содержит MELEE_WEAPON, RANGED_WEAPON, HELMET, BODY_ARMOR, BOOTS, RING, AMULET, POTION, SCROLL, EXPLOSIVE, MISC — WAND/STAFF/ROD отсутствуют. Все «жезлы/посохи/скипетры» классифицируются как оружие ближнего боя.
    • Пример (инференс и подарки): 
      has("меч", "топор", "дубин", "посох", "копь", ...) -> ItemCategory.MELEE_WEAPON   // ItemCategoryInference.kt:15
"посох", "жезл", "скипетр" -> ItemCategory.MELEE_WEAPON                           // SessionService.kt:3076
      giftNounRegex дробит подарки, включая жезл|скипетр (SessionService.kt:3072).
    • Пример (DSL без модели): 
      WAND_USE:  { condition: "hasWand == true && wand.charges > 0",  description: "Использование жезла" }   # :96-98
STAFF_USE: { condition: "hasStaff == true && staff.charges > 0", description: "Использование посоха" } # :99-101
ROD_USE:   { condition: "hasRod == true && rod.charges > 0",     description: "Использование скипетра" }# :102-104
      Соответствующего резолвера/категории/зарядов нет. Прочее: в sim/AiPlayer.kt:43 «Атаковать посохом» — только нарративная персонаa.

    13.8 Применение ItemBonuses¶

    • Где: rules/GameState.kt:559-603; rules/TurnResolver.kt:769,786,1676,1701,2098-2105,2206-2211; rules/ReactionResolver.kt:174; catalog/ItemCatalogService.kt:276.
    • Что: бонусы применяются из equippedItems, и только для предметов со слотом (category.slot != null) — GameState.kt:562,585. | Бонус | Где применяется | Эффект | | :--- | :--- | :--- | | acBonus | effectiveAc (GameState.kt:560-562) | AC + Σ acBonus надетого | | attackBonus | weaponAttackBonus → атака (GameState.kt:569; TurnResolver.kt:769,1676) | бонус к попаданию | | damageBonus | weaponDamageBonus → урон (GameState.kt:576; TurnResolver.kt:786,1701); ReactionResolver (:174); свиток (:2119-2121) | бонус к урону | | str…chaBonus | effectiveAttributes (GameState.kt:583-603) | бонус к характеристикам (coerce 1..30) | | hpBonus | только зелье (TurnResolver.kt:2098-2105); текст экипировки (:2211) | мгновенное лечение, не maxHp | | manaBonus | — | не читается нигде |
    • Пример (слот-фильтр 27.5): 
      return ac + equippedItems.filter { it.category?.slot != null }.sumOf { it.bonuses.acBonus } + dexDelta // GameState.kt:562
val bonus = equippedItems.filter { it.category?.slot != null }.fold(ItemBonuses()) { acc, item -> ... } // :585
    • Пример (описание экипировки, без manaBonus/attackBonus): 
      if (item.bonuses.damageBonus > 0) add("+${item.bonuses.damageBonus} урон") // TurnResolver.kt:2206
if (item.bonuses.acBonus > 0) add("+${item.bonuses.acBonus} AC")           // :2207
if (item.bonuses.hpBonus > 0) add("+${item.bonuses.hpBonus} HP")           // :2211
    • Следствия:
    • amulet-bone/amulet-arcane с hp_bonus=5/15 (0022:331,343) при надевании дают 0 механического эффекта (только текст).
    • amulet-arcane.mana_bonus=10 (0022:344) нигде не превращается в maxMana (GameState.kt:342).
    • attackBonus не заполняется каталогом (13.2) → вклад в атаку нулевой.
    • Что (EXPLOSIVE): grenade-ww2 имеет damage_bonus=4, tags=aoe (0022:386-397), но resolveUseItem не содержит ветки взрывчатки (TurnResolver.kt:2093-2136) → использование гранаты уходит в общую ветку «Использован предмет».

    Открытые вопросы¶

    1. manaBonus мапится из каталога (ItemCatalogService.kt:276) и хранится в модели (GameState.kt:211), но нигде не читается — задумано ли повышение maxMana от предметов?
    2. attackBonus есть в ItemBonuses, но источника (колонки каталога/лут-таблицы) нет — где предполагалось заполнять?
    3. hpBonus на надетых аксессуарах (amulet-bone, amulet-arcane) не влияет на maxHp — это intended или недоделка применения бонусов?
    4. action-whitelist-magic.yaml:90-110 ссылается на wand/staff/rod charges, hasSpellScroll, scroll.spell.level, hasMagicItem — подкреплённой модели нет; мёртвые условия или план?
    5. Свиток наносит плоский урон в ENEMY без спасброска/типа урона/школы — это осознанное упрощение MVP или разрыв с механикой заклинаний?
    6. Attunement отсутствует полностью — входит ли в скоуп продукта?
    7. grenade-ww2 (EXPLOSIVE) с damage_bonus=4 не имеет ветки резолва — intended или дыра?
    8. LootShowcaseService маппит gloves → AMULET и shield → MISC (:62,66) — типы без слотов; нужно ли это фиксировать в модели (перчатки/щит как экипировка)?
    9. Теги предметов (tags, в т.ч. aoe,fire) читаются каталогом (ItemCatalogService.kt:252-257,279), но в резолве предметов не используются — есть ли потребитель?

    Сводка¶

    • Реализовано: чтение каталога архетипов и лут-каталога; ItemBonuses с 11 полями; применение acBonus/damageBonus/attackBonus-поля/атрибутных бонусов для надетых предметов со слотом; лечение зелий из hpBonus (fallback 2d4); урон свитков из damageBonus; расход предметов через ConsumeItem; генерация бонусов лут-таблицами.
    • Частично: магические бонусы (attackBonus без источника, manaBonus не применяется, hpBonus только зелье); зелья (только hpBonus, прочие бонусы игнорируются); свитки (плоский урон без семантики заклинания); применение ItemBonuses (MISC без слота не даёт AC/атрибутов; hpBonus/manaBonus на экипировке не работают).
    • Отсутствует: attunement (поле/колонка/логика); charges (поле/колонка/recharge); категории WAND/STAFF/ROD; изучение/применение конкретных заклинаний из свитков; типы магического урона у предметов; DC спасброска предмета; резолв EXPLOSIVE; повышение maxHp/maxMana от надетых предметов; потребитель tags.

    Фактура из кода¶

    2.4.A tough только в ручном пути¶

    • Где: backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:187-196; backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:1837-1853; backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:2188-2219.
    • Что: начисление HP за tough выполняется только в ручном пути SessionService.levelUp (:1837) → LevelUpService.levelUp (:94). В авто-ветке GainXp (applyStateChanges) черты не обрабатываются — feats не читается и не пишется.
    • Пример: 
      // LevelUpService.kt:188-196
if (req.featId == "tough") {
    hpDelta += 2 * nextLevel
} else if ("tough" in newFeats) {
    // if already had tough before and CON didn't change, no extra
}

    2.4.B pendingASI без Feat¶

    • Где: backend/app/src/main/kotlin/com/yorva/sessions/SessionDtos.kt:107-109; backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:1687-1755; backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:33-39.
    • Что: AsiRequest содержит только allocations; featId отсутствует. allocateASI обрабатывает только повышение характеристик. featId присутствует только в LevelUpRequest.
    • Пример: 
      data class AsiRequest(
    val allocations: Map<String, Int>, // ability -> +1 or +2, sum must be 2, max 20
)

    2.4.C Frontend хардкодит 12¶

    • Где: frontend/components/game/LevelUpModal.tsx:260-275; backend/app/src/main/kotlin/com/yorva/leveling/LevelController.kt:21-22.
    • Что: список черт во фронте — 12 статических <option>. Вызова GET /api/feats во фронтенде нет. Эндпоинт существует и возвращает featRegistry.getAll().
    • Пример: 
      // LevelUpModal.tsx:263-274
<option value="tough">Крепкий +2 HP/ур</option>
<option value="alert">Бдительный</option>
...

    2.4.D tough — ветка пустая¶

    • Где: backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:187-196.
    • Что: ветка if (req.featId == "tough") начисляет 2 * nextLevel; ветка else if ("tough" in newFeats) пуста. Трекера прожитых уровней и ретроактивного начисления за прошлые уровни нет.
    • Пример: 
      if (req.featId == "tough") {
    hpDelta += 2 * nextLevel
} else if ("tough" in newFeats) {
}

    2.4.E xor¶

    • Где: backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:105-122.
    • Что: на ASI-уровне требуется ровно один из asiChoice/featId; иначе — исключение.
    • Пример: 
      require(hasAsi xor hasFeat) { "On ASI level must provide exactly one of asiChoice or featId" }

    2.4.F healer — алиас класса¶

    • Где: backend/app/src/main/kotlin/com/yorva/classes/ClassMatcherService.kt:25.
    • Что: healer и medic входят в keyword-список класса cleric; это синоним класса, не черта.
    • Пример: 
      "cleric" to listOf("жрец", "клирик", ..., "целитель", "хил", "медик", "врач", "cleric", "priest", "healer", "medic"),

    • Что: черты mobile в каталоге нет; комментарий feats.yml:62 заявляет «полноты 42».

    2.4.I Нет fallback¶

    • Где: backend/app/src/main/kotlin/com/yorva/classes/FeatRegistry.kt:24-50.
    • Что: при отсутствии feats.yml — logger.warn и return; карта остаётся пустой. Fallback-каталога нет.
    • Пример: 
      if (!res.exists()) {
    logger.warn("feats.yml not found")
    return
}

    • Что: ветка StateChange.GainXp увеличивает level, maxHp, maxHitDice, spell slots и pendingASI. feats не читается, tough-надбавка не начисляется.
    • Пример: 
      is StateChange.GainXp -> {
    xp += change.amount
    while (xp >= xpForNextLevel(level)) {
        ...
        val hpIncrease = (hitDie / 2) + 1 + conMod

    2.4.K Нет DTO Feat¶

    • Где: backend/app/src/main/kotlin/com/yorva/leveling/LevelController.kt:21-22; backend/app/src/main/kotlin/com/yorva/classes/FeatRegistry.kt:9-15.
    • Что: эндпоинт возвращает доменный Feat; отдельного DTO нет.
    • Пример: 
      @GetMapping("/api/feats")
fun feats() = featRegistry.getAll()

    2.4.L Нет проверки дубликатов¶

    • Где: backend/app/src/main/kotlin/com/yorva/classes/FeatRegistry.kt:36-45.
    • Что: загрузка кладёт черту в MutableMap по ключу id.lowercase(); при дубле существующая запись перезаписывается без предупреждения.
    • Пример: 
      val id = (it["id"] as? String ?: return@forEach).lowercase()
feats[id] = Feat(...)

    2.4.M Prerequisite «skip strict»¶

    • Где: backend/app/src/main/kotlin/com/yorva/classes/FeatRegistry.kt:13,42; backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:114-115.
    • Что: prerequisite хранится как String? и читается из YAML, но при выборе черты не проверяется. sealed Prerequisite в Kotlin-коде отсутствует.
    • Пример: 
      // LevelUpService.kt:114-115
// prereq check simplified: if contains "13" check ability >=13 (e.g., CHA 13)
// skip strict for now, just store

    2.4.N repeatable в авто-пути¶

    • Где: backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:113; backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:2188-2219.
    • Что: repeatable учитывается только в ручном levelUp. В авто-ветке GainXp механика черт отсутствует.
    • Пример: 
      if (feat.id in state.feats && !feat.repeatable) throw IllegalArgumentException("Feat already taken ${feat.id}")

    2.4.O Формулы HP различаются¶

    • Где: backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:2195-2200; backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:178-186.
    • Что: авто-формула — (hitDie / 2) + 1 + conMod от текущего CON. Ручная — avgHitDie + conModAfter плюс ретроактивная разница CON за прошлые уровни.
    • Пример: 
      // SessionService.kt:2197
val hpIncrease = (hitDie / 2) + 1 + conMod

      // LevelUpService.kt:178-186
val avg = avgHitDie(cls.hitDie)
var hpDelta = avg + conModAfter
if (conModAfter != conModBefore) {
    val retro = (conModAfter - conModBefore) * state.level
    hpDelta += retro
}

    2.4.P pendingASI сбрасывается¶

    • Где: backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:270.
    • Что: результат копирования состояния всегда содержит pendingASI = 0 — на любом уровне, не только ASI.
    • Пример: 
      pendingASI = 0, // consumed

    2.4.Q Каскад уровней + ASI¶

    • Где: backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:2190-2214.
    • Что: весь каскад уровней проходится в while; на 4/8/12/16/19 инкрементируется pendingASI. Выбор ASI/Feat в этом пути не запрашивается.
    • Пример: 
      while (xp >= xpForNextLevel(level)) {
    xp -= xpForNextLevel(level)
    level += 1
    ...
    if (level in setOf(4, 8, 12, 16, 19)) {
        pendingASI += 1
    }
}

    2.4.R Нет валидации featId¶

    • Где: backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:105-119.
    • Что: проверяются существование черты в реестре и repeatable; проверка prerequisite отсутствует.
    • Пример: 
      val feat = featRegistry.get(req.featId!!) ?: throw IllegalArgumentException("Unknown feat ${req.featId}")
if (feat.id in state.feats && !feat.repeatable) throw IllegalArgumentException("Feat already taken ${feat.id}")

    2.4.S 41 vs 42¶

    • Что: фактическое число черт — 41; комментарий в каталоге заявляет «полноты 42», во фронте — «12 MVP из 42 SRD».
    • Пример: 
      # feats.yml:62
# Остальные SRD — заглушки для полноты 42

      {/* LevelUpModal.tsx:260 */}
Выберите фит (12 MVP из 42 SRD). Задел под все.

    2.4.T healer не реализована¶

    • Где: backend/app/src/main/resources/feats.yml:22-26; Kotlin-код (отсутствует).
    • Что: черта healer есть в каталоге, но обработки её эффекта в Kotlin нет; FeatEffect в коде отсутствует.
    • Пример: 
      - id: healer

    Открытые вопросы¶

    • applyStateChanges в чек-листе указан вызываемым только из processTurn (SessionService.kt:759); в текущем коде вызовы — :959, :976 (processTurn) и :1628 (processReactionTurn) — требует уточнения охвата авто-ветки GainXp реакционным путём.
    • Ручной путь входа — SessionService.levelUp (SessionService.kt:1837-1853), вызывающий LevelUpService.levelUp (LevelUpService.kt:94); в чек-листе точка входа описана как LevelUpService.levelUp (LevelUpService.kt:94-122) — промежуточный слой SessionService в чек-листе не отражён.
    • Формулировка 2.4.D «ветка пустая» (04-feats-check-list.md:58) в текущем коде не подтверждается для основной ветки if (req.featId == "tough") (LevelUpService.kt:188-193); пустой является только else if (:194-196).
    • FeatRegistry перемещён в пакет com.yorva.classes (файл backend/app/src/main/kotlin/com/yorva/classes/FeatRegistry.kt), LevelUpService — в com.yorva.leveling; ссылки чек-листа без пути к файлу требуют уточнения пакета.
    • «FeatEffect» и «sealed Prerequisite» как типы в Kotlin-коде отсутствуют (поиск по *.kt); назначение этих терминов — из решений чек-листа, не из кода.

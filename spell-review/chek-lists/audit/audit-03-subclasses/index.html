    Фактура из кода¶

    2.2.1 subclassLevel¶

    • Где: backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:63,126; backend/app/src/main/kotlin/com/yorva/classes/CharacterClass.kt:7-22; backend/app/src/main/resources/classes.yml; backend/app/src/main/kotlin/com/yorva/rules/GameState.kt:459.
    • Что: поля subclassLevel нет ни в CharacterClass, ни в classes.yml (0 вхождений). Уровень выбора подкласса захардкожен == 3 в двух местах — preview-функции (:63) и levelUp (:126). Поле subclassId: String? = null есть в CharacterState (GameState.kt:459).
    • Пример: 
      val needsSubclass = nextLevel == 3 && state.subclassId == null && state.canonicalClassId != null // :63
val needsSubclass = nextLevel == 3 && state.subclassId == null                                   // :126

    2.2.2 Парсинг фич подкласса¶

    • Где: backend/app/src/main/kotlin/com/yorva/classes/SubclassRegistry.kt:41-47; сравнение — classes/ClassRegistry.kt:71-101,132-158; модель — classes/CharacterClass.kt:51-65.
    • Что: загрузчик подклассов строит ClassFeature только из name/level/description; поля actionType, resourceId, usesPerLevel, recharge, choice, которые модель поддерживает (CharacterClass.kt:51-65) и парсит ClassRegistry (ClassRegistry.kt:71-101, parseFeatureChoice :132-158), для 139 фич подклассов не читаются.
    • Пример: 
      ClassFeature(
    name = it["name"] as String,
    level = (it["level"] as? Int) ?: 3,
    description = it["description"] as? String ?: "",
)

    2.2.3 choice в подклассах¶

    • Где: backend/app/src/main/resources/subclasses.yml; backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:137-173.
    • Что: в subclasses.yml вхождений choice — 0. При этом generic-механизм обработки choice-фич на level-up существует: фичи класса/подкласса уровня с choice != null собираются (LevelUpService.kt:141-159), выбор валидируется и пишется в newL1Choices (:160-173).
    • Пример: 
      if (featuresGainedWithChoice.isNotEmpty()) {
    val choice = feature.choice ?: continue
    val chosen = reqChoices[feature.name] ?: throw IllegalArgumentException("Требуется выбор для фичи '${feature.name}'")
    ...
    newL1Choices[feature.name] = normalized   // :169
}

    2.2.4 Подкласс-ресурсы¶

    • Где: backend/app/src/main/kotlin/com/yorva/rules/GameState.kt:1370-1398; backend/app/src/main/kotlin/com/yorva/classes/ClassResourceHelper.kt:10-66,68-121; backend/app/src/main/resources/whitelist/action-whitelist-core.yaml:101; action-whitelist-magic.yaml:231.
    • Что: ClassResources содержит только классовые поля (rage, ki, bardicInspiration, channelDivinity, wildShape, actionSurge, secondWindUsed, layOnHands, sorceryPoints, pactSlots, arcaneRecoveryUsed, naturalRecoveryUsed). Инициализация и level-up ветвятся по characterClass.id (ClassResourceHelper.kt:12), resourceId не используется. Условие superiorityDice > 0 встречается в whitelist-YAML, но в Kotlin-коде источник переменной отсутствует (grep — 0).
    • Пример: 
      "warrior" -> ClassResources(secondWindUsed = false, actionSurge = 0, ...) // ClassResourceHelper.kt:37-41

    2.2.5 Восстановление ресурсов¶

    • Где: backend/app/src/main/kotlin/com/yorva/classes/ClassResourceHelper.kt:128-144; вызовы — backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:2266,2282.
    • Что: restore(resources, restType) реализован и различает SHORT/LONG. Ссылки чек-листа SessionService.kt:1756/:1769 устарели и сместились на :2266/:2282. Отдельного действия не требуется.
    • Пример: 
      pactSlots = resources.pactSlots?.let { if (isLong || isShort) it.restore() else it }, // :141
arcaneRecoveryUsed = if (isLong) false else resources.arcaneRecoveryUsed,           // :142

    2.2.6 Spell lists подкласса¶

    • Где: backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:225-252; модель — classes/SubclassRegistry.kt:9-15.
    • Что: дополнительные заклинания подклассов захардкожены в resolveL1Choices: домены life/light/war (:225-239), покровитель archfey/fiend/great_old_one (:240-246), происхождение чародея draconic (:247-252). Ссылка чек-листа :217-244 сместилась. Поля spellList в модели Subclass нет.
    • Пример: 
      "life" -> { extraArmor.add("HEAVY"); domainPrepared.addAll(listOf("bless", "cure-wounds")) } // :228-231
"archfey" -> patronSpells.addAll(listOf("faerie-fire", "sleep"))                           // :242

    2.2.7 Improved Critical¶

    • Где: backend/app/src/main/kotlin/com/yorva/rules/TurnResolver.kt.
    • Что: критическое попадание определяется сравнением с 20 — 21 место (:63,572,640,695,761,881,984,1101,1172,1228,1385,1462,1563,1649,1833,2252,2359,2523,2561,2630,2865). Поля/переменной critRange в коде нет. Чек-лист ссылался на «5 мест».
    • Пример: 
      val crit = attackRoll == 20 // :1649

    2.2.8 Sneak Attack¶

    • Где: backend/app/src/main/kotlin/com/yorva/rules/TurnResolver.kt:1592-1766,1737.
    • Что: реального sneak-урона нет; единственное упоминание — текст метки при скрытности с преимуществом (:1737). Поля sneakDice в CharacterState нет. Чек-лист ссылался на :1499 — ссылка сместилась.
    • Пример: 
      } + if (hidden && hasAdv) " (скрытая атака, с преимуществом)" else "" // :1737

    2.2.9 Фичи подкласса в бою¶

    • Где: backend/app/src/main/resources/reaction_triggers.yml:53,57,61,65,69,85; backend/app/src/main/kotlin/com/yorva/rules/ReactionTriggerRegistry.kt:40-90; backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:753-773; backend/app/src/main/kotlin/com/yorva/rules/TurnResolver.kt:779,1691,2605,2612,2653,2654,2677.
    • Что: из боевых фич подкласса подключены только реакции с условием subclass == ... (PARRY, CUTTING_WORDS, WARDING_FLARE, ENTROPIC_WARD, RETALIATION, RIPOSTE). Контекст реакций собирается в reactionContext (subclass = state.subclassId, :765). В TurnResolver читаются features монстров (armor_heavy, regeneration, enrage, legendary, multiattack, poison_strike); механики фич персонажа-подкласса отдельной веткой не обрабатываются. fightingStyle учитывается в атаке (TurnResolver.kt:1668-1670; старая ссылка :1430-1432 сместилась).
    • Пример: 
      condition: "hasReaction == true && subclass == 'battle_master' && level >= 3" # reaction_triggers.yml:53

    2.2.10 Синхронизация l1Choices ↔ subclassId¶

    • Где: backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:179-190,192-267,462-483; backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:126.
    • Что: resolveL1Choices обрабатывает фичи класса уровня 1 (it.level == 1, :197) и возвращает domainId среди прочего (:179-190). При создании персонажа (:462-483) сохраняются l1Choices, expertiseSkills, fightingStyle; domainPreparedSpells/patronExpandedSpells идут в подготовленные/известные (:463,469). domainId нигде не персистится (поля в CharacterState нет), subclassId при создании не выставляется — выбор подкласса остаётся отдельным шагом на L3 (LevelUpService.kt:126).
    • Пример: 
      l1Choices = l1Result.l1Choices,
expertiseSkills = l1Result.expertiseSkills,
fightingStyle = l1Result.fightingStyle, // SessionService.kt:480-482; domainId/subclassId отсутствуют

    2.2.11 SRD-каталог¶

    • Что: 318 строк, 31 подкласс, 139 записей фич - { name: ... }. Число подклассов не менялось.
    • Пример:

  classId: cleric
  name: Домен жизни

    2.2.12 resource в Subclass¶

    • Пример: 
      data class Subclass(val id: String, val classId: String, val name: String, val description: String, val features: List<ClassFeature> = emptyList())

    2.2.13 spellList в Subclass¶

    • Где: backend/app/src/main/kotlin/com/yorva/classes/SubclassRegistry.kt:9-15.
    • Что: поля spellList в модели Subclass нет.
    • Пример: 
      // полей spellList/spellListType/alwaysPrepared в Subclass нет

    2.2.14 Fallback subclasses.yml¶

    • Где: backend/app/src/main/kotlin/com/yorva/classes/SubclassRegistry.kt:24-60; сравнение — classes/ClassRegistry.kt:22,30,41,44,160.
    • Что: при отсутствии файла (:28-31) или ошибке (:57-59) логируется warn/error и происходит возврат; subclasses остаётся пустым. ClassRegistry в тех же случаях вызывает loadFallback() (:160, 12 классов).
    • Пример: 
      if (!res.exists()) { logger.warn("subclasses.yml not found"); return } // SubclassRegistry.kt:30-31

    2.2.15 Superiority Dice¶

    • Где: backend/app/src/main/kotlin/com/yorva/rules/GameState.kt:1370-1398; backend/app/src/main/resources/whitelist/action-whitelist-core.yaml:101; action-whitelist-magic.yaml:231.
    • Что: полей superiorityDiceSize/Count/Recharge в ClassResources нет. superiorityDice присутствует только как переменная в условиях whitelist-YAML; в Kotlin-контекст ActionWhitelist.evaluate она не передаётся (grep — 0).
    • Пример: 
      condition: "class == 'Fighter' && subclass == 'Battle Master' && superiorityDice > 0" # action-whitelist-core.yaml:101

    2.2.16 Тип механики spell list¶

    • Где: backend/app/src/main/kotlin/com/yorva/classes/SubclassRegistry.kt:9-15; backend/app/src/main/resources/subclasses.yml.

val finalSpellsKnown = (spellsKnown + l1Result.patronExpandedSpells).distinct()       // :469

    Открытые вопросы¶

    • subclassLevel vs хардкод == 3 (LevelUpService.kt:63,126) — требуется подтверждение выбора источника истины (согласуется с 2.1.8).
    • choice подклассов: generic-механизм уже реализован (LevelUpService.kt:137-173); требуется уточнить, достаточно ли ввода данных в subclasses.yml или нужны правки парсера SubclassRegistry.
    • superiorityDice в whitelist-YAML (action-whitelist-core.yaml:101, action-whitelist-magic.yaml:231) не имеет источника в Kotlin-контексте — условие заведомо ложно или поле планируется.
    • domainId вычисляется и используется для списков (SessionService.kt:226,463), но не персистится в CharacterState — требуется уточнить место хранения и связь с subclassId.
    • subclasses.yml без fallback (SubclassRegistry.kt:24-60) — риск пустого каталога при packaging; требуется подтвердить необходимость.
    • Каталог 31 vs ~40: какие именно подклассы SRD отсутствуют (в чек-листе упомянуты Cleric 7/7 и Wizard 8/8).

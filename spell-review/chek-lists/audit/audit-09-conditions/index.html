    Фактура из кода¶

    2.8.A Дебаффы заклинаний и target¶

    • Где: backend/app/src/main/kotlin/com/yorva/rules/GameState.kt:1120-1122,1199; backend/app/src/main/kotlin/com/yorva/spells/SpellService.kt:235-238; backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:2353-2356,2382-2387.
    • Что: ApplyStatus/RemoveStatus уже имеют target, но AddCondition(condition) и ApplyDebuff(condition, durationRounds) — без target. applyStateChanges применяет оба безусловно к игроку. SpellService.resolveDebuff при провале спасброска врага эмитит оба состояния.
    • Пример: 
      data class AddCondition(val condition: String) : StateChange                            // GameState.kt:1122
data class ApplyDebuff(val condition: String, val durationRounds: Int) : StateChange    // GameState.kt:1199
stateChanges.add(StateChange.AddCondition(effect.condition))                            // SpellService.kt:235
stateChanges.add(StateChange.ApplyDebuff(effect.condition, effect.durationRounds))      // SpellService.kt:236-238

    2.8.B applyEnemyStateChanges¶

    • Где: TurnResolver.kt:933-936; SessionService.kt:2134-2147.
    • Что: функции нет (0 вхождений). Манёвры эмитят ApplyStatus(..., StateTarget.ENEMY), но applyStateChanges обрабатывает статусы только при target == PLAYER. Враг — immutable data class, обновляется только прямыми enemy.copy(...) в TurnResolver.
    • Пример: 
      is StateChange.ApplyStatus -> {
    if (change.target == StateTarget.PLAYER) { ... }          // SessionService.kt:2134-2139
    if (change.durationRounds > 0) statusDurations[...] = ... // :2141-2143 (без гейта)
}

    2.8.C + 2.8.OO Спасброски врага¶

    • Где: GameState.kt:643-665; SavingThrowResolver.kt:62-68; TurnResolver.kt:2556-2571.
    • Что: полей conMod/saveBonusOverrides нет. resolveEnemySave читает enemy.statusSaveBonus; спас врага в бою добавляет character.effectiveAttributes.conMod.
    • Пример: 
      val saveTotal = saveRoll + character.effectiveAttributes.conMod + enemy.statusSaveBonus // TurnResolver.kt:2560
val saveDc = 13 + profile.mechanics.dcOffset                                            // TurnResolver.kt:2557

    2.8.D + 2.8.MM Длительности врага¶

    • Где: GameState.kt:643-665; SessionService.kt:2520-2540.
    • Что: Enemy.statusDurations отсутствует, tickEnemyDurations отсутствует. Игрок тикается tickDurations в конце хода.

    2.8.CC Порядок пассов и источник врага¶

    • Где: SessionService.kt:844,953,959-967.
    • Что: currentEnemy читается из session.enemyJson и обогащается mechanics.enemy при слиянии. Пассы: applyStateChanges → tickDurations → resolveSaveEnds; вражеских пассов нет.
    • Пример: 
      val allChanges = sceneChanges + mechanics.stateChanges
val stateAfterChanges = applyStateChanges(playerState, allChanges)   // :959
val tickedState = tickDurations(stateAfterChanges)                   // :963
val (newStateBeforeAutoDeathSave, saveEndRolls) = resolveSaveEnds(...) // :964

    2.8.F + 2.8.BB + 2.8.QQ Реестр состояний¶

    • Где: GameState.kt:334,441,1120-1122,1199; backend/app/src/main/resources/whitelist/action-whitelist-core.yaml:240-264; backend/app/src/main/kotlin/com/yorva/dsl/ActionWhitelist.kt:27.
    • Что: ConditionId/ConditionRegistry/ConditionResolver отсутствуют; conditions.yml нет. Словарь conditions (24 English-кода) — справочный: ActionWhitelist читает только root["action_whitelist"]. Состояния — свободные строки List<String>, маппинга English↔русский нет.
    • Пример: 
      val aw = root["action_whitelist"] as? Map<String, Any> ?: continue // ActionWhitelist.kt:27

    2.8.SS Наборы помехи через registry¶

    • Где: TurnResolver.kt:2223-2233.
    • Что: оба хелпера — хардкод-наборы строк; hasAdvantageOnAttacks не существует (0 вхождений). hasAdvantageOnSkill — только stealth + Скрыт.
    • Пример: 
      private fun hasDisadvantageOnChecks(character: CharacterState): Boolean =
    character.statuses.any { it in setOf("Отравлен", "Ошеломлён", "Испуган", "Связан", "Опутанный", "Оглушён", "Ослеплён") }

    2.8.M Модель возможностей¶

    • Где: GameState.kt:489,492,495,498,501,507-540,607-629; TurnResolver.kt:196.
    • Что: геттеры canAct/canMove/canSpeak/canAttack/canPerceive и blockedCapabilityReason есть, но точка блокировки действия гейтит только !canAct || !canAttack. Отдельных гейтов на движение/речь/восприятие нет.
    • Пример: 
      if (!character.canAct || !character.canAttack) { ... } // TurnResolver.kt:196

    2.8.N DSL-команды состояний¶

    • Где: backend/app/src/main/resources/dsl-registry.yml:114-121; ActionParser.kt:597,601.
    • Что: категория CONDITION содержит 7 команд. Пять SAVE_* маппятся в ActionType.CHECK; REMOVE_CONDITION/APPLY_CONDITION уходят в else → ActionType.NO_ROLL. Веток apply/remove condition в TurnResolver нет.
    • Пример: 
      "SAVE_DEATH","SAVE_POISON","SAVE_FIRE","SAVE_FEAR","SAVE_CHARM" -> ActionRequest(ActionType.CHECK, ...) // :597
else -> ActionRequest(ActionType.NO_ROLL, action, lower, dslId=dslId, dslTarget=target)                  // :601

    2.8.E + 2.8.JJ Снятие и чистка метаданных¶

    • Где: SessionService.kt:2145-2147,2520-2540.
    • Что: RemoveStatus удаляет только строку из statuses; statusDurations не чистится. statusSources в коде нет. tickDurations уменьшает длительности статусов и модификаторов и удаляет истёкшие статусы.
    • Пример: 
      is StateChange.RemoveStatus -> { if (change.target == StateTarget.PLAYER) statuses.remove(change.status) } // :2145-2147

    2.8.G + 2.8.FF + 2.8.TT Invisible¶

    • Где: GameState.kt (нет Невидим); spells.json:1995; TurnResolver.kt:2226-2233.
    • Что: статуса нет (0 вхождений), see_invisibility/hasAdvantageOnAttacks нет. «Невидимость» существует как заклинание, но наложение статуса не задано. Послабления укрытия для Скрытности нет.

    2.8.H + 2.8.DD + 2.8.RR Petrified¶

    • Где: GameState.kt:489,492,613-614; SpellService.kt:163-168.
    • Что: строки Окаменел/Окаменевший встречаются только в CONCENTRATION_BREAK_STATUSES. Петрификация не даёт incapacitating, сопротивления всему урону, иммунитета к яду, unconscious-семантики.
    • Пример: 
      val CONCENTRATION_BREAK_STATUSES =
    INCAPACITATING_STATUSES + setOf("Без сознания", "Окаменел", "Окаменевший") // :613-614

    2.8.I + 2.8.EE + 2.8.NN + 2.8.UU Exhaustion¶

    • Где: GameState.kt:363,484; RestService.kt:90,97,107; TurnResolver.kt (чтений character.exhaustion нет).
    • Что: поле exhaustion: Int 0..6 с инвариантом; снятие −1 за long rest. Механических штрафов (помеха с 1 уровня, ×0.5 maxHp с 4, скорость, помеха атакам/спасброскам с 3), автосмерти на 6 и applyExhaustion нет. Статус Истощён (statusNameForFamily) с полем не связан.
    • Пример: 
      val exhaustionRemoved = minOf(1, character.exhaustion) // RestService.kt:90

    2.8.J / 2.8.K + 2.8.KK / 2.8.L Профиль врага¶

    • Где: GameState.kt:643-665; SavingThrowResolver.kt:62-68; TurnResolver.kt:2556-2571.
    • Что: conditionImmunities, creatureType, targetCreatureTypes, legendaryResistance отсутствуют (0 вхождений). immunities/resistances описывают только типы урона. Расхода легендарных сопротивлений при провале спасброска нет.

    2.8.O Whitelist-контекст¶

    • Где: SessionService.kt:929-939; action-whitelist-core.yaml:65,77,137,155; ActionWhitelist.kt:263-328.
    • Что: ctx содержит только hasEnemy, enemy, hasSpellSlots, hasRangedWeapon, inCombat, hasSpell, isConcentrating, hasReaction. Статусных ключей нет; неизвестная переменная в eval даёт false, поэтому условия isRaging/hasAdvantage/isGrappled/isRestrained/hasCover/hasConcealment не выполняются.

    2.8.P / 2.8.Q Единые наборы¶

    • Где: GameState.kt:607,684; TurnResolver.kt:2229-2230,2619.
    • Что: CharacterState.INCAPACITATING_STATUSES включает Недееспособен, Enemy.INCAPACITATING_STATUSES — нет. Набор помехи атакам игрока шире (включает Связан, Опутанный, Оглушён, Ослеплён, Сбит с ног + isProne), у врага — только Отравлен, Ошеломлён, Испуган.

    2.8.R + 2.8.HH / 2.8.S + 2.8.GG / 2.8.T / 2.8.U Charmed/Frightened/Deafened/Saves¶

    • Где: GameState.kt:611,620,629; TurnResolver.kt:2224,2230,2619; SavingThrowResolver.kt:62-90.
    • Что: Очарован/Зачарован — только NO_SPEAK (:620); источника, запрета атаки по очарователю и бонуса к social нет. Испуган даёт помеху проверкам/атакам и входит в SAVE_END (:629), но без источника и запрета приближения. Оглушён (Deafened) ошибочно в INCAPACITATING (:607) и SAVE_END (:629). Модификаторов спасбросков от состояний (помеха DEX, авто-провал) нет.

    2.8.V / 2.8.W / 2.8.X Длительность и двойное наложение¶

    • Где: SessionService.kt:2141-2143,2353-2356,2382-2387; SpellService.kt:235-238.
    • Что: ApplyStatus пишет statusDurations без гейта по target (:2141-2143). ApplyDebuff игнорирует durationRounds (:2382-2387). resolveDebuff добавляет состояние дважды — через AddCondition и ApplyDebuff (SpellService.kt:235-238).
    • Пример: 
      is StateChange.ApplyStatus -> {
    if (change.target == StateTarget.PLAYER) { if (change.status !in statuses) statuses.add(change.status); ... }
    if (change.durationRounds > 0) statusDurations[change.status] = change.durationRounds  // :2141-2143
}

    2.8.Y + 2.8.LL Source tracking¶

    • Где: GameState.kt:334,441,643-665; SessionService.kt:2145-2147.
    • Что: statusSources и statusSpellLevels отсутствуют (0 вхождений). Dispel Magic не может отбирать состояния по источнику/уровню.

    2.8.Z / 2.8.AA REST и DC¶

    • Где: SessionController.kt; TurnResolver.kt:49,2557.
    • Что: эндпоинтов conditions/apply|remove нет. DC спасброска снятия захардкожен: dc = 12 для игрока (:49) и 13 + profile.mechanics.dcOffset для врага (:2557).

    Открытые вопросы¶

    • Ссылки в 08-conditions-facts.md (например, SessionService.kt:1712-2190, :844-852, :1808-1815) устарели: актуальный applyStateChanges — 2025-2460, пассы — 959-967, ApplyStatus — 2134-2144. Требуется сверить весь facts-документ или перегенерировать его.
    • Манёвры TurnResolver.kt:933-936 эмитят ApplyStatus(StateTarget.ENEMY); фактический статус не появляется нигде. Считать ли это уже подтверждённым game-breaking багом (да) или требуется отдельный тест-кейс.
    • CastSpell в applyStateChanges (:2358-2363) уже реализует смену концентрации, хотя в 08-conditions-facts.md обозначен как «заглушка». Расхождение факт-документа и кода.
    • У Enemy есть resistances/immunities только по урону — где будет храниться resistsAllDamage для Petrified: в ConditionRegistry или как вычисляемый флаг, зависит от решения 2.8.DD.

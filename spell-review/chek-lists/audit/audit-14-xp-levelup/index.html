    14.2 Таблица уровней¶

    Где: resources/level-table.yml:1-61; classes/LevelTableRegistry.kt:51-76. 

    fun xpFor(level: Int): Int = forLevel(level)?.xpRequired ?: 0        // :53
fun canLevelUp(currentLevel: Int, xp: Int): Boolean {               // :61-64
    if (currentLevel >= 20) return false
    val next = forLevel(currentLevel + 1) ?: return false
    return xp >= next.xpRequired
}
    xpRequired — кумулятивные пороги (L2=300, L3=900, L4=2700 … L20=355000). Fallback-таблица :67-76.

    14.3 Источники XP (движок)¶

    Где: rules/TurnResolver.kt. - Победа/добивание/сброс в опасность: :806, 911, 1060, 1238, 1267, 1490, 1577, 1728, 1849. Реакция: ReactionResolver.kt:87. - xpForEnemy (:1274-1279): enemy.xpReward ?: (maxHp>=30 -> 100; >=15 -> 75; else 50). - Небоевые проверки: nonCombatXp(base, character) = (base * (1.0 + character.level / 4.0)).toInt() (:1009-1011). - Исследование: addExplorationXp (:1025-1038) — разово по ключу xpTriggers; база по DC (XpRules.baseForDc, XpRules.kt:20-24); первый раз max(base, FIRST_EXPLORATION_BONUS=50) (XpRules.kt:14,30-31); пишет AddXpTrigger (:1036-1037). - NPC: :2884-2892 (nonCombatXp(75) / (50) + AddXpTrigger(npcXpTag)).

    14.4 Milestone XP за сцену¶

    Где: sessions/SessionService.kt:2068-2082. 

    val milestoneChanges = changes.asSequence()
    .filterIsInstance<StateChange.SetScene>()
    .map { it.scene }
    .filter { it.isNotBlank() }
    .distinct()
    .filter { "milestone@$it" !in state.xpTriggers }
    .flatMap { scene -> sequenceOf(
        StateChange.AddXpTrigger("milestone@$scene"),
        StateChange.GainXp((XpRules.MILESTONE_BASE * (1.0 + state.level / 4.0)).toInt().coerceAtLeast(1)),
    ) }.toList()
    MILESTONE_BASE = 50 (XpRules.kt:17). Смена сцены — computeSceneTransition (:2014-2023): combat:<name> при появлении врага, after_combat:<name> при победе; нарративный маркер [SCENE:...] (:1375-1377).

    14.5 Авто-каскад GainXp (второй путь level-up)¶

    Где: sessions/SessionService.kt:2188-2219. 

    is StateChange.GainXp -> {
    xp += change.amount
    while (xp >= xpForNextLevel(level)) {
        xp -= xpForNextLevel(level)
        level += 1
        if (level > 20) { level = 20; break }
        val hitDie = state.canonicalClassId?.let { classRegistry?.getClass(it)?.hitDie } ?: 8
        val conMod = state.effectiveAttributes.conMod
        val hpIncrease = (hitDie / 2) + 1 + conMod
        val newMaxHp = maxHp + hpIncrease.coerceAtLeast(1)
        hp = newMaxHp
        maxHp = newMaxHp
        maxHitDice += 1
        hitDice = (hitDice + 1).coerceAtMost(maxHitDice)
        val canonical = state.canonicalClassId?.let { classRegistry?.getClass(it) }
        if (canonical?.spellcastingAbility != null) {
            val newSlots = SpellSlots.forLevel(level)
            spellSlots = newSlots
            maxSpellSlots = newSlots
        }
        if (level in setOf(4, 8, 12, 16, 19)) pendingASI += 1
    }
    if (level >= 20) { level = 20; xp = 0 }
}
    xpForNextLevel (:2546-2567) — инкрементальные дельты (300, 600, 1800, 3800, 7500, 9000, 11000, 14000, 16000, 21000, 15000, 20000, 20000, 25000, 30000, 30000, 40000, 40000, 50000).

    applyStateChanges вызывается из processTurn (:959, 976), из ветки реакции (:1628) и определён в :2025; эмиссия GainXp встречается в computeSceneTransition-контексте (milestone) и в резолверах TurnResolver/ReactionResolver.

    14.7 HP при level-up — формулы различаются¶

    Авто: (hitDie/2)+1+conMod (текущий effectiveAttributes.conMod), fallback hitDie=8; hp = maxHp (полное лечение) — SessionService.kt:2195-2200. Ручной (LevelUpService.kt:175-201): 

    val conModBefore = state.effectiveAttributes.conMod
val conModAfter = newAttributes.conMod
val avg = avgHitDie(cls.hitDie)
var hpDelta = avg + conModAfter
if (conModAfter != conModBefore) hpDelta += (conModAfter - conModBefore) * state.level   // :184
if (req.featId == "tough") hpDelta += 2 * nextLevel                                      // :189
var newMaxHp = state.maxHp + hpDelta
var newHp = state.hp + hpDelta
newHp = newHp.coerceIn(0, newMaxHp)                                                       // :201
    avgHitDie (:306-308): 6→4, 8→5, 10→6, 12→7, иначе 5. Превью hpDelta (:59, 360-363) = avgHitDie(hitDie) + state.effectiveAttributes.conMod — без ретро-CON и без tough. allocateASI пересчёт CON: maxHp + conDelta * state.level (SessionService.kt:1737-1738) по базовым state.attributes (не effectiveAttributes).

    14.8 ASI¶

    • pendingASI инкремент: авто SessionService.kt:2211-2213 (hardcode setOf(4,8,12,16,19)); ручной LevelUpService.kt:270 обнуляет.
    • allocateASI (SessionService.kt:1686-1755): pendingASI <= 0 → ошибка (:1695), sum=2 и правила +2/+1+1 (:1698-1706), cap 20 с проверкой before+inc<=20 (:1720-1729), пересчёт maxHp/hp по CON и ac по DEX (:1733-1742), pendingASI = state.pendingASI - 1 (:1749).
    • В ручном levelUp pendingASI не расходуется как ресурс: выбор ASI применяется напрямую (:109-111), pendingASI обнуляется.

    14.9 ASI vs Feat¶

    14.11 Feature/spell choices¶

    Где: LevelUpService.kt:137-173, 215-247, 365-375. - featureChoices — поле Kotlin LevelUpRequest (:38); фронт отправляет (LevelUpModal.tsx:85); в openapi.yaml LevelUpRequest (:2129-2152) поле отсутствует. - Валидация SINGLE/MULTIPLE, allow-list, лишние ключи — :149-173; «Боевой стиль» → fightingStyle (:163-165). - Wizard: ровно 2 заклинания в книгу каждый уровень ≥2 (:218-237); sorcerer/bard/warlock known-caster: expected по spellChoicesFor (:238-244); иначе spellChoices должны быть пустыми (:245-247). - spellChoicesFor (:365-375): wizard 2 (≥2), FULL — 1 на уровнях {2..11,13,15,17}, HALF — {2,3,5,7,9,11,13,15,17,19}, PACT — {2,3,4,5,7,9,11,13,15,17,19}.

    14.12 Hit dice / spell slots / class resources¶

    • Ручной: maxHitDice = nextLevel; hitDice = state.hitDice + 1 (без cap) (:249-251); слоты через spellSlotsFor с учётом casterType FULL/HALF/PACT (:310-358); classResources через ClassResourceHelper.resourcesForLevelUp (:253-256; реализация ClassResourceHelper.kt:68-…).
    • Авто: maxHitDice += 1, hitDice = (hitDice+1).coerceAtMost(maxHitDice) (:2202-2203); слоты только если spellcastingAbility != null и всегда SpellSlots.forLevel (FULL-таблица), без учёта HALF/PACT (:2205-2210); classResources, features, subclass, l1Choices, fightingStyle, classLevels не трогаются.

    • SetScene: эмиссия SessionService.kt:2017,2020 и нарратив :1377; обработка :2421-2423 — только currentScene.

    14.16 Расхождение смысла xp между путями¶

    • Авто-путь хранит xp как остаток внутри текущего уровня: xp -= xpForNextLevel(level) (SessionService.kt:2191).
    • Ручной LevelUpService.canLevelUp (:92) и фронт (levelUp.ts:12) сравнивают xp с кумулятивным порогом forLevel(level+1).xpRequired (LevelTableRegistry.kt:61-64).
    • Превью xpRequired (LevelUpService.kt:78) и XP-бар (CharacterPanel.tsx:161-166) тоже используют кумулятивные значения.
    • Пример расхождения порогов L2→L3: авто xpForNextLevel(2)=600 (SessionService.kt:2548) vs ручной/фронт forLevel(3).xpRequired=900 (level-table.yml:8-9).

    Открытые вопросы¶

    1. Какое представление xp канонично — кумулятивное (таблица/фронт/ручной путь) или остаток (авто-каскад)? Требует решения до объединения путей.
    2. Авто-путь не обрабатывает features/subclass/ASI-выбор/classResources/classLevels — это осознанный «быстрый» путь или дыра?
    3. pendingASI в авто-пути инкрементируется по hardcode {4,8,12,16,19}, игнорируя cls.asiLevels (warrior/rogue имеют доп. уровни) — уточнить.
    4. Ручной levelUp обнуляет pendingASI (LevelUpService.kt:270) — теряются накопленные ASI; уточнить intended (ср. 2.4.P).
    5. featureChoices есть в Kotlin/фронте, но нет в OpenAPI LevelUpRequest (openapi.yaml:2129-2152) — синхронизировать контракт?
    6. ClearXpTriggers не эмитится; комментарий XpRules.kt:9 о сбросе по смене сцены не соответствует коду — уточнить.
    7. Формула HP: ретро-CON (LevelUpService.kt:182-185) и tough 2*nextLevel (:188-196) vs авто (hitDie/2)+1+conMod; превью hpDelta не учитывает оба — какую формулу принять (ср. 2.4.O).
    8. Авто-путь использует FULL-таблицу слотов для любого заклинателя с spellcastingAbility (игнор HALF/PACT) и fallback hitDie=8 при canonicalClassId=null — подтвердить.

    Сводка¶

    • Реализовано: модель level/xp/classLevels/xpTriggers/pendingASI; кумулятивная level-table.yml + LevelTableRegistry; источники XP в бою/реакции/небоевых проверках/исследовании/NPC/milestone; ручной детерминированный LevelUpService (ASI, feat, подкласс, feature/spell choices, слоты, hit dice, class resources, classLevels); allocateASI; 3 REST-endpoint; фронт (XP-бар, баннер, ASI-модал, LevelUpModal).
    • Частично: авто-каскад GainXp — самостоятельный мини level-up без features/subclass/ASI-выбора/classResources; HP-формулы ручного и авто путей различаются; превью hpDelta не учитывает ретро-CON и tough; prereq черт не валидируется; реализован только tough; смысл xp расходится между путями.
    • Отсутствует: эмиссия ClearXpTriggers; totalLevel/суммирование classLevels; выбор подкласса и черт в авто-пути; featureChoices в OpenAPI; учёт cls.asiLevels в авто-пути; очистка xpTriggers по смене сцены (вопреки комментарию XpRules.kt:9).

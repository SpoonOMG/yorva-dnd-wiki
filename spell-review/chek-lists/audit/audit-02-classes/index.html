    Фактура из кода¶

    2.1.1 Выбор навыков¶

    • Где: backend/app/src/main/kotlin/com/yorva/classes/CharacterClass.kt; backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:431-433; backend/app/src/main/resources/classes.yml:22-24; backend/app/src/main/kotlin/com/yorva/sessions/SessionDtos.kt:15-40.
    • Что: поля skillChoices нет ни в CharacterClass, ни в CreateSessionRequest. Навыки берутся напрямую из proficiencies.skills класса плюс фоновые.
    • Пример: 
      val classProficiencies = canonicalClass?.let {
    (it.proficiencies.skills + it.proficiencies.savingThrows).map { s -> s.lowercase() }
} ?: proficienciesForClass(request.characterClass)

      skills:
- ATHLETICS
- PERCEPTION

    2.1.2 Стартовое снаряжение¶

    • Где: CharacterClass.kt:15; ClassRegistry.kt:63-69,122; SessionService.kt:474.
    • Что: startingEquipment парсится в модель, но при создании персонажа не применяется — инвентарь пуст.
    • Пример: 
      inventory = emptyList(), proficiencies = finalProficiencies,

    2.1.3 multiclassRequirements¶

    • Где: CharacterClass.kt (поля нет); GameState.kt:461; LevelUpService.kt:207-213.
    • Что: поля multiclassRequirements в модели нет. Каркас мультикласса — classLevels — присутствует.
    • Пример: 
      val classLevels: List<ClassLevelEntry> = emptyList(),

    2.1.4 Выбор экипировки¶

    • Где: CharacterClass.kt:15,32-35.
    • Что: StartingEquipmentChoice отсутствует, используется плоский список.
    • Пример: 
      val startingEquipment: List<StartingItem>,
...
data class StartingItem(val id: String, val quantity: Int = 1)

    2.1.5 spellList¶

    • Где: ClassRegistry.kt:50-51; SessionService.kt:95-105,174-176,1798; LevelUpService.kt:229.
    • Что: resolveSpellSelection не принимает spellList и для известных кастеров (sorcerer, bard, warlock) сохраняет запрошенное как есть (без проверки принадлежности классу). getClassesForSpell используется только тестом. Реальное использование spellList — валидация подготовки (SessionService.kt:1798) и wizard-книга (LevelUpService.kt:229).
    • Пример: 
      // SessionService.kt:174-176 — без фильтра по spellList
val known = (requestedKnown ?: emptyList()).map { it.lowercase() }.distinct()
val prepared = (requestedPrepared ?: emptyList()).map { it.lowercase() }.distinct()
return Triple(known, emptyList(), prepared)

    2.1.6 L1-слоты¶

    • Где: SessionService.kt:444, SessionService.kt:2206-2209; эталон — LevelUpService.kt:310-319; GameState.kt:998-1000.
    • Что: при создании и при level-up по XP слоты выдаются по spellcastingAbility != null и full-caster таблице SpellSlots.forLevel(1), а не по casterType. Для HALF (paladin, ranger) и PACT (warlock) это даёт неверные L1-слоты. В LevelUpService уже есть casterType-ветвление.
    • Пример: 
      val spellSlots = if (canonicalClass?.spellcastingAbility != null) SpellSlots.forLevel(1) else SpellSlots()

      "FULL" -> SpellSlots.forLevel(level)   // LevelUpService.kt:314
"HALF" -> halfSlotsFor(level)
"PACT" -> pactSlotsFor(level)

    2.1.7 asiLevels¶

    • Где: classes.yml:110-117 (warrior), classes.yml:353-359 (rogue); ClassRegistry.kt:103-107.
    • Что: значения корректны, фолбэк в ClassRegistry совпадает. Дыры нет.
    • Пример: 
      asiLevels:
- 4
- 6
- 8
- 12
- 14
- 16
- 19

    2.1.8 subclassLevel¶

    • Где: CharacterClass.kt (поля нет); classes.yml (ключ отсутствует); LevelUpService.kt:63,126.
    • Что: уровня подкласса в модели/YAML нет, он захардкожен значением 3.
    • Пример: 
      val needsSubclass = nextLevel == 3 && state.subclassId == null && state.canonicalClassId != null

    2.1.9 Владение оружием/бронёй¶

    • Где: TurnResolver.kt:1676; GameState.kt:227-229.
    • Что: бонус мастерства к атаке добавляется всегда, проверки владения оружием нет. Проверок ношения брони (disadvantage STR/DEX, запрет каста) нет. ItemProperty не содержит классов simple/martial/light/medium/heavy/shield.
    • Пример: 
      } + proficiencyBonus(character.level) + character.weaponAttackBonus + fsAttackBonus

      enum class ItemProperty {
    LIGHT, HEAVY, FINESSE, REACH, TWO_HANDED, VERSATILE, THROWN, AMMUNITION, LOADING,
}

    2.1.10 Заглушки¶

    • Где: classes.yml (31 вхождение «задел»); CharacterClass.kt (поля нет); LevelUpService.kt:61,82.
    • Что: флага placeholder нет. Фичи-заглушки попадают в featuresGained без фильтрации.
    • Пример: 
      - name: Потусторонний покровитель (задел)

      var featuresGained = cls?.features?.filter { it.level == nextLevel } ?: emptyList()

    2.1.11 Ресурсы ranger/rogue¶

    • Где: ClassResourceHelper.kt:52-53.
    • Что: для ranger и rogue возвращаются пустые ресурсы — соответствует решению «оставить до подклассов».
    • Пример: 
      "ranger" -> ClassResources()
"rogue" -> ClassResources()

    2.1.12 CharacterState.features¶

    • Где: GameState.kt:658 (только Enemy.features); TurnResolver.kt:1307; SessionService.kt:480; LevelUpService.kt:274.
    • Что: у CharacterState поля features нет. Классовые фичи при создании/level-up не сохраняются, кроме l1Choices. features пишется только у врага.
    • Пример: 
      // SessionService.kt:480 — сохраняется только выбор, не фичи
l1Choices = l1Result.l1Choices,

    2.1.13 Метки предметов¶

    • Где: GameState.kt:227-229; backend/app/src/main/resources/db/changelog/changes/0022-item-archetypes.yaml:27; ItemCatalogService.kt:252-279.
    • Что: колонка tags в item_archetypes создана и читается сервисом каталога, но weapon/armor-классы владения в неё не пишутся и в бою не используются.
    • Пример: 
      - column: { name: tags, type: VARCHAR(256), defaultValue: "" }

    2.1.14 Мультикласс-casting¶

    • Где: CharacterClass.kt:13.
    • Что: задел Map<classId, spellcastingAbility> не создан, поле одно.
    • Пример: 
      val spellcastingAbility: String?, // INTELLIGENCE, WISDOM, CHARISMA или null

    2.1.15 casterType¶

    • Где: CharacterClass.kt:20; ClassRegistry.kt:108-113.
    • Что: тип остаётся String с .uppercase() и фолбэком по id; enum CasterType в коде отсутствует; валидации значения нет.
    • Пример: 
      val casterType: String = "NONE", // FULL/HALF/PACT/NONE

    2.1.16 Подкласс на L1¶

    • Где: classes.yml:1178, classes.yml:1193; SessionService.kt:240-246.
    • Что: дубль «Потусторонний покровитель» присутствует (полноценная фича с choice и «(задел)»). subclassId на L1 не выставляется; выбор покровителя обрабатывается отдельно через l1Choices.
    • Пример: 
      - name: Потусторонний покровитель
  ...
- name: Потусторонний покровитель (задел)

    2.1.17 Проверка каста¶

    • Где: SessionService.kt:444, SessionService.kt:2206.
    • Что: условие выдачи слотов — spellcastingAbility != null, а не casterType != NONE. Для текущих классов не баг, латентный риск для homebrew.
    • Пример: 
      if (canonical?.spellcastingAbility != null) { val newSlots = SpellSlots.forLevel(level); ... }

    2.1.18 Эффекты l1Choices¶

    • Где: SessionService.kt:462-471; LevelUpService.kt:138,274.
    • Что: эффекты выбора L1 (draconic HP/AC, доменные/патронные заклинания) применяются один раз при создании. На level-up l1Choices только копируются, пересчёта нет.
    • Пример: 
      val finalHp = hp + l1Result.draconicHpBonus
val finalAc = l1Result.draconicAcFloor?.let { maxOf(ac, it + attrs.dexMod) } ?: ac

    2.1.19 Валидация subclassId¶

    • Где: LevelUpService.kt:130.
    • Что: проверка принадлежности подкласса классу реализована. Расхождения нет.
    • Пример: 
      require(sub.classId == cls.id) { "Subclass $sid не принадлежит классу ${cls.id}" }

    Открытые вопросы¶

    • getClassesForSpell (ClassRegistry.kt:50-51) не используется в продуктивном коде — только в тесте (ClassRegistryTest.kt:49-50); назначение требует уточнения.
    • Решение 2.1.11 («оставить пустыми до подклассов») фактически выполнено; считать ли пункт закрытым или это ожидающее состояние — требует уточнения.
    • Заявленное в чек-листе поле CharacterState.features (GameState.kt:567) в текущем коде отсутствует; по адресу GameState.kt:567 расположен weaponAttackBonus — требует уточнения, имелся ли в виду Enemy.features.
    • Число заглушек «(задел)» в classes.yml — 31; соответствует формулировке чека «31 заглушка».

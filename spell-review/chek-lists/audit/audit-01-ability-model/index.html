    Аудит: Модель данных умений (Spell, ClassFeature, Feat, Subclass, SkillDef, Activatable, AbilityResolver)¶

    Дата: 2026-09-15 База: 01-ability-model-check-list.md

    Вердикт¶

    Подблок Статус Комментарий

    Фактура из кода¶

    1.1 Activatable / AbilityResolver¶

    • Где: backend/app/src/main/kotlin/com/yorva/spells/Spell.kt:9-23; backend/app/src/main/kotlin/com/yorva/classes/CharacterClass.kt:51-65; backend/app/src/main/kotlin/com/yorva/classes/FeatRegistry.kt:9-15; backend/app/src/main/kotlin/com/yorva/skills/SkillRegistry.kt:9-16; backend/app/src/main/kotlin/com/yorva/classes/ClassFeatureHelper.kt:22-37.
    • Что: interface Activatable и AbilityResolver в коде отсутствуют (поиск по backend/app/src/main/kotlin/ не находит ни одного объявления). Spell — обычный data class без интерфейсов. Единственный носитель полей контракта — ClassFeature. ClassFeatureHelper.detectFeature работает напрямую с ClassFeature по подстроке имени.
    • Пример: 
      data class Spell(
    val id: String,
    val name: String,
    ...
)

      data class ClassFeature(
    val name: String,
    val level: Int,
    val description: String,
    val actionType: com.yorva.rules.FeatureActionType? = null,
    val resourceId: String? = null,
    val usesPerLevel: Map<Int, Int>? = null,
    val recharge: com.yorva.rules.RestType? = null,
    val choice: FeatureChoice? = null,
)

    1.2 Расширение Spell¶

    • Где: Spell.kt:9-23,37-41,89-104; backend/app/src/main/resources/spells.json; backend/app/src/main/kotlin/com/yorva/spells/SpellRegistry.kt:29-105.
    • Что: в Spell нет duration, durationRounds, area, ritual, upcast, maxTargets. concentration объявлена только в SpellEffect.Buff (Spell.kt:92) и SpellEffect.Debuff (Spell.kt:102); SpellService вычисляет её через when по эффекту (SpellService.kt:70-74). В spells.json maxTargets встречается 90 раз, в parseSpell ключ не читается. Поля duration/durationRounds присутствуют только внутри JSON-эффектов; duration в SpellDto вычисляется из effect.durationRounds (SpellDto.kt:90-94).
    • Пример: 
      // Spell.kt:9-23 — нет duration/area/ritual/upcast/maxTargets
data class Spell(
    val id: String, val name: String, val level: Int, val school: String,
    val castingTime: CastingTime, val range: Int, val components: Components,
    val targets: TargetType, val savingThrow: SavingThrow?,
    val saveEffect: SaveEffect = SaveEffect.NONE, val effect: SpellEffect,
    val description: String, val classes: List<String>
)

      "targets": "SINGLE_ENEMY",
"maxTargets": 1,

    1.2.1 SaveEffect¶

    • Где: backend/app/src/main/kotlin/com/yorva/rules/SavingThrowResolver.kt:127-136; backend/app/src/main/kotlin/com/yorva/spells/SpellService.kt:158-164.
    • Что: enum содержит HALF, NEGATES, NONE. В resolveDamage при успешном спасброске применяется соответствующая ветка. PARTIAL отсутствует.
    • Пример: 
      enum class SaveEffect { HALF, NEGATES, NONE }

      if (saveResult.success) {
    when (spell.saveEffect) {
        SaveEffect.HALF -> totalDamage /= 2
        SaveEffect.NEGATES -> totalDamage = 0
        SaveEffect.NONE -> {}
    }
}

    1.2.2 Проверка компонентов V/S/M в canCast¶

    • Где: SpellService.kt:26-54.
    • Что: canCast проверяет caster.isIncapacitated и наличие слота (с отдельной веткой pact slots для warlock). Компоненты components в метод не передаются и не проверяются; проверок немоты/оглушения (V), свободной руки (S), наличия/расхода материала (M), дальности/видимости нет.
    • Пример: 
      fun canCast(caster: CharacterState, spell: Spell): CanCastResult {
    if (caster.isIncapacitated) { return CanCastResult(false, "...") }
    if (spell.level == 0) return CanCastResult(true, null)
    ...
    val availableSlots = caster.spellSlots.slots[spell.level] ?: 0
    if (availableSlots <= 0) { return CanCastResult(false, "...") }
    // MVP: материальные компоненты не проверяем (только флаг в JSON)
    return CanCastResult(true, null)
}

    1.2.3 school → enum School¶

    • Где: Spell.kt:13; backend/app/src/main/kotlin/com/yorva/spells/SpellDto.kt:13; SpellRegistry.kt:95.
    • Что: school — String в модели, DTO и парсере; enum школ отсутствует. Значения из spells.json ("conjuration", "abjuration" и т.п.) читаются как текст.
    • Пример: 
      val school: String,

    1.2.4 range → sealed SpellRange¶

    • Где: Spell.kt:15,46-52; SpellDto.kt:15,102.
    • Что: range — Int (футы, 0 = касание/self). SpellRange/Area отсутствуют. Геометрия области не выражена; есть только TargetType (SELF, SINGLE_ENEMY, MULTIPLE_ENEMIES, ALL_ENEMIES, SINGLE_ALLY) без размеров/форм.
    • Пример: 
      val range: Int, // футы, 0 = касание/self

    1.2.5 Вычисляемый spell save DC¶

    • Где: SpellRegistry.kt:63-66,83-86; SavingThrowResolver.kt:39,47,72,80; SpellService.kt:154; CharacterClass.kt:13; backend/app/src/main/kotlin/com/yorva/sessions/SessionService.kt:122-128,1776-1786.
    • Что: DC приходит из spells.json фиксированным ("dc": 13 для acid-splash, spells.json:19) и передаётся в SavingThrowResolver напрямую. Формула 8 + proficiencyBonus + spellcastingAbilityModifier в коде не встречается (поиск по 8 +, spellSaveDc пуст). spellcastingAbility используется только для лимита подготовленных заклинаний и для spellMod.
    • Пример: 
      // SavingThrowResolver.kt:39
val success = total >= savingThrow.dc

      // SessionService.kt:128
val preparedLimit = ((spellMod - 10) / 2 + 1).coerceAtLeast(1) // L1: mod + level

    1.2.6 MaterialComponent¶

    • Где: Spell.kt:28-32; SpellRegistry.kt:74-79; SpellService.kt:52.
    • Что: материальный компонент представлен Components.material: String? с описанием. Отдельного MaterialComponent(description, cost, consumed, focusCanSubstitute) нет; проверка расхода материала не производится (явный комментарий // MVP: материальные компоненты не проверяем).
    • Пример: 
      data class Components(
    val verbal: Boolean,
    val somatic: Boolean,
    val material: String? // описание материального компонента
)

    1.3 FeatEffect (sealed)¶

    • Где: FeatRegistry.kt:9-15; backend/app/src/main/kotlin/com/yorva/leveling/LevelUpService.kt:105-119.
    • Что: Feat содержит только id/name/description/prerequisite/repeatable. FeatEffect и подтипы (PassiveModifier, ResourcePool, TriggeredAction, Choice) отсутствуют. При level-up черта сохраняется как id; отдельно обрабатывается только tough (ad-hoc начисление HP).
    • Пример: 
      data class Feat(
    val id: String, val name: String, val description: String,
    val prerequisite: String? = null, val repeatable: Boolean = false,
)

      newFeats = newFeats + feat.id
// tough feat gives immediate HP: +2 per level (retroactive)

    1.3.1 Trigger для триггерных черт¶

    • Где: backend/app/src/main/kotlin/com/yorva/rules/GameState.kt:413.
    • Что: enum/класс Trigger и событийный хук для черт (ON_CRIT, ON_HIT, ON_DAMAGE_TAKEN и т.п.) отсутствуют. Единственное близкое по имени поле — xpTriggers (набор строк для выдачи XP).
    • Пример: 
      val xpTriggers: Set<String> = emptySet(),

    1.4 Парсер подклассов¶

    • Где: backend/app/src/main/kotlin/com/yorva/classes/SubclassRegistry.kt:41-47; ClassRegistry.kt:70-102.
    • Что: SubclassRegistry создаёт ClassFeature(name, level, description) — без actionType/resourceId/usesPerLevel/recharge/choice. Парсер ClassRegistry.parseClass/parseFeatureChoice не переиспользуется. Данные подклассов лежат в backend/app/src/main/resources/subclasses.yml.
    • Пример: 
      val feats = featsRaw.map {
    ClassFeature(
        name = it["name"] as String,
        level = (it["level"] as? Int) ?: 3,
        description = it["description"] as? String ?: "",
    )
}

    1.4.1 FeatureChoice подклассов¶

    • Где: CharacterClass.kt:37-49; ClassRegistry.kt:132-158; LevelUpService.kt:142-147.
    • Что: механизм FeatureChoice/FeatureOption/FeatureChoiceType существует и парсится для классов. LevelUpService ищет choice у фич подклассов (state.subclassId и выбираемого сейчас), но SubclassRegistry поле choice не заполняет, поэтому коллекция всегда пуста.
    • Пример: 
      state.subclassId?.let { sid ->
    subclassRegistry.get(sid)?.features?.filter { it.level == nextLevel && it.choice != null }?.forEach { featuresGainedWithChoice.add(it) }
}

    1.5 RaceRegistry / raceId¶

    • Где: GameState.kt:701; backend/app/src/main/kotlin/com/yorva/worlds/BackstoryService.kt:33; backend/app/src/main/resources/ (файла рас нет).
    • Что: классов RaceRegistry/RacialTrait и поля CharacterState.raceId нет. races.yml в ресурсах отсутствует. Раса выражается текстом через origin (используется в промптах/бэкстори).
    • Пример: 
      val origin: String? = null,

    1.6 MetamagicRegistry / InvocationRegistry + SpellModifier¶

    • Где: ClassFeatureHelper.kt:63-64; backend/app/src/main/resources/classes.yml:1104,1196; classes.yml:1080-1082,1176.
    • Что: реестры MetamagicRegistry/InvocationRegistry и SpellModifier-хук отсутствуют. В ресурсах есть заголовки «(задел)» — «Метамагия (задел)» (classes.yml:1104) и «Мистические воззвания (задел)» (classes.yml:1196). Ресурсы SORCERY_POINTS и PACT_SLOTS обрабатываются в hasResource.

      "SORCERY_POINTS" -> resources.maxSorceryPoints?.let { it - (resources.sorceryPoints ?: 0) }

    1.6.1 Комбинирование метамагии¶

    • Где: не реализовано; поиск по Metamagic/metamagic в backend/app/src/main/kotlin/ совпадений не даёт.
    • Что: механизма порядка применения и суммарной стоимости метамагии нет. Зависит от 1.6.
    • Пример: отсутствует.

    1.7 MulticlassService¶

    • Где: GameState.kt:634-637,461; LevelUpService.kt:207-213.
    • Что: MulticlassService отсутствует. Есть только задел: ClassLevelEntry(classId, level) и запись/обновление одного элемента classLevels в LevelUpService. Слоты считаются по одному canonicalClassId (LevelUpService.spellSlotsFor), PB — по level, стакание Extra Attack/pact slots не реализовано.
    • Пример: 
      data class ClassLevelEntry(val classId: String, val level: Int)

      val newClassLevels = if (state.classLevels.isEmpty()) {
    listOf(com.yorva.rules.ClassLevelEntry(cls.id, nextLevel))
} else {
    state.classLevels.map { if (it.classId == cls.id) it.copy(level = nextLevel) else it }
}

    1.8 character_json¶

    • Где: backend/app/src/main/kotlin/com/yorva/characters/CharacterEntity.kt:20-21; backend/app/src/main/kotlin/com/yorva/characters/CharacterRepository.kt; SessionService.kt:509,556,560.
    • Что: колонка character_json объявлена в entity, но characterJson нигде не читается и не пишется (внешних использований нет). Фактическое состояние персонажа — sessions.participants_json.
    • Пример: 
      @Column(name = "character_json", columnDefinition = "text")
val characterJson: String?,

    1.9 Homebrew-контент в БД¶

    • Где: backend/app/src/main/resources/spells.json; backend/app/src/main/resources/classes.yml; backend/app/src/main/resources/feats.yml; backend/app/src/main/resources/db/changelog/changes/.
    • Что: данные заклинаний/классов/черт поставляются статическими ресурсами. Liquibase-миграции создают таблицы каталога (активные каталоги action-catalog, creature-archetypes, loot-catalog и др.), но таблиц homebrew-контента для spells/classes/feats нет; поиск homebrew в backend/app/src/main/kotlin/ и resources/ совпадений не даёт.
    • Пример: отсутствует.

    1.10 sealed Prerequisite¶

    • Где: FeatRegistry.kt:13,42; backend/app/src/main/resources/feats.yml:50,55,116; LevelUpService.kt:112-116.
    • Что: prerequisite — String?, читается как текст без валидации. sealed Prerequisite/PrerequisiteGroup(AND/OR) отсутствуют. В feats.yml форматы неструктурны: "CHA 13" (стр.50), "INT или WIS 13" (стр.55), "Средняя броня" (стр.116). В LevelUpService заявлена упрощённая проверка if contains "13", фактически не реализована (сохранён комментарий).
    • Пример: 
      val prerequisite: String? = null,

      prerequisite: "INT или WIS 13"

    Открытые вопросы¶

    • maxTargets присутствует в spells.json (90 вхождений), но в Spell/SpellRegistry отсутствует: назначение ключа и причина неподключения требуют уточнения.
    • SpellDto.duration вычисляется из effect.durationRounds (SpellDto.kt:90-94), тогда как в Spell поля нет: неясно, планировалось ли поле на модели или DTO-вычисление является целевым.
    • character_json (CharacterEntity.kt:20-21) объявлен, но не используется: подтвердить, что колонка оставлена под 1.8 и не является мёртвой.
    • В чек-листе 1.1 ожидался RacialTrait в перечне реализующих Activatable, но ни RacialTrait, ни RaceRegistry (1.5) в коде нет — порядок реализации 1.1 относительно 1.5 требует уточнения.
    • LevelUpService.kt:114-116 содержит комментарий о упрощённой проверке prerequisite (по вхождению «13»), фактическая проверка отсутствует: уточнить, является ли это намеренным отложенным решением или незавершённым кодом.
    • В чек-листе 1.4.1 сказано «данные не заполнены»: в subclasses.yml поле choice не встречается — требуется подтвердить, что данные подклассов под choice вообще не готовились.

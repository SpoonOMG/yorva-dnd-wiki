    Фактура из кода¶

    Фаза 0. ADR и OpenAPI¶

    • Где: docs/adr/0010-turn-and-round-model.md:5; api-specification/openapi.yaml.
    • Что: ADR существует, но не утверждён. В OpenAPI нет ни MOVE/BONUS_ATTACK/OBJECT_INTERACTION/READY_ACTION, ни actionEconomy, ни turnSerial (поиск — 0 совпадений). Ссылки внутри ADR устарели:
    • сброс: ADR SessionService.kt:723-724 → факт SessionService.kt:822;
    • ветка реакции: ADR SessionService.kt:728-737 → факт SessionService.kt:826-835;
    • CombatState.nextRound/nextTurn: ADR GameState.kt:1436,1439 → факт GameState.kt:1466,1469;
    • 4 флага: ADR GameState.kt:1387-1390 → факт GameState.kt:1412-1420;
    • LongRest-сброс: ADR SessionService.kt:2065 → факт SessionService.kt:2283.

    2.9.L Дублирующие флаги CombatState¶

    • Где: GameState.kt:1412-1420.
    • Что: флаги не удалены; помечены @Deprecated("Use character.actionEconomy..."), но остаются полями data-класса и участвуют в nextRound()/nextTurn() (GameState.kt:1466,1469).
    • Пример: 
      @Deprecated("Use character.actionEconomy.actionUsed")
val actionUsed: Boolean = false,

    2.9.B/JJ/OO beginPlayerTurn / turnSerial / beginTurn(serial)¶

    • Где: SessionService.kt:822; GameState.kt:1282-1306.
    • Что: методов beginPlayerTurn/beginTurn и поля CharacterState.turnSerial в коде нет. Сброс — единственная строка в начале processTurn.
    • Пример: 
      // SessionService.kt:822
playerState = playerState.copy(actionEconomy = playerState.actionEconomy.reset())

    2.9.A Сброс на нормальном ходу vs follow-up реакции¶

    • Где: SessionService.kt:822,826-835.
    • Что: сброс выполняется до проверки request.reaction != null, поэтому follow-up реакция обнуляет экономию перед собственным исполнением.

    2.9.E BONUS_ATTACK¶

    • Где: ActionParser.kt:560; ActionType.kt:8-73.
    • Что: константы ActionType.BONUS_ATTACK нет. Строка "BONUS_ATTACK" из классификатора попадает в ту же ветку, что ATTACK_MELEE/ATTACK_RANGED/...; дальнейший тип определяется внутри ветки.
    • Пример: 
      "ATTACK_MELEE","ATTACK_RANGED","ATTACK_UNARMED","ATTACK_MULTI","BONUS_ATTACK",... -> {

    2.9.G castingTime¶

    • Где: TurnResolver.kt:418-449.
    • Что: слот выбирается по ActionType/dslId через ActionEconomyRegistry, castingTime не читается; маппинга «бонусное заклинание → SpendBonusAction» нет.

    2.9.F/2.7.LL TurnMechanics.merge / enemyHp¶

    • Где: TurnResolver.kt:99-119.
    • Что: у TurnMechanics нет методов merge/свойства enemyHp; агрегация Extra Attack не реализована.

    2.9.M/U ResetActionEconomy / RestoreAction¶

    • Где: GameState.kt:1211,1203-1213; SessionService.kt:2403.
    • Что: StateChange.ResetActionEconomy есть и применяется (actionEconomy = actionEconomy.reset()). StateChange.RestoreAction в sealed-иерархии отсутствует.

    2.9.N Сброс в LongRest¶

    • Где: SessionService.kt:2283.
    • Что: actionEconomy = actionEconomy.reset() в ветке LongRest сохранён.

    2.9.Q/HH bonusSpellCastThisTurn¶

    • Где: GameState.kt:1282-1306.
    • Что: поля bonusSpellCastThisTurn в ActionEconomy нет; ограничение «бонус + основное → только cantrip» не реализовано.

    2.9.C/AA/BB speed / SpeedResolver / movementUsed¶

    • Где: GameState.kt:327-471 (CharacterState), GameState.kt:643-686 (Enemy).
    • Что: CharacterState.speed, ActionEconomy.movementUsed, Enemy.speed отсутствуют. Класс SpeedResolver в backend/app/src/main не найден.

    2.9.D/MM ActionType.MOVE / MOVE_TELEPORT¶

    • Где: ActionType.kt:70; ActionParser.kt:593.
    • Что: ActionType.MOVE есть. MOVE_TELEPORT (и MOVE_CRAWL/CLIMB/SWIM/SNEAK) по-прежнему классифицируются как ActionType.CHECK, а не как SPELL/предмет.

    2.9.DD StateChange.SpendMove¶

    • Где: GameState.kt:1117-1231.
    • Что: change отсутствует; списания дистанции нет.

    2.9.R/LL Dash¶

    • Где: TurnResolver.kt:622-628.
    • Что: resolveDash возвращает нарратив и (в бою) consumesAction = true; скорость не удваивается, dashUsedThisTurn/StateChange.MarkDash отсутствуют.

    2.9.S/T Stand Up, difficult terrain¶

    • Где: action_economy.yml:21; модель движения отсутствует.
    • Что: MOVE_STAND_UP в реестре объявлен FREE; расчёт «половина speed» и ×2 за difficult terrain не реализованы.

    2.9.P/II/NN Авто-OA и Enemy.reactionUsed¶

    • Где: GameState.kt:643-686 (Enemy); TurnResolver.kt:658-674 (resolveMove); TurnResolver.kt:2535+ (applyEnemyTurn).
    • Что: у Enemy нет reactionUsed; StateChange.EnemyReactionUsed отсутствует; resolveMove не триггерит провокационную атаку. Одноразовая реакция врага не отслеживается.

    2.9.CC ActionIntent.distance¶

    • Где: ActionIntent.kt:55-61.
    • Что: поля distance нет; structured-дистанция и regex-fallback отсутствуют.

    2.9.KK Движение вне боя¶

    • Где: TurnResolver.kt:658-674; TurnResolver.kt:366-368,424; action_economy.yml:17.
    • Что: движение не тратит Action (checkActionEconomy возвращает null для MOVE, buildEconomyChanges — пусто) и помечено isNarration = true. Различия бой/вне боя нет; бюджет движения не ведётся.
    • Пример: 
      // TurnResolver.kt:366-368
if (req.type == ActionType.MOVE) return null
if (req.type == ActionType.REST) return null

    2.9.K economyCost¶

    • Где: action_economy.yml; rules/economy/ActionEconomyRegistry.kt.
    • Что: economyCost в dsl-registry.yml и whitelist/*.yaml отсутствует. Вместо него — отдельный action_economy.yml со слотами ACTION/BONUS_ACTION/REACTION/FREE/NONE и ActionEconomyRegistry (приоритет class_bonus_dsl > dsl > action_types > default).
    • Наблюдение: часть DSL-ключей MOVE_* в YAML фактически недостижима, т.к. парсер маппит их в ActionType.CHECK, а не в MOVE (ActionParser.kt:592-593); MOVE_STAND_UP в ветках парсера не встречается вовсе.

    2.9.J Free interaction¶

    • Где: GameState.kt:1209,1286,1303; SessionService.kt:2400-2401.
    • Что: StateChange.SpendFreeInteraction, ActionEconomy.freeInteractionUsed и withFreeInteractionUsed() реализованы, но ActionType.OBJECT_INTERACTION отсутствует и логики «первое взаимодействие бесплатно, затем Action» нет.

    2.9.H/EE/FF/GG READY¶

    • Где: отсутствует.
    • Что: CharacterState.readiedAction, класса/структуры ReadiedAction, ActionType.READY_ACTION, детекта триггера, истечения в beginTurn и READIED_ACTION в availableReactions нет.

    2.9.O MechanicsBlock.actionEconomy¶

    • Где: GameState.kt:1054-1099.
    • Что: поля actionEconomy в MechanicsBlock нет.

    2.9.Z Тесты¶

    • Где: backend/app/src/test/kotlin/com/yorva/rules/ActionEconomyTest.kt.
    • Что: unit-тесты есть (11 тестов: списание/отказ слота, composite-splitter, реестр слотов, Cunning Action, Action Surge). Gherkin-сценариев по action economy в component-tests/ не найдено; теста обратной совместимости JSON-сессий нет.

    Открытые вопросы¶

    • В ADR-0010 указаны строки SessionService.kt:723-724,728-737,2065 и GameState.kt:1387-1390,1436,1439; в текущем коде эти сущности находятся по другим адресам (см. Фазу 0). Требует решения: обновлять ссылки в ADR или считать ADR устаревшим.
    • Чек-лист ссылается на SessionService.kt:2144-2163 как на заглушку концентрации (TODO); в текущем коде обработка концентрации расположена около SessionService.kt:2375-2386, явного TODO не найдено.
    • action_economy.yml содержит DSL-ключи MOVE_CRAWL/CLIMB/SWIM/SNEAK/TELEPORT/STAND_UP, но ActionParser.kt:592-593 маппит первые пять в ActionType.CHECK, а MOVE_STAND_UP не маппится вовсе — часть реестра недостижима. Требует уточнения намерения (DSL-слой vs ActionType).
    • Ветка ActionType.CHECK в ActionParser.kt:560 смешивает ATTACK_MULTI и BONUS_ATTACK; фактический разбор внутри ветки не проверялся детально — требуется отдельная проверка, теряется ли BONUS_ATTACK в ATTACK.

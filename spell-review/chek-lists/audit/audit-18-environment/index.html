    Дата: 2026-09-15 База: нет (область без чек-листа)

    Фактура из кода¶

    18.1 Каталог опасностей окружения¶

    Где: db/changelog/changes/0035-environmental-hazards.yaml. Таблица environmental_hazards(code, name_ru, type, damage_per_turn, damage_type, save_attribute, save_dc, on_fail_status, description); 9 записей: open_flame, toxic_cloud, spike_pit, acid_pool, freezing_wind, collapsing_ceiling, darkness_magic, quicksand, crushed_floor.

    HazardCode — один-к-одному с каталогом (intent/ActionIntent.kt:11-21), fromCatalogCode отбрасывает неизвестные значения в null (:24-26). Загрузка: CatalogService.EnvironmentalHazardRow (catalog/CatalogService.kt:255-265), findEnvironmentalHazard (:268-285).

    Особенности данных: darkness_magic и crushed_floor имеют damage_per_turn=NULL; darkness_magic.save_attribute=NULL; quicksand без урона/статуса (только save_attribute='str').

    18.2 Разрешение опасности¶

    Где: rules/TurnResolver.kt:538-546 (dispatch), :1358-1424 (resolveHazard). 

    ActionType.HAZARD -> {
    val code = req.templateCode
    val hazard = code?.let { catalogService?.findEnvironmentalHazard(it) }
    if (hazard != null && hazard.saveAttribute != null) resolveHazard(...)
    else resolveNoRoll(action)
}
    Спасбросок: мод атрибута + proficiency при совпадении, преимущество «Уклонение» только для DEX, DC = save_dc + profile.mechanics.dcOffset (coerceIn(5,30)) (:1362-1387). Провал: урон parseDice(damagePerTurn) (:1394-1398) + статус onFailStatus (кроме «Без сознания», :1400-1403). Урон эмитится как StateChange.Damage(damage, StateTarget.PLAYER, hazard.damageType) (:1397), но damageType далее не используется (см. 18.9). Опасность срабатывает один раз за действие — повторного урона по раундам нет.

    18.3 Классификация опасностей¶

    Где: rules/ActionParser.kt. - LLM-enum имеет приоритет: intent.hazard != null → templateCode = intent.hazard.catalogCode (:397-398). - DSL-маппинг: "HAZARD_*" → hazardCodeForDsl(dslId) (:595, :658-660). - Keyword-fallback: hazardCodeFor(lower) (:508-525), вызывается при отсутствии enum (:313, :475). - Generic-HAZARD без DSL жёстко даёт open_flame: templateCode=hazardCodeForDsl("HAZARD_FIRE") (:556).

    Семантические несоответствия DSL→каталог (:659): HAZARD_LIGHTNING → freezing_wind, HAZARD_FALL → crushed_floor, HAZARD_DROWN → quicksand. freezing_wind, quicksand, crushed_floor имеют damage_per_turn=NULL, поэтому провал по этим путям не наносит урона.

    18.4 Ловушки¶

    Где: 0031-action-templates.yaml:67 (disarm_trap, keywords «ловушк\w*…»), 0015-action-catalog.yaml (таблица skill_checks — ни одной записи про ловушки), whitelist/action-whitelist-objects.yaml:197-208. Whitelist содержит DISARM_TRAP, SET_TRAP, TRIGGER_TRAP, AVOID_TRAP, SEARCH_FOR_TRAPS с условиями на trap.isDisarmed, trap.isTriggerable, hasThievesTools, hasPerception (:183-208). Эти переменные в контекст whitelist не попадают: ActionParser.kt:70-77 передаёт только hasEnemy, hasSpellSlots, hasRangedWeapon, inCombat, hasReaction; SessionService.kt:929-939 — hasEnemy, enemy, hasSpellSlots, hasRangedWeapon, inCombat, hasSpell, isConcentrating, hasReaction.

    Модели/сущности ловушки (isDisarmed, isTriggerable, trap_*) в коде нет (grep пуст). Классификация DISARM_TRAP/PICK_LOCK/SET_TRAP идёт в ActionType.OBJECT (ActionParser.kt:580) и разрешается через object_templates/resolveGenericObject (TurnResolver.kt:1342-1348); механика обнаружения, срабатывания и перезарядки ловушек отсутствует.

    18.5 Difficult terrain / перемещение¶

    Где: whitelist/action-whitelist-core.yaml:163-165 (MOVE_DIFFICULT_TERRAIN.condition: "terrain == 'difficult'"), MOVEMENT_CONDITIONAL. В GameState/TurnResolver нет поля скорости, оставшегося перемещения или типа террейна (grep по speed, terrain, difficult вне Difficulty-конфигов пуст). MOVE_DIFFICULT_TERRAIN отсутствует в action_economy.yml; дефолт для движения — FREE (action_economy.yml:17-30), тяжёлое перемещение действием не учитывается.

    18.6 Укрытие (cover/concealment)¶

    Где: whitelist/action-whitelist-core.yaml:154-156 (MOVE_HIDE.condition: "hasCover == true || hasConcealment == true"). Переменные hasCover/hasConcealment в контекст не передаются (см. 18.4), поле укрытия/степени укрытия в GameState отсутствует. Расчёт укрытия в атаках отсутствует (упоминание в 0031-action-templates.yaml ranged_attack — только в описании шаблона).

    18.7 Освещение / тьма / тёмное зрение¶

    Где: ActionParser.kt:520 (darkness_magic), action-whitelist-objects.yaml — переменных освещения нет. darkness_magic в каталоге имеет damage_per_turn=NULL, save_attribute=NULL, on_fail_status=NULL, поэтому в resolveHazard не проходит условие hazard.saveAttribute != null (TurnResolver.kt:541) и уходит в resolveNoRoll. Уровня освещения, тёмного зрения, источников света (кроме заклинания light в списке заговоров, SessionService.kt:133-158) и штрафов за темноту в правилах нет.

    18.8 Падение / утопление / истощение¶

    • Падение: fallDamagePercent применяется только при успешном ломании объекта с врагом — урон врагу (TurnResolver.kt:1484-1492); в resolveGenericObject — урон врагу maxHp/2 (:1571-1579). Урона от падения по игроку с высоты нет; HAZARD_FALL → crushed_floor (без damage_per_turn) игроку урона не наносит.
    • Утопление: HAZARD_DROWN → quicksand (ActionParser.kt:659), у quicksand нет урона/статуса; отдельной механики дыхания/утопления нет.
    • Истощение: поле exhaustion (GameState.kt:360,363) только декрементируется при long rest (SessionService.kt:2277, RestService.kt:90,97); инкремента нет. HAZARD_LIGHTNING/HAZARD_LIGHTNING→freezing_wind статусов не накладывают.

    18.9 Сопротивления/иммунитеты к урону окружения¶

    Enemy.resistances/immunities объявлены (GameState.kt:662,664) и применяются только в spells/SpellService.kt:168-178. Урон hazards эмитится StateChange.Damage(..., hazard.damageType), но SessionService.applyStateChanges для StateChange.Damage по игроку вычитает change.amount без учёта damageType, сопротивлений и иммунитетов (SessionService.kt:2086-2089). У CharacterState полей сопротивлений/иммунитетов нет (grep по GameState.kt — только Enemy). damageType hazards используется лишь в тексте описания (TurnResolver.kt:1398).

    18.10 Длительность/повторяемость опасностей¶

    Поле damage_per_turn читается один раз за срабатывание (TurnResolver.kt:1395-1397); механизма «урон каждый раунд, пока в зоне» нет. Статус накладывается StateChange.ApplyStatus(hazard.onFailStatus, StateTarget.PLAYER) без durationRounds (:1401), дефолт durationRounds=1 (GameState.kt:1120). Зоны/состояния окружения (persistent hazard) в GameState не хранятся.

    18.11 Модель объектов окружения¶

    Где: db/changelog/changes/0032-object_templates.yaml (таблица object_templates: category, ac, hp, break_attribute, break_skill, break_dc, fall_damage_percent), CatalogService.ObjectTemplateRow. Категории: door, container, barrier (ObjectCategory, ActionIntent.kt:33-44). Разрешение: resolveObjectTemplate (TurnResolver.kt:1427-1514) — контейнеры через LootTable, остальные через бросок атаки/ломания; resolveGenericObject (:1547-1589) — хардкод-fallback. Ловушек в категориях нет.

    18.12 Что отсутствует¶

    • Модель ловушки и жизненный цикл (обнаружение → обезвреживание/срабатывание → перезарядка).
    • Укрытие/степень укрытия и связанные штрафы к атакам.
    • Освещение, тёмное зрение, штрафы/помехи в темноте.
    • Скорость, оставшееся перемещение, тип террейна (difficult terrain).
    • Урон от падения по игроку с высоты, дыхание/утопление.
    • Инкремент истощения от среды/марша.
    • Повторяющийся урон зон (damage_per_turn как механика по раундам).
    • Применение сопротивлений/иммунитетов игрока к урону окружения.
    • Передача в whitelist переменных trap, area, container, door, lock, terrain, hasCover, hasConcealment, space.

    Открытые вопросы¶

    1. Поле damage_per_turn подразумевает повторяющийся урон, но реализовано как одиночный — intended ли это?
    2. Generic-HAZARD без DSL всегда маппится в open_flame (ActionParser.kt:556) — нужно ли использовать intent.hazard в этом пути?
    3. Маппинг HAZARD_FALL→crushed_floor, HAZARD_DROWN→quicksand, HAZARD_LIGHTNING→freezing_wind — намеренное упрощение или дефект?
    4. hasCover/terrain/space в whitelist без источника данных — должны ли эти поля появиться в GameState/контексте?
    5. darkness_magic без save_attribute уходит в resolveNoRoll — предполагалась ли проверка/эффект?
    6. Должны ли hazards учитывать сопротивления/иммунитеты игрока, если damageType уже проставляется?

    Сводка¶

    • Реализовано: каталог environmental_hazards (9 записей) + enum HazardCode; разрешение опасности через спасбросок с уроном/статусом (resolveHazard); три пути классификации (LLM-enum, DSL, keyword-fallback); каталог объектов окружения object_templates с ломанием/обвалом; урон врагу от обрушения объектов.
    • Частично: повторяемость опасностей (damage_per_turn — одиночный урон); связь damageType с сопротивлениями (только текст); семантика DSL→каталог (переиспользование freezing_wind/quicksand/crushed_floor).
    • Отсутствует: ловушки и их жизненный цикл; укрытие; освещение/тёмное зрение; скорость/террейн/ difficult terrain; падение с высоты по игроку; дыхание/утопление; инкремент истощения; повторяющиеся зоны; применение сопротивлений игрока к урону окружения; источник данных для переменных whitelist trap/terrain/hasCover/space.

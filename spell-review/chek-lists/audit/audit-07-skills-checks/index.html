    2.6.G Generic CHECK advantage¶

    • Где: rules/TurnResolver.kt:2246-2247 (generic); rules/TurnResolver.kt:2226 (hasAdvantageOnSkill).
    • Что: generic resolveCheck применяет только disadvantage; advantage для generic не запрашивается. hasAdvantageOnSkill используется в resolveCheckCatalog (:975) и resolveActionTemplate (:1091) и даёт advantage только для skill == "stealth" при статусе «Скрыт».
    • Пример: 
      val disadvantage = hasDisadvantageOnChecks(character)
val roll = if (disadvantage) dice.d20WithDisadvantage().first else dice.d20()

    2.6.R DC от LLM¶

    • Где: rules/TurnResolver.kt:2237 (сигнатура без dc); rules/TurnResolver.kt:2985-2992 (detectDc).
    • Что: входной dc от LLM в резолверы не передаётся; DC берётся из каталога/паттернов и зажимается coerceIn(5, 30). Например, detectDc задаёт 20/15 иначе defaultDc=10.
    • Пример: 
      private fun detectDc(action: String, defaultDc: Int, profile: DifficultyProfile): Int {
    val base = when {
        HARD_PATTERN.containsMatchIn(action) -> 20
        MEDIUM_PATTERN.containsMatchIn(action) -> 15
        else -> defaultDc
    }
    return (base + profile.mechanics.dcOffset).coerceIn(5, 30)
}

    Открытые вопросы¶

    • Расхождение ссылок чек-листа: attributeForSkill указан как TurnResolver.kt:985-993 — фактически 1211-1218 (TurnResolver.kt:985-993 соответствует resolveCheckCatalog).
    • Расхождение ссылок чек-листа: adv/disadv-хардкод указан как TurnResolver.kt:1933-1940 — фактически 2223-2224,2226.
    • activeModifiers со stat="ability_check" читаются в generic resolveCheck (TurnResolver.kt:2251), но grep по main не находит ни одного места, где такие модификаторы создаются — производитель отсутствует, требует уточнения.
    • В чек-листе 2.6.A/S поле названо CharacterState.passiveSkills — в коде поля нет (GameState.kt:327-470), как и самого passiveSkill.
    • help_action продублирован в двух источниках: skills.yml:250-256 и action_templates (0031-action-templates.yaml:35); назначение дубля требует уточнения.
    • Вайтлист уже содержит tool-специфичные CHECK_* (action-whitelist-skills.yaml:49-69), но без toolProficiencyBonus; требуется ли унификация к виду CHECK_TOOL_{type} — открыто.
    • База сессий — /api/v1/sessions (SessionController.kt:14), тогда как решения 2.6.Q/X/Y указывают путь /api/sessions/{id}/...; версия API требует уточнения.

    Аудит умений/заклинаний — Блок 2.5: Предыстории (чеклист решений)¶

Паттерны: ClassRegistry, ClassController, CharacterClass/StartingItem. Корень: каталог backgrounds.yml есть, но не читается; вся логика захардкожена в SessionService.

    Принятые решения (ядро)¶

    BackgroundRegistry + модель (2.5.A/B/C)¶

    • com.yorva.classes.BackgroundRegistry — копия-схема ClassRegistry (ClassRegistry.kt:14-49): @Component, ResourceLoader, @PostConstruct, snakeyaml, classpath:backgrounds.yml, корневой ключ backgrounds → Map<String, Map<String, Any>>.
    • Методы: get(id): Background?, getAll(): List<Background>.
    • data class Background (flat, в com.yorva.classes), зеркало CharacterClass/StartingItem: 
      data class Background(
    val id: String,
    val name: String,
    val description: String,
    val skills: List<String>,                 // lowercase, фикс. 2 навыка (SRD)
    val tools: List<String>,                  // lowercase
    val languageChoices: Int,                 // = YAML `languages` (только доп. языки; Common — всегда)
    val languagePool: LanguagePool = LanguagePool.STANDARD,  // STANDARD / EXOTIC / ANY (resolve() без Common)
    val defaultLanguages: List<String> = emptyList(),  // опц. YAML `defaultLanguages` (Z.2)
    val feature: BackgroundFeature? = null,   // через `featureId` из YAML
    val startingEquipment: List<StartingItem> = emptyList(), // переиспользуем StartedItem (CharacterClass.kt:32)
)

    Логика создания (2.5.D/E/F + P/Q/R/X)¶

    • 2.5.E: удалить getBackgroundProficiencies (SessionService.kt:69-84 [ОБНОВЛЕНО: 2026-09-15: актуальные строки — SessionService.kt:77-92]); читать из registry.get(bgId).
    • 2.5.D: bgId != null && registry.get(bgId) == null → throw NoSuchElementException("Background $id not found") (паттерн ClassController.kt:25, SessionService.kt:496,628 [ОБНОВЛЕНО: 2026-09-15: NoSuchElementException в SessionService.kt теперь на :570, :806; ссылки :496,628 устарели]). НЕ тихий fallback.
    • 2.5.F языки: languageChoices:Int (YAML languages) + languagePool: LanguagePool.
    • 2.5.P: val finalLanguages = listOf("Common") + playerChoices.take(bg.languageChoices) — Common автоматически, languageChoices только на доп. языки.
    • 2.5.Q: LanguagePool.STANDARD / EXOTIC / ANY. В YAML опц. languagePool (напр. sage: ANY).
    • 2.5.Z.1 (дополнение 2.5.Q): LanguagePool.resolve() — БЕЗ Common (Common исключён из пула, добавляется только после выбора): 
      fun LanguagePool.resolve(): List<String> = when (this) {
    STANDARD -> listOf("Dwarvish", "Elvish", "Giant", "Gnomish", "Goblin", "Halfling", "Orc") // без Common
    EXOTIC   -> listOf("Abyssal", "Celestial", "Draconic", "Deep Speech", "Infernal", "Primordial", "Sylvan", "Undercommon")
    ANY      -> STANDARD.resolve() + EXOTIC.resolve()
}
    • 2.5.R: pickDefaultLanguages детерминированно — первые N из languagePool.resolve(), сортировка по алфавиту.
    • 2.5.Z.2 (дополнение 2.5.R): defaultLanguages: List<String>? в YAML (опционально, каноничная ассоциация). Если указано — использовать его; если нет — fallback «первые N по алфавиту»: 
      acolyte:
  languages: 2
  defaultLanguages: ["Celestial", "Elvish"]
sage:
  languages: 2
  defaultLanguages: ["Draconic", "Elvish"]
    • 2.5.X валидация: 
      val choices = request.languageChoices ?: pickDefaultLanguages(bg)
require(choices.size == bg.languageChoices)     // точное число
require(choices.all { it in bg.languagePool.resolve() })
require("Common" !in choices)                    // Common автоматически

    Model: feature (2.5.G + S + T)¶

    • sealed class BackgroundFeature(id: String, name: String, description: String) — дескриптивный (подсказка для нарратива, не числовая механика).
    • Объекты ShelterOfTheFaithful, PositionOfPrivilege, Custom.
    • 2.5.S: Custom(slug: String, title: String, text: String) — slug латиница/snake_case, НЕ title, НЕ кириллица.
    • 2.5.T: маппинг через featureId в YAML (вариант B), не словарь в коде: 
      acolyte:
  feature: "Приют верующих"
  featureId: "shelter_of_faithful"
    • 2.5.Z.5 (дополнение 2.5.T): валидация featureId при загрузке BackgroundRegistry — BackgroundFeature.byId(featureId); если featureId != null && feature == null → logger.warn("Unknown featureId '$id' for background '${bg.id}'") (или строже require).
    • 2.5.Z.4 (дополнение 2.5.G/O): заполнение backgroundFeatureId в SessionService.create из bg.feature?.id: 
      val bg = backgroundRegistry.get(bgId)
val backgroundFeatureId = bg?.feature?.id
    • В CharacterState добавить backgroundFeatureId: String? (для 2.5.O — контекст/нарратив).

    Model: снаряжение (2.5.H + V)¶

    • 2.5.H: добавить startingEquipment (список {id, quantity}) в YAML + Background.startingEquipment.
    • 2.5.Z.3 (дополнение 2.5.H): валидация startingEquipment.id в каталоге предметов. Важно: статического ItemCatalog.ALL_IDS в коде нет — каталог предметов это ItemCatalogService (com.yorva.catalog.ItemCatalogService.kt:48, fun findById(id): ItemArchetype?, работает через JdbcTemplate → БД, не YAML). Проверка — require(item.id in ...) не применима статически; использовать itemCatalogService.findById(item.id) при загрузке BackgroundRegistry, при null — logger.warn + пропуск (рекомендация) либо require (строже).
    • 2.5.V: применить в grantStarterEquipment (SessionService.kt:1481-1506 [ОБНОВЛЕНО: 2026-09-15: актуальные строки — SessionService.kt:1903-1928]), дополнив фикс. sword+leather; дедупликация по id (суммировать quantity): 
      val finalInventory = (classEquipment + backgroundEquipment)
    .groupBy { it.id }
    .map { (id, items) -> items.first().copy(quantity = items.sumOf { it.quantity }) }

    REST API (2.5.J/K)¶

    • BackgroundController (паттерн ClassController.kt:6-29): GET /api/backgrounds (опц. setting для reskin), GET /api/backgrounds/{id} (throw NoSuchElementException :25).
    • 2.5.K: сериализуем Background напрямую, без DTO (flat).
    • reskin: SettingReskinService.reskin(id, "background", name, setting).

    Fallback (2.5.M + Y)¶

    • 2.5.M: loadFallback() — 13 предысторий (зеркало текущего хардкода, SessionService.kt:69-84 + :362-366 [ОБНОВЛЕНО: 2026-09-15: актуальные строки — SessionService.kt:77-92 (хардкод 13 фонов) + :439-443 (языки)]).
    • 2.5.Y: fallback только при полной неудаче (файл не найден / парсинг упал / пуст). При частичной — logger.warn + работать с тем, что есть. Каждый background валидируется отдельно (напр. пустые skills → warn/пропуск).

    Сводный отчёт: реализованные механики игрового движка¶

    Дата: 2026-09-06
    Версия движка: 0.3.0
    Архитектура: Гибридный движок (детерминированный rules-engine + LLM-нарратив)

    Общая статистика¶

    Показатель Значение
    Всего механик 45 (35 базовых + 10 новых)
    Готово к продакшену 40 (89%)
    Требует доработки 5 (11%)
    Покрытие тестами 543 tests (534 passed, 98%)
    Длинные симуляции ✅ 100/100 ходов (100%)

    Новые механики за 0.3.0: SavingThrows, ModifierApplication, DurationTracking, Enemy Multiattack, Stealth Advantage, Concentration, Skill Proficiency, ClassSystem, HitDice-классовая, ASI, Initiative Surprise.

    1. Боевая система (Combat)¶

    1.1 Атаки оружием¶

    Параметр Описание
    Механика Атака оружием ближнего/дальнего боя
    Описание d20 + STR/DEX vs AC, при попадании weapon_dice + mod
    Принцип работы Intent→ATTACK, TurnResolver: d20+mod vs AC, StateChange.Damage, Enemy.hp-=dmg
    Готовность ✅ 95%

    1.2 Критические удары¶

    Параметр Описание
    Механика Natural 20 = крит, урон ×2 (d6→2d6)
    Принцип работы if d20==20 → critDoubles (armor_heavy блокирует удвоение)
    Готовность ✅ 90%

    1.3 Преимущество/Помеха (Advantage)¶

    Параметр Описание
    Механика 2d20 → лучший/худший; скрытность/Врасплох дают advantage, Отравлен/Испуган — disadvantage, взаимная отмена
    Принцип работы hasAdv=(surprised||hidden||targetAdv)&&!disadv, hasDisadv=disadv&&!adv, max/min(2d20)
    Готовность ✅ 100% — допатчено в 0.3.0 (devlog 82), тесты StealthAdvantageTest 6/6

    1.4 Уклонение (Dodge)¶

    Параметр Описание
    Механика Статус Уклонение — враг атакует с помехой, снимается в конце хода
    Принцип работы ApplyStatus("Уклонение") + applyEnemyTurn hasDisadv
    Готовность ✅ 85%

    1.5 Смерть персонажа¶

    Параметр Описание
    Механика Permadeath + death saves (хардкор) + checkpoint 50% HP
    Принцип работы hp<=0 → isDead (permadeath) или deathSaveSuccess/Fail 0..3, Stabilized → hp=1
    Готовность ✅ 100%

    2. Система заклинаний (Spells)¶

    2.1 Применение заклинаний¶

    Параметр Описание
    Механика cast <id> → SpellService.canCast (слоты, incapacitated) → castSpell → SpendSpellSlot + Damage/Heal/Buff/Debuff
    Готовность ✅ 95%

    2.2 Справочник заклинаний¶

    Параметр Описание
    Механика SpellRegistry из spells.json (5 заклинаний), classes.yml: spellList фильтрует по классу
    Готовность ✅ 85% — нужно расширение до 30+

    2.3 Типы эффектов¶

    Параметр Описание
    Механика Damage/Healing/Buff/Debuff (sealed) + concentration флаг
    Принцип работы Buff: ApplyBuff(StatModifier, requiresConcentration), Debuff: AddCondition + savingThrow
    Готовность ✅ 95% — баффы применяются via applyModifiers

    2.4 Слоты заклинаний¶

    Параметр Описание
    Механика SpellSlots(Map level→count), forLevel(1..20) (SRD), spend/restore, half-caster ещё в коде, вынос в classes.yml — следующий
    Готовность ✅ 95%

    2.5 Концентрация — патч 0.3.0¶

    Параметр Описание
    Механика Одно активное concentrationSpell, новое прерывает старое, при уроне CON save DC=max(10, dmg/2), провал → удаление всех модификаторов источника
    Принцип работы ApplyBuff(requiresConcentration=true) → concentrationSpell=source, Damage>0 && concentrationSpell!=null → dice.d20()+conMod+prof vs DC → removeAll(source)
    Тесты ConcentrationTest 7/7
    Готовность ✅ 90% — нет уведомлений в UI, нет авто-прерывания при недееспособности

    10. Система классов — новое 0.3.0¶

    Параметр Описание
    Механика Канонические классы warrior/wizard/rogue/cleric из classes.yml (hitDie, primaryAbility, spellcastingAbility, proficiencies, startingEquipment, spellList, features, narrativeHint)
    Принцип работы ClassRegistry (SnakeYAML, fallback), ClassMatcherService keyword+hint + matchWithLlm(json) → ClassMatchResult(canonicalClassId, displayName, confidence, reasoning), CharacterState.canonicalClassId/displayClassName + Participant аналогично, HP=hitDie+CON, levelUp=hitDie/2+1+CON
    API GET /api/classes, GET /api/classes/{id}, POST /api/classes/match {input, llmJson?} (public)
    Тесты ClassRegistryTest 5, ClassMatcherTest 9 — Драконий всадник→warrior, Кибер-шаман→cleric
    Готовность ✅ 90% — нет проверки proficiencies при экипировке, нет выдачи startingEquipment
